# 框架里的例外越来越多，先找能从源头删掉的冗余设计

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

同一个前置状态在多个下游入口反复检查、补建或解释，希望先找出可以从上游消除的复杂度，再决定是否修改。

需要的材料：

- **框架位置**：当前框架仓库，或明确指定的仓库路径。
- **关注线索**：重复机制、配置或说明；没有具体线索时由实际文件定位候选。

## 前置条件与适用范围

- 被审工作区可读，包含当前未提交改动；只看 HEAD 不能代表本次材料。
- 本次只输出删减方案，不修改文件、不提交，不运行测试、构建或 Godot，也不创建游戏项目。
- 目标是找出有证据的简化机会。已确定删减范围并要求实施时，转入对应实施场景。

## 参与角色与职责边界

- **协调 Agent**：确认材料与范围，委派独立子智能体，核对报告覆盖。
- **独立审核 Agent**：阅读实际源材料，追查上游与消费者，独立形成结论。
- **用户**：在报告交付后选择实施范围；报告建议本身不是实施授权。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 维护与复盘 → 框架里的例外越来越多，先找能从源头删掉的冗余设计”。填入仓库位置和关注线索；已有对话直接补齐材料。本页采用独立审核 Agent 与框架维护规则，不启动生成项目的执行 Skill。

**S1｜确认当前材料并委派审核**

协调 Agent 在被审仓库核对 `git status --short` 与 `git rev-parse HEAD`，读取根 `AGENTS.md` 和 `framework/progress.md`。将实际路径、有效范围和只读限制交给独立子智能体；保留现有差异。

**S2｜追到产生例外的上游**

独立审核 Agent 从具体重复或分支追到产生该状态的实现、配置与直接消费者，按需读取复制清单、Skill、规范、提示词及测试源码。

- 查明下游为何需要该分支、是否已有上游保证，以及哪些正常使用者仍依赖它。
- 先核实历史简化方向的当前完成情况，只展开仍存在或新发现的问题。
- 读取测试源码只判断设计的检查范围，不宣称执行通过。

**S3｜比较最小简化与能力损失**

独立审核 Agent 按[职责设计准则](../../../../docs/framework-maintenance/design-guidelines/README.md)评价候选，说明小改动能具体删除什么，以及会失去什么。

保留授权、实际人工验收、已有内容、数据保护和真实错误处理；不把复杂度转移为用户手工操作、隐含约定或新增包装层。

**S4｜交付可选择的方案**

独立审核 Agent 在对话中给出候选的场景、证据位置、上下游关系、最小修改、可删除内容、能力代价及最小验证建议。按收益、局部性与行为可确认程度排序，区分建议实施、需要决定和不建议简化。

协调 Agent 核对覆盖及证据限制。文本、Skill、脚本、提示词分别说明实际涉及的结论；同一根因只展开一次。交付后结束本次只读审核，等待用户选择修改范围。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 独立实例已获得当前工作区和只读范围；不能委派时已如实说明 |
| S2 | 候选能追到上游条件、消费者和真实用途 |
| S3 | 可删除内容与必须保留的能力均有具体依据 |
| S4 | 用户能据报告选择范围；无成立候选也可形成结论 |

## 资源与文件影响

- **只读**：当前实现、配置、复制清单、规则、Skill、提示词、手册、回归源码及已有差异。
- **输出**：对话中的审核报告；不落盘、不创建修复任务或修改业务项目。

## 阻塞、异常与范围变化

无法取得源码、消费者或运行证据时保留未知，继续能够独立判断的部分。不能实际委派时说明独立审核未完成，不以协调者的自查替代。需要运行或修改才能确认的事项只给出建议，不能在本入口自动实施。

## 完成状态与验证标准

审核报告已交付，成立候选均可定位到当前文件，并说明最小改变、可删除内容、能力代价与验证建议。未涉及和证据不足的范围明确，被审文件及项目状态未被修改；报告完成不表示方案已实施。
