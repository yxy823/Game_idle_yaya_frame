# 当前任务反复返工，先复盘原因

[返回场景索引](../../scenario-index.md)

## 触发场景与使用时机

只读复盘当前或最近一次任务中反复沟通、尝试或返工的原因，给出有依据的改进建议。可以在任务仍进行时提出，不必等一个阶段正式结束，也不必另找一个对话。

## 前置条件与适用范围

在框架维护仓库处理。只分析指定任务的实际经过，不要求任务已经结束，也不扩展为其他对话或全项目审核。本次只读分析，结论留在对话。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 维护与复盘 → 当前任务反复返工，先复盘原因”。提供任务目标、当时的要求与授权、相关对话或执行记录、具体反复环节和原始结果。已有对话直接补齐必要材料，不必重发模板。当前 Agent 按实际证据与现有职责准则处理。

**S1｜还原指定的反复环节**

核对时间顺序、事发版本、有效决定、实际动作和结果；区分已证实原因、局部失误、环境限制、规则冲突与仍待检验的假设。

**S2｜交付有依据的原因与建议**

交付主要原因与证据、值得保留的做法、最小改进及其归属；说明无法确认的部分。没有必要修改也是有效结论；未知原因如实保留。

## 资源与文件影响

相关材料可按需只读查阅，包括文件与 Git 历史；不写知识、报告或流程文件，不执行项目运行或验证命令，不创建自动任务。

## 阻塞、异常与范围变化

缺少相关经过或原件时，说明能确认与不能确认的部分，不编造因果。本场景不授予实施权限，后续明确授权由原有负责者承接。

## 完成状态与验证标准

指定反复环节已有可追查的分析和建议，尚不能确认的原因明确标为未知，没有自动修改规则或实现工具。对照相关原件检验因果解释与适用边界，检查已有覆盖；未读取的对话、未执行的验证和今天才存在的规则不得作为当时事实。

## 流程关联与衔接关系

依据：[框架维护约定](../../../../../AGENTS.md)与[职责设计准则](../../../../docs/framework-maintenance/responsibility-design-guidelines.md)。用户已识别一类重复工作、希望设计以后怎么处理时，转到[方法设计场景](../设计与借鉴/同类工作总要重复交代，先设计复用方法.md)由当前 Agent 讨论；本页只分析实际经过。场景结束不撤销原任务仍有效的后续授权。
