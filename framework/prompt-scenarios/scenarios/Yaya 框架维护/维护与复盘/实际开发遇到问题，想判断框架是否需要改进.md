# 实际开发遇到问题，想判断框架是否需要改进

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

实际开发遇到问题，想判断框架是否需要改进。需要的材料：

- **开发现场：** 实际开发输出、关键对话、日志和原始结果。
- **原任务：** 当时的目标、范围、有效授权与期望行为。
- **核对线索：** 实际项目、框架版本或相关来源；缺失时保留为待核实项。
- **关注点与交付：** 需要判断的具体问题，以及是否需要保存报告、获准的输出位置。

## 前置条件与适用范围

有实际项目的原始输出与过程；本次做归因而非重跑开发。

## 执行步骤

使用[集中提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 维护与复盘 → 实际开发遇到问题，想判断框架是否需要改进”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 按实际证据与现有职责准则处理；需要独立审核的步骤明确交给独立实例。

**S1｜还原反馈现场**

当前 Agent 读取任务指令、实际输出和版本，区分要求、行为与证据缺失。

**S2｜核对框架责任**

对照对应规则、Skill 与工具，判断框架缺陷、使用方式或环境原因。

**S3｜提出最小改进**

给出保留、简化或修正建议及验证方式，必要时起草下一条指令。原项目后续查 [Godot 开发提示词库](../../../prompts/godot-development-prompts.json)，框架修正查 [Yaya 框架维护提示词库](../../../prompts/yaya-maintenance-prompts.json)，说明所选场景及接收位置；没有适用条目时直接起草，不强套模板。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 问题触发链可追查 |
| S2 | 归因和不确定性分开 |
| S3 | 接收者可判断是否实施 |

## 资源与文件影响

被审源与原始证据只读；只写获准报告。

## 阻塞、异常与范围变化

证据不可用时收窄结论；不把静态推演写成真实运行。

## 完成状态与验证标准

反馈已有可追查归因和建议；未代替原项目修改或重跑。
