# 收到外部审核意见，先核实哪些值得修改

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

收到外部审核意见，先核实哪些值得修改。需要的材料：

- **复核对象与范围：** 检查范围、版本或原始材料。
- **交付位置：** 报告输出位置。

## 前置条件与适用范围

已有外部报告与可核实的被审版本，需要判断问题与改法。

## 执行步骤

使用[集中提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 维护与复盘 → 收到外部审核意见，先核实哪些值得修改”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用现有规则和工具处理；需要独立审核的步骤明确交给独立实例。

**S1｜核对报告版本**

当前 Agent 在本次静态复核范围内对照报告所指版本与当前源，标明已变更和无法复核部分，再按下文分别判断事实与改法。

**S2｜分别判断事实与建议**

逐项追查触发和实现，分别判断问题成立与改法值得采用，不默认全部照做。

涉及文本与职责意见时，按[职责设计准则](../../../../maintenance/design-guidelines/README.md)区分文本层级、Skill 目标、脚本公开接口与副作用、提示词和同名场景的边界。篇幅长或步骤多本身不是拆分理由。

**S3｜交付复核结论**

列建议实施顺序、范围与验证，待已有授权或新的明确选择承接实施。

报告分别说明文本编写、Skill 职责、脚本职责、提示词与场景的相关结论。原报告未涉及的类别明确标注，不因此开展无关全量审核，也不写成已通过。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 意见对应对象清楚 |
| S2 | 去重后的取舍建议有依据 |
| S3 | 可选择的具体调整已说明 |

## 资源与文件影响

被审源与原始证据只读；只写获准报告。

## 阻塞、异常与范围变化

证据不可用时收窄结论；不把静态推演写成真实运行。

## 完成状态与验证标准

全部范围内意见有事实与取舍结论，本次不自行实施建议。
