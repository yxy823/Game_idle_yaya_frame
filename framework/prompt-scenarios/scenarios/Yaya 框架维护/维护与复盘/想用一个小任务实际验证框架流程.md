# 想用一个小任务实际验证框架流程

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

想用一个小任务实际验证框架流程。需要的材料：

- **验证依据与范围**：指定外部项目、已有 GDD、微型交付范围及被测框架版本。
- **交付位置**：报告输出位置。

## 前置条件与适用范围

已授权指定外部验证项目、GDD 中已有的微型交付和运行范围；项目已采用本次被测文件且有真实 GDD，框架源只读。本次不覆盖创建器或 GDD 初始化。

## 执行步骤

使用[集中提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 维护与复盘 → 想用一个小任务实际验证框架流程”。填入上述材料。

**S1｜核对验证项目**

- **核对输入**：当前 Agent 确认指定项目路径、真实 GDD 和微型交付边界，核对被测文件对应当前框架版本。需要同步时只修改已明确授权的具体文件，保留机器配置及无关内容。
- **核对环境**：在目标项目读取其 `docs/methodology-config.json`，复用仍有效的实际准备，必要时执行 `yaya/tools/checks/check-project-environment.py --require-ready` 并读取真实结果。

**S2｜完成微型任务**

- **需求与实施**：只在外部验证项目中使用 `product-author` 对照已有 GDD 预拆分当前约定范围，再细化已轮到的微型 Product；`feature-plan` 覆盖其完整必要范围，再由 `feature-execute` 完成实际实现和适用检查。
- **计划与自动测试**：项目 Python 调用 `yaya/tools/checks/check-feature-list.py` 核对计划，自动测试通过 `yaya/tools/testing/run-gdunit-tests.py --feature <实际ID> --scope <实际范围>` 执行；保留所有原始结果。
- **人工义务与执行边界**：人工义务到真实体验交接点停止，不伪造接受；维护仓库不激活这些项目流程。

**S3｜回报流程问题**

区分原框架、使用误解和环境问题，保存实际命令、失败、停止位置及最小改进建议。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 项目及运行授权可核实 |
| S2 | 每阶段有原始结果而非模拟通过 |
| S3 | 动态覆盖及未覆盖范围明确 |

## 资源与文件影响

- **只读对象**：框架维护源及未选作验证目标的其他游戏项目只读。
- **可写对象**：指定外部验证项目获准维护相关 Product、计划、业务实现、测试、运行报告、必要进度记录和本地提交。
- **Git 责任**：保留已有仓库和历史，来源、规划及交付提交遵循该项目实际规则。
- **验证保护**：不得修改复制后的框架规则、Skill 或公共工具来使验证通过；原始证据保留。

## 阻塞、异常与范围变化

缺少真实 GDD、指定项目不可访问或被测版本无法核实时说明缺口并停止依赖工作，不现场生成占位设计。证据不可用时收窄结论；不把静态推演写成真实运行。

## 完成状态与验证标准

指定微型流程的实际证据报告完成；未获得人工验收的工作如实保留。

## 流程关联与衔接关系

项目 Skill 在目标自己的 `.agents/skills/` 使用；源契约可核对 [product-author](../../../../../project-source/skills/product-author/SKILL.md)、[feature-plan](../../../../../project-source/skills/feature-plan/SKILL.md)和 [feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md)。

依据：[维护约定](<../../../../../AGENTS.md>)、[职责设计准则](<../../../../maintenance/design-guidelines/README.md>)。
