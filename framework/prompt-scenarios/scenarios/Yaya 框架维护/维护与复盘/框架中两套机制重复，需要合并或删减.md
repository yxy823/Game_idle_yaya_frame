# 框架中两套机制重复，需要合并或删减

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

两个 Skill、脚本或文档在做同一件事，例如两处都在维护同一张路径表，改一处时另一处总被漏掉。需要的材料：

- **重复机制**：两套机制的路径或名称，以及发现重复的依据（审核报告、实际漏改的例子）。
- **保留要求**：必须保留的职责或入口；没写时由 Agent 按实际消费者判断后在修改前说明。
- **验证范围**：允许运行的检查；没写时只做静态核对和仓库回归。

实际消费者由 Agent 搜索调用方得出，不需要提供。

## 前置条件与适用范围

已有重复证据，需要消除重复同时保留有效能力。

## 执行步骤

使用[集中提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 维护与复盘 → 框架中两套机制重复，需要合并或删减”。填入上述材料。

**S1｜列清实际责任**

当前 Agent 阅读两套机制及调用者，确认各自独有行为、失败保护与保留价值。

**S2｜合并活动入口**

将有效职责保留到唯一实现，更新引用、配置和复制清单后删除失去用途的副本。

**S3｜核对行为保留**

验证被合并能力与必要异常路径，检查失效引用和差异后本地提交。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 两套机制的独有行为与接替位置已列出 |
| S2 | 搜索不到对已删除副本的引用 |
| S3 | 实际运行的检查及结果、本地提交哈希 |

## 资源与文件影响

重复实现可能删除；保留实现、调用者和说明同步修改。

## 阻塞、异常与范围变化

发现独有且仍需的行为时先安排接替，不能因文件相似直接删除。

## 完成状态与验证标准

重复入口已消除，有效职责有明确承接，引用和适用验证无缺口。
