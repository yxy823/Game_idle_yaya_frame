# 想检查本地框架是否自洽，先做静态审核

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

想检查本地框架是否自洽，先做静态审核。需要的材料：

- **审核对象与范围**：检查范围、版本或原始材料。
- **交付位置**：报告输出位置。

## 前置条件与适用范围

本地源可读，指定检查范围与报告位置；本次不实施修复。

## 执行步骤

使用[集中提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 维护与复盘 → 想检查本地框架是否自洽，先做静态审核”。填入上述材料。

**S1｜固定检查基线**

独立审核 Agent 核对当前提交和真实差异，按范围建立生产入口、规范与调用者清单。

**S2｜追查实际契约**

独立审核 Agent 逐对象读取正文与实现，检查读写方、完成语义、复制边界和说明关系；不能用目录枚举代替审查。按[职责设计准则](../../../../maintenance/design-guidelines/README.md)分别检查：

其中 AGENTS.md、Skill、任务提示词与条件规则按[规则与提示词文件维护约定](../../../../maintenance/design-guidelines/instruction-files.md)核对；脚本和其他材料按各自依据审查。作者自查不能代替本次请求的独立结论。

- **文本编写**：标题、术语、段落与列表层级、实体分类目录、重复正文及内容归属。
- **Skill 职责**：意图、输出、依赖、生命周期和授权边界。
- **脚本职责**：公开入口、成功条件、副作用、失败重试和资源清理。
- **提示词与场景**：单一目标、同名路径、输入、授权与出口。

整体审核须覆盖范围内的实际对象，有限抽查只能给出相应范围结论。

**S3｜交付独立结论**

独立审核 Agent 区分已确认问题、推断与运行缺口，列最小调整及复验建议。报告分别列出上述四类的覆盖、依据和结论，未发现问题、证据不足与未涉及明确区分；详情只展开一次。默认在对话中交付，仅按明确路径保存到 `tmp/reports/<任务>/`。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 被审版本和覆盖边界明确 |
| S2 | 问题具有可定位依据 |
| S3 | 报告覆盖、发现与限制明确 |

## 资源与文件影响

被审源与原始证据只读；只写获准报告。

## 阻塞、异常与范围变化

证据不可用时收窄结论；不把静态推演写成真实运行。

## 完成状态与验证标准

有当前文件依据的审核报告已交付，未修改被审源。
