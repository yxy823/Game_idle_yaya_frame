# 框架文件位置混乱，需要整理目录

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

框架文件位置混乱，需要整理目录。需要的材料：

- **整理目标**：目标目录、职责划分。
- **保留边界**：需要保留的入口。

## 前置条件与适用范围

本次只调整组织与命名，不改变 Skill 或工具行为。

## 执行步骤

使用[集中提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 维护与复盘 → 框架文件位置混乱，需要整理目录”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用现有规则和工具处理；需要独立审核的步骤明确交给独立实例。

**S1｜确定职责归属**

当前 Agent 按维护源、可复制材料、手册、审核材料核对文件实际用途并安排目标位置。

多专题正文按读者主题建立实体子目录，索引分组与目录对应；根目录保留入口、公共资料和必要生成产物。简述移动方案，不只在 README 中分组后继续平铺所有正文，也不创建空分类或过深目录。

**S2｜移动并修复引用**

验证源和目标绝对路径均在获准目录内，再逐项移动，追踪脚本、复制清单、文档及测试夹具引用。

**S3｜检查可达性**

运行现有路径及链接检查，核对没有遗失文件或残留活动入口，按根规则提交。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 每类材料有唯一归属 |
| S2 | 新位置及全部调用路径一致 |
| S3 | 目录可导航且运行契约未变 |

## 资源与文件影响

文件路径和引用修改；不借整理改变实现语义。

## 阻塞、异常与范围变化

发现需要职责拆分时单独记录或使用已有明确授权，不能在纯目录整理里静默改变行为。

## 完成状态与验证标准

材料按职责可定位，原有有效引用已更新，结构检查通过。
