# 框架文件位置混乱，需要整理目录

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

框架某个目录里功能不同的文件平铺在一起，或同类文件散在几处，找文件要靠记忆，想按职责重新分目录、改名。需要的材料：

- **整理目标**：要整理的目录，以及你期望的职责划分（原话即可）；只给目录时，由 Agent 先提出划分方案。
- **保留边界**（可选）：必须保持原路径的入口，例如被外部固定引用的文件；不填时只保留工具约定的文件名和根 AGENTS.md 写明的固定路径。

## 前置条件与适用范围

本次只调整组织与命名，不改变 Skill 或工具行为。

## 执行步骤

使用[集中提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 维护与复盘 → 框架文件位置混乱，需要整理目录”，把上述材料填入 `${1}`。

**S1｜确定职责归属**

当前 Agent 核对每个文件的实际用途，按[目录组织](../../../../maintenance/design-guidelines/document-responsibilities.md#目录组织)的三个问题确定位置：材料讲述的对象决定顶层目录，功能不同就建子目录，脚本放进所属对象的 `tools/`。先简述移动方案，不只在 README 中分组后继续平铺，也不创建空分类或过深目录。

**S2｜移动并修复引用**

确认源和目标路径都在获准目录内，再逐项移动，追踪脚本路径常量、复制清单、文档链接与锚点、两份提示词库中的路径文本和测试夹具。

**S3｜检查可达性**

运行链接检查、提示词与场景路径检查和仓库回归，核对没有遗失文件或残留活动入口，按[本地提交](../../../../../AGENTS.md#本地提交)提交。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 每个文件的目标路径和归属理由已列出 |
| S2 | 旧路径在仓库和两份提示词库中已无残留引用 |
| S3 | 各项检查的结果和提交哈希已记录 |

## 资源与文件影响

文件路径和引用修改；不借整理改变实现语义。

## 阻塞、异常与范围变化

发现需要职责拆分时单独记录或使用已有明确授权，不能在纯目录整理里静默改变行为。

## 完成状态与验证标准

材料按职责可定位，原有有效引用已更新，结构检查通过。
