# 想知道框架还有哪些待办，并确定下一步

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

隔了几天回到框架维护，或刚做完一项框架修改，想先弄清还有什么没做完、哪一项该先做。需要的材料：

- **关注的主题**（可选）：例如“调试台还差什么”；不填时看全部待办。

待办、工作区状态和最近的提交由 Agent 直接读取。

## 前置条件与适用范围

只读查询，不修改文件，也不执行建议。要把当前对话的未完成工作交给新对话时，改用[框架任务还没做完，准备换一个对话继续](<框架任务还没做完，准备换一个对话继续.md>)。

## 执行步骤

使用[预设提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 现状与交接 → 想知道框架还有哪些待办，并确定下一步”。填入上述材料。当前 Agent 使用已有方法只读处理。

**S1｜读取待办与工作区**

当前 Agent 读取 `framework/todo.md`、`git status`、`git diff --stat` 和最近的提交；只凭待办条目无法判断下一步时，补读条目引用的 `tmp/` 报告中与判断相关的部分。

**S2｜说明待办与推荐下一步**

按主题列出待办及各自的下一步、阻塞与依据；工作区有未提交的改动时，说明它们属于哪一项待办或无法归属。然后给出优先下一步、推荐理由、对应的维护提示词入口与最少所需材料。`framework/todo.md` 与实际状态不一致时，写明需要更新的条目。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 待办条目、未提交改动和最近的提交已读取 |
| S2 | 待办清单、优先下一步、对应入口和需要更新的待办条目已说明；或说明没有待办的依据 |

## 资源与文件影响

仓库文件只读；输出在对话，不更新 `framework/todo.md`。

## 阻塞、异常与范围变化

待办条目引用的报告缺失或与当前文件冲突时，标为未知并说明核实方法，不把推测写成结论。

## 完成状态与验证标准

当前待办、工作区状态和有依据的下一步建议已说明，需要更新的待办条目已指出；本次没有修改文件或执行建议。

## 流程关联与衔接关系

依据：`framework/AGENTS.md` 的[框架待办](<../../../../AGENTS.md#框架待办>)。待办条目不授予实施权限；选定下一步后，用推荐的入口另行发起。
