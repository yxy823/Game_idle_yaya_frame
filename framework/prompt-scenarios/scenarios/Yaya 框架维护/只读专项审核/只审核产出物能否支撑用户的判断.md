# 只审核产出物能否支撑用户的判断

[返回场景索引](../../scenario-index.md#只读专项审核) · [通用模板](专项审核通用模板.md)

## 触发场景与使用时机

框架交给你看的东西，你看了却做不出决定，例如用 ASCII 线框图讨论布局时看不出比例和对齐；或者想提前查一遍，哪些交给你判断的产出物用错了形式。其他专题只核对文件之间是否一致，查不出这类问题。

## 前置条件与适用范围

本专题回答的问题：框架要求交给用户判断的每个产出物，形式能否让用户真的看出要判断的东西；看不出时会在哪一步做错决定，应该换成什么形式。

具体范围、必读来源和检查要点都写在提示词里，无需填写参数。审核只读，不修改任何文件。只给 Agent 自己读的产出物不在范围内。

## 执行步骤

**S1｜拼接并发送提示词**

1. 打开一个新对话；这个对话不能参与过被审内容的修改。
2. 复制[Yaya 框架维护提示词库](../../../prompts/yaya-maintenance-prompts.json)中的「只读专项审核 → 专项审核通用模板」。
3. 把「只读专项审核 → 只审核产出物能否支撑用户的判断」的内容粘贴到模板末尾的「本次专题」下方。只想查某一类产出物时，在专题末尾加一句写明，例如“只查调试台和人工验收”。
4. 发送。

**S2｜等待审核报告**

审核 Agent 先用 ASCII 线框图这个正例校准判断标准，再逐个产出物扮演用户尝试做决定，写出看不出来的步骤和替代形式。在对话中交付报告。需要留存时，明确要求保存到 `tmp/reports/<任务>/`。

## 完成状态与验证标准

收到按通用模板结构交付的报告：先逐步写出 2–3 个具体任务的推演，再用一张表列出每个产出物、用户要判断什么、当前形式、能否判断、理由和建议的替代形式。报告只给建议，不包含实现。

## 流程关联与衔接关系

本专题查产出物的形式是否合适；产出物根本不存在时，改用[只审核能力覆盖与缺口](只审核能力覆盖与缺口.md)。拿到报告后，某个替代形式要不要做，使用[想给框架增加一项能力，先判断是否值得做](<../新想法与改动/想给框架增加一项能力，先判断是否值得做.md>)。
