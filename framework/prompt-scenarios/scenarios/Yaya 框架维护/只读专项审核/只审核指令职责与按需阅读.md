# 只审核指令职责与按需阅读

[返回场景索引](../../scenario-index.md#只读专项审核) · [通用模板](专项审核通用模板.md)

## 触发场景与使用时机

同类任务总会误用 Skill、重复阅读无关资料，或同一规则散落在多个位置；或者按 Skill 写的步骤做完，结果却不是它承诺的。

## 前置条件与适用范围

本专题回答的问题：Agent 从实际入口进入时，能否读到完成任务所需的规则，且不被要求阅读无关材料；同一条规则是否只在一处完整维护；Skill 写的方法能否从合法输入得到它承诺的结果。专门领域的方法（例如 GDD 到 Feature 的衔接、测试选择、advisor 的选择逻辑）仍由对应专题审核。

具体范围、必读来源和检查要点都写在提示词里，无需填写参数。审核只读，不修改任何文件。

## 执行步骤

**S1｜拼接并发送提示词**

1. 打开一个新对话；这个对话不能参与过被审内容的修改。
2. 复制[Yaya 框架维护提示词库](../../../prompts/yaya-maintenance-prompts.json)中的「只读专项审核 → 专项审核通用模板」。
3. 把「只读专项审核 → 只审核指令职责与按需阅读」的内容粘贴到模板末尾的「本次专题」下方。
4. 发送。

**S2｜等待审核报告**

审核 Agent 按专题范围只读核对，在对话中交付报告。需要留存时，明确要求保存到 `tmp/reports/<任务>/`。

**S3｜决定后续处理**

阅读报告，自行决定哪些问题要修、修到什么范围；审核结论本身不授权修改。

## 完成状态与验证标准

收到按通用模板结构交付的报告：先逐步写出 2–3 个具体任务的推演，问题清单分为已确认问题、有依据的风险和可选改进，每项都能定位到原文；没有问题时列出核查过的入口。报告分开写全部对象已核对的方面和只在选定任务中推演过的 Skill 方法。报告只给建议，不包含修复。

## 流程关联与衔接关系

不确定该从哪里查起时，先用[框架好像有问题，先判断从哪里查起](<框架好像有问题，先判断从哪里查起.md>)。拿到报告后，需要判断哪些意见值得改时，使用[收到外部审核意见，先核实哪些值得修改](<../改完检查/收到外部审核意见，先核实哪些值得修改.md>)；确定修复范围后，使用[框架出现可复现问题，需要修复](<../出了问题/框架出现可复现问题，需要修复.md>)。
