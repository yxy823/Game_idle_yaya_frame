# 只审核用词与写法

[返回场景索引](../../scenario-index.md#只读专项审核) · [通用模板](专项审核通用模板.md)

## 触发场景与使用时机

发现同一个东西在不同文档里叫法不同，链接文字和点进去的标题对不上，规则里的要求读不出是必须还是可以，或者框架起的名称在 Godot 里通常指别的东西；想全仓查一遍这类用词问题，而不是只查本次改过的文件。

## 前置条件与适用范围

本专题回答的问题：同一概念在全仓文档和两份提示词库中是否只用一个叫法；有没有使用术语表登记的不用说法、链接文字与目标标题不符、要求的强弱词不合规定或含糊措辞；框架起的名称（术语、`project-source/defaults/` 下的目录名、调试对象键名等）是否和 Godot 或通用约定中同名词的常见含义冲突。

具体范围、必读来源和检查要点都写在提示词里，无需填写参数。审核只读，不修改任何文件；除通用模板允许的操作外，本专题只额外允许运行术语检查（带 `--discover`）、措辞检查和带 `--check-link-text` 的链接检查这三个只读脚本，用来找候选写法、要复核的措辞和链接文字与目标标题不符的链接。链接文字的规则见框架文档写作指南的[表达与排版](../../../../../.agents/skills/technical-documentation-writing-yaya/references/writing-guide.md#表达与排版)；链接是否失效由[检查链接与锚点](../../../../maintenance/tools/README.md#检查链接与锚点)负责，不在本专题内。

## 执行步骤

**S1｜拼接并发送提示词**

1. 打开一个新对话；这个对话不能参与过被审内容的修改。
2. 复制[Yaya 框架维护提示词库](../../../prompts/yaya-maintenance-prompts.json)中的「只读专项审核 → 专项审核通用模板」。
3. 把「只读专项审核 → 只审核用词与写法」的内容粘贴到模板末尾的「本次专题」下方。
4. 发送。

**S2｜等待审核报告**

审核 Agent 先运行三个检查拿到候选位置，再读上下文判断哪些确实是同一概念的不同叫法、哪些措辞让要求读不清，在对话中交付报告。需要留存时，明确要求保存到 `tmp/reports/<任务>/`。

## 完成状态与验证标准

收到按通用模板结构交付的报告：先逐步写出 2–3 个具体任务的推演，问题清单分为已确认问题、有依据的风险和可选改进，每项都能定位到原文，叫法问题写出各种叫法和建议的正式名称；没有问题时列出核查过的入口。报告分别写明人工读全文、自动检查和只核对链接三档各包含哪些文件；本轮任务涉及的手册和场景页人工读全文，其余页面只经过自动筛查，不写“用词全部通过”。报告只给建议，不改写正文。

## 流程关联与衔接关系

不确定该从哪里查起时，先用[框架好像有问题，先判断从哪里查起](<框架好像有问题，先判断从哪里查起.md>)。拿到报告后，需要判断哪些意见值得改时，使用[收到外部审核意见，先核实哪些值得修改](<../改完检查/收到外部审核意见，先核实哪些值得修改.md>)；确定统一的叫法和修改范围后，使用[框架修改方案已确定，现在实施](<../新想法与改动/框架修改方案已确定，现在实施.md>)。
