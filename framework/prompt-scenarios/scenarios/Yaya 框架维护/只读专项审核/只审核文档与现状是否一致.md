# 只审核文档与现状是否一致

[返回场景索引](../../scenario-index.md#只读专项审核) · [通用模板](专项审核通用模板.md)

## 触发场景与使用时机

一个阶段的修改结束后，想确认文档没有随代码和配置的变化过时；或者发现某段文档写的路径、数值或状态已经不对，但链接检查查不出来。

## 前置条件与适用范围

本专题回答的问题：文档写的路径、文件名、符号、命令和参数、默认值与数值、状态说法，是否与当前的代码、配置和目录一致。

具体范围、必读来源和检查要点都写在提示词里，无需填写参数。审核只读，不修改任何文件；除通用模板允许的操作外，本专题只额外允许 `git log`、`git show`、`git diff` 这类只读查询，用来预筛最可能过时的文档。

## 执行步骤

**S1｜拼接并发送提示词**

1. 打开一个新对话；这个对话不能参与过被审内容的修改。
2. 复制[Yaya 框架维护提示词库](../../../prompts/yaya-maintenance-prompts.json)中的「只读专项审核 → 专项审核通用模板」。
3. 把「只读专项审核 → 只审核文档与现状是否一致」的内容粘贴到模板末尾的「本次专题」下方。
4. 发送。

**S2｜等待审核报告**

审核 Agent 先用 git 历史找出“链接或写明的代码、配置在文档最后一次修改之后改过”的文档，优先复核这些段落，再逐条核对文档写的内容与实际文件；预筛没有命中时，从与任务相关的文档中选，并在报告中写明预筛结果。报告在对话中交付；需要留存时，明确要求保存到 `tmp/reports/<任务>/`。

## 完成状态与验证标准

收到按通用模板结构交付的报告：先逐步写出 2–3 个具体任务的推演，问题清单分为已确认问题、有依据的风险和可选改进，每项都能定位到文档原文和对应的实际文件；没有问题时列出核查过的文档。报告只给建议，不包含修复。

## 流程关联与衔接关系

不确定该从哪里查起时，先用[框架好像有问题，先判断从哪里查起](<框架好像有问题，先判断从哪里查起.md>)。只想核对两份文档之间的复述是否一致时，改用[只审核文档职责与存放位置](只审核文档职责与存放位置.md)。拿到报告后，需要判断哪些意见值得改时，使用[收到外部审核意见，先核实哪些值得修改](<../改完检查/收到外部审核意见，先核实哪些值得修改.md>)；确定修复范围后，使用[框架出现可复现问题，需要修复](<../出了问题/框架出现可复现问题，需要修复.md>)。
