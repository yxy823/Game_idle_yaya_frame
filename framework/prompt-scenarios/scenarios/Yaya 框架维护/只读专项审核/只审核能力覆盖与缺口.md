# 只审核能力覆盖与缺口

[返回场景索引](../../scenario-index.md#只读专项审核) · [通用模板](专项审核通用模板.md)

## 触发场景与使用时机

想知道框架对某类工作（例如调试、数值、素材）还缺哪些能力，或者想按情境逐格查一遍：用户会遇到的事情，框架是不是都有 Skill、工具、调试台、模板或流程承接。

## 前置条件与适用范围

本专题回答的问题：在框架承诺支持的使用场景下，用户要做的每件事是否都有能力承接；哪些只写了规则、没有实现或没有试用过，缺口会卡住哪个真实任务。

具体范围、必读来源和检查要点都写在提示词里，无需填写参数。审核只读，不修改任何文件。已在[框架待办](../../../../progress.md)登记、内容仍然准确的缺口，在覆盖表中标为已登记，不计入问题数；框架明确不支持的引擎、平台、输入方式和多人协作不算缺口。

## 执行步骤

**S1｜拼接并发送提示词**

1. 打开一个新对话；这个对话不能参与过被审内容的修改。
2. 复制[Yaya 框架维护提示词库](../../../prompts/yaya-maintenance-prompts.json)中的「只读专项审核 → 专项审核通用模板」。
3. 把「只读专项审核 → 只审核能力覆盖与缺口」的内容粘贴到模板末尾的「本次专题」下方。想让审核者只查某一类工作时，在专题末尾加一句写明，例如“只查调试要做的事”。任务走查默认按放置类游戏选任务；想按某个试用项目走查时，在专题末尾写明项目。
4. 发送。

**S2｜等待审核报告**

审核 Agent 按情境 × 对象，或按某类工作实际要做的事列出需要的能力，逐项标出已验证、部分验证、只写了规则、没有；验证状态只引用已有的试用、回归测试或人工验收记录，不重跑。在对话中交付报告。需要留存时，明确要求保存到 `tmp/reports/<任务>/`。

## 完成状态与验证标准

收到按通用模板结构交付的报告：先逐步写出 2–3 个具体任务的走查，再用一张表列出每件事、承接的能力、状态和依据；问题清单中的每个缺口写明会卡住哪个真实任务。报告只给建议，不包含实现。

## 流程关联与衔接关系

本专题找缺少的能力；想找可以删掉的多余设计时，改用[框架里的例外越来越多，先找能从源头删掉的冗余设计](<../整体体检与整理/框架里的例外越来越多，先找能从源头删掉的冗余设计.md>)。拿到报告后，某个缺口要不要补，使用[想给框架增加一项能力，先判断是否值得做](<../新想法与改动/想给框架增加一项能力，先判断是否值得做.md>)；只写了规则、还没试用的能力，按[审核的判断方法](../../../../maintenance/design-guidelines/reviews-and-reports.md#审核的判断方法)中试用一条按缺口选验证入口，例如 GDD 到交付的流程用[想用一个小任务实际验证框架流程](<../整体体检与整理/想用一个小任务实际验证框架流程.md>)，工具行为用[框架刚改完，在指定外部项目验证工具行为](<../改完检查/框架刚改完，在指定外部项目验证工具行为.md>)。
