# 只审核授权、续接与完成边界

[返回场景索引](../../scenario-index.md#只读专项审核) · [通用模板](专项审核通用模板.md)

## 触发场景与使用时机

已经批准的工作仍反复确认，任务换步骤就停下，或测试通过被写成用户已经验收。

## 前置条件与适用范围

本专题回答的问题：在只讨论、已授权实施、明确只读、暂停、换对话续接这些情形下，Agent 是否会正确地继续、停止或询问；「完成」是否被正确判断。

具体范围、必读来源和检查要点都写在提示词里，无需填写参数。审核只读，不修改任何文件。

## 执行步骤

**S1｜拼接并发送提示词**

1. 打开一个新对话；这个对话不能参与过被审内容的修改。
2. 复制[Yaya 框架维护提示词库](../../../prompts/yaya-maintenance-prompts.json)中的「只读专项审核 → 专项审核通用模板」。
3. 把「只读专项审核 → 只审核授权、续接与完成边界」的内容粘贴到模板末尾的「本次专题」下方。
4. 发送。

**S2｜等待审核报告**

审核 Agent 按专题范围只读核对，在对话中交付报告。需要留存时，明确要求保存到 `tmp/reports/<任务>/`。

## 完成状态与验证标准

收到按通用模板结构交付的报告：先逐步写出 2–3 个具体任务的走查，问题清单分为已确认问题、有依据的风险和可选改进，每项都能定位到原文；没有问题时列出核查过的入口。报告逐步写出三个推演情形（「按这个改」「先暂停」「继续上次的 Feature」）每一步依据的原文。报告只给建议，不包含修复。

## 流程关联与衔接关系

不确定该选哪个专题时，先做[结构总览](<想先总览框架，再选择审核专题.md>)。拿到报告后，需要判断哪些意见值得改时，使用[核实外部审核意见](<../改完检查/收到外部审核意见，先核实哪些值得修改.md>)；确定修复范围后，使用[框架出现可复现问题，需要修复](<../出了问题/框架出现可复现问题，需要修复.md>)。
