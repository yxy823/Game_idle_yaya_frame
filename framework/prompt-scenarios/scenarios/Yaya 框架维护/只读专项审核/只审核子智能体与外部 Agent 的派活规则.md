# 只审核子智能体与外部 Agent 的派活规则

[返回场景索引](../../scenario-index.md#只读专项审核) · [通用模板](专项审核通用模板.md)

## 触发场景与使用时机

派出去的子智能体、独立审核实例或 Codex 做了规则不允许的事，或者交回的汇报格式、验证范围和要求不一致；想确认问题出在派活规则本身，还是只是一次偶发。

## 前置条件与适用范围

本专题回答的问题：派出子智能体、独立审核实例或外部 Agent 时，规则能否让被派出的一方读到它要遵守的约束（Git 禁令、验证范围、汇报格式），派活的要求之间有没有自相矛盾。

具体范围、必读来源和检查要点都写在提示词里，无需填写参数。审核只读，不修改任何文件。审核对象是规则文本，不统计或评价 Agent 的执行。全局个人规则只作对照：审核者可以指出它和仓库规则的冲突，但不提议修改它；验证范围以仓库的验证规则为准。

## 执行步骤

**S1｜拼接并发送提示词**

1. 打开一个新对话；这个对话不能参与过被审内容的修改。
2. 复制[Yaya 框架维护提示词库](../../../prompts/yaya-maintenance-prompts.json)中的「只读专项审核 → 专项审核通用模板」。
3. 把「只读专项审核 → 只审核子智能体与外部 Agent 的派活规则」的内容粘贴到模板末尾的「本次专题」下方。
4. 发送。

**S2｜等待审核报告**

审核 Agent 按专题范围只读核对，在对话中交付报告。需要留存时，明确要求保存到 `tmp/reports/<任务>/`。

## 完成状态与验证标准

收到按通用模板结构交付的报告：先逐步写出 2–3 个具体任务的推演，其中包括派子智能体实施修改、派子智能体做独立审核两个情形，每个情形按 Claude Code 子智能体和通过 `codex exec` 派出的外部 Codex 分别推演，或写明两者没有区别；问题清单分为已确认问题、有依据的风险和可选改进，冲突项列出双方原文。报告只给建议，不包含修复。

## 流程关联与衔接关系

问题是某一次执行没按规则做、而规则本身清楚时，改用[当前任务反复返工，先复盘原因](<../改进做事方法/当前任务反复返工，先复盘原因.md>)。拿到报告后，需要判断哪些意见值得改时，使用[收到外部审核意见，先核实哪些值得修改](<../改完检查/收到外部审核意见，先核实哪些值得修改.md>)；确定修复范围后，使用[框架出现可复现问题，需要修复](<../出了问题/框架出现可复现问题，需要修复.md>)。
