# 只审核提示词、场景与 Advisor 的对应关系

[返回场景索引](../../scenario-index.md#只读专项审核) · [通用模板](专项审核通用模板.md)

## 触发场景与使用时机

新增提示词后担心缺少场景或索引，或 Advisor 的建议与当前项目事实不匹配。

## 前置条件与适用范围

本专题回答的问题：用户或 advisor 能否从当前情况找到唯一、语义匹配的入口；提示词、场景页、索引和开发场景图是否表达同一件事。

具体范围、必读来源和检查要点都写在提示词里，无需填写参数。审核只读，不修改任何文件。

## 执行步骤

**S1｜拼接并发送提示词**

在一个没有参与过被审内容修改的新对话中，先复制[Yaya 框架维护提示词库](../../../prompts/yaya-maintenance-prompts.json)的「只读专项审核 → 专项审核通用模板」，再把「只读专项审核 → 只审核提示词、场景与 Advisor 的对应关系」的内容粘贴到模板末尾的「本次专题」下方，然后发送。

**S2｜等待审核报告**

审核 Agent 按专题范围只读核对，在对话中交付报告。需要留存时，明确要求保存到 `tmp/reports/<任务>/`。

**S3｜决定后续处理**

阅读报告，自行决定哪些问题要修、修到什么范围；审核结论本身不授权修改。

## 完成状态与验证标准

收到按通用模板结构交付的报告：问题清单分为已确认问题、有依据的风险和可选改进，每项都能定位到原文；没有问题时列出核查过的入口。报告只给建议，不包含修复。

## 流程关联与衔接关系

不确定该选哪个专题时，先做[结构总览](<想先总览框架，再选择审核专题.md>)。拿到报告后，需要判断哪些意见值得改时，使用[外部意见复核](<../维护与复盘/收到外部审核意见，先核实哪些值得修改.md>)；确定修复范围后，使用[框架出现可复现问题，需要修复](<../维护与复盘/框架出现可复现问题，需要修复.md>)。
