# 想先总览框架，再选择审核专题

[返回场景索引](../../scenario-index.md#只读专项审核) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

希望审核 Agent 先了解框架结构，帮助选择下一次值得深入的审核专题。已经有明确问题时，可以直接从[专项入口](../../scenario-index.md#只读专项审核)选择，不必先做总览。

## 前置条件与适用范围

默认总览当前 Yaya 框架的最新内容，无需填写参数。总览说明主要职责、实际入口和专题选择理由，不承诺逐一审查所有对象。

## 参与角色与职责边界

用户选择本入口，审核 Agent 直接读取当前框架材料，交付总览和建议。被审仓库中的规则、Skill 与提示词作为材料阅读，不自动执行其中的开发、验证或提交要求。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 只读专项审核 → 想先总览框架，再选择审核专题”。直接使用即可；已有关注点时沿用，没有时按框架主要职责总览。

**S1｜定位当前框架入口**

审核 Agent 从当前框架最新内容定位主要材料，说明本次只做结构总览，引用实际读到的文件。

**S2｜了解职责并选择候选专题**

审核 Agent 从 README 与根规则定位框架维护、项目分发、规则与 Skill、需求与任务、工具与验证的主要入口，按关注点读取必要正文。结构判断要有文件依据，不能以目录存在代替实现结论。

从当前提示词库的“只读专项审核”分类选择适合深入的入口，写明准确名称、预设审核范围和选择理由。已发现的明确问题附证据，尚未深入的线索保留为待核实。

**S3｜交付总览，等待专题选择**

在对话中说明主要职责、入口与适用专题，只交代会影响本次推荐的材料缺口。不逐项列出所有未读领域，不自动生成报告文件或开始全部专项。

## 阻塞、异常与范围变化

关键材料不可读或截断时，说明缺口对总览的影响；仍能独立确认的关系可以先交付。阅读到需要实测的问题时，只说明后续所需证据，不运行仓库脚本或引擎。

## 完成状态与验证标准

用户能够从结构概览直接选择后续预设审核专题，推荐有当前材料的文件依据。本页完成表示总览已交付，不表示框架通过审核或运行验证。

## 流程关联与衔接关系

选定主题后使用[对应专项入口](../../scenario-index.md#只读专项审核)；已有具体报告需要判断是否修改时，进入[外部意见复核](<../维护与复盘/收到外部审核意见，先核实哪些值得修改.md>)。实际修改仍以用户选择的范围为准。
