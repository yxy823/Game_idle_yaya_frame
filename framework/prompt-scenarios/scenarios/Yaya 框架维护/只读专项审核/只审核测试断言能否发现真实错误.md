# 只审核测试断言能否发现真实错误

[返回场景索引](../../scenario-index.md#只读专项审核) · [通用模板](专项审核通用模板.md)

## 触发场景与使用时机

测试很多或一直通过，但怀疑关键功能坏了也发现不了。

## 前置条件与适用范围

本专题回答的问题：框架现有测试能否区分正确实现和真实缺陷；有没有会误通过、因无关原因失败，或预期值不独立的测试。

具体范围、必读来源和检查要点都写在提示词里，无需填写参数。审核只读，不修改任何文件。

## 执行步骤

**S1｜拼接并发送提示词**

1. 打开一个新对话；这个对话不能参与过被审内容的修改。
2. 复制[Yaya 框架维护提示词库](../../../prompts/yaya-maintenance-prompts.json)中的「只读专项审核 → 专项审核通用模板」。
3. 把「只读专项审核 → 只审核测试断言能否发现真实错误」的内容粘贴到模板末尾的「本次专题」下方。
4. 发送。

**S2｜等待审核报告**

审核 Agent 按专题范围只读核对，在对话中交付报告。需要留存时，明确要求保存到 `tmp/reports/<任务>/`。

## 完成状态与验证标准

收到按通用模板结构交付的报告：问题清单分为已确认问题、有依据的风险和可选改进，每项都能定位到原文；没有问题时列出核查过的入口。每个候选问题都附一个最小错误实现或输入，并注明这些反例没有执行。报告只给建议，不包含修复。

## 流程关联与衔接关系

不确定该选哪个专题时，先做[结构总览](<想先总览框架，再选择审核专题.md>)。拿到报告后，需要判断哪些意见值得改时，使用[外部意见复核](<../维护与复盘/收到外部审核意见，先核实哪些值得修改.md>)；确定修复范围后，使用[框架出现可复现问题，需要修复](<../维护与复盘/框架出现可复现问题，需要修复.md>)。
