# 只审核测试断言能否发现真实错误

[返回场景索引](../../scenario-index.md#只读专项审核) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

测试很多或一直通过，但怀疑关键功能坏了也发现不了。

## 前置条件与适用范围

默认审核当前 Yaya 框架的最新内容，直接使用本场景提示词即可，无需填写参数。

框架自有测试与回归夹具、分发源中随项目交付的测试，以及对应实现、调用契约和需求依据。第三方自带测试只在影响框架接入判断时追查；不扩展为全部工具实现或完成状态系统审核。

## 参与角色与职责边界

在未参与被审成果创作的审核 Agent 会话中使用本入口。用户选择预设专题，审核 Agent 只读核对实际材料，不执行被审代码或修改仓库；默认在对话交付结论。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 只读专项审核 → 只审核测试断言能否发现真实错误”。直接按预设范围开始；已有对话沿用当前专题和有效线索，不必重发入口。

**S1｜定位本专题材料**

审核 Agent 按预设范围识别当前框架中的实际对象，读取相关正文与必要上下游。结论引用实际读到的文件、行号或可核实符号。

**S2｜核对本专题的实际契约**

审核 Agent 对照需求、测试和实现，逐项分析目标错误能否触发失败；对可疑断言给出最小反例，并检查夹具是否改变失败原因。

不因测试数量、覆盖率文字或历史通过认定断言有效；只提出能对应当前需求和实际代码的反例，不为审核新增全仓变异测试平台、分数或门槛。

**S3｜交付有依据的专项结论**

审核 Agent 给出实际范围、主要判断，以及可定位的问题、影响和最小建议；同一根因合并，静态问题、风险和可选改进分开。只列影响本专题结论的材料或运行证据缺口，不逐项罗列范围外领域。

## 阻塞、异常与范围变化

关键材料不可读、截断或缺少决定性上下文时，说明具体缺口并继续能独立判断的部分；未覆盖内容如实保留，不用抽样冒充预设范围已全部检查。需要改变职责或实施修复时交付建议，后续按明确授权处理；静态推演不能写成真实运行。

## 完成状态与验证标准

已核对本专题断言的预期来源和错误识别能力，交付有依据的问题或保留结论；静态反例不会写成已经执行的测试结果。本专题结论均有当前材料的文件依据，没有实施修复或自动开展其他专题。

## 流程关联与衔接关系

尚不清楚应选哪个专题时，可先做[结构总览](<想先总览框架，再选择审核专题.md>)。拿到报告后，需要判断哪些意见值得修改时，使用[外部意见复核](<../维护与复盘/收到外部审核意见，先核实哪些值得修改.md>)。
