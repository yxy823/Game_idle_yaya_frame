# 框架好像有问题，先判断从哪里查起

[返回场景索引](../../scenario-index.md#只读专项审核) · [通用模板](专项审核通用模板.md)

## 触发场景与使用时机

觉得框架有问题，但说不清该用哪个入口查，例如“同一个默认规则有两种写法”“工具能打开，但不知道怎样完成操作”“Agent 又做了禁止的操作”“只在真实运行时坏”。也可以在完全没有线索、只想先了解框架结构时使用。已经知道要查哪一类问题时，直接从场景速查索引的[只读专项审核](../../scenario-index.md#只读专项审核)选专题。

## 前置条件与适用范围

本专题回答的问题：根据症状、卡住的任务和已有记录，应该先用哪 1–3 个现有入口，每个入口能回答什么。候选不限于专项审核，也包括整体静态审核、复盘和实际验证。

提示词中有一个可选占位「本次线索」：写看到的症状、卡住的任务或相关记录的位置；不填时 Agent 先做结构总览。审核只读，不修改任何文件。

## 执行步骤

**S1｜拼接并发送提示词**

1. 打开一个新对话；这个对话不能参与过被审内容的修改。
2. 复制[Yaya 框架维护提示词库](../../../prompts/yaya-maintenance-prompts.json)中的「只读专项审核 → 专项审核通用模板」。
3. 把「只读专项审核 → 框架好像有问题，先判断从哪里查起」的内容粘贴到模板末尾的「本次专题」下方，填写「本次线索」或留空。
4. 发送。

**S2｜等待推荐**

Agent 先读线索相关的记录和候选入口；症状可能对应几个入口时，由 Agent 查记录或文件区分，不要求你判断专题分工。没有线索时改为读框架各部分的入口文件。结果在对话中交付；需要留存时，明确要求保存到 `tmp/reports/<任务>/`。

## 完成状态与验证标准

收到线索整理（没有线索时是结构概览）和 1–3 个推荐入口，每个推荐写明它能回答什么、回答不了什么，并附具体证据；实际验证类入口写明目标项目，没指定时写“待指定”。本专题不做任务走查，不是全面审核，推荐后结束，不自动执行任何入口。

## 流程关联与衔接关系

按推荐使用对应入口：专项审核从场景速查索引的[只读专项审核](../../scenario-index.md#只读专项审核)选专题，整体审核用[想检查本地框架是否自洽，先做静态审核](<../整体体检与整理/想检查本地框架是否自洽，先做静态审核.md>)，能复现的具体错误用[框架出现可复现问题，需要修复](<../出了问题/框架出现可复现问题，需要修复.md>)。已有报告需要判断是否修改时，使用[收到外部审核意见，先核实哪些值得修改](<../改完检查/收到外部审核意见，先核实哪些值得修改.md>)。
