# 只审核提示词、场景与 advisor 的对应关系

[返回场景索引](../../scenario-index.md#只读专项审核) · [通用模板](专项审核通用模板.md)

## 触发场景与使用时机

新增提示词后担心缺少场景或索引，调整了提示词分类后想确认用户能凭自己的情况找到唯一入口，或 advisor 的建议与当前项目事实不匹配。

## 前置条件与适用范围

本专题回答的问题：用户或 advisor 能否从当前情况找到唯一、语义匹配的入口；提示词、场景页、索引和各场景页的下一步清单是否表达同一件事，下一步清单还核对每项的条件和目标；固定字段是否有实质内容按抽查做，结论只适用于抽查的条目。

具体范围、必读来源和检查要点都写在提示词里，无需填写参数。审核只读，不修改任何文件。

## 执行步骤

**S1｜拼接并发送提示词**

1. 打开一个新对话；这个对话不能参与过被审内容的修改。
2. 复制[Yaya 框架维护提示词库](../../../prompts/yaya-maintenance-prompts.json)中的「只读专项审核 → 专项审核通用模板」。
3. 把「只读专项审核 → 只审核提示词、场景与 advisor 的对应关系」的内容粘贴到模板末尾的「本次专题」下方。
4. 发送。

**S2｜等待审核报告**

审核 Agent 按专题范围只读核对，在对话中交付报告。需要留存时，明确要求保存到 `tmp/reports/<任务>/`。

## 完成状态与验证标准

收到按通用模板结构交付的报告：先逐步写出 2–3 个具体任务的推演，问题清单分为已确认问题、有依据的风险和可选改进，每项都能定位到原文；没有问题时列出核查过的入口。报告只给建议，不包含修复。

## 流程关联与衔接关系

不确定该从哪里查起时，先用[框架好像有问题，先判断从哪里查起](<框架好像有问题，先判断从哪里查起.md>)。拿到报告后，需要判断哪些意见值得改时，使用[收到外部审核意见，先核实哪些值得修改](<../改完检查/收到外部审核意见，先核实哪些值得修改.md>)；确定修复范围后，使用[框架出现可复现问题，需要修复](<../出了问题/框架出现可复现问题，需要修复.md>)。
