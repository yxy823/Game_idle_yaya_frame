# 想给框架增加一项能力，先判断是否值得做

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

想给框架加一个新 Skill、脚本或流程步骤（例如自动检查某类文件），但还没想清楚现有能力能否覆盖、值不值得新增。需要的材料：

- **问题**：实际遇到的问题，有记录时附一次具体经过或日志路径；只是预想时注明。
- **频率与期望**（可选）：大约多久遇到一次、希望改善成什么样；不知道就写“未知”。

## 前置条件与适用范围

尚未选定实施方案，本次只需必要性与落点建议。

## 执行步骤

使用[预设提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 新想法与改动 → 想给框架增加一项能力，先判断是否值得做”，把上述材料填入 `${1}`。

**S1｜核对已有能力**

当前 Agent 阅读受影响实现和调用者，确认现有命令、说明或人工操作能否满足问题。

**S2｜比较最小方案**

比较不新增、说明改进、复用或合并、最小新增的成本，并给推荐落点与验证方法。

## 资源与文件影响

相关 framework/ 和 project-source/ 文件只读；建议在对话交付。

## 阻塞、异常与范围变化

缺少复现场景时说明证据不足，不凭外部能力数量推定必须新增。

## 完成状态与验证标准

必要性、推荐方案、影响文件及验证建议明确；没有修改维护源。

## 流程关联与衔接关系

依据：[核心决策原则](../../../../../AGENTS.md#核心决策原则)（目标驱动、奥卡姆剃刀）与职责设计准则的[适用范围与判断原则](../../../../maintenance/design-guidelines/README.md#适用范围与判断原则)。决定新增并选定方案后，转到[框架修改方案已确定，现在实施](框架修改方案已确定，现在实施.md)。
