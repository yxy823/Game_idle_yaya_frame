# 框架修改方案已确定，现在实施

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

框架的一项修改方案已经确认，现在要把它写进框架。方案可能来自三种来源：

- **新增能力**：在[想给框架增加一项能力，先判断是否值得做](<想给框架增加一项能力，先判断是否值得做.md>)或其他讨论中确认的方案。
- **修改现有规则或写法**：已确认要改现有的规则、提示词、Skill 或文档写法，它不是缺陷，也不是新增能力。
- **引入外部设计**：已经比较过某个外部框架的具体做法（例如它的 Skill 触发写法），决定借鉴。还没决定是否借鉴时，先用[看到外部框架的一个设计，先判断是否适合借鉴](<看到外部框架的一个设计，先判断是否适合借鉴.md>)。

修复可复现的框架问题改用[框架出现可复现问题，需要修复](<../出了问题/框架出现可复现问题，需要修复.md>)。

需要的材料：

- **方案来源**：上面三种之一。
- **已确认方案**：方案原文、所在的对话或 `tmp/` 中的方案文件路径。引入外部设计时，另写外部仓库或文档链接、具体文件或版本；已知的许可证可选，不填时由 Agent 从外部仓库核对。
- **写入范围**（可选）：允许修改的目录或文件；没写时以方案涉及的框架仓库文件为限。
- **验证方式**（可选）：允许的检查；需要外部项目验证时给出项目绝对路径。没给时按[按修改选择验证范围](../../../../maintenance/validation/validation-scope.md#按修改选择验证范围)在仓库内选择。

## 前置条件与适用范围

方案与实施边界已经明确，本次完成方案内容的最小完整实现。

## 执行步骤

使用[预设提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 新想法与改动 → 框架修改方案已确定，现在实施”。填入上述材料。

**S1｜核对方案与调用链**

当前 Agent 对照根 AGENTS.md、复制清单和受影响工具读取当前实现，复用已确认决定。引入外部设计时，还读取选中版本，直接复用代码前核对许可和所需声明。

**S2｜完成最小实现**

修改框架仓库中获准的文件，追到读写方、配置、复制映射、说明和适用回归；外部设计按现有职责最小适配，保留必要出处声明，排除外部历史、缓存和无关业务。不自动同步生成项目。

**S3｜验证并交付**

执行与影响相称且获准的检查，保留实际结果，核对完整差异只含方案内容及其直接消费者，然后按[本地提交](<../../../../../AGENTS.md#本地提交>)提交。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 要修改的文件和受影响的调用方已列出；引入外部设计时，外部版本、许可和需要的出处声明已写明 |
| S2 | 读写方、复制清单和说明都已改到，搜索不到旧写法；差异只涉及方案内容及其直接消费者 |
| S3 | 实际运行的检查及结果、本地提交哈希 |

## 资源与文件影响

方案涉及的框架仓库文件与必要说明、回归和许可声明会修改；外部仓库只读；生成项目仅在明确指定验证范围内使用。

## 阻塞、异常与范围变化

方案实质扩展时仅暂停依赖新增决定的部分；外部设计许可不明时暂停代码搬入，已授权的自主重新实现按具体范围继续；验证失败不写成完成。

## 完成状态与验证标准

方案内容已在当前框架实现，相关调用与说明一致，未引入无关体系，适用验证完成并交付本地提交。
