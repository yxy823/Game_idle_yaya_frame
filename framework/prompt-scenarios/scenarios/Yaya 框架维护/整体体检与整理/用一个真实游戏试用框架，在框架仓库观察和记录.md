# 用一个真实游戏试用框架，在框架仓库观察和记录

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

你在做一个准备发布的游戏，想同时用它试用框架：项目里的开发由你自己发提示词，框架仓库里另开一个会话旁观、记录、找框架问题。开始试用、每做完一步、想商量下一步提示词、阶段结束想集中修问题时，都用这一条。需要的材料：

- **游戏项目路径**：开始试用时必填，并把项目挂成这个会话的附加目录。
- **试用目录**：续接时填 `tmp/<游戏>-trial-<日期>/`。
- **本次要做的事**：例如“第 08 步做完了”。

## 前置条件与适用范围

游戏项目已经用创建器建好。只想复盘一段已经结束的经过时，用[实际开发遇到问题，想判断框架是否需要改进](../出了问题/实际开发遇到问题，想判断框架是否需要改进.md)；想在验证项目里亲自走一遍流程时，用[想用一个小任务实际验证框架流程](想用一个小任务实际验证框架流程.md)。

## 执行步骤

使用[Yaya 框架维护提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 整体体检与整理 → 用一个真实游戏试用框架，在框架仓库观察和记录”：`${1}` 填游戏项目路径，`${2}` 填试用目录，`${3}` 填本次要做的事。当前 Agent 使用 [framework-trial-yaya](../../../../../.agents/skills/framework-trial-yaya/SKILL.md) 完成全程。

**S1｜建立或读取试用记录**

开始试用时，Agent 征得你同意后读取项目，建立 `plan.md` 和 `trial-log.md`；续接时先读这两份文件。

**S2｜核对现状**

Agent 读项目提交、`docs/progress.md` 和会话日志，更新步骤记录和当前停点，写出你没发现的问题。

**S3｜商量下一步或修问题**

你先从提示词浮窗挑下一步，Agent 再说自己的推荐；挡住进度的框架问题当场修，其他问题记进问题清单，阶段结束后逐条讨论、按修复计划修复。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 试用目录里有 `plan.md` 和 `trial-log.md` |
| S2 | 步骤记录和当前停点反映项目的最新提交和各条线的状态 |
| S3 | 下一步提示词已定；修过的问题在问题清单里写了提交号 |

## 资源与文件影响

只写试用目录里的记录和框架仓库的修改；游戏项目只读，同步框架修改进项目要你另行同意。

## 阻塞、异常与范围变化

读不到项目或会话日志时，Agent 说明缺什么并只按能读到的记录工作。修复中遇到修复计划没覆盖的决定，Agent 停下提问。

## 完成状态与验证标准

本次要做的事已完成，记录已更新；修过的框架问题已提交，提交号写回问题清单。

## 流程关联与衔接关系

阶段结束需要复盘时，Agent 用 [framework-retro-yaya](../../../../../.agents/skills/framework-retro-yaya/SKILL.md)；修改提示词、场景或关系图时用 [prompt-and-graph-maintenance-yaya](../../../../../.agents/skills/prompt-and-graph-maintenance-yaya/SKILL.md)。
