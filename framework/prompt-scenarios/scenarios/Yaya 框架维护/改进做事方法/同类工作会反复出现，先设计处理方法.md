# 同类工作会反复出现，先设计处理方法

[返回场景索引](../../scenario-index.md)

## 触发场景与使用时机

框架维护中某类工作已经反复出现、每次都要重新交代，或者预计今后会经常做，想先确定一套固定的处理方法。例如：经常要评估外部 Skill 是否值得借鉴，想讲清每次需要什么输入、交付怎样的建议。

## 前置条件与适用范围

在框架仓库处理。本次只在对话里分析，不写文件。要查明某个任务为什么反复返工，改用[当前任务反复返工，先复盘原因](<当前任务反复返工，先复盘原因.md>)。

## 执行步骤

使用[Yaya 框架维护提示词库](../../../prompts/yaya-maintenance-prompts.json)中的「改进做事方法 → 同类工作会反复出现，先设计处理方法」。

**S1｜提供这类工作的信息**

填写这类工作是什么、何时发生、每次的输入与产出和限制；有过往实例就附上，没有就注明属于预计工作。

**S2｜确认处理方案**

Agent 区分每次相同和每次变化的部分，比较沿用现有入口、补充引用和最小新增，交付建议的入口、输入、关键判断、产出、完成条件和正文位置。你从中决定是否采用、采用到什么范围。

## 完成状态与验证标准

得到一份可以直接采用或修改的处理方案，采用前需要你决定的选择都已列出。方案只经过推演，还没有实施或实际验证。
