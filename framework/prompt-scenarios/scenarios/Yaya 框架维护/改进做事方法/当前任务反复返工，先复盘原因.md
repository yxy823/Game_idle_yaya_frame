# 当前任务反复返工，先复盘原因

[返回场景索引](../../scenario-index.md)

## 触发场景与使用时机

框架任务中反复沟通、尝试或返工，想查清原因并找出值得改的地方。可以在任务仍进行时提出，不必等一个阶段正式结束，也不必另找一个对话。

## 前置条件与适用范围

在框架仓库处理。只分析指定任务和指定的反复环节，不扩展为其他任务或全项目审核。证据默认取当前对话；需要读最近几次对话时在输入中写明。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 改进做事方法 → 当前任务反复返工，先复盘原因”，`${1}` 填哪项任务、哪个环节反复了；当前对话里已有的经过不必另外整理。当前 Agent 使用 [framework-retro-yaya](../../../../../.agents/skills/framework-retro-yaya/SKILL.md) 完成全程。

**S1｜还原经过与归类**

Agent 从对话记录、提交和日志还原时间顺序与耗时，标出重复的动作，把每条观察归为一次性失误、工具或环境限制、规则冲突、反复出现的摩擦或值得保留的做法。

**S2｜提出建议并写报告**

Agent 对照根规则的核心决策原则检查做法与改法，判断每条建议归分发源、框架维护文档、具体项目还是用户全局规则，写成复盘报告；没有必要修改也是有效结论。

## 资源与文件影响

只写一份复盘报告，位置按 Skill 的约定；规则、Skill、提示词、工具和用户全局规则都不修改，不运行项目或验证命令。

## 阻塞、异常与范围变化

缺少相关经过或原件时，报告说明能确认与不能确认的部分，不编造因果。本场景不授予实施权限，你选定范围后由对应的维护任务实施。

## 完成状态与验证标准

指定的反复环节已有可追查的分析和带归属的建议，报告已保存，无法确认的原因标为未知；没有自动修改规则或实现工具。
