# 已经选定外部设计，现在引入框架

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已经比较过某个外部框架的具体做法（例如它的 Skill 触发写法），决定借鉴，现在要把它落到本框架。需要的材料：

- **选中的设计**：外部仓库或文档链接、具体文件或版本，以及比较时确定的方案（原话，或指明在哪个对话、报告里）。
- **许可信息**（可选）：已知的许可证；不填时由 Agent 从外部仓库核对。
- **验证范围**（可选）：允许运行的检查和外部项目路径；不填时按[按修改选择验证范围](../../../../maintenance/validation/validation-scope.md#按修改选择验证范围)在仓库内选择。

## 前置条件与适用范围

已确定具体借鉴项，本次落地其最小实现。还没决定是否借鉴时，先用[看到外部框架的一个设计，先判断是否适合借鉴](看到外部框架的一个设计，先判断是否适合借鉴.md)。

## 执行步骤

使用[集中提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 设计与借鉴 → 已经选定外部设计，现在引入框架”，把上述材料填入 `${1}`。

**S1｜核对出处与契约**

当前 Agent 读取选中版本与当前调用方；直接复用代码前核对许可和所需声明。

**S2｜实施所选设计**

按现有职责最小适配，保留必要出处声明，排除外部历史、缓存和无关业务。

**S3｜验证关联入口**

同步受影响配置、复制映射、说明与回归，按验证范围检查后按[本地提交](../../../../../AGENTS.md#本地提交)提交。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 外部版本、许可和需要的出处声明已写明，接入位置已列出 |
| S2 | 差异只涉及选中能力及其直接消费者 |
| S3 | 受影响配置、复制映射和说明已同步，检查结果和提交哈希已记录 |

## 资源与文件影响

选中维护源与必要许可声明会修改；外部仓库本身只读。

## 阻塞、异常与范围变化

许可不明时暂停代码搬入；已授权的自主重新实现按具体范围继续。

## 完成状态与验证标准

所选设计已在当前框架适配并通过必要检查，未引入无关体系。

## 流程关联与衔接关系

依据：[核心决策原则](../../../../../AGENTS.md#核心决策原则)（最小完整修改）与根 AGENTS.md 的[修改时的联动检查](../../../../../AGENTS.md#修改时的联动检查)。
