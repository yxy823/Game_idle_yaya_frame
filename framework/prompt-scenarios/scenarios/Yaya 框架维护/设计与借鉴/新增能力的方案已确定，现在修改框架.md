# 新增能力的方案已确定，现在修改框架

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已经在[想给框架增加一项能力，先判断是否值得做](<想给框架增加一项能力，先判断是否值得做.md>)或其他讨论中确认了方案，现在要把它写进框架。需要的材料：

- **已确认方案**：方案原文、所在的对话或 `tmp/` 中的方案文件路径。
- **写入范围**：允许修改的目录或文件；没写时以方案涉及的维护源为限。
- **验证方式**：允许的检查；需要外部项目验证时给出项目绝对路径，没给时只做静态核对和仓库回归。

## 前置条件与适用范围

方案与实施边界已经明确，本次完成所选能力。

## 执行步骤

使用[集中提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 设计与借鉴 → 新增能力的方案已确定，现在修改框架”。填入上述材料。

**S1｜核对方案与调用链**

当前 Agent 对照根 AGENTS.md、复制清单和受影响工具读取当前实现，复用已确认决定。

**S2｜完成最小实现**

修改获准维护源，追到读写方、配置、复制映射、说明和适用回归；不自动同步生成项目。

**S3｜验证并交付**

执行与影响相称且获准的检查，保留实际结果，核对完整差异后按根规则本地提交。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 要修改的文件和受影响的调用方已列出 |
| S2 | 读写方、复制清单和说明都已改到，搜索不到旧写法 |
| S3 | 实际运行的检查及结果、本地提交哈希 |

## 资源与文件影响

所选维护源与必要说明、回归会修改；生成项目仅在明确指定验证范围内使用。

## 阻塞、异常与范围变化

方案实质扩展时仅暂停依赖新增决定的部分；验证失败不写成完成。

## 完成状态与验证标准

选定能力已实现，相关调用与说明一致，适用验证完成并交付本地提交。
