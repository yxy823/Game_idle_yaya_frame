# 框架刚改完，在指定外部项目验证工具行为

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

刚改了 `project-source/tools/` 中的项目工具或测试运行方式，静态核对已经做完，需要在一个已有的外部 Godot 项目里实际跑一遍，确认工具行为符合修改目的。需要的材料：

- **被测变更**：本次修改的提交或文件清单。
- **外部项目**：项目的绝对路径。
- **运行与同步范围**：要跑的工具回归或测试，以及允许同步到该项目的文件；没写同步范围时只运行、不同步。

## 前置条件与适用范围

外部验证项目已经存在且获准使用。只读核对文件和引用用[框架刚改完，只检查文件和引用](<框架刚改完，只检查文件和引用.md>)。

## 执行步骤

使用[预设提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 改完检查 → 框架刚改完，在指定外部项目验证工具行为”。填入上述材料。

**S1｜核对并同步被测文件**

当前 Agent 按[按修改选择验证范围](<../../../../maintenance/validation/validation-scope.md#按修改选择验证范围>)中“同步到外部项目”的规定逐个文件比对允许同步的文件：外部项目中的文件与上次同步时的框架版本相同，才更新为新版本；项目自己改过的文件列出来逐个判断，不直接覆盖。项目的机器配置和无关内容保留。

**S2｜运行针对性验证**

在框架仓库根目录运行工具回归，`--project` 换成外部项目路径：

```powershell
python -B framework/tests/external-project/run_project_tool_tests.py --project <外部项目绝对路径>
```

需要跑 gdUnit 测试时，在外部项目中使用包装脚本 `yaya/tools/testing/run-gdunit-tests.py`，不用 `--headless` 直接调用运行器。其他夹具和参数见[按需检查](<../../../../tests/README.md#按需检查>)。保留实际命令、退出码、原始结果和失败。

**S3｜报告覆盖与限制**

分别写出工具回归、真实引擎运行和人工体验各自做了什么、没做什么。缺少外部项目时停止并说明，由用户指定已有项目或另行授权创建，不擅自新建。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 已同步文件、跳过的项目自改文件及判断结果已列出 |
| S2 | 每条命令的退出码和原始结果位置 |
| S3 | 已执行与未执行的验证层次分别列出 |

## 资源与文件影响

指定项目内获准同步的被测文件与运行产物可能改变；框架其他内容不随验证修改。

## 阻塞、异常与范围变化

权限、环境或版本不符时保留现场与具体阻塞；旧通过不适用于新版本。

## 完成状态与验证标准

被授权的工具行为已实际验证，原始证据和未执行项可定位。
