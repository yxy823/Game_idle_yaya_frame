# 框架刚改完，只检查文件和引用

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

刚完成一轮框架修改（例如移动了几篇文档、改了复制清单），只想确认文件、配置和引用前后对得上，不运行测试、不生成项目。需要的材料：

- **检查范围**（可选）：默认当前工作区相对 HEAD 的全部未提交差异；也可以写提交区间或具体路径。

## 前置条件与适用范围

修改已完成，本次仅判断文件契约和引用是否一致。

## 执行步骤

使用[预设提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 改完检查 → 框架刚改完，只检查文件和引用”，`${1}` 填检查范围。

**S1｜读取实际差异**

当前 Agent 用 `git status --short` 和 `git diff` 固定当前版本，追查受影响规范、实现、配置与复制映射。

**S2｜核对结构与引用**

在仓库根目录运行只读检查，命令说明见[维护命令](../../../../README.md#维护命令)：

- `python -B framework/maintenance/tools/check_repository_links.py`：Markdown 链接、锚点和提示词正文中的路径与标题引用。
- 改了提示词或场景时，再运行 `python -B framework/prompt-scenarios/tools/check_scenario_prompt_paths.py`。
- 改动的 JSON 只做解析，Python 脚本只做语法解析，不执行；再对照调用方核对参数和路径。

**S3｜说明证据边界**

报告静态发现、失败和需要运行才能判断的内容，不生成项目或启动引擎。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 差异文件及其读写方、复制映射已列出 |
| S2 | 每条检查命令及其结果已记录，失败保留原始输出 |
| S3 | 需要运行才能判断的项已列为验证缺口 |

## 资源与文件影响

修改范围只读；输出静态检查结论。

## 阻塞、异常与范围变化

用户本次明确只检查时，交付发现和验证缺口，不据较早的实施授权顺手修复。若静态检查是已授权完整任务中的一个步骤，则将发现交回原任务的获准修复范围，不因步骤切换重新索取同一授权。

## 完成状态与验证标准

所选静态契约已核对，失败和未验证运行项明确。

## 流程关联与衔接关系

依据：[按修改选择验证范围](../../../../maintenance/validation/validation-scope.md#按修改选择验证范围)（仅静态请求不生成项目、不启动 Godot、不运行测试）与框架维护与说明同步的[修改时的联动检查](../../../../maintenance/maintenance-and-sync.md#修改时的联动检查)。需要在外部项目验证工具行为时，转到[框架刚改完，在指定外部项目验证工具行为](框架刚改完，在指定外部项目验证工具行为.md)。
