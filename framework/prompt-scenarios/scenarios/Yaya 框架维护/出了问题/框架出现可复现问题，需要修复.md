# 框架出现可复现问题，需要修复

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

框架的工具、Skill 或说明在实际使用中偏离了现有契约，而且能用步骤或日志重现，例如创建器按某份清单复制时漏了文件。需要的材料：

- **问题与证据**：复现步骤或命令、期望与实际行为、日志或报错原文（粘贴或给路径）。
- **验证范围**（可选）：允许运行的检查；需要外部项目回归时写明项目路径。不填时按[按修改选择验证范围](../../../../maintenance/validation/validation-scope.md#按修改选择验证范围)在仓库内选择，不运行外部项目。

## 前置条件与适用范围

实际框架行为偏离现有契约，目标是修复已定位的问题。

## 执行步骤

使用[集中提示词库](<../../../prompts/yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 出了问题 → 框架出现可复现问题，需要修复”，把上述材料填入 `${1}`。

**S1｜建立复现依据**

当前 Agent 读取报错及实际调用链，区分工具缺陷、说明失效与运行环境问题。原因尚不明确时，用原症状对应的复现和证据区分候选原因，复用已有结果后继续本次修复，不增加独立阶段。

**S2｜修复根因**

在维护源局部修正，同步直接调用者与回归用例，不放宽既有验收规则。

**S3｜复核修复**

按验证范围检查原触发路径及相邻失败行为，报告失败与未执行项后按[本地提交](../../../../../AGENTS.md#本地提交)提交。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 根因或仍待区分的候选原因、触发条件已写明 |
| S2 | 修复及直接调用者、回归用例的改动已完成 |
| S3 | 原触发路径的修复后结果、未执行项和提交哈希已记录 |

## 资源与文件影响

相关源文件、必要回归和说明修改；已有游戏不自动更新。

## 阻塞、异常与范围变化

无法复现时保留静态推断与待运行项，不能称故障已消失。

## 完成状态与验证标准

原问题有对应修复与适用验证；影响范围、剩余限制和提交明确。

## 流程关联与衔接关系

依据：根 AGENTS.md 的[修改时的联动检查](../../../../../AGENTS.md#修改时的联动检查)（路径与字段追到全部读写方；重复的症状先找根因）与[按修改选择验证范围](../../../../maintenance/validation/validation-scope.md#按修改选择验证范围)。
