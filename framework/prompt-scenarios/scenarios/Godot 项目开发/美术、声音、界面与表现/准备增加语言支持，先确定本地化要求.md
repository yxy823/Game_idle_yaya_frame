# 准备增加语言支持，先确定本地化要求

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如游戏打算在中文之外增加英文，实现之前需要先写清覆盖哪些语言和文本、缺译时怎样回退、排版和字体有什么约束。

需要的材料：

- 目标语言和要覆盖的文本范围（例如“英文；全部界面文本，不含剧情对话”）。
- 已知的字体、版面或用词约束；不提供时由 Agent 从 GDD、项目术语和界面规格中读取，读不到的在规格中标为待定。

## 前置条件与适用范围

项目已有真实 GDD，本地化目标待定稿，本次只补足规格。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 美术、声音、界面与表现 → 准备增加语言支持，先确定本地化要求”。填入上述材料。本页使用 [$design-localization-spec](../../../../../project-source/skills/design-localization-spec/SKILL.md)。

**S1｜确认语言与显示需求**

当前 Agent 使用 design-localization-spec 核对目标语言、文本所有者、术语和字体覆盖。

**S2｜定义最小约定**

说明键管理、回退、复数或格式化的实际需要、排版和验收样本，不为未用语言扩建框架。

**S3｜保存规范**

语言覆盖、回退、排版与本地化用词规格固定保存到 `docs/localization/localization-spec.md`；原先写在 GDD 的当前范围内规格迁入该文件并更新引用，GDD 保留整体体验目标。游戏术语定义引用 `docs/terminology.md`；目标语言用词统一写入本地化规范的“术语译名”章节，记录概念链接、目标语言、已采纳译名和语境，候选标为待定。完整译文继续由运行资源维护。

保存后在游戏项目根目录运行 `python -B yaya/tools/checks/check-markdown-links.py`，确认受影响的来源链接有效；它只检查链接，规格能否指导实现仍要按内容核对。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 目标语言、文本范围和字体覆盖已列出，待定项已标明 |
| S2 | 键管理、回退、排版和验收样本各有可验证的要求，不需要的写明不需要 |
| S3 | `docs/localization/localization-spec.md` 已保存，GDD 原有规格已改为引用，链接检查通过 |

## 资源与文件影响

本地化规格及必要来源引用修改；不写翻译资源或运行接入。

## 阻塞、异常与范围变化

语言和措辞决定不足时保留待定，不通过生成占位翻译掩盖。

## 完成状态与验证标准

当前语言支持要求已确认且可实现验证，链接检查通过，未宣称翻译完成。
