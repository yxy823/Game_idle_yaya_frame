# 已经记录了几个代码问题，想选一个值得重构的

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

几个 Feature 的 notes 里记了 TODO 或代码坏味道，想知道现在先处理哪一个，或者是否暂时不重构。

需要的材料（可选）：限定的 Feature ID 或类别，例如“只看 F01-004”或“只看跨文件的坏味道”；不填时检查全部 Feature notes。notes 和对应源码由 Agent 直接读取。

## 前置条件与适用范围

候选已经记录在 Feature notes 中。问题来自外部观察、还没写进 notes 时，不走本入口：已知要调整哪处结构，用[重构目标已经选定，现在调整结构并保持行为](<重构目标已经选定，现在调整结构并保持行为.md>)；已交付行为坏了，用[发现 Bug，需要修复](<../出了问题/发现 Bug，需要修复.md>)。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 代码、性能与存档 → 已经记录了几个代码问题，想选一个值得重构的”。填入上述材料。本页使用 [$engineering-refactor-select](<../../../../../project-source/skills/engineering-refactor-select/SKILL.md>)。

**S1｜核对候选仍成立**

当前 Agent 使用 engineering-refactor-select 读取既有 notes 和对应当前代码，排除已解决或失效项。

**S2｜比较实际收益**

按当前变化需要、风险与成本推荐一个最小候选及不变行为，或说明暂缓的理由。

## 资源与文件影响

现有 notes 与代码只读；不创建或执行重构任务。

## 阻塞、异常与范围变化

没有值得处理的候选时直接说明，不为使用 Skill 造任务。

## 完成状态与验证标准

已给出有当前证据的一个推荐目标或明确不重构结论。

## 流程关联与衔接关系

依据：[任务路由表](<../../../../../project-source/methodology/00-overview.md#任务路由表>)、[重构 Feature 契约](<../../../../../project-source/methodology/07-engineering-change.md#重构-feature-契约>)。交付推荐或暂缓结论后等待用户选择；选中候选不等于批准实施，选定后以 refactor 模式交回 engineering-change-plan，即进入[重构目标已经选定，现在调整结构并保持行为](<重构目标已经选定，现在调整结构并保持行为.md>)。
