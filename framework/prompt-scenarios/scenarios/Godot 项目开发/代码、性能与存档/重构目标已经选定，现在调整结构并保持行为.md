# 重构目标已经选定，现在调整结构并保持行为

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已经知道要重构哪一处，例如从选重构入口选中了 F004 notes 里的某个坏味道，或自己指出某个模块“改一个数值要同时改三处”。

需要的材料：

- 重构目标：要调整的文件或模块，以及当前痛点的原话；来自选重构入口时，说明选中的候选即可。
- 保持边界（可选）：额外要保持的契约或允许改动的范围；不提供时 Agent 按现有 API 和已验收行为确定，并在方案中列出。

实现、依赖和已有计划由 Agent 直接读取。

## 前置条件与适用范围

已有具体重构目标，不再在本入口筛选候选。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 代码、性能与存档 → 重构目标已经选定，现在调整结构并保持行为”。填入上述材料。本页使用 [$engineering-change-plan](<../../../../../project-source/skills/engineering-change-plan/SKILL.md>)、[$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)。

**S1｜建立重构任务**

当前 Agent 阅读实际实现与依赖，用 engineering-change-plan 的 refactor 模式明确不变 API 和行为、维护收益与回归范围，展示重构 Feature 与结构调整方案，取得用户批准后写入；当前请求已明确批准具体方案及其执行时沿用。

**S2｜实施结构调整**

当前 Agent 使用 feature-execute 核对现有行为证据，再完成最小结构改动。按共用工程规则控制影响，保持无需变化的依赖与代码风格，不顺带改玩法。

**S3｜验证不变契约**

当前 Agent 运行相称回归和支持的适用静态检查，检查最终差异与维护目标。交付说明关键文件、行为保持依据及实际维护收益，不能只凭测试通过判定重构有价值。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 重构 Feature（不变行为、AC、回归范围）已获批写入，`check-feature-list` PASS |
| S2 | 结构改动的差异只涉及选定目标，没有行为变化 |
| S3 | 回归与静态检查的实际结果；关键文件、行为保持依据和维护收益已说明 |

## 资源与文件影响

获准代码结构、必要测试和工程任务记录修改；GDD 设计和约定行为不变。

## 阻塞、异常与范围变化

发现必须改变行为才能继续时明确范围变化，不把它藏进重构。

## 完成状态与验证标准

结构目标达成且约定行为保持，适用验证与交付完成。
