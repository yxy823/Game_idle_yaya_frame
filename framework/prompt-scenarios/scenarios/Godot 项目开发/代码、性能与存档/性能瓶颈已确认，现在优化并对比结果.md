# 性能瓶颈已确认，现在优化并对比结果

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如已测出打开背包时某个刷新函数占了大部分帧时，现在要改它，并在同样条件下对比改前改后。

需要的材料：

- 瓶颈测量报告或原始采样的路径，作为对比基线。
- 优化目标指标（例如“打开背包的 p95 帧时低于 16 ms”）；不提供时以“同条件下比基线改善且没有回归”为目标。
- 其余（所属任务、允许修改的范围）由 Agent 直接读取。

## 前置条件与适用范围

有可比较的瓶颈基线和实现授权，原任务或独立 maintenance 已承接。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 代码、性能与存档 → 性能瓶颈已确认，现在优化并对比结果”。填入上述材料。本页使用 [$diagnostics-performance](../../../../../project-source/skills/diagnostics-performance/SKILL.md)、[$feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md)。

**S1｜核对比较基线**

当前 Agent 用 diagnostics-performance 确认采样条件、瓶颈与允许改变的范围。

**S2｜实施最小优化**

feature-execute 优先修正数据访问、算法或生命周期，不凭猜测搭缓存框架。

**S3｜对比收益和代价**

在同一场景测量当前结果，并检查行为、画质、内存和资源成本，移除无收益复杂改动。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 基线的版本、场景、设备和采样条件已列出，可以重复 |
| S2 | 修改只涉及已证实瓶颈的代码路径 |
| S3 | 同条件下的前后指标、行为回归和内存/资源成本对比已记录 |

## 资源与文件影响

获准实现和必要回归修改，保留前后原始测量；性能方法本身不把任务标记为完成。

## 阻塞、异常与范围变化

指标条件变更时重新说明可比范围，不能混用数据宣称提升。

## 完成状态与验证标准

瓶颈目标得到可比较改善且副作用可接受，所属任务适用验证完成。
