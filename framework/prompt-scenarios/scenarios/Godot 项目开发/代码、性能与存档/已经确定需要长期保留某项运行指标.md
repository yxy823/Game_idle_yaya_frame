# 已经确定需要长期保留某项运行指标

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如离线收益结算耗时需要一直显示在调试面板上，供以后持续查看，而不是一次排查后删掉。

需要的材料：

- 指标要回答的问题和使用者（例如“调试面板显示每次离线结算耗时”）。
- 开关、保留范围和可接受的开销；不提供时由 Agent 提出默认值，实现前请用户确认。

## 前置条件与适用范围

长期观测有已确认用途，本次实现可维护的持久能力。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 代码、性能与存档 → 已经确定需要长期保留某项运行指标”。填入上述材料。本页使用 [$feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md) 实现，信号定义方法参照 [$diagnostics-instrumentation](../../../../../project-source/skills/diagnostics-instrumentation/SKILL.md)；还没有所属任务、需要独立工程工作时，先用 [$engineering-change-plan](../../../../../project-source/skills/engineering-change-plan/SKILL.md) 的 maintenance 模式规划。

**S1｜明确维护责任**

当前 Agent 在所属任务内写清指标含义、消费者、采集开关、保留/清理与成本。

**S2｜实现最小观测**

按 diagnostics-instrumentation 的方法定义信号的单位、采集方式和开销，标明这是保留的支持代码及其启停方式；feature-execute 完成采集与必要消费，避免通用平台。

**S3｜验证生命周期**

检查启停、重置、开销和长期资源释放，按所属任务完成验证与交付。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 指标含义、使用者、开关、保留与清理方式、开销上限已写进所属任务 |
| S2 | 采集代码和使用位置已实现，启停方式可以操作 |
| S3 | 启停、重置、开销测量和资源释放的结果已记录 |

## 资源与文件影响

获准代码、配置和必要指标说明修改；不另外复制 Feature 状态。

## 阻塞、异常与范围变化

没有实际消费者或保留理由时重新评估必要性，不能只因临时日志有用永久保留。

## 完成状态与验证标准

所选指标可用，开销和生命周期有验证，持久责任归属明确。
