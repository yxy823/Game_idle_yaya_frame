# 存档结构需要修改，旧数据不需要继续使用

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如开发期的存档字段要重排，现有存档都是测试数据，已决定不再读取旧格式。

需要的材料：

- 不保留旧数据的决定：用户原话，或已批准 Product 变更的位置。
- 其余（所属任务、当前与目标结构、读写实现）由 Agent 直接读取。

## 前置条件与适用范围

数据变化已明确且由正式任务承接；玩家含义变化先在 GDD 中确认，并核对 Product 交付影响。承接的是 maintenance 任务时，放弃旧存档兼容需要已批准的 Product 变更，“不保留旧数据”的决定必须来自该批准。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 代码、性能与存档 → 存档结构需要修改，旧数据不需要继续使用”。填入上述材料。本页使用 [$feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md)。

**S1｜确认数据含义**

当前 Agent 核对新结构与正式玩家需求，确认没有旧数据继续使用义务。

**S2｜修改当前读写**

所属 maintenance 或 Feature 完成最小字段与读写调整，不增加版本迁移层。

**S3｜验证新数据**

在测试数据范围核对默认值、往返读写和失败行为，不操作用户唯一存档。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 不保留旧数据的决定来源已写明（原话或 Product 变更位置） |
| S2 | 新结构的读写代码已修改，没有版本迁移分支 |
| S3 | 测试数据上的默认值、往返读写和失败行为结果已记录 |

## 资源与文件影响

获准数据实现和样本副本修改；真实唯一存档与未授权个人数据不动。

## 阻塞、异常与范围变化

新结构的字段含义、默认值或失败处理尚未确定时，停止依赖该决定的修改并说明缺口。若发现旧数据实际仍需继续使用，先确认保留要求，再按数据转换场景处理；本入口不增加旧格式转换义务，也不扩大数据访问范围。

## 完成状态与验证标准

新结构读写和失败行为验证完成，没有多余历史兼容层。
