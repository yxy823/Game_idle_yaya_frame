# 共享能力准备修改，先明确契约和影响范围

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

准备改一个多处在用的工具函数、Autoload 模块或资源格式，例如给存档读取函数加一个参数，想先知道哪些调用方要跟着改、改完要验证什么。

准备材料：

- 要改的共享对象：文件路径，或类、函数、资源的名称。
- 打算怎么改：用原话说明参数、返回值、信号或行为的变化；还没想好时写出要解决的问题。
- 这次分析的用途：只分析就写“只分析”；属于某个已授权任务时写出任务或 Feature ID。不写时按只分析处理。

调用方、配置和现有数据由 Agent 直接追查。

## 前置条件与适用范围

当前独立游戏项目的共享工具、模块或规则即将变更，需要在实施前明确影响；本页只分析该项目的边界与验证范围，不处理框架维护源。

## 执行步骤

使用[集中提示词库](../../../prompts/godot-development-prompts.json)中的“Godot 项目开发 → 代码、性能与存档 → 共享能力准备修改，先明确契约和影响范围”。没有专用 Skill，由当前 Agent 按项目 `AGENTS.md` 的[修改前先定位](<../../../../../project-source/Project_AGENTS.md#修改前先定位>)执行。

**S1｜确认项目内的对象职责**

当前 Agent 在用户指定的游戏项目内读取真实共享对象、公开入口和消费者，确认对象属于本次范围。项目独立拥有其文件，不向框架维护源同步修改。

**S2｜追查契约影响**

- 契约与责任：核对输入输出、错误传播、权限、副作用、状态、生命周期和清理责任。
- 影响对象：沿实际调用与数据路径定位配置、直接/间接调用方、现有数据及必要说明，不只按显式引用或文件名推断。

**S3｜交付修改边界**

给出必须一起修改的最小集合、保留行为、原子性/重试与验证建议。实现交原授权任务，不在分析中顺手改共享代码。

## 步骤产出与状态变化

| 步骤 | 继续条件 |
| --- | --- |
| S1 | 共享对象的文件位置、公开入口和所属项目已写明 |
| S2 | 消费者清单（含间接调用与数据）和每处的失败影响已列出 |
| S3 | 必须一起修改的文件清单、保留行为和对应的验证项已给出 |

## 资源与文件影响

共享实现、配置、调用者和现有证据只读；默认输出影响分析，不建立共享修改记录文件。

## 阻塞、异常与范围变化

对象在范围外仓库或实际调用无法确认时明确缺口；不把消费者相似当允许批量替换。

## 完成状态与验证标准

具体共享变更的契约、消费者、改动集合和相称验证范围已明确。

## 流程关联与衔接关系

依据：[范围判断](<../../../../../project-source/Project_AGENTS.md#范围判断>)（修改共享契约时迁移全部已知消费方）。

用户本次明确只分析时，即使之前有实施授权，也在交付边界后结束。
