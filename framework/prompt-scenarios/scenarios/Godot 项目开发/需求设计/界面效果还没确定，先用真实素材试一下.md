# 界面效果还没确定，先用真实素材试一下

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

背包格子用 64px 还是 96px 的物品图标拿不准，想把真实图标和最长的物品名放进 Godot 场景，在目标分辨率下看哪种更清楚、一屏能放下多少。

需要的材料：

- 视觉问题：要比较的一个尺寸、布局或色彩关系，例如“背包格子 64px 和 96px 哪个更易读”。
- 真实素材：有代表性的图片、字体或音频路径，例如 `assets/icons/items/`；没有时 Agent 列出需要的样本，对应检查保持未验证。
- 显示条件（可选）：目标分辨率和缩放方式；不写时按 UI 规格或项目设置中的视口，仍缺时作为待定项提出。
- 预算（可选）：最多花多少时间；不写时 Agent 先提出预算，请你确认后再构建。

覆盖本界面的 GDD、UI 规格、Art Bible 和项目 Godot 配置由 Agent 直接读取。

## 前置条件与适用范围

项目有覆盖本界面用途的实质 GDD；缺少时，说明缺的是哪部分设计和 [design-gdd](../../../../../project-source/skills/design-gdd/SKILL.md) 路由，然后停止。你已要求做这次独立的视觉实验。本页回答一个布局、尺寸或可读性问题，不承担完整界面交付；属于已规划交付的视觉基础时，在对应 Feature 内处理。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 界面效果还没确定，先用真实素材试一下”。填入上述材料。当前 Agent 使用 [$prototype-godot](../../../../../project-source/skills/prototype-godot/SKILL.md)，按[依赖实现前的视觉原型](../../../../../project-source/methodology/13-prototypes.md#依赖实现前的视觉原型)执行。

**S1｜限定视觉问题**

按[范围与资源](../../../../../project-source/methodology/13-prototypes.md#范围与资源)写明原型要回答的问题、目标视口和缩放条件、核心元素和状态，以及现有素材和缺口。

**S2｜搭建可观察样本**

在独立的 `.tscn` 中放入真实素材、贴近实际的文字长度和内容密度，使用本地示例状态，不连接正式规则、存档或实时数据；需要时使用既有资源工作台。完成后告诉你运行入口和要看的地方。

**S3｜观察并记录**

你在约定的显示条件下实际运行并给出判断。Agent 把入口场景、问题、观察结果（注明实际看到还是推断）和文件保留或移除的决定记在 Progress。你确认的布局、尺寸或可读性变化交回 [design-ui-spec](../../../../../project-source/skills/design-ui-spec/SKILL.md) 或对应规格 Skill 写回来源。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 问题、目标视口、核心元素和素材缺口已写明 |
| S2 | 原型场景可独立运行，使用真实素材，你已拿到运行入口 |
| S3 | 你的观察、结论、文件去向和要交回的规格变化已记在 Progress |

## 资源与文件影响

只新增或修改获准的原型场景和本地脚本；实验记录写在 Progress，不另建报告或第二份规格。UI 规格、GDD、Product 和 Feature 记录不在本页修改。

## 阻塞、异常与范围变化

达到预算时停止扩展原型，用已有版本取得观察。缺少某类代表性素材时，对应检查保持未验证，用文字、方块或占位文件名代替不算通过。你还没看过实际画面时，本页停在 S3 等待。

## 完成状态与验证标准

已取得你针对该视觉问题的实际观察和下一步决定，记录已写在 Progress，确认的变化已交给所属规格。
