# 项目里同一个词有不同理解，需要统一并记录

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

项目里同一个词有不同理解，需要统一并记录。

需要的材料：

- 待统一用语：术语、冲突用法。
- 确认依据与范围：已确认含义和引用范围。

## 前置条件与适用范围

本次统一词义与别名，不改变玩家行为或数据含义。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 项目里同一个词有不同理解，需要统一并记录”。填入上述材料。本页使用 [$project-grill-me](<../../../../../project-source/skills/project-grill-me/SKILL.md>)、[$project-terminology](<../../../../../project-source/skills/project-terminology/SKILL.md>)。

**S1｜确认唯一含义**

存在未决歧义时由 project-grill-me 讨论；已确认定义直接沿用，核对与现有行为是否一致。

**S2｜写入项目术语文档**

当前 Agent 使用 project-terminology，按[项目术语规范](../../../../../project-source/methodology/14-project-terminology.md#项目术语文件)将已确认定义与别名统一写入 `docs/terminology.md`。当前只用于一个主题的术语也使用该文件；范围内 GDD 或专业规格中的重复定义改为引用，详细规则保留在所属设计。

**S3｜修复引用**

维护别名、废弃说明和范围内链接，核对用词一致后按项目文档约定提交。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 词义与排除范围明确 |
| S2 | 已确认定义在 `docs/terminology.md` 只有一处正文 |
| S3 | 定义可被实际消费者找到 |

## 资源与文件影响

修改 `docs/terminology.md`，将范围内其他文档的重复定义改为引用；不改代码、不迁移数据、不生成或同步 Feature。

## 阻塞、异常与范围变化

拟定义实际改变规则或行为时先核对并维护 GDD 设计及相关交付范围，不能以改名掩盖需求变化。

## 完成状态与验证标准

确认含义已记录且相关引用一致，没有引入行为变更。
