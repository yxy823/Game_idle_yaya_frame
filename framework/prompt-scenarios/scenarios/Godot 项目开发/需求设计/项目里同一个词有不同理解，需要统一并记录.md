# 项目里同一个词有不同理解，需要统一并记录

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

GDD 里“材料”有时指背包里的物品，有时指配方的输入，Product 和 Feature 里的用法也不一致，需要定一个说法并让各处指向同一条定义。

需要的材料：

- 术语与冲突用法：哪个词、在哪里用法不同，可以附文件路径。
- 已确认的含义（可选）：已经决定的说法，用原话写；不提供时先由 project-grill-me 澄清。
- 引用范围（可选）：只改哪些文档；不写时覆盖 GDD、Product、Feature 和专业文档中用到这个词的位置。

现有定义、使用这个词的文档和相关代码由 Agent 直接读取。

## 前置条件与适用范围

本次统一词义与别名，不改变玩家行为或数据含义。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 项目里同一个词有不同理解，需要统一并记录”。填入上述材料。本页使用 [$project-grill-me](<../../../../../project-source/skills/project-grill-me/SKILL.md>)、[$project-terminology](<../../../../../project-source/skills/project-terminology/SKILL.md>)。

**S1｜确认唯一含义**

存在未决歧义时由 project-grill-me 讨论；已确认定义直接沿用，核对与现有行为是否一致。

**S2｜写入项目术语文档**

当前 Agent 使用 project-terminology，按[项目术语文件](../../../../../project-source/methodology/14-project-terminology.md#项目术语文件)将已确认定义与别名统一写入 `docs/terminology.md`。当前只用于一个主题的术语也使用该文件；范围内 GDD 或专业规格中的重复定义改为引用，详细规则保留在所属设计。

**S3｜修复引用**

维护别名、废弃说明和范围内链接。在项目根目录运行 `python -B yaya/tools/checks/check-markdown-links.py`，确认受影响的链接有效，核对用词一致后按项目 Git 规则提交。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 唯一含义和要区分的相近概念已确认，引用了确认来源 |
| S2 | 已确认定义在 `docs/terminology.md` 只有一处正文 |
| S3 | 范围内的用法已改为链接 `docs/terminology.md`，链接检查通过，提交哈希 |

## 资源与文件影响

修改 `docs/terminology.md`，将范围内其他文档的重复定义改为引用；不改代码、不迁移数据、不生成或同步 Feature。

## 阻塞、异常与范围变化

拟定义会改变规则、数值或流程时，停止本页，转[玩法要求变更](<已有模块的玩法要求变了，需要更新需求.md>)：由 design-gdd 确定选择、feature-sync 同步受影响的工作后，再回来记录术语。不能以改名掩盖需求变化。

## 完成状态与验证标准

确认含义已记录且相关引用一致，没有引入行为变更。
