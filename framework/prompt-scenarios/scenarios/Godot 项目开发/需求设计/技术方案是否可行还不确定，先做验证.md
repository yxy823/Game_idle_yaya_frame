# 技术方案是否可行还不确定，先做验证

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

技术方案是否可行还不确定，先做验证。

需要的材料：

- 技术假设与输入：单个技术假设、目标版本、最小输入。
- 验证边界：运行预算与通过标准。

## 前置条件与适用范围

关键方案尚未确定；已授权一个有预算的技术实验。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 技术方案是否可行还不确定，先做验证”。填入上述材料。

**S1｜固定技术判断**

当前 Agent 使用 [prototype-godot](../../../../../project-source/skills/prototype-godot/SKILL.md)，确认要验证的能力、约束和失败标准，先复用已有证据。

**S2｜执行最小探针**

只在获准位置实现和运行最小实验，保留参数、原始输出与版本，不改生产架构。

**S3｜交付技术结论**

说明可行范围、失败原因和后续成本，记录实验代码去向。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 实验可给出可行或受限结论 |
| S2 | 测量或运行结果可复现 |
| S3 | 结果足以支持下一次技术选择 |

## 资源与文件影响

只修改获准实验文件和必要报告；正式 Product 与 Feature 状态保持真实。

## 阻塞、异常与范围变化

达到预算、输入不可用或观察条件不足时停止实验并保留原始结果，不把未测内容写成通过。

## 完成状态与验证标准

技术假设有版本明确的真实证据与局限，未自动进入正式实现。
