# 玩法效果还没确定，在调试台试逻辑候选

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

三消棋盘已经能玩，GDD 里“三连消后额外掉落一个棋子”还有两种写法拿不准：每次都掉，还是连击两次以上才掉。你想在真实棋盘上切换着玩一玩，再决定规则怎么写。

需要的材料：

- 待定的规则和要比较的做法，例如上面的两种掉落条件。
- 观察标准（可选）：试玩时看到什么算成立；不写时 Agent 根据规则提出，请你确认。
- 所属 Feature ID（可空）：不填表示你要求的限定范围试玩。
- 预算（限定范围试玩时可选）：最多花多少时间、准备几个候选；不写时 Agent 先提出预算，请你确认后再准备。

覆盖本问题的 GDD 章节、相关的游戏实现与调参资源、项目的调试台说明 `dev/debug/README.md` 和已有记录由 Agent 直接读取。

## 前置条件与适用范围

项目有覆盖本问题的实质 GDD；缺少时，说明缺的是哪部分设计和 [design-gdd](../../../../../project-source/skills/design-gdd/SKILL.md) 路由，然后停止。本页比较一处会改变游戏结果的规则的两个以上候选，结论不会自动成为 GDD 规则。下列情况不用本页：

- **游戏还没有这块玩法的骨架**：不在 `dev/` 写假系统，按[界面的开发顺序](../../../../../project-source/methodology/13-debug-console-and-validation.md#界面的开发顺序)先规划骨架 Feature。
- **只是数值大小的问题**：例如掉落概率取 10% 还是 15%，改用[已有数值需要调整，更新模型与参数](<已有数值需要调整，更新模型与参数.md>)。
- **能不能实现还不确定**：改用[技术方案是否可行还不确定，先做验证](<技术方案是否可行还不确定，先做验证.md>)。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 玩法效果还没确定，在调试台试逻辑候选”。填入上述材料。当前 Agent 使用 [$debug-console-godot](../../../../../project-source/skills/debug-console-godot/SKILL.md)，按[逻辑候选](../../../../../project-source/methodology/13-debug-console-and-validation.md#逻辑候选)执行。

**S1｜界定规则候选**

当前 Agent 写明要比较的规则候选、相关的已确认 GDD 规则和观察标准，找到游戏里调用这条规则的位置。未确定的设计选择保持为提议。

**S2｜让规则可替换并放入候选**

在当前授权内，把这处规则调用改成从调参资源取实现，候选放在 `dev/debug/<对象>/slots/` 下；登记能暴露候选差异的固定局面，例如一个会触发三连消的棋盘。对 `game/` 的修改运行所选测试，至少包括依赖方向测试。完成后告诉你启动命令和试玩要点。

**S3｜试玩并记录**

你用 `dev/debug/README.md` 中的启动命令打开调试台，切换候选、播放固定局面或直接玩，给出感受。Agent 把试玩条件、你的反馈、能支持的结论和未覆盖的范围记在 Feature notes（限定范围试玩记在 Progress），说明候选保留还是退役。要采用的规则交回 design-gdd 写进 GDD，在你授权修改设计时写入；数值交回 [design-balance](../../../../../project-source/skills/design-balance/SKILL.md)。把候选采纳到游戏，只在实现这条规则的已授权 Feature 内进行。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 规则候选、观察标准和相关 GDD 规则已写明 |
| S2 | 候选和固定局面在调试台中可见；测试结果；你已拿到启动命令 |
| S3 | 你的试玩反馈、结论、未覆盖范围和候选去向已记录 |

## 资源与文件影响

- 修改：持有规则实现的调参资源及调用它的游戏代码，`dev/debug/<对象>/` 下的候选与固定局面，`dev/debug/README.md` 的登记，以及试玩记录。
- 不修改：GDD、Product 和 Feature 的要求；采用的规则交回所属来源。

## 阻塞、异常与范围变化

- **做法与代码对不上**：逻辑候选的做法还没有在真实项目中用过。按 13 号执行时遇到与实际代码不符的地方，Agent 停下报告具体位置和原因，不自行绕过。
- **达到预算**：限定范围试玩停止增加候选，用已有候选取得你的反馈。
- **你还没试玩**：本页停在 S3 等待；没有你的实际反馈，不写体验结论。

## 完成状态与验证标准

已取得你实际试玩的反馈及其能支持的结论，证据允许的未决取舍如实写出，记录已写好；对游戏的修改已验证并提交。
