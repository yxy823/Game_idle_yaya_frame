# 图片用途已确定，需要列出视觉文件准备要求

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

图片用途已确定，需要列出视觉文件准备要求。

需要的材料：

- 视觉用途：视觉对象、设计或实际使用位置、已采用方案。
- 显示与方向要求：已知显示条件和共享方向。

## 前置条件与适用范围

已确定用途，需要为实际所需的图片等视觉文件写出准备与接收依据。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 图片用途已确定，需要列出视觉文件准备要求”。填入上述材料。本页使用 [$design-visual-asset-spec](<../../../../../project-source/skills/design-visual-asset-spec/SKILL.md>)。

**S1｜核对显示用途**

当前 Agent 使用 design-visual-asset-spec 核对用途、已采用方案、已有资源和显示条件。先确认是否需要独立文件；影响文件需求的方案仍未确定时，保留具体选择，不代为选定。

**S2｜形成文件要求**

只写准备和接收需要的尺寸、透明、切片等适用参数，保留影响准备的未知项。字体等对象按自身用途写约束，不套用图片字段。已采用方案无需独立文件时简要说明，不生成空规格条目。

**S3｜保存唯一条目**

按[资源规格归属](../../../../../project-source/methodology/11-specialist-workflows.md#资源需求与交接)保存到所属表现、UI、组件或 Art Bible 章节，记录真实准备状态、来源和已知去向；交付待准备文件、已有覆盖、待定选择及必要的规格入口，不另建重复清单。

## 资源与文件影响

所属表现、UI 或共享组件的资源章节，以及 Art Bible 的“共享资源规格”按实际归属修改；本页不画图或导入。

## 阻塞、异常与范围变化

缺少会影响准备的显示条件或方案选择时，说明受影响的文件与规格，继续不依赖它的部分，不随意定稿导入参数。

## 完成状态与验证标准

所需视觉文件的准备与接收依据明确；关键规格仍待决定时指出受影响部分，不宣称已定稿。
