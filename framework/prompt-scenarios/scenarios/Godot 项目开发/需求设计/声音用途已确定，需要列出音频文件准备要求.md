# 声音用途已确定，需要列出音频文件准备要求

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

商店购买成功的表现已采用“金币飞入＋提示音”，现在要告诉准备音效的人：这段提示音多长、能不能连续叠加、要不要循环。

需要的材料：

- 声音用途：哪个界面或表现、在什么时刻播放，例如“商店购买成功”；可以附上表现或 UI 文档路径。
- 准备范围（可选）：只列哪几个声音；不写时，按当前 Product 已采用方案中需要独立文件的声音列出。

GDD 触发条件、Product 交付范围、已采用方案、Sound Bible 和已有音频资源由 Agent 直接读取。

## 前置条件与适用范围

已确定用途，需要为实际所需的音频文件写出准备与接收依据；不制作文件也不接入播放。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 声音用途已确定，需要列出音频文件准备要求”。填入上述材料。本页使用 [$design-audio-asset-spec](<../../../../../project-source/skills/design-audio-asset-spec/SKILL.md>)。

**S1｜核对声音用途**

当前 Agent 使用 design-audio-asset-spec 读取 GDD 触发条件、Product 交付范围、已采用方案、已有资源和 Sound Bible。先确认当前范围是否需要声音、是否需要独立文件；影响文件需求的方案仍未确定时，说明差异，表现方案交 [design-game-presentation](../../../../../project-source/skills/design-game-presentation/SKILL.md)、界面方案交 [design-ui-spec](../../../../../project-source/skills/design-ui-spec/SKILL.md) 澄清，不代为选定。

**S2｜形成文件要求**

只写准备和接收需要的时长、循环、叠加等适用约束，保留影响准备的未知项，指出实际试听缺口。不把未经确认的响度或采样率写成要求；已采用方案无需独立文件时简要说明，不生成空规格条目。

**S3｜保存唯一条目**

按[资源规格归属](../../../../../project-source/methodology/11-specialist-workflows.md#资源需求与交接)保存到所属表现、UI、组件或 Sound Bible 章节，记录真实准备状态、来源和已知去向；交付待准备文件、已有覆盖、待定选择及必要的规格入口，不另建重复清单。

## 资源与文件影响

所属表现、UI 或共享组件的资源章节，以及 Sound Bible 的“共享资源规格”按实际归属修改；共用方向保持唯一引用。

## 阻塞、异常与范围变化

方向、触发语义或方案选择未定时，说明受影响的文件与规格，继续不依赖它的部分；不能凭占位音频确认最终听感。

## 完成状态与验证标准

所需音频文件的准备与接收依据明确；关键规格仍待决定时指出受影响部分，文件制作与播放尚未实施。
