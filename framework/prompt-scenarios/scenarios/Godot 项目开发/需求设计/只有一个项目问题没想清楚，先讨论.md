# 只只有一个项目问题没想清楚，先讨论

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

在犹豫离线收益要不要设上限、上限几小时，这会牵动存档和数值，想先讨论清楚，再决定要不要改 GDD。

需要的材料：

- 当前疑问：一两句原话即可。
- 已有决定（可选）：对话中已确认、但还没写进文件的限制，例如“不做付费加速”。

GDD、Product、项目规则和相关代码由 Agent 按问题直接读取。

## 前置条件与适用范围

当前问题尚有影响方向的未决内容，本次只讨论。游戏设计和工程取舍由 project-grill-me 直接讨论，Product 交付取舍交 [product-spec-elicitor](../../../../../project-source/skills/product-spec-elicitor/SKILL.md)；讨论结论需要写入 GDD 时另行授权，由 [design-gdd](../../../../../project-source/skills/design-gdd/SKILL.md) 写入。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 只只有一个项目问题没想清楚，先讨论”。填入上述材料。本页使用 [$project-grill-me](<../../../../../project-source/skills/project-grill-me/SKILL.md>)。

**S1｜补齐已有事实**

当前 Agent 按 project-grill-me 的[共享提问方法](../../../../../project-source/skills/project-grill-me/SKILL.md#共享提问方法)读取相关项目事实并沿用已有决定，包括尚未保存的限制。游戏设计或交付问题读取 GDD《设计范围与边界》、`docs/gdd/open-questions.md` 中的相关问题及相关主题；工程问题读取适用的项目规则。

**S2｜集中询问相关取舍**

将同类型关键问题一起提出，提供推荐及影响；不为固定轮数拆成零散问答。

**S3｜整理讨论结论**

总结已确定、仍待定和必要后续入口，说明有用的已确认结论尚未保存；不把提问或沉默当授权。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 已确定事项与待定问题分开列出，并注明来源 |
| S2 | 同类问题按编号和字母选项一次提出，附推荐和影响 |
| S3 | 结论、仍待定项和尚未保存的已确认结论已在对话中列出 |

## 资源与文件影响

项目资料只读，对话结论不自动写 GDD、Product 或术语。

## 阻塞、异常与范围变化

GDD 尚未形成时说明哪些问题属于设计工作，缺失规则只阻塞依赖它的规划或实施，不阻止当前讨论。发现可以直接沿用的明确决定时停止重复澄清；外部事实缺口交调研。

## 完成状态与验证标准

当前疑问得到结论或明确的待定项，没有启动实施。
