# 当前模块的声音风格不明确，需要定下来

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

GDD 已写明采矿模块要让玩家“专注、偶尔有小惊喜”，但还没定背景音乐、环境声和奖励音效该是什么感觉、哪些反馈优先，后续的音频规格无从下手。

需要的材料：

- 要覆盖的模块或声音类别，例如“采矿界面的音乐和奖励音效”。
- 参考（链接或文件），写明想借鉴的是哪一点；没有参考时，Agent 只按 GDD 的体验目标提出方案。
- 已知的播放约束，例如常在静音下游玩、主要用手机外放；没有就不写。

目标体验和已确认的反馈行为由 Agent 从 GDD 读取。

## 前置条件与适用范围

GDD 已写明当前范围的体验目标，不要求完整；需要补足当前范围可实施的专业规范。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 当前模块的声音风格不明确，需要定下来”。填入上述材料。本页使用 [$design-audio-direction](<../../../../../project-source/skills/design-audio-direction/SKILL.md>)。

**S1｜收集专业依据**

当前 Agent 使用 design-audio-direction 读取 GDD 已有设计、已确认行为与参考，区分偏好和必须满足的约束。

**S2｜确定当前方向**

围绕情绪、声音角色、优先级、重复疲劳和必要静默提出取舍，与用户确认影响结果的关键选择。

**S3｜维护唯一规范**

共享声音规格与专业决定固定写入 `docs/audio/sound-bible.md`；原先写在 GDD 的当前范围内规格迁入该文件并更新引用，GDD 保留整体体验目标与玩法触发规则。明确适用对象并核对已有消费者影响。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | GDD 体验目标、参考与约束已列出，偏好与硬约束已分开 |
| S2 | 关键选择已由用户确认，未决项已标明 |
| S3 | `sound-bible.md` 已写入并注明适用对象；GDD 中被迁出的规格已改为链接 |

## 资源与文件影响

`docs/audio/sound-bible.md` 及必要 GDD 引用修改；其他专业规格按需链接，本页不制作或接入素材。

## 阻塞、异常与范围变化

没有试听样本时，明确方向尚未经过试听验证；不能宣称专业体验已经通过。

## 完成状态与验证标准

当前范围的方向已确认、保存并明确适用对象，制作和接入未冒充完成。
