# 功能已经写出来，需要补齐需求和任务记录

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

功能已经写出来，需要补齐需求和任务记录。

需要的材料：

- 行为与意图：实现范围、原始意图、已确认要求。
- 现有记录：现有任务与文档。

## 前置条件与适用范围

项目已有真实 GDD，已有代码但缺少当前交付范围或任务记录，本次只补文档；缺少 GDD 时说明缺口并停止。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 功能已经写出来，需要补齐需求和任务记录”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$product-author](<../../../../../project-source/skills/product-author/SKILL.md>)、[$feature-plan](<../../../../../project-source/skills/feature-plan/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜核对意图与实现**

当前 Agent 对照 GDD 和有效决定，区分实际代码行为与已批准设计，对实质冲突补问，不从代码倒推用户接受。

**S2｜补齐正式来源**

通过 [design-gdd](../../../../../project-source/skills/design-gdd/SKILL.md) 在已有 GDD 中保存确认的设计补充，再由 product-author 补齐当前 Product 交付范围与来源映射；专业细节交所属方法，保持原实现不动。

**S3｜对齐当前任务**

通过 feature-plan 或已有计划的 feature-sync 补齐范围与 AC，保留原 ID 和真实历史。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 要记录的当前要求明确 |
| S2 | 正式需求可用于规划 |
| S3 | 记录说明当前实现与验证缺口 |

## 资源与文件影响

GDD、当前 Product、必要专业来源和任务文档修改；代码、运行证据、历史接受只读。

## 阻塞、异常与范围变化

来源意图未确认时保留差异；不能以补录时间代替未知完成时间。

## 完成状态与验证标准

当前需求与任务能解释已有实现和真实缺口，没有制造交付或测试通过。
