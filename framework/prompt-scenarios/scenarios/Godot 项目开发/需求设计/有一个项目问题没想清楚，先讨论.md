# 有一个项目问题没想清楚，先讨论

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

有一个项目问题没想清楚，先讨论。

需要的材料：

- 讨论问题与事实：当前疑问、已知事实。
- 决定与目标：已有决定与期望结果。

## 前置条件与适用范围

当前问题尚有影响方向的未决内容，本次只讨论。游戏设计问题由 design-gdd 承接，Product 交付取舍由 product-spec-elicitor 承接，不因选择方法自动写入或实施。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 有一个项目问题没想清楚，先讨论”。填入上述材料。本页使用 [$project-grill-me](<../../../../../project-source/skills/project-grill-me/SKILL.md>)。

**S1｜补齐已有事实**

当前 Agent 使用 project-grill-me 的共用提问方法读取相关项目事实并沿用已有决定，包括尚未保存的限制。游戏设计或交付问题读取 GDD《设计范围与边界》及相关主题；工程问题读取适用 Project Rules。游戏设计按需使用 [design-gdd](../../../../../project-source/skills/design-gdd/SKILL.md)，交付问题按需使用 product-spec-elicitor。

**S2｜集中询问相关取舍**

将同类型关键问题一起提出，提供推荐及影响；不为固定轮数拆成零散问答。

**S3｜整理讨论结论**

总结已确定、仍待定和必要后续入口，说明有用的已确认结论尚未保存；不把提问或沉默当授权。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 已知与未知分开 |
| S2 | 关键选择能一次比较 |
| S3 | 讨论结果可用于下一步 |

## 资源与文件影响

项目资料只读，对话结论不自动写 GDD、Product 或术语。

## 阻塞、异常与范围变化

GDD 尚未形成时说明哪些问题属于设计工作，缺失规则只阻塞依赖它的规划或实施，不阻止当前讨论。发现可以直接沿用的明确决定时停止重复澄清；外部事实缺口交调研。

## 完成状态与验证标准

当前疑问得到结论或明确的待定项，没有启动实施。
