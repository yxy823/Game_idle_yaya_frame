# 已有模块的玩法要求变了，需要更新需求

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

GDD 里写着“背包满时拾取失败”，现在决定改成“背包满时物品进入暂存区”，而 F003 已经按旧规则规划或做完。

需要的材料：

- 新决定：改成什么，用原话写，例如“背包满时进入暂存区，暂存区最多 10 格”。
- 所属模块或 GDD 章节（可选）：不写时，Agent 按新决定在 GDD 中定位原要求，请你确认。
- 是否同时同步计划（可选）：写明“改完后同步 Feature 计划”时，提交来源后直接运行 feature-sync；不写时只列出受影响的 Feature 和同步入口。

原要求、Product、专业规格和受影响的 Feature 由 Agent 直接读取。

## 前置条件与适用范围

项目已有真实 GDD，需要修改已确认的玩家行为，并核对相关交付范围。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 已有模块的玩法要求变了，需要更新需求”。填入上述材料。当前 Agent 使用 [design-gdd](../../../../../project-source/skills/design-gdd/SKILL.md) 处理玩法，使用 [product-author](../../../../../project-source/skills/product-author/SKILL.md) 处理交付影响。

**S1｜核对行为差异**

当前 Agent 使用 design-gdd 只补问实质未决的玩法差异，区分新需求与对既有要求的 Bug；交付取舍才使用 product-spec-elicitor。

**S2｜更新所属来源**

design-gdd 将确认的整体设计变化写回 GDD，数值主题由 [design-balance](../../../../../project-source/skills/design-balance/SKILL.md) 在授权内直接维护；product-author 维护相关 Product 交付范围与引用。专业规格按[归属与决策](../../../../../project-source/methodology/11-specialist-workflows.md#归属与决策)由所属方法维护，原先写在 GDD 的当前范围内规格迁入所属正文并更新引用；GDD 保留整体目标与玩法规则，未轮到的 Product 只更新预拆分。

**S3｜交接计划影响**

列出受影响的已有 Feature 与尚未规划的范围。在项目根目录运行 `python -B yaya/tools/checks/check-markdown-links.py`，确认受影响的链接和锚点有效，再按项目 Git 规则提交来源修改。你已授权同步计划时，提交后使用 [feature-sync](../../../../../project-source/skills/feature-sync/SKILL.md)；否则只交付受影响 Feature 清单和同步入口。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 原要求与新决定的差异已列出；属于旧要求 Bug 的项已分出 |
| S2 | GDD、Product 和所属专业来源已写入新决定，迁出的规格已改为链接 |
| S3 | 链接检查通过、来源修改的提交哈希、受影响 Feature 清单；已授权时 feature-sync 的结果 |

## 资源与文件影响

GDD、Product 交付范围、必要专业来源与链接修改；历史 Feature 验收不重写。

## 阻塞、异常与范围变化

未确认的新想法不自动进入需求；明确旧要求的 Bug 走修复。

## 完成状态与验证标准

新要求已写入并提交到所属来源，受影响 Feature 已列出；已授权同步时计划已对齐。

## 流程关联与衔接关系

依据：[编写与采纳](<../../../../../project-source/methodology/11-specialist-workflows.md#编写与采纳>)、[源同步前先提交来源修改](<../../../../../project-source/methodology/11-specialist-workflows.md#源同步前先提交来源修改>)。之后单独同步计划时，按受影响 Feature 的状态选择[未开工](<../任务规划/要求已经改好，开工前需要同步 Feature 计划.md>)、[正在开发](<../任务规划/Feature 正在开发，已确认要求发生变化.md>)或[已交付](<../任务规划/Feature 已交付，后来确认要改变要求.md>)的同步场景。
