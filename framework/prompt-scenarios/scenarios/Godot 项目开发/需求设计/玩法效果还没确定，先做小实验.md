# 玩法效果还没确定，先做小实验

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

GDD 写了“连续点击可以加速采集”，但不确定点击节奏和加速幅度玩起来是否有爽快感，想先做一个能实际操作的小场景试一试，再决定规则怎么写。

需要的材料：

- 玩法假设：要判断的一点，例如“连续点击三次后加速，是否让人想继续点”。
- 观察标准（可选）：试玩时看到什么算成立；不写时 Agent 根据假设提出，请你确认。
- 预算（可选）：最多花多少时间、做到什么程度；不写时 Agent 先提出预算，请你确认后再构建。

覆盖本问题的 GDD 章节、已有实验记录和项目 Godot 配置由 Agent 直接读取。

## 前置条件与适用范围

项目有覆盖本问题的实质 GDD；缺少时，说明缺的是哪部分设计和 [design-gdd](../../../../../project-source/skills/design-gdd/SKILL.md) 路由，然后停止。你已要求做这次独立的玩法实验。本页回答一个循环、反馈或手感问题；实验结果不会自动成为 GDD 规则。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 玩法效果还没确定，先做小实验”。填入上述材料。当前 Agent 使用 [$prototype-godot](../../../../../project-source/skills/prototype-godot/SKILL.md)，按[限定范围的逻辑原型](../../../../../project-source/methodology/13-prototypes.md#限定范围的逻辑原型)执行。

**S1｜界定玩法假设**

当前 Agent 写明本次判断的是循环、反馈还是手感中的哪一点，引用相关的已确认 GDD 规则，并确定观察标准。未确定的设计选择保持为提议。

**S2｜实现最小循环**

在独立的小场景中只做真实输入、可见状态和即时反馈，支持重置到已知起点；需要时加入能暴露不确定点的固定情境。不铺完整的成长、经济或资源系统。完成后告诉你运行入口和试玩要点。

**S3｜试玩并记录**

你实际操作并给出感受。Agent 把操作条件、你的反馈、能支持的结论和未覆盖范围记在 Progress，说明试验代码保留、复用还是退役。要采纳的规则交回 design-gdd，数值交回 [design-balance](../../../../../project-source/skills/design-balance/SKILL.md)，在你授权修改设计时写入。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 假设、观察标准、预算和相关 GDD 规则已写明 |
| S2 | 场景可独立运行，能重置，你已拿到运行入口 |
| S3 | 你的试玩反馈、结论、未覆盖范围和代码去向已记在 Progress |

## 资源与文件影响

只新增或修改获准的实验场景和脚本；实验记录写在 Progress，不另建报告。GDD、Product 和 Feature 记录不修改；采纳的规则交回所属来源。

## 阻塞、异常与范围变化

达到预算时停止扩展实验，用已有版本取得反馈。你还没试玩时，本页停在 S3 等待；没有你的实际反馈，不写体验结论。

## 完成状态与验证标准

已取得你实际试玩的反馈及其能支持的结论，证据允许的未决取舍如实写出，记录已写在 Progress。
