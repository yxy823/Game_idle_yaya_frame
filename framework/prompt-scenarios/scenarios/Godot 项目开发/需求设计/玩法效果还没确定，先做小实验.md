# 玩法效果还没确定，先做小实验

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

玩法效果还没确定，先做小实验。

需要的材料：

- 玩法假设与样本：一个玩法假设、最小循环。
- 试验边界：试验时间与观察标准。

## 前置条件与适用范围

关键方案尚未确定；已授权一个有预算的玩法实验。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 玩法效果还没确定，先做小实验”。填入上述材料。

**S1｜界定玩法假设**

当前 Agent 使用 [prototype-godot](../../../../../project-source/skills/prototype-godot/SKILL.md)，确认本次判断的是循环、反馈或手感中的哪一点。

**S2｜实现最小循环**

在获准隔离试验范围仅补必要输入、反馈和记录，不铺完整成长或资源系统。

**S3｜记录实际体验**

保留操作条件、用户反馈和未覆盖范围，说明试验代码是否进入后续设计。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 观察标准可用于判断实验 |
| S2 | 用户可以实际试玩待验证部分 |
| S3 | 玩法结论与实验边界明确 |

## 资源与文件影响

只修改获准实验文件和必要报告；正式 Product 与 Feature 状态保持真实。

## 阻塞、异常与范围变化

达到预算、输入不可用或观察条件不足时停止实验并保留原始结果，不把未测内容写成通过。

## 完成状态与验证标准

一个玩法假设已得到实际体验结论或明确未决，没有冒充正式 Feature 完成。
