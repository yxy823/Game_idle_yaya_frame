# 已经选定新框架，检查适用后在当前项目替换

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已经选定新框架，检查适用后在当前项目替换。

需要的材料：

- 授权与验证：授权范围与验证条件。

当前项目即对话的工作目录，框架来源固定为 `D:/A_Games/Game_idle_yaya_frame`，不需要填写。

## 前置条件与适用范围

明确授权适用性检查通过后在当前项目一次性替换纯框架。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 修复与改进 → 已经选定新框架，检查适用后在当前项目替换”。填入上述材料。

**S1｜审查替换影响**

当前 Agent 识别业务、数据、项目定制、插件改动与混合配置，检查新框架契约。

**S2｜完成最小替换**

只更新纯框架并无损适配必要结构，保留有效业务、状态和机器配置。

**S3｜验证并一次交付**

按授权核对工具、引用与必要回归，记录未验证项及本地提交。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 适用性与原件保护清楚 |
| S2 | 当前项目没有双份活动框架 |
| S3 | 替换结果可追查 |

## 资源与文件影响

当前项目框架文件及必要适配修改；原业务与历史不重做。

## 阻塞、异常与范围变化

严重冲突不能无损处理时保留现场并说明，不以许可性检查结果冒充适用。

## 完成状态与验证标准

选定框架已在当前项目采用，数据与有效成果保留，适用验证和提交明确。
