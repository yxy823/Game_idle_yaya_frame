# 项目约束已确认要改，现在维护规则文档

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

项目约束已确认要改，现在维护规则文档。

需要的材料：

- 规则内容与范围：已确认约束、适用范围。
- 写入位置：所属规则文件。

## 前置条件与适用范围

变更只涉及 Project Rules 或所属工程规则中的开发约束、协作或工程原则，已有明确写入授权。游戏设计范围与排除项由 [design-gdd](../../../../../project-source/skills/design-gdd/SKILL.md) 按 GDD 正文归属维护，不在本入口重复保存。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 修复与改进 → 项目约束已确认要改，现在维护规则文档”。填入上述材料。

**S1｜判断规则归属**

当前 Agent 核对现有项目规则、Skill、工具和 README，确认不可由配置推断的约束应保留在哪里。

**S2｜修改最小条款**

合并同义要求，说明适用条件与边界，修复直接引用，不扩展所有任务的前置检查。

**S3｜核对冲突并交付**

静态检查新旧优先关系、链接与授权语义，按文档修改约定提交。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 唯一正文位置合理 |
| S2 | 规则能据以行动且没有重复 |
| S3 | 规则文本与实际约定一致 |

## 资源与文件影响

获准规则文档和必要链接修改；不创建虚构 Feature、不运行业务测试。

## 阻塞、异常与范围变化

归属或行为含义尚不明确时只澄清具体缺口；不能用措辞整理扩大权限。

## 完成状态与验证标准

确认约束已在正确位置保存，没有重复或相冲突的规则正文。
