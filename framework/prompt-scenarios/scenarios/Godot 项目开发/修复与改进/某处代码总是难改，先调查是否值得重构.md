# 某处代码总是难改，先调查是否值得重构

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

某处代码总是难改，先调查是否值得重构。

需要的材料：

- 调查对象与问题：相关模块、维护痛点。
- 后续变化：下一项预期变化。

## 前置条件与适用范围

需要从实际源码发现重构候选，本次不实施。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 修复与改进 → 某处代码总是难改，先调查是否值得重构”。填入上述材料。

**S1｜追查修改阻力**

当前 Agent 阅读实际模块、调用关系与必要历史，找到重复变化和不清晰责任。

**S2｜比较最小调整**

比较不改、局部整理和结构重构的收益与成本，明确保持的行为和验证建议。

## 资源与文件影响

代码只读；建议或获准调查报告不修改任务状态。

## 阻塞、异常与范围变化

只有风格偏好或未来假设时不强行提出架构层。

## 完成状态与验证标准

重构机会、依据和最小候选已交付，不自动开始重构。

## 流程关联与衔接关系

依据：[项目路由依据](<../../../../../project-source/methodology/00-overview.md>)。本入口只承担重构调查，不由结论授予实施重构的权限。用户本次明确只要求重构调查时，在建议交付后结束本次范围；若它是已授权完整任务中的一个步骤，按仍有效的具体授权进入后续所属流程，不因步骤结束重复确认。当前明确限制不能由旧授权撤销，检查结论也不代替 Feature 正式完成。
