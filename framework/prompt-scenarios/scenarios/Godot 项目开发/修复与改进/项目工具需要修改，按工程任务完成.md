# 项目工具需要修改，按工程任务完成

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

项目自有的工具（例如 `yaya/tools/` 下的脚本）出错、行为与自己的说明不符，或需要新增参数、调整行为；不涉及玩家可见的游戏需求。

需要的材料：

- 哪个命令：完整的命令行。
- 现状：当前输出或错误原文。
- 期望：期望的结果；新增或调整行为时，写清期望的输入和输出。

工具实现、调用方和说明文档由 Agent 直接读取。

## 前置条件与适用范围

需要实现或配置类工程修改，不改变玩家需求。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 修复与改进 → 项目工具需要修改，按工程任务完成”。填入上述材料。本页使用 [$engineering-change-plan](<../../../../../project-source/skills/engineering-change-plan/SKILL.md>)、[$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)。

**S1｜明确维护契约**

当前 Agent 阅读实际命令、实现和调用者，用 engineering-change-plan 按[分类边界](<../../../../../project-source/methodology/07-engineering-change.md#分类边界>)选择模式：工具违反已写成文档的契约时用 bug 模式并填写 `bug_diagnosis`，其他调整用 maintenance。说明公开入口、成功条件、副作用、失败重试与资源清理，展示 Feature 方案和验证范围，取得用户批准后写入；当前请求已明确批准具体方案及其执行时沿用。

**S2｜修改工具及调用者**

当前 Agent 使用 feature-execute 按职责准则完成最小实现，保持无需变化的 CLI/API 和依赖，同步必要配置、调用链和说明；不把查询入口顺带变成写入入口。

**S3｜验证工具结果**

当前 Agent 覆盖受影响正常与失败路径、错误传播及必要清理，检查差异并说明关键改动与限制，按项目完成条件交付；不靠 --help 当行为通过。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 工程 Feature（模式、AC，bug 模式含 `bug_diagnosis`）已获批写入，`check-feature-list` PASS |
| S2 | 工具改动及同步的调用方、配置和说明已完成 |
| S3 | 正常与失败路径的实际运行结果；差异已核对 |

## 资源与文件影响

项目工具、必要配置与调用方、回归和任务记录修改。

## 阻塞、异常与范围变化

- 机器上的工具路径失效：改用[配置中的工具路径失效了，需要恢复可用环境](<../项目创建与接入/配置中的工具路径失效了，需要恢复可用环境.md>)。
- 只改规则文字：改用[项目约束已确认要改，现在维护规则文档](<项目约束已确认要改，现在维护规则文档.md>)。

## 完成状态与验证标准

工具目标及关联契约已实现并验证，工程任务完成条件满足。
