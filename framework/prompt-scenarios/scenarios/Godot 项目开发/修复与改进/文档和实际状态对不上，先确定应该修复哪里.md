# 文档和实际状态对不上，先确定应该修复哪里

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

文档和实际状态对不上，先确定应该修复哪里。

准备材料：

- 冲突材料：冲突文档或记录、实际实现/运行证据。
- 判断依据：有效需求与相关历史。

## 前置条件与适用范围

发现任意来源和实际状态冲突，不要求曾有手工修改或可用 diff；本次只定位正确修复位置。

## 执行步骤

使用[集中提示词库](../../../prompts/godot-development-prompts.json)中的“Godot 项目开发 → 修复与改进 → 文档和实际状态对不上，先确定应该修复哪里”。

**S1｜明确冲突双方**

当前 Agent 使用 [feedback-triage-godot](../../../../../project-source/skills/feedback-triage-godot/SKILL.md)，读取实际文档、代码、Feature 记录或运行原件，区分正式要求、当前实现、历史结果和 Agent 摘要。

**S2｜核对有效依据**

根据用户确认、来源版本和实际历史判断是文档过期、实现不符、记录错误还是无法判定；代码存在不批准新需求。

**S3｜给出所属修复入口**

说明应该更新的唯一正文或实现位置、必须保留的历史、下游同步及必要验证；不直接按当前代码改 AC。

## 步骤产出与状态变化

| 步骤 | 继续条件 |
| --- | --- |
| S1 | 冲突不是只由旧摘要推定 |
| S2 | 修复依据具有真实权威 |
| S3 | 下一步修复范围可以明确选择 |

## 资源与文件影响

冲突双方、历史和证据只读；分析不改 Product、AC、实现或验收记录。

## 阻塞、异常与范围变化

有效来源或历史不足时保留尚未确定修复位置的状态，指出所需证据和可继续核对的位置；不能以让文档相等为目标重写接受记录。

## 完成状态与验证标准

冲突原因与应修复位置已有可核实依据，没有静默选择实现或文档一方为正确。
