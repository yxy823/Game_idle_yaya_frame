# 经验已经确认，需要整理进项目知识

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

经验已经确认，需要整理进项目知识。

需要的材料：

- 经验与适用范围：已确认经验、适用范围。
- 依据：经验的证据。

## 前置条件与适用范围

当前目标和写入范围已明确。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 经验沉淀 → 经验已经确认，需要整理进项目知识”。填入上述材料。

**S1｜核对知识归属**

当前 Agent 按[知识维护约定](../../../../../project-source/defaults/docs/knowledge/README.md)读取最近主题索引和已有条目，判断更新或合并到唯一正文。

**S2｜整理可复用解释**

使用 [technical-documentation-writing-godot](../../../../../project-source/skills/technical-documentation-writing-godot/SKILL.md) 整理 docs/knowledge/ 的合适条目及最近索引，写场景、做法、原因、边界与原始依据链接。

**S3｜交付文档变化**

检查链接和语义，按项目规则提交；局部事件经过仍留原 notes，不复制整段历史。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 经验不是重复事件流水 |
| S2 | 知识可独立使用且事实可追查 |
| S3 | 知识与历史职责分开 |

## 资源与文件影响

相关知识条目与索引修改，原始记录只读。

## 阻塞、异常与范围变化

证据不足的经验保留假设身份；跨项目规则或 Skill 修改需其实际授权，不能从本场景推导。

## 完成状态与验证标准

已确认经验进入适当主题，索引和证据链接有效。
