# 一个阶段已经结束，先总结值得保留的经验

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

一个 Product 或一组 Feature 刚做完，想在下一阶段开始前看看哪些做法值得保留、哪些问题以后要避免。

需要的材料：

- 阶段范围：Feature ID 范围或时间段，例如“F001–F006”。
- 关注点（可选）：想重点看的问题，例如“验收总是返工”。

任务记录、原始结果和已有知识由 Agent 直接读取。

## 前置条件与适用范围

复盘阶段、问题范围和可核实原始材料已明确；本次只交付对话中的经验建议，不包含文件写入。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 经验沉淀 → 一个阶段已经结束，先总结值得保留的经验”。填入上述材料。本页由当前 Agent 使用 [retro-godot](../../../../../project-source/skills/retro-godot/SKILL.md) 处理。

**S1｜核对真实经过**

当前 Agent 阅读相关知识索引、任务与原始证据，区分已证明做法与未经验证猜想。

**S2｜比较已有覆盖**

查现有规则、Skill、知识和工具，判断保留、合并或不固化，说明适用边界。

## 资源与文件影响

所有项目文件只读；结论在对话。

## 阻塞、异常与范围变化

证据不足的经验保留假设身份；跨项目规则或 Skill 修改需其实际授权，不能从本场景推导。

## 完成状态与验证标准

经验建议与真实依据已交付，没有自动写规则或实现脚本。
