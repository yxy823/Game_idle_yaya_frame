# 想知道项目现在做到哪里、下一步做什么

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如隔了几天回来，想先弄清各个 Feature 停在哪里、哪些在等人工验收；或者一个 Product 刚交付、某个 Feature 停在阻塞，想先看清现状，再决定下一步做什么。

需要的材料（都可选）：

- 关注的模块或疑问：例如“Product 02 还差什么”。不提供时看整个项目。
- 已有决定：已经定下、会影响下一步的选择，例如“先不做本地化”。
- 只要现状：注明“只要现状、不要建议”时，Agent 只做 S1。不注明时同时给出下一步建议。

进度、Feature 状态和证据由 Agent 直接读取。

## 前置条件与适用范围

适用于正常推进、暂停、等待验收或遇到阻塞时的进度与下一步查询，不要求已经停住。本次只提供说明和指导，不执行建议。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 现状、暂停与续接 → 想知道项目现在做到哪里、下一步做什么”。填入上述材料。本页使用 [$project-next-step-advisor](<../../../../../project-source/skills/project-next-step-advisor/SKILL.md>)，由当前 Agent 只读处理。

**S1｜说明当前进度**

使用 advisor 核对相关 Progress、Feature 记录及必要原始证据，只补读必要文件；概括已计划、已实现、已验证、待人工验收和已完成的实际状态，说明阻塞、已明确的决定及证据缺口。无法核实处保留未知，不把旧报告或测试通过单独当作当前交付完成。

**S2｜推荐下一步**

用户只要现状时跳过本步。根据当前进度与有效授权，按现有路由确定优先动作，再由 advisor 从本机共享 Godot 开发提示词库中核对适用场景。说明选中的分类、场景、理由、对应 Skill、最少所需材料、必要决定和预期结果。需要帮助发起下一动作时，填入当前事实起草可复制指令，不自动发送或执行。

没有匹配场景时，区分缺少输入、现有条目可以适配和真实覆盖缺口。只有目标未覆盖或执行边界明显不同，才提出场景补充建议，说明最接近条目和差异，不修改共享库；当前无需后续动作时说明依据，不为凑建议增加任务。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 各状态的实际进度、阻塞和证据缺口已说明，无法核实处标为未知 |
| S2 | 优先下一步、选中的场景、所需材料和理由已说明；或说明当前无需后续动作的依据 |

## 资源与文件影响

项目文件、原始证据和共享 Godot 提示词库只读；输出在对话。

## 阻塞、异常与范围变化

原件缺失时说明限制，不把摘要当已验证结果。

## 完成状态与验证标准

当前进度和证据缺口已说明；需要建议时，下一步建议有真实依据且能从当前状态衔接，无后续动作时理由明确。本次没有修改项目或执行建议。

## 流程关联与衔接关系

依据：[任务路由表](<../../../../../project-source/methodology/00-overview.md#任务路由表>)中的“查询状态”一行。本次查询到说明与建议交付为止，不因旧实施授权自动继续开发。
