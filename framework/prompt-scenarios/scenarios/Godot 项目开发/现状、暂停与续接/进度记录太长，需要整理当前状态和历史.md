# 进度记录太长，需要整理当前状态和历史

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

`docs/progress.md` 越写越长，已完成 Feature 的经过和当前事项混在一起，找不到现在该做什么。需要的材料：

- **整理范围**：只整理某几个 Feature 或某段历史时写明；没写时整理整份 Progress。

现有 Progress、Feature 记录和归档由 Agent 直接读取。

## 前置条件与适用范围

需要整理可读性与有效状态，本次不生成交接或停止开发的指令。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 现状、暂停与续接 → 进度记录太长，需要整理当前状态和历史”。填入上述材料。

**S1｜核对当前事项**

当前 Agent 读取 Progress、相关任务和必要原件，区分未完成工作与已完成经过。

**S2｜合并唯一正文**

使用 [technical-documentation-writing-godot](../../../../../project-source/skills/technical-documentation-writing-godot/SKILL.md) 整理表达，按 [Progress](../../../../../project-source/methodology/09-records-reports-and-handoff.md#progress) 保留正文归属：当前状态留 Progress，已完成工作的执行历史归档到 `docs/progress/`，Feature notes 只保留提醒、TODO 和链接，每段内容只保留一处正文。

**S3｜检查整理差异**

确认未改 Feature ID、状态、AC 和验收语义，按项目文档约定交付。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 仍未完成、阻塞和已完成的事项分别列出 |
| S2 | 已完成的执行历史在 `docs/progress/<key>.md`，Progress 留有链接 |
| S3 | 差异中没有 Feature ID、状态、AC 或验收结论的变化 |

## 资源与文件影响

现有进度、必要历史与链接修改；不改业务代码或完成状态。

## 阻塞、异常与范围变化

事实无法核实就标未知，不把摘要压缩为虚构成功。

## 完成状态与验证标准

Progress 能直接读到真实当前事项，必要历史有明确位置。
