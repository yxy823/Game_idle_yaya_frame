# 项目问题还没讨论清楚，继续原来的讨论

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

之前讨论过的项目问题（设计取舍、交付边界或技术选择）还没定下来，现在接着讨论。准备材料：

- **原讨论**：不在当前对话时，给出原问题和已确认决定的原话或记录路径。
- **本次补充**（可选）：新的信息，或想先解决的疑问。

## 前置条件与适用范围

原工作仅为讨论，尚未形成需要的决定；用户继续讨论，不授权落盘或实现。

## 执行步骤

使用[预设提示词库](../../../prompts/godot-development-prompts.json)中的“Godot 项目开发 → 现状、暂停与续接 → 项目问题还没讨论清楚，继续原来的讨论”。沿用原讨论的负责方：原来由 [$grill-me](../../../../../project-source/skills/grill-me/SKILL.md) 澄清的问题（包括游戏设计和工程取舍）继续由它处理；原来就是 [design-gdd](../../../../../project-source/skills/design-gdd/SKILL.md) 共创对话或 product-spec-elicitor 澄清交付取舍的，继续由它们处理；原讨论涉及多项相互依赖的未知时沿用 [wayfinder](../../../../../project-source/skills/wayfinder/SKILL.md)。

**S1｜恢复已有决定**

当前 Agent 沿用原讨论方法，核对原问题、相关事实、用户明确选择及尚未解决的依赖。游戏设计或交付问题读取 GDD《设计范围与边界》及相关主题；工程问题读取适用的项目规则。仍有效的已读内容与未保存决定直接复用，不重复询问已回答问题。

**S2｜集中讨论剩余取舍**

将同类关键问题一起提出推荐与影响；多项问题相互依赖时，先处理已有前提的疑问并继续获准的只读调查。新材料只改变对应部分，不重新开始整套访谈，也不因续接默认创建原型或 worktree。

**S3｜总结当前结论**

交付已确定结论、仍缺的决定和必要下一步，说明有用的已确认结论尚未保存；不写文件或自动调用实现 Skill。

## 步骤产出与状态变化

| 步骤 | 继续条件 |
| --- | --- |
| S1 | 已确认决定与待定问题分别列出 |
| S2 | 剩余问题已附推荐和影响一起提出 |
| S3 | 当前结论、仍缺的决定和尚未保存的结论已列出 |

## 资源与文件影响

项目材料只读，结论在对话；不因续接生成术语文档、Product 或 Feature。

## 阻塞、异常与范围变化

发现原摘要与真实决定冲突时核对具体依据，不能把 Agent 建议当用户选择。

## 完成状态与验证标准

原讨论问题得到当前结论或明确剩余取舍，没有重复已完成澄清。
