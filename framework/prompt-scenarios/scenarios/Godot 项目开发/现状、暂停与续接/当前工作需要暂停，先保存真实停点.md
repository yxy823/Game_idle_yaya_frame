# 当前工作需要暂停，先保存真实停点

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

当前工作要先停一停，留下下次能直接接着做的记录，但暂时不开新对话。例如 F003 做到一半、测试还在跑，你要去忙别的；或者一次没有建立 Feature 的调研、讨论或审核要先停下。是否属于 Feature 由 Agent 判断。

需要的材料：暂停原因（一句话）；有正在运行、需要保留而不能中断的命令或 Godot 进程时说明是哪个。当前工作、任务目标、授权、方法和原件由 Agent 从对话、Progress 和项目文件核对。

## 前置条件与适用范围

用户明确要求暂停当前工作，需要留下可恢复记录；本页只保存停点，不生成新对话交接文本。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 现状、暂停与续接 → 当前工作需要暂停，先保存真实停点”。填入上述材料。

**S1｜停止当前实施**

当前 Agent 使用 [task-handoff-godot](../../../../../project-source/skills/task-handoff-godot/SKILL.md)，从对话和 Progress 判断工作是否属于某个 Feature；按实际运行权限处理尚在执行的命令、查询或读取，记录已知进程状态，保留日志，不假定已启动的命令已经结束。

**S2｜记录真实停点**

在现有 Progress 和必要 notes 保存以下信息；没有 Feature 的工作已有任务报告时，报告只保留调查正文，Progress 链接它：

- **任务停点**：原目标、当前方法，有 Feature 时还写所处 Stage、尚未满足的验证与验收条件；未完成动作与阻塞。
- **已有依据**：有效决定、已读版本和原始证据。
- **恢复安排**：恢复第一步。

只保留必要一处正文及链接。

## 资源与文件影响

只更新必要现有进度或任务记录；保留未完成实现和资料，不为暂停强制提交或清理，不建立 Feature、Handoff.md 或新状态机。

## 阻塞、异常与范围变化

事实无法恢复时标未知；不能安全停止的进程或命令说明实际情况，不自动批量结束无关工具。

## 完成状态与验证标准

当前工作已暂停，现场、状态、有效授权和恢复第一步明确，没有标完成；等待用户续接。

## 流程关联与衔接关系

依据：[任务交接](<../../../../../project-source/methodology/09-records-reports-and-handoff.md#任务交接>)、[Progress](<../../../../../project-source/methodology/09-records-reports-and-handoff.md#progress>)。

本页完成后暂停原工作的实施，保留原有具体授权和真实现场；收到用户续接指令后，再从记录的停点恢复。不得因先前存在实施授权而立即继续已被要求暂停的工作。
