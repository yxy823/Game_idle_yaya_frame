# 继续上次没做完的 Feature

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

Feature 做到一半停下了，现在要接着做。可能是上一个对话太长或中途断开、换到新对话继续，也可能是在同一个对话里等你做决定或先处理了别的问题。两种情况用同一个入口，不需要先区分。需要的材料：

- **Feature ID**：例如 `F003`；仍在原对话且只有一个暂停的 Feature 时可省略。
- **交接材料**（可选）：上个对话留下的交接摘要或续接提示词原文；不提供时 Agent 从 Progress 和 Feature 记录恢复。
- **新增信息**（可选）：上次之后或暂停后的新决定、补充要求，或手动改过的文件。

## 前置条件与适用范围

同一项目的一项 Feature 尚未完成，用户要求继续其已有范围。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 现状、暂停与续接 → 继续上次没做完的 Feature”。填入上述材料。本页使用 [$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)。

**S1｜恢复真实停点**

当前 Agent 先看自己是否保有这项 Feature 的工作上下文：

- 新对话：核对同一项目目录、当前规则、Progress、任务原文和实际差异，交接摘要仅作线索。
- 原对话：复用仍有效的上下文，核对暂停后实际文件与证据变化，不重复读取无关历史。

**S2｜继续剩余工作**

使用 feature-execute 从真实阶段推进，保留有效成果与证据，不因换对话或暂停重建记录文件。

**S3｜完成或交接缺口**

完成适用实现、验证与交付；缺实质决定或人工结果时说明具体需要。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 新对话：目录、Progress、任务原文与实际差异已核对，交接摘要与事实的出入已列出。原对话：暂停后的文件、任务记录与证据变化已列出 |
| S2 | 剩余工作从真实 Stage 推进，有实际验证结果 |
| S3 | 有完成证据和提交哈希，或写明具体缺口与恢复条件 |

## 资源与文件影响

只修改原任务剩余授权范围；保留现有内容和真实 Git 差异。

## 阻塞、异常与范围变化

具体重叠内容或不可分离提交边界才构成需解决的冲突，不要求整树清空或逐文件证明归属。

缺少实质决定、验证前置或实际人工验收时保留未完成停点，说明具体缺口及恢复条件；不把已恢复上下文或已报告阻塞写成原任务完成。

## 完成状态与验证标准

原任务已授权范围内的剩余工作、适用验证、验收与交付均已完成；当前记录和证据能够支持该结论。
