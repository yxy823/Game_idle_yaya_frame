# 测试证据不可用，需要恢复有效验证

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

某个 Feature 的测试证据用不了，需要恢复有效的完成证据。常见的情况：

- `record-tests` 因 `--run` 写错了运行目录或 Feature ID 而报错，但那次 gdUnit 运行本身已经成功结束。
- Feature notes 或 Progress 写着 F012 的测试已经通过，但 `reports/gdunit-wrapper/F012/` 下找不到对应的 `result.json` 或 JUnit 原件。
- F012 的测试已经通过并导入，之后又改了实现（例如修了一处边界判断），原来的结果绑定的是旧内容。
- 运行 `run-gdunit-tests.py --feature F012` 时终端被关、对话中断或超时，没看到结束摘要。

你不需要先判断是哪一种，Agent 读取报告、进程和差异后判定。

需要的材料（都可空）：

- Feature ID：不提供时用当前对话中正在执行的 Feature。
- 看到的提示：导入错误或中断时最后的输出原文。
- 线索：摘要出处（哪份文件或哪段对话写了“测试通过”）、你记得的报告路径或运行位置（例如另一个 worktree）、原命令或运行目录。不提供时由 Agent 在 Feature notes、Progress 和 `reports/gdunit-wrapper/<Feature-ID>/` 中查找。

最终差异、既有报告、当前 AC 和测试影响由 Agent 直接读取。

## 前置条件与适用范围

一个 Feature 的测试证据无法支持当前内容，需要恢复真实验证依据。本页只处理 `--feature` 运行。原运行是 `--target` 聚焦运行时，用同一 `--target` 重跑并只报告结果，不调用 `record-tests`；聚焦运行不产生完成证据，见[没有 Feature，只想运行指定组件的自动测试](<../自动检查与测试/没有 Feature，只想运行指定组件的自动测试.md>)。

Agent 在 S1 判定原因，每种原因只做必要的恢复：

| 原因 | 判定依据 | 恢复范围 |
| --- | --- | --- |
| 报告路径填错 | 真实成功原件完整且仍覆盖当前内容，只是导入时引用路径错误 | 只重新导入，不重跑仍有效的测试 |
| 原始报告缺失 | 摘要所称成功的原件在既有报告和实际运行输出中都找不到 | 原件确实丢失时只重跑替换它所需的测试 |
| 证据过期 | 原始结果绑定的内容与最终差异不一致 | 只补失效或缺失的检查，保留仍适用的结果 |
| 运行中断 | 没有完整结束结果，可能仍在运行或已中断 | 只重跑没有取得完整结果的范围 |

同时命中多种时，先处理运行中断和原件缺失，再判断剩余证据是否过期。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 出了问题 → 测试证据不可用，需要恢复有效验证”。填入上述材料。本页由当前 Agent 使用项目自己的 [$verification-evidence-godot](<../../../../../project-source/skills/verification-evidence-godot/SKILL.md>)，链接指向框架中的源文件，仅供核对。

**S1｜判定证据为什么不可用**

当前 Agent 核对 `reports/gdunit-wrapper/<ID>/run-<id>/result.json`、引用的原始报告和 `engine.log`、实际进程，以及原始结果绑定的内容与最终差异，按上表判定原因。不依赖旧会话句柄可续接的假设，不把没读到当不存在。

**S2｜保留现场并处理运行状态**

保留原日志和旧原件。运行中断时，进程仍在运行就等它结束；只终止能确认属于原运行、且有停止授权的进程，归属或授权不明时只报告具体进程，不按名称批量结束进程。中断结果不导入。

**S3｜补足真实验证**

报告路径填错时跳过本步。其余原因由当前 Agent 使用 [project-verification-godot](<../../../../../project-source/skills/project-verification-godot/SKILL.md>) 按当前义务只重跑上表所列范围，读取完整结果。证据过期且人工内容版本发生实质变化时，用[Feature 已能体验，需要准备人工验收清单](<../审核与人工验收/Feature 已能体验，需要准备人工验收清单.md>)为当前版本提供实际体验，再按[已经实际体验，记录验收结果](<../审核与人工验收/已经实际体验，记录验收结果.md>)记录真实结论；自动重测不能恢复过期人工接受。

**S4｜导入当前证据并核对**

当前 Agent 回到 `verification-evidence-godot`，在项目根目录用配置的 Python 调用 `record-feature-completion.py record-tests` 导入当前有效的整组引用，再用 `show` 核对保存内容，需要时用 `validate` 判断依据是否足够。无法恢复的旧摘要只保留为历史限制，不作通过证据。

调用示例的准备与限制：

- 位置与参数：在游戏项目根目录执行，将 `F0XX`、测试范围和运行编号换成实际值；以运行器输出的真实结果路径为准。报告路径填错时只运行后三条命令。
- 导入前提：先确认运行实际结束成功及报告完整。失败、零测试或中断不得作为成功结果导入。

```powershell
$projectConfig = Get-Content -LiteralPath 'docs/methodology-config.json' -Raw | ConvertFrom-Json
$projectPython = $projectConfig.python_executable
& $projectPython -B yaya/tools/testing/run-gdunit-tests.py --feature F0XX --scope affected
$LASTEXITCODE
& $projectPython -B yaya/tools/features/record-feature-completion.py record-tests --feature F0XX --run 'reports/gdunit-wrapper/F0XX/run-<实际编号>/result.json'
$LASTEXITCODE
& $projectPython -B yaya/tools/features/record-feature-completion.py show --feature F0XX
$LASTEXITCODE
& $projectPython -B yaya/tools/features/record-feature-completion.py validate --feature F0XX
$LASTEXITCODE
```

参数与结果规则：

- 测试范围：`--scope` 按真实义务选择 `auto`、`required`、`affected` 或 `full`。
- 整组导入：多份结果必须在同一次 `record-tests` 调用重复提供 `--run <真实result.json>`，包括需要保留且相互兼容的全部运行。该命令用这一整组替换当前测试引用，不要拆成多次调用并假定累加。
- 导入失败：清除旧测试引用，但保留原始报告。
- 查看与核对：`show` 只显示已保存的记录，读到记录不等于能支持完成。需要确认当前测试与人工依据能否支持完成时运行 `validate`：退出码 `0` 表示依据有效，`2` 表示依据不足；人工部分尚待验收时也会返回不足，要如实说明是哪一部分。`validate` 通过也不等于 Feature 已完成。
- 免执行结果：仅在运行器按当前合法 manual 计划实际返回 `not_required` 时，说明本次不需要自动测试且没有运行报告，不导入不存在的原件或写成测试通过。既有失败和未完成结果仍按[没有自动义务：`not_required`](<../../../../../project-source/methodology/08-test-traceability-and-evidence.md#没有自动义务not_required>)处理；不能因报告丢失、证据失效或运行中断自行宣布免测。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 判定的原因及依据已写明；已查过的位置、要导入或缺失的原件、仍有效与已失效的义务已分别列出 |
| S2 | 原日志和旧原件已保留，残留进程已结束或已报告 |
| S3 | 重跑的 `result.json` 已生成，退出码已读取；需要时新清单已交给用户 |
| S4 | `record-tests` 退出码为 0，`show` 输出的测试引用与实际有效原件一致，`validate` 的结果和不足部分已报告 |

## 资源与文件影响

该 Feature 的 `docs/features/F0XX-evidence.json` 中的测试引用整组更新；导入失败会清除旧测试引用，原报告保留。新增必要运行报告和验收材料；原报告、失败日志不修改，不伪造旧报告、结束时间或通过记录。

## 阻塞、异常与范围变化

缺少运行权限或环境、不能确认原进程、重新运行失败或再次中断、报告仍不完整、现有成功运行覆盖不足时，保留验证尚未恢复的状态并报告缺口与恢复条件，不让人工接受抵消必要自动证据缺失。无法判断覆盖时明确缺口并做必要检查。任何情况下都不修改报告、哈希或时间戳来放行。

## 完成状态与验证标准

最终内容的适用验证义务有当前有效依据：需要测试证据时真实原件完整且整组引用已正确导入，当前结论来自完整实际结果，仍有效的测试和无变化部分没有重复验证；若当前规范确实允许运行器返回 `not_required`，则已核实该结果及适用前提，没有伪造测试原件。其他适用验证义务仍由所属任务完成，本入口不代替 Feature 交付。
