# 配置中的工具路径失效了，需要恢复可用环境

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

运行测试或检查时报 Godot 或 Python 找不到、无法启动，例如配置里的路径指向已删除的目录。需要的材料：

- **失败信息**：报错原文或失败命令的输出。
- **新路径**（可选）：已知可用的新位置或安装信息；不提供时 Agent 只报告缺口并询问，不自行找替代。

## 前置条件与适用范围

现有命令因已配置工具不存在或无法启动而受阻。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 出了问题 → 配置中的工具路径失效了，需要恢复可用环境”。填入上述材料。本页由当前 Agent 使用项目自己的 [$project-environment-godot](<../../../../../project-source/skills/project-environment-godot/SKILL.md>)，链接指向框架中的源文件，仅供核对。

**S1｜确认失败位置**

当前 Agent 检查配置路径存在性和原始报错，区分文件缺失、权限与版本问题。

**S2｜恢复指定工具**

用户提供或确认有效路径后，Agent 更新对应字段；未提供时只补问该缺口，不全盘猜找替代。

**S3｜重新检查**

在项目根目录运行 `& $projectPython -B yaya/tools/checks/check-project-environment.py --require-ready`（`$projectPython` 为配置中的 `python_executable`），追加初始化记录、更新 Progress 并按项目规则提交，再交回原任务的失败步骤。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 失败对应的配置字段和原因（缺失、权限或版本）已写明 |
| S2 | 更新后的字段值，来源是用户给出或确认 |
| S3 | 就绪检查的实际输出；原任务的恢复位置；提交哈希 |

## 资源与文件影响

配置中的对应路径、初始化记录（默认只在本地）和 Progress 修改，按项目规则提交；保留原始失败。

## 阻塞、异常与范围变化

权限审批未通过或工具尚未安装时保留阻塞，不改项目规则绕过。

## 完成状态与验证标准

所需工具可以被当前项目调用，环境检查结果明确，原任务恢复位置可定位。
