# 独立审核：已准备好视觉成果的美术效果

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

一组角色立绘或界面图标已经接入游戏，你想让没参与制作的新实例在实际显示尺寸下检查它是否符合 Art Bible 和资源规格。

需要的材料：

- 要审核的画面或资源：场景、界面或资源路径；版本不指定时用当前 HEAD。
- 显示条件（可空）：目标分辨率、显示尺寸或背景；不写时按资源规格中的条件。
- 实际画面（可空）：游戏内截图的路径。
- 允许的验证（可空）：是否允许审核实例在隔离副本中运行游戏取得证据；不写时只在隔离副本中做必要的针对性运行，副作用无法隔离就不运行。

Art Bible 和资源规格由审核实例按[归属与决策](<../../../../../project-source/methodology/11-specialist-workflows.md#归属与决策>)查找。

## 前置条件与适用范围

成果版本和权威要求明确，本次明确启用该领域独立审核。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 独立审核：已准备好视觉成果的美术效果”。填入上述材料。本页使用 [$review-art](<../../../../../project-source/skills/review-art/SKILL.md>)。

**S1｜交接审核材料**

主 Agent 向新上下文 independent-reviewer 交范围、版本、来源、原始证据与验证权限，作者总结仅作待核实陈述。

**S2｜按领域检查**

独立 Agent 使用 review-art 核对信息层级、视觉一致性与目标场景可读性，需要结论时取得指定显示条件下的实际画面。

**S3｜交付审核报告**

给出美术符合性和未观察部分；成果、原件和验收只读，获准验证缓存和数据隔离。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 交接内容按“范围、权威要求、快照、原始证据、允许的验证”五项写明，实例确认为新的 `independent-reviewer` |
| S2 | 每条发现都写明对应的规格条目、显示条件和画面证据位置 |
| S3 | 报告列出发现（标有 `must_fix`、`suggest` 或 `acceptable`）和没有目标视图证据的部分 |

## 资源与文件影响

被审成果、原证据和验收记录只读；只写获准报告与隔离验证产物。

## 阻塞、异常与范围变化

- 证据不足：无法取得必要真实证据时明确未验证，不能以作者声明代替。
- 独立性不足：无法独立时说明限制。

## 完成状态与验证标准

该范围的独立报告已交付，美术符合性和未观察部分明确，没有修复被审成果。
