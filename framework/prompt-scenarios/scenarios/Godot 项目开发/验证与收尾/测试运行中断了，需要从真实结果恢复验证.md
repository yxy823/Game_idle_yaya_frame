# 测试运行中断了，需要从真实结果恢复验证

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

运行 `run-gdunit-tests.py --feature F012` 时终端被关、对话中断或超时，没看到结束摘要，不知道测试是跑完了、还在跑，还是失败了。

需要的材料：

- 中断时看到的提示（可空）：最后的输出或报错原文。
- 原命令或运行目录（可空）：不提供时由 Agent 从 `reports/gdunit-wrapper/<Feature-ID>/` 最新的 `result.json` 读取实际命令。

## 前置条件与适用范围

测试未取得完整结束结果，不能假定仍在执行或已经通过。

本页只处理 `--feature` 运行。原运行是 `--target` 聚焦运行时，用同一 `--target` 重跑并只报告结果，不调用 `record-tests`；聚焦运行不产生完成证据，见[没有 Feature，只想运行指定组件的自动测试](<没有 Feature，只想运行指定组件的自动测试.md>)。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 测试运行中断了，需要从真实结果恢复验证”。填入上述材料。本页由当前 Agent 使用项目自己的 `verification-evidence-godot` Skill；[源码入口](<../../../../../project-source/skills/verification-evidence-godot/SKILL.md>)仅供核对。

**S1｜确认真实运行状态**

当前 Agent 核对实际进程和报告，不依赖旧会话句柄可续接的假设。

**S2｜保留并处理现场**

保留原日志。进程仍在运行时等它结束；只终止能确认属于原运行、且有停止授权的进程，归属或授权不明时只报告具体进程，不按名称批量结束进程。中断结果不导入。

**S3｜重新验证缺口**

原因解除后，当前 Agent 使用 [project-verification-godot](<../../../../../project-source/skills/project-verification-godot/SKILL.md>) 重新运行必要范围并读取完整结果，再回到 `verification-evidence-godot` 导入当前有效整组引用。

调用示例的准备与限制：

- 位置与参数：在游戏项目根目录执行，将 `F0XX`、测试范围和运行编号换成实际值；以运行器输出的真实结果路径为准。
- 导入前提：先确认运行实际结束成功及报告完整。失败、零测试或中断不得作为成功结果导入。

```powershell
$projectConfig = Get-Content -LiteralPath 'docs/methodology-config.json' -Raw | ConvertFrom-Json
$projectPython = $projectConfig.python_executable
& $projectPython -B yaya/tools/testing/run-gdunit-tests.py --feature F0XX --scope affected
$LASTEXITCODE
& $projectPython -B yaya/tools/features/record-feature-completion.py record-tests --feature F0XX --run 'reports/gdunit-wrapper/F0XX/run-<实际编号>/result.json'
$LASTEXITCODE
& $projectPython -B yaya/tools/features/record-feature-completion.py show --feature F0XX
$LASTEXITCODE
& $projectPython -B yaya/tools/features/record-feature-completion.py validate --feature F0XX
$LASTEXITCODE
```

参数与结果规则：

- 测试范围：`--scope` 按真实义务选择 `auto`、`required`、`affected` 或 `full`。
- 整组导入：多份结果必须在同一次 `record-tests` 调用重复提供 `--run <真实result.json>`，包括需要保留且相互兼容的全部运行。该命令用这一整组替换当前测试引用，不要拆成多次调用并假定累加。
- 导入失败：清除旧测试引用，但保留原始报告。
- 查看与核对：`show` 只显示已保存的记录，读到记录不等于能支持完成。需要确认当前测试与人工依据能否支持完成时运行 `validate`：退出码 `0` 表示依据有效，`2` 表示依据不足；人工部分尚待验收时也会返回不足，要如实说明是哪一部分。`validate` 通过也不等于 Feature 已完成。
- 免执行结果：仅在运行器按当前合法 manual 计划实际返回 `not_required` 时，说明本次不需要自动测试且没有运行报告，不导入不存在的原件或写成测试通过。既有失败和未完成结果仍按[没有自动义务：`not_required`](<../../../../../project-source/methodology/08-test-traceability-and-evidence.md#没有自动义务not_required>)处理；不能因证据失效或运行中断自行宣布免测。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 原运行的状态（已结束、仍在运行或中断）和对应的 `result.json` 已确认 |
| S2 | 原日志已保留，残留进程已结束或已报告 |
| S3 | 重跑的 `result.json` 已生成，`record-tests` 退出码为 0，`validate` 的结果已报告 |

## 资源与文件影响

原失败日志保留；新运行与证据引用写入。

## 完成状态与验证标准

中断情况和剩余验证已处理，当前结论来自完整实际结果。
