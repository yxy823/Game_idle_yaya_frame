# 想检查某个模块现状，不依赖 Feature 或差异

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

背包模块已经运行了一段时间，没有正在进行的 Feature，也不针对某次改动，你想让独立实例看看它现在有哪些缺陷和维护问题。

需要的材料：

- 要审核的模块：目录或文件路径，例如 `scripts/inventory/`；快照不指定时用当前 HEAD。
- 要对照的需求（可空）：GDD 条目、规格或规则文件路径；不提供时由审核实例按模块查找，找不到的需求写明缺口，不虚构 AC。
- 关注点（可空）：想重点看的行为或风险，例如存档兼容、性能。
- 允许的验证（可空）：只做静态审核，或允许在隔离副本中运行哪些测试、场景；不写时审核实例只在隔离副本中做必要的针对性验证，副作用无法隔离就不运行。

## 前置条件与适用范围

明确启用一次独立审核；现状快照已选定。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 想检查某个模块现状，不依赖 Feature 或差异”。填入上述材料。本页使用 [$review-code](<../../../../../project-source/skills/review-code/SKILL.md>)。

**S1｜核实独立实例**

主 Agent 交接范围、版本、权威来源和运行权限给新上下文 independent-reviewer，核实真实独立性。

**S2｜读取实现并追查**

独立 Agent 使用 review-code，按只读 Audit 检查当前模块及直接依赖，不要求存在差异，不虚构 Feature、AC 或历史基线。

**S3｜交付有界结论**

分别说明需求符合性和质量，给文件定位、触发、影响与最小建议；验证只在隔离范围。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 交接内容按“范围、权威要求、快照、原始证据、允许的验证”五项写明，实例确认为新的 `independent-reviewer` |
| S2 | 每条发现都有文件位置、触发条件和依据的需求或规则 |
| S3 | 报告分别给出需求符合性、代码质量和证据缺口，每条发现标有 `must_fix`、`suggest` 或 `acceptable` |

## 资源与文件影响

被审源和原证据只读；获准报告与隔离缓存可写。

## 阻塞、异常与范围变化

版本在审查中变化时补查受影响部分或限定版本；不能把作者自查称独立。

## 完成状态与验证标准

模块现状的有据问题与证据缺口明确，未修改被审内容或历史完成状态。
