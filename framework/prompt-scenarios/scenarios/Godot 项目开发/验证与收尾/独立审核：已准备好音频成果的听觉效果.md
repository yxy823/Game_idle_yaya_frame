# 独立审核：已准备好音频成果的听觉效果

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

一组音效或背景音乐已经接入游戏，你想让没参与制作的新实例在游戏里实际听过后，检查它和 Sound Bible、资源规格是否一致。

需要的材料：

- 要审核的声音：触发它的事件或场景、音频文件路径；版本不指定时用当前 HEAD。
- 播放条件（可空）：设备、音量和静音设置；不写时按资源规格中的条件。
- 试听证据（可空）：游戏内录音的路径，或你的试听记录。
- 允许的验证（可空）：是否允许审核实例在隔离副本中运行游戏取得证据；不写时只在隔离副本中做必要的针对性运行，副作用无法隔离就不运行。

GDD 触发条件、Sound Bible 和资源规格由审核实例按[归属与决策](<../../../../../project-source/methodology/11-specialist-workflows.md#归属与决策>)查找。

## 前置条件与适用范围

成果版本和权威要求明确，本次明确启用该领域独立审核。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 独立审核：已准备好音频成果的听觉效果”。填入上述材料。本页使用 [$review-audio](<../../../../../project-source/skills/review-audio/SKILL.md>)。

**S1｜交接审核材料**

主 Agent 向新上下文 independent-reviewer 交范围、版本、来源、原始证据与验证权限，作者总结仅作待核实陈述。

**S2｜按领域检查**

独立 Agent 使用 review-audio 核对声音角色、响度关系、循环疲劳及实际反馈，需要结论时取得实际听取证据。

**S3｜交付审核报告**

给出听觉判断和未听取范围；成果、原件和验收只读，获准验证缓存和数据隔离。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 交接内容按“范围、权威要求、快照、原始证据、允许的验证”五项写明，实例确认为新的 `independent-reviewer` |
| S2 | 每条发现都写明时间点或触发事件、播放条件和对应的规格条目 |
| S3 | 报告列出发现（标有 `must_fix`、`suggest` 或 `acceptable`）和没有实际试听的部分 |

## 资源与文件影响

被审成果、原证据和验收记录只读；只写获准报告与隔离验证产物。

## 阻塞、异常与范围变化

- 证据不足：无法取得必要真实证据时明确未验证，不能以作者声明代替。
- 独立性不足：无法独立时说明限制。

## 完成状态与验证标准

该范围的独立报告已交付，听觉判断和未听取范围明确，没有修复被审成果。
