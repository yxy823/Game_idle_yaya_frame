# 已经实际体验，需要记录我的明确验收结论

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已经实际体验，需要记录我的明确验收结论。需要的材料：Feature ID、当前版本和用户明确接受或拒绝的具体范围。

## 前置条件与适用范围

用户已实际体验并通过对话明确给出结果，不使用文件结果入口。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 已经实际体验，需要记录我的明确验收结论”。填入上述材料。本页由当前 Agent 使用项目自己的 `manual-acceptance-godot` Skill；[源码入口](<../../../../../project-source/skills/manual-acceptance-godot/SKILL.md>)仅供核对。

**S1｜核对具体决定**

当前 Agent 确认本次结论对应当前内容和完整必要范围，区分建议、继续请求与实际接受。

**S2｜记录口头结果**

使用 tools/features/record-feature-completion.py record-acceptance --feature <ID> --status accepted 或 rejected，值只取用户实际决定。

**S3｜交回完成检查**

说明已接受与待修复内容，继续原授权剩余事项；不要求同一结果再填 JSON。

项目工具命令的使用要求：

- 工作目录：实际游戏项目根目录。
- Python 与调用形式：使用 `docs/methodology-config.json` 中的 `python_executable`，按 `& $projectPython -B <脚本路径> <参数>` 调用，每次立即检查 `$LASTEXITCODE`。
- 参数：尖括号参数替换为实际值。
- 结果边界：命令成功只证明该操作完成。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 可记录的决定真实明确 |
| S2 | 记录不伪造 JSON 来源 |
| S3 | 人工证据与后续处理正确衔接 |

## 资源与文件影响

完成依据写入真实对话决定；不生成假的用户结果文件。

## 阻塞、异常与范围变化

决定范围不全或含义矛盾时只补问缺口；自动测试不代替口头接受。

## 完成状态与验证标准

用户明确决定已按真实来源记录，没有重复验收或伪造材料。
