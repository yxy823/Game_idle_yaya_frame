# 已经实际体验，需要记录我的明确验收结论

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

你按清单体验完 F012，不想自己编辑清单，直接在对话里说“背包全部通过，只有排序那项不对”，需要 Agent 把这句话写进清单并记录。

需要的材料：

- 你的结论原话：接受或拒绝了哪些检查项，不通过的具体表现。
- Feature ID 与清单路径（可空）：不提供时用当前对话中正在验收的 Feature，由 Agent 在 `reports/manual-acceptance/F0XX/` 查找已绑定的清单。

## 前置条件与适用范围

用户已实际体验，并在对话中明确给出结论。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 已经实际体验，需要记录我的明确验收结论”。填入上述材料。本页由当前 Agent 使用项目自己的 `manual-acceptance-godot` Skill；[源码入口](<../../../../../project-source/skills/manual-acceptance-godot/SKILL.md>)仅供核对。

**S1｜核对具体决定**

当前 Agent 确认本次结论对应当前内容和清单中的哪些检查项，区分建议、继续请求与实际接受；没有覆盖全部检查项时先补问。

**S2｜写进清单并记录**

把用户结论写进清单对应项的 status，comment 写明“来自对话”和原话。使用 yaya/tools/features/record-feature-completion.py record-acceptance --feature <ID> --checklist <清单路径>。工具列出绑定后变化的文件时，逐个核对；都不涉及本 Feature 才加 --confirm-unrelated-changes 重新记录，否则重新准备清单。

**S3｜交回完成检查**

说明已接受与待修复内容，继续原授权剩余事项；用户不需要再填一次清单。

项目工具命令的使用要求：

- 工作目录：实际游戏项目根目录。
- Python 与调用形式：使用 `docs/methodology-config.json` 中的 `python_executable`，按 `& $projectPython -B <脚本路径> <参数>` 调用，每次立即检查 `$LASTEXITCODE`。
- 参数：尖括号参数替换为实际值。
- 结果边界：命令成功只证明该操作完成。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 结论对应的检查项 ID 已列出，未覆盖或含义不清的项已补问 |
| S2 | 清单对应项的 status 已修改、comment 写有“来自对话”和原话；`record-acceptance` 退出码为 0 |
| S3 | 报告列出已接受与待修复的检查项 ID |

## 资源与文件影响

已绑定清单的状态和备注按用户结论更新；该 Feature 的完成依据 `docs/features/F0XX-evidence.json` 中的人工结果会更新。不另建结果文件。

## 阻塞、异常与范围变化

决定范围不全或含义矛盾时只补问缺口；自动测试不代替用户的结论。

## 完成状态与验证标准

用户明确结论已写进清单并按真实来源记录，没有重复验收或伪造材料。

## 流程关联与衔接关系

依据：[记录用户的结论](<../../../../../project-source/methodology/contracts/manual-acceptance-files.md#记录用户的结论>)、[绑定之后内容又有变化](<../../../../../project-source/methodology/contracts/manual-acceptance-files.md#绑定之后内容又有变化>)。

验收记录后 Feature 仍待收尾：记录本身不推进 Stage。只单独发了本提示词（例如在新对话里），或你要求暂停时，再发续接提示词：仍在原对话时用[仍在原对话，想继续暂停的 Feature](<../项目恢复与交接/仍在原对话，想继续暂停的 Feature.md>)，换了对话时用[换了一个对话，想继续上次没做完的 Feature](<../项目恢复与交接/换了一个对话，想继续上次没做完的 Feature.md>)。
