# 实现又改过了，需要更新已经过期的验证证据

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

实现又改过了，需要更新已经过期的验证证据。

需要的材料：

- 内容与证据：最终修改、既有报告。
- 验证义务：当前 AC 和测试影响。

## 前置条件与适用范围

已有成功证据可能不覆盖最终内容，需要重新确定仍有效与失效范围。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 实现又改过了，需要更新已经过期的验证证据”。填入上述材料。本页由当前 Agent 使用项目自己的 `verification-evidence-godot` Skill；[源码入口](<../../../../../project-source/skills/verification-evidence-godot/SKILL.md>)仅供核对。

**S1｜比较内容变化**

当前 Agent 对照原始结果绑定和最终差异，按当前测试策略判断受影响义务。

**S2｜重验失效范围**

当前 Agent 使用 [project-verification-godot](<../../../../../project-source/skills/project-verification-godot/SKILL.md>) 只补失效或缺失检查，保留仍适用结果；必要人工版本变化通过 [manual-acceptance-godot](<../../../../../project-source/skills/manual-acceptance-godot/SKILL.md>) 准备当前版本材料，由用户实际体验。

**S3｜更新完成依据**

当前 Agent 回到 `verification-evidence-godot` 导入当前兼容整组测试结果；真实人工结论由 `manual-acceptance-godot` 按其来源记录，旧原件保留历史身份。

调用示例的准备与限制：

- 位置与参数：在游戏项目根目录执行，将 `F0XX`、测试范围和运行编号换成实际值；以运行器输出的真实结果路径为准。
- 导入前提：先确认运行实际结束成功及报告完整。失败、零测试或中断不得作为成功结果导入。

```powershell
$projectConfig = Get-Content -LiteralPath 'docs/methodology-config.json' -Raw | ConvertFrom-Json
$projectPython = $projectConfig.python_executable
& $projectPython -B yaya/tools/testing/run-gdunit-tests.py --feature F0XX --scope affected
$LASTEXITCODE
& $projectPython -B yaya/tools/features/record-feature-completion.py record-tests --feature F0XX --run 'reports/gdunit-wrapper/F0XX/run-<实际编号>/result.json'
$LASTEXITCODE
& $projectPython -B yaya/tools/features/record-feature-completion.py show --feature F0XX
$LASTEXITCODE
```

参数与结果规则：

- 测试范围：`--scope` 按真实义务选择 `auto`、`required`、`affected` 或 `full`。
- 整组导入：多份结果必须在同一次 `record-tests` 调用重复提供 `--run <真实result.json>`，包括需要保留且相互兼容的全部运行。该命令用这一整组替换当前测试引用，不要拆成多次调用并假定累加。
- 导入失败：清除旧测试引用，但保留原始报告。
- 查看结果：`show` 仅用于查看匹配记录；读到记录不等于整个 Feature 完成。
- 免执行结果：仅在运行器按当前合法 manual 计划实际返回 `not_required` 时，说明本次不需要自动测试且没有运行报告，不导入不存在的原件或写成测试通过。既有失败和未完成结果仍按[测试规范](<../../../../../project-source/methodology/08-test-traceability-and-evidence.md>)处理；不能因证据失效或运行中断自行宣布免测。

人工内容版本发生实质变化时，用[准备人工验收清单](<Feature 已能体验，需要准备人工验收清单.md>)为当前版本提供实际体验，再按[用户填写的清单](<人工验收清单已填好，需要记录结果.md>)或[明确口头结论](<已经实际体验，需要记录我的明确验收结论.md>)的真实来源记录。自动重测不能恢复过期人工接受。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 证据有效性有实际依据 |
| S2 | 最终内容被适用证据覆盖 |
| S3 | 记录不混用不相容版本 |

## 资源与文件影响

新增必要运行与验收材料，更新完成证据引用；原报告不修改。

## 阻塞、异常与范围变化

无法判断覆盖时明确缺口并做必要检查，不能改哈希或时间戳使旧证据变新。

## 完成状态与验证标准

最终内容的适用义务有当前有效证据，不要求无变化部分重复验证。
