# 场景或资源刚改完，需要实际启动检查

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

场景或资源刚改完，需要实际启动检查。

需要的材料：

- 运行对象与状态：指定场景、初始状态。
- 变更与操作范围：资源变化和允许操作。

## 前置条件与适用范围

需要当前场景真实加载和运行反馈。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 场景或资源刚改完，需要实际启动检查”。填入上述材料。本页由当前 Agent 使用项目自己的 `project-verification-godot` Skill；[源码入口](<../../../../../project-source/skills/project-verification-godot/SKILL.md>)仅供核对。

**S1｜确定运行入口**

当前 Agent 核对场景路径、配置 Godot 与所需初始状态，明确观察动作和停止条件。

**S2｜启动实际场景**

在项目根目录用配置 Godot --path . <实际场景路径> 启动；按获准动作观察加载、资源和运行错误。

**S3｜记录观察边界**

区分可由日志确认的行为与仍需用户视觉、声音或手感判断的部分。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 运行目标可重复 |
| S2 | 真实启动与日志已取得 |
| S3 | 实际反馈不被模拟结果替代 |

## 资源与文件影响

运行产生必要缓存、日志和已授权测试数据；场景与资源内容不修改。

## 阻塞、异常与范围变化

涉及真实存档时先采用允许的测试数据；无法隔离不扩大写入。

## 完成状态与验证标准

目标场景实际启动并完成所选观察，错误和未体验部分明确。

## 流程关联与衔接关系

依据：[项目路由依据](<../../../../../project-source/methodology/00-overview.md>)、[测试与证据规范](<../../../../../project-source/methodology/08-testing-strategy.md>)。本入口只承担场景启动检查，不由检查结果授予修复权限。用户本次明确只验证时，在结果交付后结束该范围；若检查属于已授权完整任务的步骤，按仍有效的具体授权进入后续所属流程，不因检查结束重复确认。当前明确限制不能由旧授权撤销，检查结果也不代替 Feature 正式完成。
