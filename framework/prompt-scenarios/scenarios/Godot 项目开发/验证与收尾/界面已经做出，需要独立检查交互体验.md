# 界面已经做出，需要独立检查交互体验

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

背包界面已经做进游戏，可以从主菜单打开并操作，你想让没参与制作的新实例检查操作是否好找、反馈是否清楚、出错后能否恢复。

需要的材料：

- 要审核的界面与流程：例如“从主菜单打开背包，到丢弃一件物品”；版本不指定时用当前 HEAD。
- 已有的交互证据（可空）：录屏、截图或操作记录的路径。
- 允许的验证（可空）：是否允许审核实例在隔离副本中运行游戏取得证据；不写时只在隔离副本中做必要的针对性运行，副作用无法隔离就不运行。

UI 规格、GDD 和 Product 由审核实例按[归属与决策](<../../../../../project-source/methodology/11-specialist-workflows.md#归属与决策>)查找。

## 前置条件与适用范围

成果版本和权威要求明确，本次明确启用该领域独立审核。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 界面已经做出，需要独立检查交互体验”。填入上述材料。本页使用 [$review-ux](<../../../../../project-source/skills/review-ux/SKILL.md>)。

**S1｜交接审核材料**

主 Agent 向新上下文 independent-reviewer 交范围、版本、来源、原始证据与验证权限，作者总结仅作待核实陈述。

**S2｜按领域检查**

独立 Agent 使用 review-ux 核对入口、操作、反馈、错误与可达性，需要结论时取得真实运行交互及目标状态。

**S3｜交付审核报告**

给出交互问题和覆盖限制；成果、原件和验收只读，获准验证缓存和数据隔离。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 交接内容按“范围、权威要求、快照、原始证据、允许的验证”五项写明，实例确认为新的 `independent-reviewer` |
| S2 | 每条发现都写明具体操作、观察到的障碍和证据位置 |
| S3 | 报告列出发现（标有 `must_fix`、`suggest` 或 `acceptable`）和没有实际交互证据的部分 |

## 资源与文件影响

被审成果、原证据和验收记录只读；只写获准报告与隔离验证产物。

## 阻塞、异常与范围变化

- 证据不足：无法取得必要真实证据时明确未验证，不能以作者声明代替。
- 独立性不足：无法独立时说明限制。

## 完成状态与验证标准

该范围的独立报告已交付，交互问题和覆盖限制明确，没有修复被审成果。
