# 测量数据已经取得，需要独立核实结论是否成立

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

做完一次性能剖析或长时间运行测试，得到“优化后帧时间下降 30%”“连续运行 4 小时内存不增长”这样的结论，想让没参与测量的新实例核实原始数据能否支持它。

需要的材料：

- 要核实的结论：结论原话。
- 测量记录：原始数据和测量报告的路径；报告里没记下版本、设备、负载、时长或运行模式（编辑器、调试或导出版本）时，在这里补充。
- 允许的复测（可空）：允许在隔离副本中重跑哪些测量；不写则不复测。

测量和统计代码由审核实例直接读取。

## 前置条件与适用范围

已有测量结果和具体结论，本次是独立评估证据是否支持该结论；不重新执行整套诊断或优化。

## 执行步骤

使用[集中提示词库](../../../prompts/godot-development-prompts.json)中的“Godot 项目开发 → 验证与收尾 → 测量数据已经取得，需要独立核实结论是否成立”。审核实例按[证据与结论](<../../../../../project-source/methodology/12-independent-review.md#证据与结论>)核实测量证据；涉及测量或统计代码时用 [$review-code](../../../../../project-source/skills/review-code/SKILL.md)。

**S1｜交接独立审核**

主 Agent 将结论、被测版本、完整原件、设备/负载/时长、采样方法及权限交给新上下文 independent-reviewer，作者说明仅作待核实陈述。

**S2｜核实证据与推导**

独立 Agent 读取实际数据，按结论类型核对：

- 性能结论：前后条件是否可比、样本与指标是否支持差异。
- 长测结论：是否达到声明负载/时长且保留中断。
- 两类结论都要核对：测量用的构建（编辑器、调试或导出版本）与结论适用的构建是否一致。

涉及采集和统计实现时使用 review-code，追查单位、采样、聚合及遗漏数据。

**S3｜交付有界判断**

分别说明已支持、不能支持及待补证据；确需针对性复测只在明确授权隔离范围运行，不能用审核请求自动授权优化。

## 步骤产出与状态变化

| 步骤 | 继续条件 |
| --- | --- |
| S1 | 交接内容包含结论原话、原始数据路径和测量条件，实例确认为新的 `independent-reviewer` |
| S2 | 每项结论都对应到具体的原始数据和测量条件 |
| S3 | 报告逐项标出“支持”“不支持”或“证据不足”，并写明适用的构建和负载 |

## 资源与文件影响

原始测量、被审实现和验收记录只读；可写获准报告和隔离复测产物，不改原始数据。

## 阻塞、异常与范围变化

- 原件缺失、版本不明或条件不可比：给出受限结论。
- 没有真实满时长：不能认可长跑完成。
- 缺少用户体验：不能推定人工接受。

## 完成状态与验证标准

独立报告逐项判断测量结论是否受支持，并明确版本、覆盖和局限，没有修改被审成果。
