# 人工验收清单已填好，需要记录结果

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

人工验收清单已填好，需要记录结果。

需要的材料：

- 所属任务：Feature ID。
- 用户填写过的清单：已绑定、状态和备注由用户填写。

## 前置条件与适用范围

用户已实际体验，并直接在已绑定的清单中填写了各项结果。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 人工验收清单已填好，需要记录结果”。填入上述材料。本页由当前 Agent 使用项目自己的 `manual-acceptance-godot` Skill；[源码入口](<../../../../../project-source/skills/manual-acceptance-godot/SKILL.md>)仅供核对。

**S1｜核对清单**

当前 Agent 读取清单的状态和备注，确认检查项定义未被改动、结果确由用户填写；备注与状态矛盾时只就具体问题澄清。

**S2｜记录结果**

使用 tools/features/record-feature-completion.py record-acceptance --feature <ID> --checklist <清单路径>。工具列出绑定后变化的文件时，逐个核对；都不涉及本 Feature 才加 --confirm-unrelated-changes 重新记录，否则重新准备清单。

**S3｜报告接受范围**

核对记录结果；全部 passed 即为明确接受，不再重复确认；failed/pending 保留给对应处理。

项目工具命令的使用要求：

- 工作目录：实际游戏项目根目录。
- Python 与调用形式：使用 `docs/methodology-config.json` 中的 `python_executable`，按 `& $projectPython -B <脚本路径> <参数>` 调用，每次立即检查 `$LASTEXITCODE`。
- 参数：尖括号参数替换为实际值。
- 结果边界：命令成功只证明该操作完成。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 结果属于当前验收范围 |
| S2 | 工具接受清单与实际状态 |
| S3 | 接受与待处理范围准确 |

## 资源与文件影响

清单的状态和备注保持用户填写的原样；该 Feature 的完成依据 `docs/features/F0XX-evidence.json` 中的人工结果会更新。

## 阻塞、异常与范围变化

清单缺失、检查项定义被改、绑定后变化涉及本 Feature，或状态与备注冲突时保留失败，只澄清具体缺口。

## 完成状态与验证标准

结果已记录，实际接受或失败范围明确；尚需其他完成检查不跳过。
