# 素材已收到，需要独立检查技术规格

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

外包或素材商交来一批图标、角色序列帧或音效，接入前想让独立审核确认尺寸、格式、透明、时长和来源记录是否符合规格。

需要的材料：

- 被审素材：文件或目录路径，以及被审版本（提交哈希，或“当前工作区”）。
- 来源与许可：仓库里没有记录时，提供来源说明或授权文件；没有就写“未知”。
- 允许的验证：例如“只做静态检查”。不写时允许必要的隔离验证（复制到 `reports/scratch/` 下运行）。

资源规格、已有使用方和导入设置由审核实例直接读取。

## 前置条件与适用范围

成果版本和权威要求明确，本次明确启用该领域独立审核。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 素材已收到，需要独立检查技术规格”。填入上述材料。本页使用 [$review-assets](<../../../../../project-source/skills/review-assets/SKILL.md>)。

**S1｜交接审核材料**

主 Agent 向新上下文 independent-reviewer 交范围、快照、权威来源、原始证据与允许的验证（见[触发与独立性](<../../../../../project-source/methodology/12-independent-review.md#触发与独立性>)的输入表），作者总结仅作待核实陈述。

**S2｜按领域检查**

独立 Agent 使用 review-assets 核对路径与 UID、格式与尺寸、通道、时长、透明与裁切、动画数据、导入与压缩设置，以及来源与许可记录；需要结论时取得文件实物与必要隔离工具输出。

**S3｜交付审核报告**

给出技术规格符合性及接入前缺口，发现按 `must_fix`、`suggest`、`acceptable` 标注严重程度。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 审核实例确认是新上下文的 independent-reviewer，交接内容含范围、快照、来源、原始证据和允许的验证 |
| S2 | 每项结论对应具体文件、导入设置或工具输出；没取得证据的项列为未验证 |
| S3 | 报告写明被审快照、实际覆盖、带严重程度的发现和未验证项 |

## 资源与文件影响

被审成果、原证据和验收记录只读；只写获准报告与隔离验证产物。

## 阻塞、异常与范围变化

- 证据不足：无法取得必要真实证据时明确未验证，不能以作者声明代替。
- 独立性不足：无法独立时说明限制。

## 完成状态与验证标准

该范围的独立报告已交付，技术规格符合性及接入前缺口明确，没有修复被审成果。
