# 测试已经通过，但填错报告路径导致导入失败

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

测试已经通过，但填错报告路径导致导入失败。

需要的材料：

- 任务与成功原件：实际 Feature ID；知道完整成功运行目录时一并提供。
- 失败证据：原始导入错误。

## 前置条件与适用范围

真实成功原件完整且仍覆盖当前内容，只是填写了错误引用路径。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 测试已经通过，但填错报告路径导致导入失败”。填入上述材料。本页由当前 Agent 使用项目自己的 `verification-evidence-godot` Skill；[源码入口](<../../../../../project-source/skills/verification-evidence-godot/SKILL.md>)仅供核对。

**S1｜定位完整原件**

当前 Agent 核对 reports/gdunit-wrapper/<ID>/run-<id>/result.json 和引用的原始报告，确认结束成功及无未解决较新失败。

**S2｜重新导入整组引用**

用项目 Python 调用 record-feature-completion.py record-tests --feature <ID> --run <真实result.json>，有多份时同一次重复 --run。

**S3｜查看保存结果**

调用同工具 show --feature <ID> 核对保存内容。show 只读记录，不判断整个 Feature 完成。

- 参数：替换 F0XX 和实际运行编号；需要多份结果时在同一次 record-tests 后重复 --run。
- 结果：先核对导入退出码和内容，show 的退出 0 仅说明匹配记录已读取。

```powershell
$projectConfig = Get-Content -LiteralPath 'docs/methodology-config.json' -Raw | ConvertFrom-Json
$projectPython = $projectConfig.python_executable
& $projectPython -B yaya/tools/features/record-feature-completion.py record-tests --feature F0XX --run 'reports/gdunit-wrapper/F0XX/run-<实际编号>/result.json'
$LASTEXITCODE
& $projectPython -B yaya/tools/features/record-feature-completion.py show --feature F0XX
$LASTEXITCODE
```

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 原件内容与覆盖仍有效 |
| S2 | 导入以当前整组替换旧引用 |
| S3 | 引用组与实际原件一致 |

## 资源与文件影响

该 Feature 的 docs/features/F0XX-evidence.json 中的测试引用整组更新；导入失败会清除旧测试引用，原报告保留。

## 阻塞、异常与范围变化

原件丢失、内容变化、覆盖不足或运行失败不属于路径恢复；不修改报告或哈希放行。

## 完成状态与验证标准

导入成功且保存的完整引用可回到真实有效原件，无需重跑仍有效测试。
