# 界面布局已经确定，想先做一个能点击的原型

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

界面布局已经确定，想先做一个能点击的原型。

需要的材料：

- 任务与规格：当前 Feature、确认 UI 规格。
- 体验输入：真实素材、原型体验范围。

## 前置条件与适用范围

布局与行为已确认，本次实现可点击原型而非探索布局。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 日常开发 → 界面布局已经确定，想先做一个能点击的原型”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜固定原型范围**

当前 Agent 由 feature-execute 调用 [prototype-godot](../../../../../project-source/skills/prototype-godot/SKILL.md)，核对规格和原型承载位置，明确当前 Feature 内检查点或独立原型任务；后续制作和检查使用真实 Godot 场景。

**S2｜接入真实交互**

用已确认素材搭建目标界面与必要点击、切换和反馈，不提前铺无关业务。

**S3｜提供体验入口**

完成适用解析和运行检查，交用户确认可观察行为，记录接受范围后返回原任务。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 本次验收只覆盖原型目标 |
| S2 | 用户可以从指定入口操作 |
| S3 | 原型结论与完整功能交付区分 |

## 资源与文件影响

原型场景、脚本、实际资源引用和当前任务记录修改；UI 上游规格只读。

## 阻塞、异常与范围变化

素材或关键规格未定时退出既定原型实施，不在本页混入设计探索。

## 完成状态与验证标准

原型可运行可点击，目标反馈可观察，实际体验结论与后续依赖明确。
