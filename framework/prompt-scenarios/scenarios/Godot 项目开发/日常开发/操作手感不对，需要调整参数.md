# 操作手感不对，需要调整参数

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如角色移动已经做好，你玩的时候觉得停下来会往前滑、跳跃按下去要等一下才起跳，想边玩边调到顺手。

需要的材料：

- 哪个操作、在什么情况下感觉不对，用自己的话说，例如“松开方向键后还往前滑一段”。
- 想保持不变的地方（可空），例如“最高速度不要变”。
- 其余（所属 Feature、参数所在的资源或节点）由 Agent 直接读取。

## 前置条件与适用范围

操作已经实现、能运行。调整属于一个已授权的 Feature 或你要求的限定范围实验；没有这类授权时，Agent 只给调整建议，不改文件。操作所属的 Feature 已经完成时，改已确认的值是需求变化：先把要调的参数在所属文档中改为“待定，由调优确定”，用[Feature 已交付，后来确认要改变要求](<../任务规划/Feature 已交付，后来确认要改变要求.md>)建立新的 Feature，再在新 Feature 中从这里开始调。感觉不对其实来自规则或数值设计时，例如关卡节奏、经济成长，改用[已有数值需要调整，更新模型与参数](<../需求设计/已有数值需要调整，更新模型与参数.md>)。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 日常开发 → 操作手感不对，需要调整参数”。填入上述材料。本页使用 [$feel-tuning-godot](../../../../../project-source/skills/feel-tuning-godot/SKILL.md)。

**S1｜让参数可调**

当前 Agent 找到相关参数。参数还写死在代码里时，在当前授权内把它们提到参数资源或导出变量。

**S2｜一轮轮对比**

每一轮 Agent 说明要改哪一两个参数、改多少、为什么。你可以重新运行后感受，也可以在编辑器运行时的“远程”场景树里按 Agent 给的值直接改属性、边玩边比较。Agent 在 Feature notes 中记下这一轮。

**S3｜写回采用的值**

你满意后，Agent 把值写进参数资源，删除只为对比加的临时代码，再继续 Feature 的验证。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 要调的参数已集中在资源或导出变量中，并告诉你它们的位置 |
| S2 | notes 中每一轮有改动的参数和你的选择 |
| S3 | 参数资源中是采用的值，没有残留的临时对比代码，相关自动测试通过 |

## 资源与文件影响

修改参数资源或导出变量；把写死的参数提到资源中属于本次实现修改。不为调参新增调试面板或热键，除非你要求。

## 阻塞、异常与范围变化

- 两三轮下来仍然没有接近你想要的手感时，Agent 停下来说明可能的原因，例如输入延迟、动画锁住了输入，需要先查原因时转[发现异常，先定位原因，不修改实现](<../修复与改进/发现异常，先定位原因，不修改实现.md>)。
- 要改变操作规则本身（例如新增二段跳），属于游戏设计的变化，不在调参中完成。

## 完成状态与验证标准

你对手感满意，采用的值已写进参数资源，相关自动测试仍然通过。调参中说的“这个好”不是人工验收；需要验收的 Feature 仍在 Stage 5 正式验收。
