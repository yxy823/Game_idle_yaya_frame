# 已有实现和任务已对齐，现在补验证并办理交付

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已有实现和任务已对齐，现在补验证并办理交付。

需要的材料：

- 任务与来源：Feature ID、对齐后的来源。
- 实现与验证现状：已有实现、实际证据与待补缺口。

## 前置条件与适用范围

需求和任务记录已确认，本次授权完成剩余验证、必要修复和交付。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 日常开发 → 已有实现和任务已对齐，现在补验证并办理交付”。填入上述材料。本页使用 [$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)。

**S1｜确认真实缺口**

当前 Agent 按 feature-execute 读取现有实现、AC、原始验证及历史，不重演已有效完成步骤。

**S2｜补足适用验证**

运行实际需要的静态、测试和专项检查，修复已授权范围内失败，真实人工部分交用户。

**S3｜进行完成检查**

核对当前完成条件、用户指定评审与真实接受，按项目规则记录实际完成时间并提交。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 剩余义务已确定 |
| S2 | 证据覆盖最终实现 |
| S3 | 交付结论对应当前事实 |

## 资源与文件影响

当前 Feature 实现及必要修复、测试证据、完成记录和 Progress 会修改；历史证据不篡改。

## 阻塞、异常与范围变化

缺失人工体验或原始报告时不能倒推接受；保留未完成状态，说明具体缺口和恢复所需条件。取得当前有效证据和必要决定后，再沿原授权继续收尾。

## 完成状态与验证标准

当前 Feature 的适用验证和验收已满足，并完成实际收尾；完成状态及记录对应当前内容和真实证据。
