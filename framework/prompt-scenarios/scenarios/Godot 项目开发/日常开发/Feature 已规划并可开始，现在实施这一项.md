## 触发场景与使用时机

Feature 已规划并可开始，现在实施这一项。需要的材料：Feature ID 或下一项可开始任务、本次补充范围。

实施指导委派是可选输入，默认由当前 Agent 准备。需要指定顾问时，在对应提示词中明确选择委派 `implementation-advisor`；未填写、保留占位符或任务复杂本身都不触发委派，当前任务仍有效的具体委派授权则继续沿用。

## 前置条件与适用范围

选定任务未开工且依赖满足，本次授权实施一项。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 日常开发 → Feature 已规划并可开始，现在实施这一项”。填入上述材料。本页使用 [$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)。

**S1｜确认开工任务**

当前 Agent 用 feature-execute 核对任务、依赖、来源、AC 和实际 Git 现场。

将 AC 对应到当前实现、直接消费者和验证义务，简述必要修改范围；复用仍有效的计划，不新增批准步骤。

需要实施指导时使用 [implementation-guidance-godot](../../../../../project-source/skills/implementation-guidance-godot/SKILL.md)，整理约束、设计、必要顺序与验证理由。明确委派后由指定顾问读取背景；主 Agent 在本对话正文展示顾问的编号问题与 A/B 选项，再把回答传回同一顾问。Stage 1 先提出方案，已有批准覆盖后在 Stage 2 保存或更新同一 `docs/features/F0XX-design.md`；顾问仅写获准设计，主 Agent 维护 notes 链接及执行记录。

**S2｜完成实现与验证**

当前 Agent 按现有执行规范完成最小完整实现，保持无需变化的 API、依赖与代码风格。完成相关测试及项目支持的适用静态检查，复用有效证据；独立评审只按用户明确请求启用。

使用顾问指导时，当前 Agent 仍读取指导、关键适用原规则和实际代码、接口与消费者，不必重复全部背景调研。顾问不运行 Godot、测试或实验；所需运行证据由当前执行者按原任务取得。

**S3｜取得接受并收尾**

人工义务交用户真实体验。当前 Agent 检查最终差异，说明关键文件、实现理由、验证结果及具体风险，满足完成条件后记录和本地提交；按既有后续授权衔接。

## 资源与文件影响

当前 Feature 实现、测试、记录与必要文档修改；不在此入口重规划已交付任务。

## 阻塞、异常与范围变化

实质需求决定缺失、必要验证阻塞或实际人工验收尚未取得时，保留真实停点和恢复所需条件，不标记任务完成。前置齐备后沿用有效授权继续，不以阶段返回提前结束授权。

已明确委派的顾问无法启动、指定模型不可用或执行失败时，停止依赖它的工作，说明原因、已完成部分与缺口；保留已有材料，不自动换模型或改由主 Agent 接管。

## 完成状态与验证标准

本项适用的实现、验证、验收与交付均已完成，状态和证据符合执行规范。受阻或等待用户决定属于未完成停点，按上面的阻塞说明处理。
