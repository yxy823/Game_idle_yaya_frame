# 已经试玩过，想根据试玩记录调整设计

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如你双击导出包玩了 20 分钟，记下“解锁第二种生产者以后，大约 5 分钟没事可做，开始频繁切窗口”。游戏没有报错，规则也和 GDD 写的一致，但你想要的“一直有下一个小目标”没有出现，不知道该改规则、改节奏还是改目标。

需要的材料：

- **试玩记录**：文件路径或直接粘贴。写明试玩的版本、谁玩的、玩了多久，以及玩家对游戏是否熟悉；不写时，Agent 按“条件未知”报告证据的局限。
- **最在意的问题**（可空）：例如“第 5 分钟以后为什么没事可做”。不写时，由 Agent 按对核心体验的影响挑选。
- 相关的 GDD 主题和开放问题由 Agent 直接读取。

## 前置条件与适用范围

项目已有 GDD，里面写了这次试玩涉及的体验目标。记录里只有一处具体错处时，直接用[已有内容表现不对，先判断是 Bug、要改要求还是只需调值](<../出了问题/已有内容表现不对，先判断是 Bug、要改要求还是只需调值.md>)；本页处理的是“按设计运行，体验却没达到”的情况，记录里夹带的具体错处在 S1 分流出去。

人工验收不在本页：验收检查的是 Feature 有没有做对，试玩记录检查的是体验目标有没有达到。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 游戏想法与 GDD → 已经试玩过，想根据试玩记录调整设计”。填入上述材料。本页由当前 Agent 使用 [$design-gdd](../../../../../project-source/skills/design-gdd/SKILL.md)，方法见其参考中的[读回试玩记录](../../../../../project-source/skills/design-gdd/references/concept-ideation.md#读回试玩记录)。

**S1｜分流具体错处**

当前 Agent 从记录中挑出能指出具体错处的条目，按 [$feedback-triage](../../../../../project-source/skills/feedback-triage/SKILL.md) 分类，只报告每条的类别和负责方，本次不修复。

**S2｜对回体验目标**

当前 Agent 把其余观察分成观察到的行为、玩家原话、原因推测和设计建议，逐条对回 GDD 的体验目标和开放问题，说明它支持还是挑战哪个假设。

**S3｜给出问题、候选和复测**

当前 Agent 选出一两个最值得处理的问题，每个问题给出少量修改候选、推荐和理由，再给出复测情境：初始条件、观察什么、什么结果说明候选有效。

**S4｜你采纳后修改 GDD**

你选定候选后，当前 Agent 修改对应的 GDD 主题，把试玩条件和结论写进开放问题；问题已解决的，写回所属主题。GDD 变化影响已规划的 Feature 时，按 design-gdd 的变更路径处理。你不采纳时跳过本步。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 具体错处已列出类别和负责方；没有时说明没有 |
| S2 | 每条主要观察都有对应的体验目标或开放问题，以及支持或挑战的结论 |
| S3 | 问题、候选、推荐和复测情境已交付 |
| S4 | 采纳的候选已写进 GDD 主题和开放问题；未采纳时 GDD 不变 |

## 资源与文件影响

- S1 到 S3 只读，不修改文件。
- S4：修改 `docs/gdd/` 下受影响的主题和 `docs/gdd/open-questions.md`；游戏代码、场景、资源和调参资源不修改。

## 阻塞、异常与范围变化

- **GDD 没写这次涉及的体验目标**：观察无法对回目标，Agent 先报告缺口；你想先补目标时，改用[只有一个项目问题没想清楚，先讨论](<只有一个项目问题没想清楚，先讨论.md>)。
- **候选只是调数值**：例如改产出速率或解锁时间，改用[体验目标已明确，需要设计数值模型](<体验目标已明确，需要设计数值模型.md>)；只想在游戏里直接试调时，用[已完成的内容要再调速度、节奏或手感](<../实施与调参/已完成的内容要再调速度、节奏或手感.md>)。
- **候选牵连多处、互相依赖**：改用[目标已有方向，多个问题互相牵连，先逐步理清](<目标已有方向，多个问题互相牵连，先逐步理清.md>)。

## 完成状态与验证标准

- **只分析时**：分流结果、观察与目标的对照、问题、候选和复测情境已交付，每条结论能回到记录中的具体条目和 GDD 中的具体位置，GDD 没有被修改。
- **采纳候选时**：对应的 GDD 主题和开放问题已修改，受影响主题的规则、术语和链接一致。修改 GDD 不代表体验已经改善，要按复测情境再试玩一次。
