# Feature 还没做完，准备换一个对话继续

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

当前对话上下文太长或要换模型，Feature 做到一半，想在同一目录开一个新对话接着做。在原对话中发送，需要的材料：

- **新对话的目的**：新对话要继续做什么，以及要保留的限制，例如“继续 F003 的 Stage 3，暂不提交”。

当前 Feature、原目标和已决定事项由 Agent 从当前对话、Progress 和 Feature 记录读取。

## 前置条件与适用范围

当前对话需要为同一目录中的原任务准备可靠交接。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 项目恢复与交接 → Feature 还没做完，准备换一个对话继续”。填入上述材料。

**S1｜核对任务现场**

当前 Agent 使用 [task-handoff-godot](../../../../../project-source/skills/task-handoff-godot/SKILL.md)，读取真实文件、Git、Progress 与原始证据，区分实施、建议、失败和待人工事项；按本页授权整理必要记录并生成交接文本。

**S2｜保存必要进度**

更新现有 Progress 和必要 notes，保留 ID、状态与验收语义，不创建 Handoff 状态文件。

**S3｜输出接收指令**

生成可整体复制的代码块，写具体目录、任务、授权、证据、真实停点和第一步；不自动建新对话。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 已完成、未验证、阻塞和待人工事项分别列出 |
| S2 | Progress 和 notes 已写入真实停点、有效授权和恢复第一步 |
| S3 | 可整体复制的续接提示词代码块 |

## 资源与文件影响

必要进度文档修改；不为清空现场提交、回滚或清理现有实现。

## 阻塞、异常与范围变化

缺少原始结果时明确未知，不凭交接摘要补通过；不要求 worktree 或改动归属流程。

## 完成状态与验证标准

完整交接文本和必要记录已准备，原任务暂停在真实位置。

## 流程关联与衔接关系

依据：[任务交接](<../../../../../project-source/methodology/09-records-reports-and-handoff.md#任务交接>)、[续接提示词](<../../../../../project-source/methodology/09-records-reports-and-handoff.md#续接提示词>)。

与一般的授权延续不同，本页完成后原对话暂停实施，不因先前有实施授权而继续；在新对话中发送续接提示词后，按[换了一个对话，想继续上次没做完的 Feature](<换了一个对话，想继续上次没做完的 Feature.md>)从记录的停点恢复。
