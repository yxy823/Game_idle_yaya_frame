# 当前工作没有 Feature，需要先暂停并保存停点

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

当前工作没有 Feature，需要先暂停并保存停点。准备材料：

- **任务范围**：真实任务目标与现有授权。
- **执行现场**：执行方法、原件与进行中的命令。
- **暂停信息**：暂停原因。

## 前置条件与适用范围

当前是研究、讨论或审核等没有 Feature 的真实工作，用户明确要求暂停；本页只保存停点。

## 执行步骤

使用[集中提示词库](../../../prompts/godot-development-prompts.json)中的“Godot 项目开发 → 项目恢复与交接 → 当前工作没有 Feature，需要先暂停并保存停点”。已有对话补齐实际材料即可，续接不重新索取已经存在的授权。 本页的执行者、角色和具体方法见各步骤；没有专用 Skill 时使用当前 Agent 与现有职责契约。

**S1｜停止当前实施**

当前 Agent 使用 [task-handoff-godot](../../../../../project-source/skills/task-handoff-godot/SKILL.md) 停止继续当前工作，核实正在执行的查询、读取或获准命令；记录实际状态，不假定启动已结束。本次只保存停点，不要求新对话交接文本。

**S2｜记录恢复所需信息**

在现有 docs/progress.md 或该任务既有报告的适当位置保存以下信息：

- **任务与决定**：原目标、已有决定。
- **依据**：已读版本、原始证据。
- **恢复信息**：当前方法与具体下一步。

只保留必要一处正文及链接。

## 资源与文件影响

仅修改必要现有进度或任务记录；保留资料和未完成成果，不建立 Feature、Handoff.md 或新状态机。

## 阻塞、异常与范围变化

事实无法恢复时标未知；不能安全停止的命令说明实际情况，不批量结束无关进程。

## 完成状态与验证标准

当前非 Feature 工作已暂停，真实停点、有效授权和恢复第一步已保存；等待用户续接。

依据：[methodology/09-artifact-lifecycle.md](<../../../../../project-source/methodology/09-artifact-lifecycle.md>)。

本页完成后停止原工作的实施。原授权保留为后续范围依据；收到用户明确续接指令后，再从记录的真实停点恢复。
