# 当前 Feature 需要暂停，先保存真实停点

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

F003 做到一半，测试还在跑，你要去忙别的，想先把它停下，留下下次能直接接着做的记录，但暂时不开新对话。

需要的材料：暂停原因（一句话）；有正在运行、需要保留而不能中断的命令或 Godot 进程时说明是哪个。当前 Feature 由 Agent 从对话和 Progress 确定。

## 前置条件与适用范围

用户明确暂停当前任务，需要留下可恢复记录。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 项目恢复与交接 → 当前 Feature 需要暂停，先保存真实停点”。填入上述材料。

**S1｜停止依赖实施**

当前 Agent 使用 [task-handoff-godot](../../../../../project-source/skills/task-handoff-godot/SKILL.md)，按实际运行权限处理尚在执行的命令，记录已知进程状态，保留日志。本次只保存暂停记录，不要求新对话交接文本。

**S2｜记录真实停点**

在现有 Progress/notes 保存以下信息：

- **任务停点**：所处 Stage、未完成动作、尚未满足的验证与验收条件，以及阻塞。
- **已有依据**：有效决定和原件。
- **恢复安排**：恢复第一步。

## 资源与文件影响

只更新必要现有记录；保留未完成实现，不为暂停强制提交或清理。

## 阻塞、异常与范围变化

不能安全停止的进程说明实际情况，不自动批量结束无关工具。

## 完成状态与验证标准

当前任务已暂停，现场、状态和恢复动作明确，没有标完成。

## 流程关联与衔接关系

依据：[任务交接](<../../../../../project-source/methodology/09-records-reports-and-handoff.md#任务交接>)、[Progress](<../../../../../project-source/methodology/09-records-reports-and-handoff.md#progress>)。

本页完成后暂停原任务的实施，保留原有具体授权和真实现场；收到用户续接指令后，再从记录的停点恢复。不得因先前存在实施授权而立即继续已被要求暂停的工作。
