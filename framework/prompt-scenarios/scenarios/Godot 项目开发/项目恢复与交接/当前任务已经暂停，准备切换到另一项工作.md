# 当前任务已经暂停，准备切换到另一项工作

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

原任务已经按暂停场景记下停点，现在想在同一个项目目录里先做另一项工作。

需要的材料：要切换到的工作（Feature ID 或一句话目标）及你对它的授权。没有给出授权时，Agent 进入目标工作的入口后按该入口的批准规则停下来请你确认。已暂停任务的停点由 Agent 从 Progress 读取。

## 前置条件与适用范围

单人同一项目目录切换，原任务停点已经记录。

常见用法：一个 Feature 停在人工验收，等你体验期间先推进另一个 Feature。目标 Feature 要依赖已满足、修改的文件不重叠；你给出验收结果后，Agent 先回到原 Feature 收尾。规则见 [Stage 0 的等待例外](<../../../../../project-source/methodology/03-execute-loop.md#stage-0--选择-feature-并加载上下文>)。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 项目恢复与交接 → 当前任务已经暂停，准备切换到另一项工作”。填入上述材料。

**S1｜核对暂停记录**

当前 Agent 确认原任务的未完成文件、运行、证据和正在等待的对象已记录在 Progress，不把它标完成。停点还没记录时，先用[保存真实停点](<当前工作需要暂停，先保存真实停点.md>)。

**S2｜核对目标前置**

读取目标任务依赖、范围和实际相关差异，确认不会覆盖现有成果。

**S3｜进入目标工作**

使用目标所属 Skill 在其已授权范围执行；原任务继续保持暂停记录。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | Progress 中有原任务的停点、等待对象和恢复第一步 |
| S2 | 两项任务计划修改的文件已对照，重叠处已列出并解决 |
| S3 | 目标工作已在所属入口开始，原任务记录未被改动 |

## 资源与文件影响

更新必要 Progress 并在目标授权范围写入；保留现有工作区与任务记录，不因普通任务切换默认创建 worktree。

## 阻塞、异常与范围变化

确实重叠的编辑或提交边界无法分离时先解决具体冲突，不要求整个目录干净。

## 完成状态与验证标准

目标工作已从正确入口开始，原任务现场和恢复信息保留。

## 流程关联与衔接关系

依据：[Progress](<../../../../../project-source/methodology/09-records-reports-and-handoff.md#progress>)。原任务在等人工验收、结果到达后，用“[已经实际体验，记录验收结果](<../验证与收尾/已经实际体验，记录验收结果.md>)”登记，再回原 Feature 收尾。
