# 当前工作还没做完，准备换一个对话继续

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

当前对话上下文太长或要换模型，工作做到一半，想在同一目录开一个新对话接着做。工作可以是某个 Feature（例如 F003 做到 Stage 3），也可以是没有建立 Feature 的外部调研、设计讨论或代码审核；是否属于 Feature 由 Agent 判断。在原对话中发送，需要的材料：

- **新对话的目的**：新对话要继续做什么，以及要保留的限制，例如“继续 F003 的 Stage 3，暂不提交”。不写时 Agent 按当前对话的原目标续接，并在交接文本中标明。

当前工作、原目标、已决定事项、授权和实际资料由 Agent 从当前对话、Progress、Feature 记录和项目文件核对。

## 前置条件与适用范围

当前对话需要为同一目录中的原工作准备可靠交接；本页产出可复制交接文本。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 项目恢复与交接 → 当前工作还没做完，准备换一个对话继续”。填入上述材料。

**S1｜核对任务现场**

当前 Agent 使用 [task-handoff-godot](../../../../../project-source/skills/task-handoff-godot/SKILL.md)，先从当前对话和 Progress 判断工作是否属于某个 Feature；再读取真实文件、Git、Progress、所属 Feature 的记录（有 Feature 时）、已有结果与原始证据，区分已证实结论、实施、建议、失败、未知事实和待人工事项。

**S2｜保存必要进度**

更新现有 Progress 和必要 notes：有 Feature 时保留 ID、状态与验收语义；没有 Feature 时只在 Progress 补充真实停点及所属报告的链接，不为交接创建 Feature。不创建 Handoff 状态文件，不为交接重跑研究或验证。

**S3｜输出接收指令**

按[续接提示词](<../../../../../project-source/methodology/09-records-reports-and-handoff.md#续接提示词>)的固定字段，生成可整体复制的代码块，写明具体目录、原目标、当前方法、任务、版本和原件、授权、证据、真实停点、未决项和第一步；没有 Feature 就明确说明，不能虚构任务 ID。不自动建新对话。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 是否属于 Feature 已写明；已完成、已证实、未验证、失败、阻塞和待人工事项分别列出，各自附原件位置 |
| S2 | Progress 和必要 notes 已写入真实停点、有效授权和恢复第一步，并链接所属报告 |
| S3 | 可整体复制的续接提示词代码块，含固定字段、原任务范围和第一步 |

## 资源与文件影响

必要进度文档修改，原资料保留；不为清空现场提交、回滚或清理现有实现，不自动新建任务或发送消息。

## 阻塞、异常与范围变化

缺少原始结果、原件缺失或事实冲突时明确未知，不凭交接摘要补通过，也不把交接摘要变成新的批准、证据或人工接受；不要求 worktree 或改动归属流程。

## 完成状态与验证标准

完整交接文本和必要记录已准备，原工作暂停在真实位置。

## 流程关联与衔接关系

依据：[任务交接](<../../../../../project-source/methodology/09-records-reports-and-handoff.md#任务交接>)、[续接提示词](<../../../../../project-source/methodology/09-records-reports-and-handoff.md#续接提示词>)。

与一般的授权延续不同，本页完成后原对话暂停实施，不因先前有实施授权而继续。在新对话中发送续接提示词后：Feature 按[继续上次没做完的 Feature](<继续上次没做完的 Feature.md>)从记录的停点恢复；没有 Feature 的工作按交接文本中的原方法恢复。
