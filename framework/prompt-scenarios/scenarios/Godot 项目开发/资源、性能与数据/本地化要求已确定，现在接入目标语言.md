# 本地化要求已确定，现在接入目标语言

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

本地化要求已确定，现在接入目标语言。

需要的材料：

- 所属任务与要求：当前 Feature、确认的本地化规格。
- 语言与内容：目标语言、获准译文。

## 前置条件与适用范围

规格已经明确，本次在所属任务实现翻译与运行接入。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 本地化要求已确定，现在接入目标语言”。填入上述材料。本页使用 [$content-localization](<../../../../../project-source/skills/content-localization/SKILL.md>)、[$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)。

**S1｜核对可用输入**

当前 Agent 使用 content-localization 读取本地化规格及其“术语译名”章节、目标键、实际译文和字体授权；概念含义追溯到项目术语，完整译文仍在运行资源中。

**S2｜接入语言资源**

维护必要翻译文件、字体和运行切换，按规格处理缺键和回退。

**S3｜检查真实显示**

返回 feature-execute 检查目标界面文本、溢出、字体、格式与回退，交用户或语言审核获得相应真实结果。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 实现不需要另行设计语言政策 |
| S2 | 目标语言可以被实际选择 |
| S3 | 运行显示与译文质量分别核对 |

## 资源与文件影响

翻译资源、字体引用、项目配置和必要代码修改；本地化规格只读。

## 阻塞、异常与范围变化

术语译名存在争议时返回 `design-localization-spec`，不在接入时另定一份用词。关键译文或字体不可用时保留缺口；键覆盖不能证明翻译质量通过。

## 完成状态与验证标准

目标语言实际可用，适用显示和语言检查有结果，原任务完成义务明确。
