# 已有动画要替换，需要保留动作衔接

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如角色的攻击动画换成新版本，原来的连招衔接和命中事件时机要保持。

需要的材料：

- 旧动画的名称或路径，以及新动画文件路径；状态机、事件轨道和共享消费者由 Agent 追查。
- 其余（所属 Feature 或实验、确认的规格、所属资源章节）由 Agent 直接读取。

## 前置条件与适用范围

文件和消费目标已经确认，当前已授权的 Feature 或限定范围的实验包含这次接入。两者都没有时不修改运行时文件，先按任务路由选择入口。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 已有动画要替换，需要保留动作衔接”。填入上述材料。当前 Agent 使用 [$content-asset-integration](../../../../../project-source/skills/content-asset-integration/SKILL.md) 接入；验证和完成回到调用它的任务：Feature 内是 [$feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md)，作为调试台候选接入时是 [$debug-console-godot](../../../../../project-source/skills/debug-console-godot/SKILL.md)。

**S1｜核对接入契约**

当前 Agent 使用 content-asset-integration 核对轨道绑定、名称、时长与事件时序，确认实际消费者及文件来源。

**S2｜更新资源并保留消费关系**

保留必要旧信息后更新资源及引用，检查所有共享消费者，不仅替换看到的一个文件。最终验证前，到所属资源章节更新准备状态、实际资源路径和使用方路径。

**S3｜验证实际反馈**

回到调用的任务（feature-execute 或 debug-console-godot），在获准运行范围检查过渡、打断和相关动作状态的运行反馈；真实视觉结果由用户体验确认。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 新旧动画的轨道、名称、时长和事件时序差异已列出，共享消费者已列全 |
| S2 | 所有共享消费者已指向新动画；所属资源章节已更新实际路径 |
| S3 | 过渡与打断的运行检查结果和用户视觉确认分别记录 |

## 资源与文件影响

- 修改：动画资源及其导入设置、场景或脚本引用、所属资源章节中的准备状态、实际资源路径和使用方路径。
- 保留：原规格与外部原件。

## 阻塞、异常与范围变化

文件缺失、规格冲突或来源不清时停在对应缺口；不在此制作素材或改变目标要求。

## 完成状态与验证标准

替换动画已生效，所有共享消费者的动作衔接有效，所属资源章节已更新；运行检查结果与用户视觉确认结果分别写明，未确认的检查明确列出。
