# 音效文件和播放位置都已确定，现在要把声音接进游戏

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如购买成功的音效文件已交付，声音规格中的播放时机已确认，需要接进游戏。

需要的材料：

- 音效文件路径，以及触发它的播放事件（例如“购买成功时播放”）。
- 其余（所属 Feature 或实验、确认的规格、所属资源章节）由 Agent 直接读取。

## 前置条件与适用范围

文件和消费目标已经确认，当前已授权的 Feature 或限定范围的实验包含这次接入。两者都没有时不修改运行时文件，先按任务路由选择入口。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 音效文件和播放位置都已确定，现在要把声音接进游戏”。填入上述材料。当前 Agent 使用 [$content-asset-integration](../../../../../project-source/skills/content-asset-integration/SKILL.md) 接入；验证和完成回到调用它的任务：Feature 内是 [$feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md)，独立实验是 [$prototype-godot](../../../../../project-source/skills/prototype-godot/SKILL.md)。

**S1｜核对接入契约**

当前 Agent 使用 content-asset-integration 核对格式、循环和导入后可播放性，确认实际消费者及文件来源。

**S2｜接入当前消费对象**

只把获准音效接入指定事件，维护实际导入设置和音频路由，不改上游要求。最终验证前，到所属资源章节更新准备状态、实际资源路径和使用方路径。

**S3｜验证实际反馈**

回到调用的任务（feature-execute 或 prototype-godot），在获准运行范围检查实际事件触发、音量与混音、停止与重复播放；真实听觉结果由用户体验确认。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 格式、时长、循环与声音规格逐项比对，不符项已列出 |
| S2 | 指定事件已触发新音效；所属资源章节已写入实际路径和使用方 |
| S3 | 运行检查结果和用户试听确认分别记录 |

## 资源与文件影响

- 修改：音效资源及其导入设置、场景或脚本引用、音频路由、所属资源章节中的准备状态、实际资源路径和使用方路径。
- 保留：原规格与外部原件。

## 阻塞、异常与范围变化

文件缺失、规格冲突或来源不清时停在对应缺口；不在此制作素材或改变目标要求。

## 完成状态与验证标准

新增音效已接入指定播放事件，所属资源章节已更新；运行检查结果与用户听觉确认结果分别写明，未确认的检查明确列出。
