# 问题缺少证据，先加临时观测信号

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如存档偶尔丢失，现有日志分不清是写入失败还是读档时被覆盖，需要临时加几处日志区分。

需要的材料：

- 要区分的几种可能原因（原话即可）。
- 允许插入信号的位置、观测运行方式和清理范围；不提供时由 Agent 提出最小插入点，用户确认后再改。

## 前置条件与适用范围

现有证据不足，已授权临时诊断修改。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 问题缺少证据，先加临时观测信号”。填入上述材料。本页使用 [$diagnostics-instrumentation](../../../../../project-source/skills/diagnostics-instrumentation/SKILL.md)。

**S1｜选择最小信号**

当前 Agent 用 diagnostics-instrumentation 从待判断假设选择事件或计数，不采集无关信息。

**S2｜观测并保存证据**

在指定版本添加临时信号，运行获准场景，记录采样条件与原始输出。

**S3｜清理临时修改**

取得所需结果后移除临时埋点及无用临时文件；保留必要原件和结论。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 每个候选原因对应的信号和插入位置已列出 |
| S2 | 原始输出与版本、采样条件一起保存 |
| S3 | 临时埋点已移除，最终差异中没有埋点残留 |

## 资源与文件影响

临时观测代码在本次范围内新增后清理；原始诊断报告按需保留。

## 阻塞、异常与范围变化

信号改变行为、开销过高或无法取得所需观测时，停止依赖该信号的判断并说明缺口；按既有权限清理临时修改，保留原始依据和恢复线索，不能把无法取得写成观测目标完成。改为长期指标需要独立明确目标。

## 完成状态与验证标准

所需信号已实际取得，临时修改已按约定清理，原始依据与采样条件可定位。
