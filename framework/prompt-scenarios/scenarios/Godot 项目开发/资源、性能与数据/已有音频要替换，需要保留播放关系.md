# 已有音频要替换，需要保留播放关系

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如点击音效换成新版本，多个界面共用它，替换后所有播放位置都要正常发声。

需要的材料：

- 旧音频路径和新音频文件路径；播放事件和共享消费者由 Agent 追查。
- 其余（所属 Feature 或实验、确认的规格、所属资源章节）由 Agent 直接读取。

## 前置条件与适用范围

文件和消费目标已经确认，当前已授权的 Feature 或限定范围的实验包含这次接入。两者都没有时不修改运行时文件，先按任务路由选择入口。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 已有音频要替换，需要保留播放关系”。填入上述材料。当前 Agent 使用 [$content-asset-integration](../../../../../project-source/skills/content-asset-integration/SKILL.md) 接入；验证和完成回到调用它的任务：Feature 内是 [$feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md)，作为调试台候选接入时是 [$debug-console-godot](../../../../../project-source/skills/debug-console-godot/SKILL.md)。

**S1｜核对接入契约**

当前 Agent 使用 content-asset-integration 核对新旧格式、循环、长度及消费路径，确认实际消费者及文件来源。

**S2｜更新资源并保留消费关系**

保留必要旧信息后更新资源及引用，检查所有共享消费者，不仅替换看到的一个文件。最终验证前，到所属资源章节更新准备状态、实际资源路径和使用方路径。

**S3｜验证实际反馈**

回到调用的任务（feature-execute 或 debug-console-godot），在获准运行范围检查所有受影响事件的实际试听、停止和过渡；真实听觉结果由用户体验确认。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 新旧音频的格式、长度、循环差异已列出，播放它的事件已列全 |
| S2 | 所有播放事件已指向新音频；所属资源章节已更新实际路径 |
| S3 | 各事件的运行检查结果和用户试听确认分别记录 |

## 资源与文件影响

- 修改：音频资源及其导入设置、场景或脚本引用、音频路由、所属资源章节中的准备状态、实际资源路径和使用方路径。
- 保留：原规格与外部原件。

## 阻塞、异常与范围变化

文件缺失、规格冲突或来源不清时停在对应缺口；不在此制作素材或改变目标要求。

## 完成状态与验证标准

替换音频已生效，所有播放事件的关系有效，所属资源章节已更新；运行检查结果与用户听觉确认结果分别写明，未确认的检查明确列出。
