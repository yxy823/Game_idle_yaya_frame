# 短测看不出问题，需要按约定负载持续运行

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如挂机十分钟一切正常，但有反馈说挂一整夜后变卡，需要按约定负载跑几小时，看内存和对象数量的趋势。

需要的材料：

- 要长跑的场景和负载（例如“主场景挂机，每 5 秒触发一次离线结算”），以及设备。
- 目标时长、资源预算和停止条件；不提供时 Agent 先提出并请用户确认，不开始没有边界的长跑。
- 允许使用的项目副本、配置和隔离的用户数据；不提供时使用隔离的测试用户数据。

## 前置条件与适用范围

需要时间跨度上的实际证据，具备运行条件及授权。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 短测看不出问题，需要按约定负载持续运行”。填入上述材料。本页使用 [$diagnostics-soak-test](../../../../../project-source/skills/diagnostics-soak-test/SKILL.md)。

**S1｜固定长跑条件**

当前 Agent 使用 diagnostics-soak-test 记录版本、负载、指标和停止条件，核对必要信号已存在。

**S2｜执行实际运行**

按获准条件持续运行并采集原始信息，故障和中断即时保留实际时长。

**S3｜解释结果**

报告趋势、异常、真实持续时间和未覆盖部分，返回所属任务处理发现。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 版本、负载、时长、采样指标和停止条件已写明，需要的信号已确认存在或已补上 |
| S2 | 原始日志带时间信息，实际运行时长已记录 |
| S3 | 报告写明实际时长、趋势、异常、停止原因和未覆盖部分 |

## 资源与文件影响

只产生获准长跑日志、缓存和报告；原实现与验收要求不改变。

## 阻塞、异常与范围变化

缺少信号时，原授权覆盖就用 diagnostics-instrumentation 补充，否则说明有效覆盖；运行被中断时只报告实际覆盖。不把长跑结果写成 gdUnit 通过。

## 完成状态与验证标准

约定负载已按预算和合法停止条件运行结束，实际运行与证据已经交付。意外中断时只交付实际覆盖和未完成项，不算完成长测。
