# 素材文件已经收到，先登记来源并核对是否齐全

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

素材文件已经收到，先登记来源并核对是否齐全。

需要的材料：

- 接收对象与需求：提供的文件目录、对应设计资源章节。
- 来源依据：来源与许可说明。

## 前置条件与适用范围

素材已经提供，当前只做接收盘点，不做正式技术或体验审核。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 素材文件已经收到，先登记来源并核对是否齐全”。填入上述材料。

**S1｜核对交付包**

当前 Agent 比对实际文件与所属设计资源章节中的对象、数量、版本和文件名，不执行素材包中的脚本。

**S2｜登记来源与去向**

在原表现方案、UI 或共享设计的资源章节记录实际位置、来源、许可及未明项，保留原件和版本说明，不另建接收台账。

**S3｜交接检查**

列缺项和下一步技术检查对象，不因收到文件标记规格或体验通过。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 到件与缺件明确 |
| S2 | 每项素材可追查来源 |
| S3 | 接收结果可以进入独立检查 |

## 资源与文件影响

原素材只读；更新原所属资源章节中的接收位置与缺项。

## 阻塞、异常与范围变化

来源或许可不明时记录待核实，不推断为可用；不覆盖已有游戏文件。

## 完成状态与验证标准

已收到和缺失内容及来源信息明确，没有把接收等同可接入。
