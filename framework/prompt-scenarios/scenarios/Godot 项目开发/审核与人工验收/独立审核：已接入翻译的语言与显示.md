# 独立审核：已接入翻译的语言与显示

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

英文和日文翻译已经接入游戏，想让独立审核确认译文含义、术语一致，以及切换语言后界面没有截断、缺字或回退到键名。

需要的材料：

- 审核范围：要审的语言区域，以及界面或流程（场景路径或“商店到结算”这样的流程名）。
- 被审版本：提交哈希，或“当前工作区”。
- 允许的验证：例如“只做静态检查”。不写时允许必要的隔离验证（复制到 `reports/scratch/` 下运行）。

本地化规格、翻译资源和项目术语由审核实例直接读取。

## 前置条件与适用范围

成果版本和权威要求明确，本次明确启用该领域独立审核。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 审核与人工验收 → 独立审核：已接入翻译的语言与显示”。填入上述材料。本页使用 [$review-localization](<../../../../../project-source/skills/review-localization/SKILL.md>)。

**S1｜交接审核材料**

主 Agent 向新上下文 independent-reviewer 交范围、快照、权威来源、原始证据与允许的验证（见[触发与独立性](<../../../../../project-source/methodology/12-independent-review.md#触发与独立性>)的输入表），作者总结仅作待核实陈述。

**S2｜按领域检查**

独立 Agent 使用 review-localization 对照本地化规范的[术语译名](<../../../../../project-source/defaults/docs/localization/localization-spec.md#术语译名>)章节及其引用的项目术语，核对含义、译名一致性、字体、截断和回退，需要结论时取得实际显示与具备依据的语言判断。

**S3｜交付审核报告**

给出语言质量与显示限制，发现按 `must_fix`、`suggest`、`acceptable` 标注严重程度，并列出仍需人工完成的语言检查。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 审核实例确认是新上下文的 independent-reviewer，交接内容含范围、快照、来源、原始证据和允许的验证 |
| S2 | 每项结论对应具体的键、文本或实际画面；没取得证据的语言区域或画面列为未验证 |
| S3 | 报告写明被审快照、语言区域与流程的实际覆盖、带严重程度的发现和仍需人工的检查 |

## 资源与文件影响

被审成果、原证据和验收记录只读；只写获准报告与隔离验证产物。

## 阻塞、异常与范围变化

- 证据不足：无法取得必要真实证据时明确未验证，不能以作者声明代替。
- 独立性不足：无法独立时说明限制。

## 完成状态与验证标准

该范围的独立报告已交付，语言质量与显示限制明确，没有修复被审成果。
