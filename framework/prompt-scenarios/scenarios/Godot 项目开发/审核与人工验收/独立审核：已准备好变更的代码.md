# 独立审核：已准备好变更的代码

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

F01-012 的实现和测试都已提交，你想在标记完成前让一个没参与编写的新实例看一遍代码，找出不符合 AC 的地方和具体的维护问题。

需要的材料：

- 被审范围：Feature ID、提交范围（例如 `abc123..HEAD`）或“当前未提交修改”；比较基线不提供时由 Agent 从该 Feature 的提交确定，并在交接中写明。
- 要对照的规则与证据（可空）：本次要对照的 AC 或规则文件路径、已有测试报告路径；不提供时按 Feature 和 `AGENTS.md`「领域规则路由」查找。
- 允许的验证（可空）：只做静态审核，或允许在隔离副本中运行哪些测试、场景；不写时审核实例只在隔离副本中做必要的针对性验证，副作用无法隔离就不运行。

## 前置条件与适用范围

明确启用一次独立审核；变更范围已准备好。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 审核与人工验收 → 独立审核：已准备好变更的代码”。填入上述材料。本页使用 [$review-code](<../../../../../project-source/skills/review-code/SKILL.md>)。

**S1｜核实独立实例**

主 Agent 交接范围、版本、权威来源和运行权限给新上下文 independent-reviewer，核实真实独立性。

**S2｜读取实现并追查**

独立 Agent 使用 review-code，读取相关 AC、最终差异和原件，追查直接调用者；按既有 Stage 6 处理已选变更。

**S3｜交付有界结论**

分别说明需求符合性和质量，给文件定位、触发、影响与最小建议；验证只在隔离范围。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 交接内容按“范围、权威要求、快照、原始证据、允许的验证”五项写明，实例确认为新的 `independent-reviewer` |
| S2 | 每条发现都有文件位置、触发条件和对应的 AC 或规则 |
| S3 | 报告分别给出需求符合性与代码质量结论，每条发现标有 `must_fix`、`suggest` 或 `acceptable` |

## 资源与文件影响

被审源和原证据只读；获准报告与隔离缓存可写。

## 阻塞、异常与范围变化

版本在审查中变化时补查受影响部分或限定版本；不能把作者自查称独立。

## 完成状态与验证标准

当前差异的需求符合性与代码质量分别有独立结论，未修改被审内容或历史完成状态。
