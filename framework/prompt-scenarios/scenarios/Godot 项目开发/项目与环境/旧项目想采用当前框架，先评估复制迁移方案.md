# 旧项目想采用当前框架，先评估复制迁移方案

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

有一个不是用本框架创建、或用旧版框架创建的 Godot 项目，想复制一份到新目录并接入当前框架，先看看有哪些做法、各要保留和转换什么。需要的材料：

- **原项目**：旧项目的绝对路径。
- **新目录**：迁移副本打算放的位置；没定时由 Agent 建议。
- **框架位置**：默认 `D:/A_Games/Game_idle_yaya_frame`，用其他副本时写明路径。
- **数据保留要求**：必须保留的存档、配置、任务历史等，以及能否转换格式；没写时按全部保留评估。

## 前置条件与适用范围

原项目与框架均只读，本次只评估方案。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 项目与环境 → 旧项目想采用当前框架，先评估复制迁移方案”。填入上述材料。

**S1｜核对两端实际内容**

当前 Agent 读取规则、复制清单、实际实现、任务和配置，使用只读 Git 确认版本及工作区成果。

**S2｜安排一次性转换**

按职责列保留、替换、合并、转换和不复制项；说明目标路径、历史接入、数据保护与验证。

**S3｜交付具体取舍**

指出不能判定的字段、旧证据限制和预期续接点，提供最小推荐方案。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 原项目的业务、资源、定制、任务记录和数据已按位置列出 |
| S2 | 每类内容的保留、替换、合并、转换或不复制方式已列出 |
| S3 | 推荐方案、不能判定的字段和验证建议已交付 |

## 资源与文件影响

原项目、当前框架只读；迁移建议不创建目标。

## 阻塞、异常与范围变化

目标嵌套、符号链接回到原件或关键数据保留不明时明确阻塞，不猜测覆盖方案。

## 完成状态与验证标准

完整的副本迁移方案已交付，包含取舍、验证和原件保护。

## 流程关联与衔接关系

依据：[复制清单](<../../../../project-creation/project-files.json>)决定框架文件复制到哪里；原项目缺少 Product 或 Feature 记录时，按[接手已有实现](<../../../../../project-source/methodology/02-feature-list-schema.md#接手已有实现>)规划接入。方案选定后转入[复制迁移方案已确定，现在迁移旧项目](<复制迁移方案已确定，现在迁移旧项目.md>)。
