# 空白项目已经创建，现在配置开发环境

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

刚用创建器生成了项目，还没有配置 Python 和 Godot 路径，也没做过就绪检查。需要的材料（都可选）：

- **工具路径**：Python 3.12+ 和 Godot 4.7.x 可执行文件的路径；不提供时 Agent 查找本机安装，写入前请用户确认。
- **项目名称**：要写进 `project.godot` 的名称；不提供时保留创建时的名称。

## 前置条件与适用范围

新项目尚未完成首次环境配置。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 项目与环境 → 空白项目已经创建，现在配置开发环境”。填入上述材料。本页由当前 Agent 使用项目自己的 [$environment-setup](<../../../../../project-source/skills/environment-setup/SKILL.md>)，链接指向框架中的源文件，仅供核对。

**S1｜写入真实配置**

当前 Agent 核对 `docs/methodology-config.json` 中的 `engine_executable` 和 `python_executable`：用户给了路径就直接填写；没给时查找本机的 Python 和 Godot，把找到的路径交用户确认后再写入，不擅自换成其他版本。插件随项目复制，不单独核对；是否可用由首次扫描、测试和 lint 的实际运行证明。

提供了项目名称时，把 `project.godot` 的 `application/config/name` 改为它，再用 [resave_godot_files.gd](<../../../../../project-source/tools/README.md#resave_godot_filesgd>) 重新保存 `project.godot`。

文档语言沿用当前配置，新项目默认中文，不需要用户再次确认；明确指定其他语言时直接采用。已有文档迁移范围或语言要求确有歧义时，才补齐相应决定。

**S2｜检查环境**

在项目根目录用配置 Python 调用 `yaya/tools/checks/check-project-environment.py --require-ready`；首次扫描仅在需要运行且获准时按工具说明执行。

**S3｜保存初始化结果**

写 `reports/initialization.md`，记录命令、失败、未执行、Git 与剩余问题，更新 Progress 后按项目规则提交。

项目工具命令按以下约定执行：

- **工作目录**：实际游戏项目根目录。
- **Python 与调用形式**：`$projectPython` 换成 `docs/methodology-config.json` 中的 `python_executable`（可写法见[调用](<../../../../../project-source/tools/README.md#调用>)），调用形式为 `& $projectPython -B <脚本路径> <参数>`，每次立即检查 `$LASTEXITCODE`。
- **参数替换**：尖括号参数替换为实际值。
- **结果边界**：命令成功只证明该操作完成。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 两个路径已写入配置，来源是用户给出或已确认；改名时重存命令退出码为 0 |
| S2 | `--require-ready` 的实际输出和观察到的 Godot 版本 |
| S3 | 初始化报告已写，Progress 已更新，有提交哈希；未执行的首次扫描已注明 |

## 资源与文件影响

环境配置、可选 project.godot 名称、初始化报告和 Progress 修改；不创建业务任务。

## 阻塞、异常与范围变化

用户给出或确认的路径无效时报告具体问题，不自行换用其他版本；空项目无业务测试不虚构测试。

## 完成状态与验证标准

真实路径已配置、环境检查通过，报告和适用提交完成；未执行的首次扫描明确。
