# 准备开始新游戏，先创建空白项目

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

要开始一款新游戏，手上还没有游戏项目目录，需要先从框架得到一个独立的空白 Godot 项目。

需要的材料：新项目的绝对路径，例如 `D:\Games\MyGodotGame`；路径不能含中文或空白，目录不存在或为空。

## 前置条件与适用范围

目标在框架仓库外且不存在或为空，只需要独立空白项目。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 项目与环境 → 准备开始新游戏，先创建空白项目”。填入上述材料。

**S1｜确认目标和清单**

当前 Agent 在框架目录核对目标路径与 framework/project-creation/project-files.json；不对非空目录运行创建器。

**S2｜调用创建器**

在框架根目录使用框架已确认 Python 执行 `python -B framework/project-creation/tools/create_project.py --output <目标目录>`（`-B` 避免在框架仓库生成字节码缓存），将尖括号参数替换为实际绝对路径，并立即检查 `$LASTEXITCODE` 与创建结果。新项目尚未完成环境配置，不使用其模板中的 Python 路径运行创建器。

**S3｜交付项目位置**

核对实际目标与初始提交，告知后续在新项目配置环境。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 目标满足创建前提 |
| S2 | 清单复制及独立 Git 初始提交完成 |
| S3 | 目标可定位，未开始 Feature |

## 资源与文件影响

仅创建目标清单内容、独立 .git（已启用复制过去的提交钩子）和初始提交；不复制维护手册或完整提示词库。

## 阻塞、异常与范围变化

目标非空、复制失败或提交钩子拒绝初始提交时，保留原始错误和现场，不覆盖、不自动清理。

## 完成状态与验证标准

独立空白项目与本地初始提交已建立，没有配置环境或推送远端。

## 流程关联与衔接关系

新项目尚无设计正文、且用户希望先把想法写成设计时，在新项目使用[只有游戏想法，先形成 GDD 草稿](<../游戏想法与 GDD/只有游戏想法，先形成 GDD 草稿.md>)；它不要求先完成 Godot 环境配置。创建项目本身不自动包含设计或开发授权。
