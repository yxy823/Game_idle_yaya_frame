# 复制迁移方案已确定，现在迁移旧项目

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已经用“[旧项目想采用当前框架，先评估复制迁移方案](<旧项目想采用当前框架，先评估复制迁移方案.md>)”选定了方案，准备把旧项目复制到一个新的空目录并接入框架，原项目保持不动。

需要的材料：

- **来源与目标**：原项目路径、已建好的空目标目录；框架来源固定为 `D:/A_Games/Game_idle_yaya_frame`。
- **迁移决定**：选定的方案（评估报告路径或原话）、保留原 Git 历史还是从新历史开始、是否带上样本存档数据。
- **允许运行的检查**：例如环境检查、自动测试、启动冒烟。不写时，Agent 在执行前的简述中提出验证方案，等你确认后再运行。

## 前置条件与适用范围

原件只读，复制及验证只在独立目标内，方案已经明确。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 项目与环境 → 复制迁移方案已确定，现在迁移旧项目”。填入上述材料。

**S1｜检查目标隔离**

当前 Agent 核对以下隔离条件：

- **目标路径**：已存在且为空、无中文空白且与两输入互不包含。
- **链接与 Git 指针**：不会写回原件。

**S2｜保留成果并转换**

按已选方案复制实际成果和必要定制，转换当前工具所需结构；保留 Feature ID、AC、真实完成历史和有效引用。

**S3｜验证目标并交接**

按获准范围检查环境、Feature 记录和业务；真实数据只用获准副本。记录原项目未变核对与续接点并提交目标。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 目标写入及运行不会触及原项目 |
| S2 | 目标可读取原有成果且无伪造历史 |
| S3 | `migration.md` 已写明保留项、转换、实际验证结果和原业务停点，并给出目标仓库的提交哈希 |

## 资源与文件影响

只写目标；保存 reports/maintenance/framework-migration/migration.md 与必要 Progress。不删除原件，也不在原项目中运行测试。

## 阻塞、异常与范围变化

无法无损表示的历史、隔离失败或缺失验收如实保留，不能改检查器或放宽 AC 放行。

## 完成状态与验证标准

独立目标保留有效成果，必要转换与验证完成；报告、提交和原业务待办明确。
