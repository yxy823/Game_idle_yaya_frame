# 工具位置或版本变了，需要更新项目环境

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

重装了 Python、换了 Python 版本，或把工具移到别的目录，项目配置里的路径需要随之更新。要把 Godot 升级到新的补丁版本时，改用[想把 Godot 升级到新的补丁版本](<../修复与改进/想把 Godot 升级到新的补丁版本.md>)：它会在改路径之外完成重存和完整验证。需要的材料：

- **工具变化**：改了哪个工具（Python 或 Godot），以及新路径或版本，原话即可。

## 前置条件与适用范围

项目已完成过首次环境配置，本次只调整指定环境项。`reports/initialization.md` 默认只留在本地，本机没有这份报告时新建一条记录。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 项目创建与接入 → 工具位置或版本变了，需要更新项目环境”。填入上述材料。本页由当前 Agent 使用项目自己的 `project-environment-godot` Skill；[源码入口](<../../../../../project-source/skills/project-environment-godot/SKILL.md>)仅供核对。

**S1｜核对改变范围**

当前 Agent 读取 `docs/methodology-config.json` 和本机已有的初始化报告，确认用户提供的新路径对应哪个字段。

**S2｜更新并检查**

修改指定字段，调用配置 Python 执行 `yaya/tools/checks/check-project-environment.py --require-ready`。

**S3｜追加记录**

在 `reports/initialization.md` 追加变更、实际检查和失败，不重写历史初始化记录；更新 Progress 后按项目规则提交。

项目工具命令按以下约定执行：

- **工作目录**：实际游戏项目根目录。
- **Python 与调用形式**：`$projectPython` 换成 `docs/methodology-config.json` 中的 `python_executable`（可写法见[调用](<../../../../../project-source/tools/README.md#调用>)），调用形式为 `& $projectPython -B <脚本路径> <参数>`，每次立即检查 `$LASTEXITCODE`。
- **参数替换**：尖括号参数替换为实际值。
- **结果边界**：命令成功只证明该操作完成。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 要改的字段和新值已列出 |
| S2 | 配置只改了指定字段；`--require-ready` 的实际输出和观察到的版本 |
| S3 | 初始化报告有新记录，Progress 已更新，有提交哈希 |

## 资源与文件影响

指定配置字段、初始化报告和 Progress 修改；不复制其他项目机器配置。

## 阻塞、异常与范围变化

新路径不可用时保留旧事实和当前失败，不静默选其他版本。

## 完成状态与验证标准

指定环境变更已生效并有当前检查，旧报告保留。
