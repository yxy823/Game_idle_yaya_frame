# 素材文件已经收到，先登记来源并核对是否齐全

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

美术或音频文件已经交过来（例如外包发来一个压缩包，或从素材站下载了一批），还没接进游戏，先要确认交的东西对不对、缺什么、来源能不能用。

需要的材料：

- **文件位置**：收到的文件所在目录的路径。
- **对应规格**：这批文件对应的设计资源章节（文档路径或章节名）；没指定时 Agent 按文件用途查找所属章节。
- **来源与许可**：作者、出处和许可说明的原话或文件；没有就如实说明，Agent 会记为待核实。

## 前置条件与适用范围

素材已经提供，当前只做接收盘点，不做正式技术或体验审核。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 素材与本地化 → 素材文件已经收到，先登记来源并核对是否齐全”。填入上述材料。

**S1｜核对交付包**

当前 Agent 比对实际文件与所属设计资源章节中的对象、数量和版本，并打开文件检查实际内容及相关的格式、尺寸或时长，不只看文件名；不执行素材包中的脚本。

**S2｜登记来源与去向**

在原表现方案、UI 或共享设计的资源章节记录实际位置、来源、许可及未明项，保留原件和版本说明，不另建接收记录文件。该素材已有来源记录时更新原条目，不另抄一份。

**S3｜交接检查**

列缺项和下一步技术检查对象，不因收到文件标记规格或体验通过。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 每项规格对应的到件、缺件和内容检查结果已列出 |
| S2 | 所属资源章节已写入实际位置、来源、许可和未明项 |
| S3 | 缺项清单和下一步要做技术检查的文件已列出 |

## 资源与文件影响

原素材只读；更新原所属资源章节中的接收位置与缺项。

## 阻塞、异常与范围变化

来源或许可不明时记录待核实，不推断为可用；不覆盖已有游戏文件。

## 完成状态与验证标准

已收到和缺失内容及来源信息明确，没有把接收等同可接入。
