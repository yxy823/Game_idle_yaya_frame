# 任务已经明确，需要列出要准备的素材

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

任务范围已经明确，需要知道哪些素材要准备、哪些已有，以及哪些选择会影响素材需求。

需要的材料：

- 要盘点的任务：Product 或 Feature ID，或一句话描述（例如“商店界面的购买反馈”）；不提供时按当前进行中的任务。
- 其余（已采用的界面或表现方案、设计中或实际的使用位置、已有资源）由 Agent 直接读取。

## 前置条件与适用范围

可以在尚无正式实现时开始盘点。先沿用已有设计判断用途和方案；本页整理准备需求，不制作、购买或接入资源，也不重新设计共享方向。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 素材与本地化 → 任务已经明确，需要列出要准备的素材”。填入上述材料。需要具体文件规格时，按媒体类型使用 [$design-visual-asset-spec](../../../../../project-source/skills/design-visual-asset-spec/SKILL.md)或 [$design-audio-asset-spec](../../../../../project-source/skills/design-audio-asset-spec/SKILL.md)；已有规格直接复用。

**S1｜核对用途与采用方案**

核对当前任务、已采用方案和已有资源。区分待决定的方案与待准备的文件，候选依赖不进入必备集合；尚无实现时以设计中的使用位置为依据。只有关键选择会改变文件需求或准备方式时，才交给对应设计 Skill 澄清（表现方案用 design-game-presentation，界面方案用 design-ui-spec），其他部分继续盘点。

**S2｜补齐适用的准备要求**

把实际需要的规格、准备状态和缺口保存到所属资源章节，只写准备或接收会用到的信息。无需独立素材的效果简短说明；无关字段直接省略，影响准备的未知项仍须明确。不把组件调查或未采用示例的详细参数写进正式规格。

**S3｜交付准备要求与缺项**

交付需要准备的素材、已有覆盖、影响准备的待定选择，以及必要的规格入口；回复可以汇总，不另存重复清单。

例如，已采用方案通过透明度变化完成棋盘淡入淡出，可以说明无需独立洗牌素材；尚未决定粒子是否用纹理时，应列为方案选择，不能提前要求提供粒子图片，也不能断言不需要图片。

## 资源与文件影响

只更新实际有变化的表现方案、UI 或共享设计资源章节；沿用现有正文与文件位置。

## 阻塞、异常与范围变化

用途或方案不足以确定文件需求时，说明具体选择及其影响，不先列全游戏素材。没有确定的外部文件需求时，区分方案仍待决定与已采用方案无需外部文件。

## 完成状态与验证标准

可确定的素材需求和准备要求已说明并保存，准备者能直接知道要提供什么。影响其余需求的待定选择及影响清楚，不把部分盘点说成全部规格已定稿。核对用途覆盖与必要引用，链接检查只证明导航有效。
