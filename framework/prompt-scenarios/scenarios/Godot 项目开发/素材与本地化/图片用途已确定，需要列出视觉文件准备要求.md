# 图片用途已确定，需要列出视觉文件准备要求

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

商店界面的物品图标、某个表现用的特效贴图等已经定了用在哪里，要交给外部准备或自己去找，需要先写清要什么尺寸、透明和切片，到件时也能照着检查。

需要的材料：

- **视觉对象**：要准备文件的对象和使用位置，例如“商店界面的物品图标”。
- **补充显示条件**：文档里还没写的目标视口、缩放或风格要求；没有就填“无”。

已采用方案、Art Bible、界面布局和已有资源由 Agent 直接读取。

## 前置条件与适用范围

已确定用途，需要为实际所需的图片等视觉文件写出准备与接收依据。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 素材与本地化 → 图片用途已确定，需要列出视觉文件准备要求”。填入上述材料。本页使用 [$design-visual-asset-spec](<../../../../../project-source/skills/design-visual-asset-spec/SKILL.md>)。

**S1｜核对显示用途**

当前 Agent 使用 design-visual-asset-spec 核对用途、已采用方案、已有资源和显示条件。先确认是否需要独立文件；影响文件需求的方案仍未确定时，保留具体选择，不代为选定。

**S2｜形成文件要求**

只写准备和接收需要的尺寸、透明、切片等适用参数，保留影响准备的未知项。字体等对象按自身用途写约束，不套用图片字段。已采用方案无需独立文件时简要说明，不生成空规格条目。

**S3｜保存唯一条目**

按[资源需求与交接](../../../../../project-source/methodology/11-specialist-workflows.md#资源需求与交接)保存到所属表现、UI、组件或 Art Bible 章节，记录真实准备状态、来源和已知去向；交付待准备文件、已有覆盖、待定选择及必要的规格入口，不另建重复清单。

## 资源与文件影响

所属表现、UI 或共享组件的资源章节，以及 Art Bible 的“共享资源规格”按实际归属修改；本页不画图或导入。

## 阻塞、异常与范围变化

缺少会影响准备的显示条件或方案选择时，说明受影响的文件与规格，继续不依赖它的部分，不随意定稿导入参数。

## 完成状态与验证标准

所需视觉文件的准备与接收依据明确；关键规格仍待决定时指出受影响部分，不宣称已定稿。
