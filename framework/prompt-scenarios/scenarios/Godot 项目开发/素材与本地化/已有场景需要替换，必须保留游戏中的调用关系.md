# 已有场景需要替换，必须保留游戏中的调用关系

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如结算弹窗换成重做的新场景，商店和关卡结束都在实例化旧弹窗并监听它的信号，替换后这些调用要继续有效。

所需材料：

- 旧场景路径和新场景路径。
- 需要保持的调用契约（信号、外部节点路径）；不提供时由 Agent 从实际消费者中追查。
- 其余（所属任务、使用方路径）由 Agent 直接读取。

## 前置条件与适用范围

已有场景由明确的新场景替换，需要保护其既有消费者。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 素材与本地化 → 已有场景需要替换，必须保留游戏中的调用关系”。填入上述材料。由当前 Agent 使用 [$content-asset-integration](../../../../../project-source/skills/content-asset-integration/SKILL.md)，运行修改与交付返回 [$feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md)。

**S1｜核对接入契约**

当前 Agent 使用 content-asset-integration，追查实际实例位置、外部节点路径、信号和脚本调用，区分需保持契约与批准改变的行为。

**S2｜完成资源接入**

在获准范围替换场景并修复直接消费者，保留必要标识和原件，不因同名覆盖跳过依赖核对。

**S3｜检查真实运行**

返回 feature-execute，运行受影响入口及重复创建/释放，检查原消费者行为和必要回归，记录真实体验结果。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 实例位置、外部节点路径、信号和脚本调用已列全，需保持与获准改变的契约已分开 |
| S2 | 新场景已替换，直接消费者已修复，引用有效 |
| S3 | 受影响入口、重复创建/释放和回归的运行结果已记录 |

## 资源与文件影响

旧场景可能替换，相关消费者和依赖引用修改；原确认需求与历史验收不篡改。

## 阻塞、异常与范围变化

资源缺失、依赖不明或要求冲突时保留缺口；不凭导入成功宣称功能或体验通过。

## 完成状态与验证标准

新场景承担已确认职责，实际消费者调用有效，必要运行与回归有结果。
