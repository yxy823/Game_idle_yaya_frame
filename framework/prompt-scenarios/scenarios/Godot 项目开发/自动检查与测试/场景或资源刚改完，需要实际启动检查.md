# 场景或资源刚改完，需要实际启动检查

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

调整了某个场景的节点结构，或替换了它引用的贴图、音频，想先确认场景还能加载、运行时没有脚本或资源报错，暂时不需要人工体验画面和手感。

需要的材料：

- 要检查的场景：`res://` 路径，例如 `res://main/main.tscn`；不提供时由 Agent 从本次改动找出受影响的场景，并在报告中写明选了哪个。
- 运行帧数（可空）：默认 120 帧。
- 存档限制（可空）：场景启动会读写存档时，可以使用哪些测试数据；不写则不读写现有存档。

## 前置条件与适用范围

只检查场景能否加载并运行到帧数上限。冒烟检查用 `--headless` 运行，不渲染画面，也不能注入点击或按键；需要看画面、听声音或实际操作时，交给用户体验或[准备人工验收清单](<../审核与人工验收/Feature 已能体验，需要准备人工验收清单.md>)。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 自动检查与测试 → 场景或资源刚改完，需要实际启动检查”。填入上述材料。本页由当前 Agent 使用项目自己的 `project-verification-godot` Skill；[源码入口](<../../../../../project-source/skills/project-verification-godot/SKILL.md>)仅供核对。

**S1｜确定场景与日志位置**

当前 Agent 核对场景文件存在、`docs/methodology-config.json` 中配置的 Godot，以及场景启动是否会读写存档；按[报告与清理](<../../../../../project-source/methodology/09-records-reports-and-handoff.md#报告与清理>)选好日志路径，不属于 Feature 时用 `reports/maintenance/<task>/`。

**S2｜运行冒烟检查**

在项目根目录按[启动场景冒烟检查](<../../../../../project-source/tools/README.md#启动场景冒烟检查>)执行（`$projectGodot` 的取法见该节）：

```powershell
& $projectGodot --headless --path . <场景路径> --quit-after <帧数> 2>&1 | Tee-Object -FilePath <日志路径> | Out-Host
$LASTEXITCODE
```

退出码非 `0` 表示启动失败。退出码为 `0` 时仍要检查日志中的 `ERROR`、`SCRIPT ERROR` 和紧随其后的 `at:` 行。

**S3｜报告结果与未检查部分**

报告命令、退出码、日志路径和日志中的错误；写明画面、声音和交互没有检查，需要时由用户实际体验。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 场景路径、Godot 路径和日志路径已确定 |
| S2 | 日志文件已保存，退出码已读取 |
| S3 | 报告列出退出码、日志中的错误行和未检查的部分 |

## 资源与文件影响

写入日志文件，运行可能更新 `.godot/` 缓存和已授权的测试数据；场景与资源内容不修改。

## 阻塞、异常与范围变化

场景启动会读写真实存档、又没有可用的测试数据时，不运行，先报告；无法隔离时不扩大写入。

## 完成状态与验证标准

场景运行到帧数上限或在启动时失败，退出码和日志错误已如实报告，未检查的画面、声音和交互已写明。
