# 想导出一个包在本机试玩

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

想离开编辑器，像玩家一样双击一个 `game.exe` 试玩当前版本；或者担心游戏导出后用到的文件被过滤掉、某些路径只在编辑器里存在，想先确认导出包能正常启动。

需要的材料：

- **运行帧数**（可空）：Agent 自动启动导出包时运行的帧数，默认 120。
- **存档限制**（可空）：导出包启动会读写存档时，自动启动可以使用哪些测试数据；不写则自动启动不读写现有存档。

由你完成的准备：在编辑器的“编辑器 → 管理导出模板”中安装与项目 Godot 版本一致的导出模板。

## 前置条件与适用范围

只导出 Windows debug 包并在本机启动，不涉及签名、release 导出、商店或分发配置。Agent 的自动启动用 `--headless`，只证明导出包能启动并运行到帧数上限；画面、声音和操作由你双击试玩确认。

项目还没有 `export_presets.cfg` 时，本次请求同时授权 Agent 新增一份最小导出预设并提交，这是一次项目配置修改。已有的导出预设不在本场景中修改。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 自动检查与测试 → 想导出一个包在本机试玩”。填入上述材料。本页由当前 Agent 使用项目自己的 `project-verification-godot` Skill；[源码入口](<../../../../../project-source/skills/project-verification-godot/SKILL.md>)仅供核对。导出方法以[本地导出检查](<../../../../../project-source/tools/README.md#本地导出检查>)为准。

**S1｜核对导出准备**

当前 Agent 读取 `docs/methodology-config.json` 中的 Godot 路径和版本，检查项目根目录的 `export_presets.cfg` 是否存在、其中是否有名为 `Windows Local` 的预设，以及导出包启动是否会读写存档。

**S2｜没有预设时新增最小预设**

`export_presets.cfg` 不存在时，当前 Agent 按[本地导出检查](<../../../../../project-source/tools/README.md#本地导出检查>)的“一次性准备”写入只含 `Windows Local` 的最小文件，排除项依据[资源与过滤](<../../../../../project-source/agent-rules/41-export-config/resources-and-filters.md>)。没写出的字段由 Godot 使用默认值，编辑器不会补写这个文件；S3 的实际导出通过后，再按项目 `AGENTS.md` 的「Git 与提交」提交它。已有预设且包含 `Windows Local` 时跳过本步。

**S3｜导出并自动启动**

当前 Agent 在项目根目录执行，`<日期>` 换成当天日期，例如 `20261005`，`120` 换成你指定的帧数：

```powershell
$exportDirectory = 'reports/exports/<日期>'
New-Item -ItemType Directory -Path $exportDirectory -Force | Out-Null
& $projectGodot --headless --path . --export-debug 'Windows Local' "$exportDirectory/game.exe" 2>&1 | Tee-Object -FilePath "$exportDirectory/export.log" | Out-Host
$LASTEXITCODE
& "$exportDirectory/game.exe" --headless --quit-after 120 2>&1 | Tee-Object -FilePath "$exportDirectory/run.log" | Out-Host
$LASTEXITCODE
```

导出退出码非 `0`、缺少 `game.exe` 与 `game.pck`，或 `export.log` 中有退出时资源泄漏提示（`leaked`、`still in use`、`PagedAllocator`）以外的 `ERROR`，表示导出失败，不再启动。启动的退出码为 `0` 时，仍要检查 `run.log` 中的 `ERROR`、`SCRIPT ERROR` 和紧随其后的 `at:` 行。

**S4｜报告并交给你试玩**

当前 Agent 报告导出与启动的命令、退出码、两份日志的路径和其中的错误行，并写明画面、声音和操作没有检查。导出成功时给出 `game.exe` 的完整路径，你双击它实际试玩；导出失败时不给路径，按下文“阻塞、异常与范围变化”处理。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | Godot 路径与版本、预设是否存在、存档读写情况已确认 |
| S2 | 项目根目录有只含 `Windows Local` 的 `export_presets.cfg`；已有 `Windows Local` 时本步跳过 |
| S3 | `export.log`、`run.log` 已保存，两个退出码已读取；导出成功时 `game.exe` 位于 `reports/exports/<日期>/` |
| S4 | 报告列出退出码、日志错误行、`game.exe` 路径和未检查的部分 |

## 资源与文件影响

- `export_presets.cfg`：只在项目原本没有时新增并提交；已有的预设不修改。
- `reports/exports/<日期>/`：导出包和两份日志，不进 Git，也不被 Godot 当成项目资源扫描。
- 运行可能更新 `.godot/` 缓存和已授权的测试数据；游戏代码、场景与资源不修改。

## 阻塞、异常与范围变化

- **缺少对应版本的导出模板**：导出会失败，停下请你安装，装好后从 S3 继续。
- **已有 `export_presets.cfg` 但没有 `Windows Local`**：不改现有文件，报告已有的预设名称，由你决定用哪一个导出或是否新增。
- **导出包启动会读写真实存档，又没有可用的测试数据**：只导出不自动启动，先报告。
- **启动报错**：常见原因是运行时用到的文件被过滤掉，或代码引用了只在编辑器中存在的路径；本场景只报告，修复按问题所属的场景处理。

## 完成状态与验证标准

- **成功时**：导出包已生成在 `reports/exports/<日期>/` 并自动启动到帧数上限，需要新增的预设已提交，`game.exe` 路径已交给你试玩，未检查的画面、声音和操作已写明。
- **失败时**：导出或启动的失败、日志中的错误行和恢复条件已如实报告；新增的预设留在工作区不提交，也不给出 `game.exe` 路径。
