# 已确认的声音方向要调整，需要更新规范并检查影响

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

Sound Bible 里原定“奖励音效清脆明亮”，现在决定改成“柔和、以低频为主”，而已有几段音效和规划中的 Feature 是按旧方向准备的。

需要的材料：已确认的新决定（原话，或记录决定的位置）；已知要改的适用范围可以一并写明，不写时 Agent 按决定内容判断。原规范、已有素材和 Feature 由 Agent 直接读取。

## 前置条件与适用范围

已有有效共享声音方向；本次修改已确认要求并说明消费者影响，不重新启动初次风格访谈。

## 执行步骤

使用[预设提示词库](../../../prompts/godot-development-prompts.json)中的“Godot 项目开发 → 要求变了 → 已确认的声音方向要调整，需要更新规范并检查影响”。适用 Skill：[$design-audio-direction](../../../../../project-source/skills/design-audio-direction/SKILL.md)。

**S1｜核对方向差异**

当前 Agent 使用 design-audio-direction 读取原规范与新决定，核对声音角色、混音关系、循环疲劳、过渡和适用场景中的实际变化；玩家行为改变先由 GDD 承接，并核对 Product 交付范围。

**S2｜修改唯一规范**

共享声音规格固定维护在 `docs/audio/sound-bible.md`，更新受影响规格、适用范围和引用；原先写在 GDD 的当前范围内规格迁入该文件，GDD 保留整体体验目标、玩法触发规则及引用。保留未改变的有效决定与真实历史。

**S3｜核对消费者并交接**

追查专业规格、素材、实际实现和已规划任务的适用关系，列需同步的计划及后续资源工作。需要源同步时，先用 `check-markdown-links.py` 校验受影响链接，并按项目 `AGENTS.md` 的「Git 与提交」提交来源修改。只交接影响，不在本页替换素材或直接实现。

## 步骤产出与状态变化

| 步骤 | 继续条件 |
| --- | --- |
| S1 | 新旧要求的差异已逐条列出，并标明是否涉及 GDD 行为 |
| S2 | `sound-bible.md` 已更新，GDD 中被迁出的规格已改为链接 |
| S3 | 受影响的素材、Feature 与同步入口已列出；来源修改的链接检查结果和提交哈希已给出 |

## 资源与文件影响

`docs/audio/sound-bible.md` 与必要来源链接修改；现有素材、运行实现和已完成 Feature 的 AC/验收历史只读。

## 阻塞、异常与范围变化

对新方向仍未作实质决定时只补齐对应选择；不能修改来源来把旧实现 Bug 改写成符合要求。

## 完成状态与验证标准

确认的新声音方向已保存，受影响消费者及待同步计划明确；资源制作与实现未被冒称完成。
