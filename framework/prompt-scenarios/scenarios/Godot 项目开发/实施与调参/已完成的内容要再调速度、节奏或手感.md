# 已完成的内容要再调速度、节奏或手感

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

某项内容所属的 Feature 早已完成，你后来才觉得它的观感不对，想在调试台改数值，不改规则。例如已验收的棋盘下落太慢、一周后想把爆炸特效调小、跳跃落地后的停顿太长。

需要的材料：

- 要调的内容和你的感受：哪个内容、在什么情况下哪里不对，例如“棋盘下落太慢”。
- 想保持不变的地方（可空）。
- 其余（所属 Feature 的完成状态、调参资源、调试台登记）由 Agent 直接读取。

## 前置条件与适用范围

内容所属的 Feature 已经完成，要改的只是观感参数。按 13 号规范的[选择方式](../../../../../project-source/methodology/13-debug-console-and-validation.md#选择方式)判断：只影响观感和节奏的参数在这里调；决定操作是否被接受、结果是否成立的参数会改变规则，先用[已有内容表现不对，先判断是 Bug、要改要求还是只需调值](<../出了问题/已有内容表现不对，先判断是 Bug、要改要求还是只需调值.md>)确认去向。所属 Feature 还没完成时，改用[特效已经做出来，需要和我一起调到满意](<特效已经做出来，需要和我一起调到满意.md>)或[操作手感不对，需要调整参数](<操作手感不对，需要调整参数.md>)。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 实施与调参 → 已完成的内容要再调速度、节奏或手感”。填入上述材料。本页使用 [$debug-console-godot](../../../../../project-source/skills/debug-console-godot/SKILL.md)；收尾后的路由按[完成后再调值](../../../../../project-source/methodology/13-debug-console-and-validation.md#完成后再调值)执行，本页不另写一套。

**S1｜准备调试台**

当前 Agent 确认要调的参数在 `game/<对象>/tuning/` 的调参资源中，需要时登记插槽、固定局面或试播动作，然后告诉你启动命令（项目 `dev/debug/README.md` 中那一条）和要调的插槽。参数还写死在已完成 Feature 的代码里时，提到调参资源属于重构，Agent 停下说明，按[完成后再调值](../../../../../project-source/methodology/13-debug-console-and-validation.md#完成后再调值)中的说明转入重构入口。

**S2｜调整并采纳**

每一轮 Agent 建议改一两个参数；你在调试台里拖参数，按 ` 键在“当前改动”和“游戏原值”之间切换比较。满意后在调试台点“采纳到游戏”并确认一次。调整记在 Progress。

**S3｜收尾并检查链接**

当前 Agent 按[收尾步骤](../../../../../project-source/defaults/dev/debug/_shared/README.md#收尾步骤)补回 UID，运行资源格式检查和所选测试（至少包括写入资源所属组件的测试和依赖方向测试），然后提交。再按[完成后再调值](../../../../../project-source/methodology/13-debug-console-and-validation.md#完成后再调值)在 `docs/` 下搜索被写入的调参资源，按命中情况处理：被已完成 Feature 的来源文档或 AC 链接时，报告受影响的 Feature 并运行 `feature-sync`，即[要求已经改好，同步受影响的 Feature](<../要求变了/要求已经改好，同步受影响的 Feature.md>)；没有被链接时，收尾提交即完成。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 要调的参数在调参资源中，你已拿到启动命令和插槽名称 |
| S2 | 调试台提示“已采纳”；`dev/debug/adoption-log.md` 有待收尾的记录 |
| S3 | 收尾提交哈希和测试结果；链接检查的命中情况；命中时 feature-sync 建立的新 Feature ID 或它的审阅点 |

## 资源与文件影响

修改被写入的调参资源和 `dev/debug/<对象>/` 下的插槽登记、固定局面或试播动作。已完成 Feature 的 AC、完成证据和验收历史不改；需要重新验收时由新的 Feature 完成。不新建调整记录文件。

## 阻塞、异常与范围变化

- 两三轮下来仍然没有接近你想要的效果时，Agent 停下来说明可能的原因和建议的入口，不继续盲目调参。
- 要调的参数会改变规则，或要换技术、新增组成部分：属于设计变化，不在调参中完成。
- 想在 Godot 编辑器里改参数：编辑器检查器显示的是编辑器自己的资源副本，不是游戏当前值，只在调试台里改。

## 完成状态与验证标准

你对效果满意并已采纳到游戏，收尾已提交，相关自动测试仍然通过，链接检查已完成；命中已完成 Feature 时，feature-sync 已建立新的 Feature 或停在它的审阅点。采纳到游戏不是人工验收。
