# Feature 需要游戏内文字，现在撰写或修改

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如升级面板的说明写得太长、玩家看不懂“转生”能得到什么，或者新功能需要一段第一次进入时的提示，想让 Agent 写好并放进游戏。

需要的材料：

- 要写或要改的文字在哪里出现，以及你对它的要求，用自己的话说，例如“升级说明不超过一行，说清楚加成多少”。
- 已有的参考写法或你喜欢的口吻（可空）；不提供时按本地化规范的语气约定。
- 其余（所属 Feature、相关设计、空间限制、术语）由 Agent 直接读取。

## 前置条件与适用范围

文字属于一个已授权的 Feature；没有这类授权时，Agent 只给出文字建议，不改文件。要改变教程的步骤或触发时机，或者文字会改变玩家对规则的理解，属于游戏设计的变化，先用[已有模块的玩法要求变了，需要更新需求](<../要求变了/已有模块的玩法要求变了，需要更新需求.md>)。翻译成其他语言用[本地化要求已确定，现在接入目标语言](<../素材与本地化/本地化要求已确定，现在接入目标语言.md>)。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 实施与调参 → Feature 需要游戏内文字，现在撰写或修改”。填入上述材料。本页由所属 Feature 的执行使用 [$feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md)，写法按[玩家可见文本](<../../../../../project-source/methodology/11-specialist-workflows.md#玩家可见文本>)。

**S1｜读约束**

当前 Agent 读取文字所属的设计说明、UI 规格中的空间限制、本地化规范的**语气与用词**章节和项目术语。语气约定还没有、而这次文字需要它时，先说明缺口，由你决定口吻后交 `design-localization-spec` 写进规范。

**S2｜写进运行时资源**

当前 Agent 把文字写进它实际所在的地方：使用翻译键时（新项目的本地化规范默认要求）写翻译表的源语言列，场景、脚本和数据文件只引用键；规范不要求翻译键时写在场景、资源或数据文件中。同一句话只放一处。概念名称与术语文件一致。

**S3｜在界面中核对**

当前 Agent 在实际界面中检查最长的那条文本和空状态有没有截断或溢出，然后请你阅读确认。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 列出了这次文字的出现位置、空间限制和适用的语气约定，或明确写出缺少哪一项 |
| S2 | 文字只在一处运行时资源中，概念名称与 `docs/terminology.md` 一致 |
| S3 | 最长文本和空状态的显示结果已报告，你给出了阅读结论 |

## 资源与文件影响

修改翻译表、场景、资源或数据文件中的文字；需要时由 `design-localization-spec` 更新本地化规范的**语气与用词**章节。不另建保存句子的 Markdown 文件。

## 阻塞、异常与范围变化

- 文字放不下：报告实际长度和可用空间，由你决定缩短文字还是调整界面；调整界面属于 UI 规格的变化。
- 你要求的写法与术语文件中的名称冲突时，先确认改术语还是改文字，不在文字里另起一个说法。

## 完成状态与验证标准

文字已写进运行时资源，在实际界面中没有截断，你读过并认可。需要验收的 Feature 仍在 Stage 5 正式验收。
