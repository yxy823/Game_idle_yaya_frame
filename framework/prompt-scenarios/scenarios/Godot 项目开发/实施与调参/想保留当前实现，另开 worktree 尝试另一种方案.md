# 想保留当前实现，另开 worktree 尝试另一种方案

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

当前实现需要保留，同时要在另一个目录尝试方案、运行不同版本或开展会互相覆盖的工作。普通暂停和换对话不必创建 worktree。

## 前置条件与适用范围

在实际游戏仓库执行，已有明确试验目标和目录准备授权。提供已知基准与希望带入的改动；Agent 先核对可读取的 Git 状态，不要求为了提供这些事实而先提交所有改动。

## 参与角色与职责边界

当前 Agent 使用 [worktree-create](../../../../../project-source/skills/worktree-create/SKILL.md) 准备目录；用户决定实质方案取舍。该入口不选择最终采用哪套成果，也不自动合并或删除 worktree。

## 执行步骤

使用[预设提示词库](../../../prompts/godot-development-prompts.json)中的“Godot 项目开发 → 实施与调参 → 想保留当前实现，另开 worktree 尝试另一种方案”。补充试验目标、已知基准、需带入的内容，以及本次是否运行编辑器或测试。

**S1｜确定要从什么内容开始**

核对仓库、现有 worktree、基准提交及相关差异。没有进行中的任务或进程依赖、已有工作已核对清楚的现有目录优先复用；未提交或被忽略的内容不会随普通检出自动带入。范围不明确时先说明缺口，保留来源内容与暂存状态。

**S2｜准备本次需要的目录与环境**

使用当前宿主支持的 worktree 能力；按实际试验需要处理本地依赖和运行准备。将要启动编辑器、导入、测试、游戏或其他写入工具时，按 Skill 的运行参考检查相关数据路径，包括适用的 user:// 和测试临时数据；只读比较无需全套运行准备。

**S3｜交付可用位置与恢复动作**

给出实际目录、分支或提交、准备结果和第一步。目录创建成功但所需运行仍受阻时分开报告；已有实现授权时，之后的工作在目标目录进行。

## 资源与文件影响

会增加或复用工作目录，可能建立本次必要分支和任务范围内的本地准备文件。保留无关改动；不为搬运或存档而提交，任务同时要求人工验收和提交许可时，两者都满足前不做中间提交。必要续接信息沿用 Feature notes 或 Progress，不建立目录管理记录文件。

## 阻塞、异常与范围变化

基准含糊、已有改动无法分离或运行可能触及未保护的数据时，只暂停依赖该条件的操作。保留已创建目录与现场，明确还缺什么；新检出、改存档槽位或工具返回成功不直接证明完整隔离。

## 完成状态与验证标准

实际目录与选定基准正确，本次工作所需输入和准备可用，已有内容未被覆盖。未执行的运行检查明确保留；此出口不代表试验功能已经完成。

## 流程关联与衔接关系

创建后按原任务实施；成果选定后可进入[已选定 worktree 中的成果，带回目标分支](<已选定 worktree 中的成果，带回目标分支.md>)。多项未知尚需逐步判断时使用[目标已有方向，多个问题互相牵连，先逐步理清](<../游戏想法与 GDD/目标已有方向，多个问题互相牵连，先逐步理清.md>)，不把两个入口变成创建前的强制步骤。Git 操作与提交遵循项目 `AGENTS.md` 的[Git 与提交](../../../../../project-source/Project_AGENTS.md#git-与提交)。
