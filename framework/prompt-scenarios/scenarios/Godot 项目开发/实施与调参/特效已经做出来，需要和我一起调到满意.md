# 特效已经做出来，需要和我一起调到满意

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如消除的爆炸特效已经接进游戏，你看了觉得连续消除时闪得刺眼、整体节奏拖沓，想一边玩一边改，直到满意为止。人工验收时说“这里还要再调一下”，也从这里开始。效果所属的 Feature 早已完成、一周后你才想把爆炸调小，改用[已完成的内容要再调速度、节奏或手感](<已完成的内容要再调速度、节奏或手感.md>)。

需要的材料：

- 要调的效果和你的感受：哪个效果、在什么情况下哪里不对，用自己的话说就行，例如“连续消除三次以上时太闪”。
- 想保持不变的地方（可空），例如“颜色不要动”。
- 其余（所属 Feature、效果的调参资源、调试台登记）由 Agent 直接读取。

## 前置条件与适用范围

效果已经实现、能在 Godot 中运行。调整属于一个已授权的 Feature，或你要求的限定范围调整；没有这类授权时，Agent 只给调整建议，不改文件。效果还没有规划时，先用[有游戏表现想法，需要拆解需求并选择实现方案](<../美术、声音、界面与表现/有游戏表现想法，需要拆解需求并选择实现方案.md>)；要在几种实现之间做选择时，用[界面效果还没确定，在调试台比较候选](<../美术、声音、界面与表现/界面效果还没确定，在调试台比较候选.md>)。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 实施与调参 → 特效已经做出来，需要和我一起调到满意”。填入上述材料。本页使用 [$debug-console-godot](../../../../../project-source/skills/debug-console-godot/SKILL.md)；调试台的具体机制见[调试台共享代码](../../../../../project-source/defaults/dev/debug/_shared/README.md)。

**S1｜准备调试台**

当前 Agent 确认效果的参数都在 `game/<对象>/tuning/` 的调参资源中；还写死在代码或场景里时，在当前授权内提到调参资源。需要反复看同一过程时，登记固定局面或试播动作。然后告诉你启动命令（项目 `dev/debug/README.md` 中那一条）和要调的插槽。

**S2｜一轮轮调整**

每一轮 Agent 说明建议改哪一两个参数、往哪个方向、为什么。你在调试台里拖参数，下一次触发就用新值；按 ` 键在“当前改动”和“游戏原值”之间切换比较，说出还差什么。Agent 在 Feature notes 中记下这一轮，Feature 之外的调整记在 Progress。

**S3｜采纳到游戏**

你满意后，在调试台点“采纳到游戏”并确认一次。

**S4｜收尾并提交**

当前 Agent 按[收尾步骤](../../../../../project-source/defaults/dev/debug/_shared/README.md#收尾步骤)补回 UID，运行资源格式检查和所选测试（至少包括写入资源所属组件的测试和依赖方向测试），然后提交。表现文档链接被写入的调参资源，不抄数值。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 要调的参数在调参资源中，你已拿到启动命令和插槽名称 |
| S2 | notes 中每一轮有建议改的参数和你的判断 |
| S3 | 调试台提示“已采纳”；`dev/debug/adoption-log.md` 有待收尾的记录 |
| S4 | 收尾提交哈希和测试结果 |

## 资源与文件影响

修改效果的调参资源和必要的场景，`dev/debug/<对象>/` 下的插槽登记、固定局面或试播动作，以及链接调参资源的表现文档位置。插槽预设和组合只是候选设定，不进验证，游戏也不读取。不新建调整记录文件。

## 阻塞、异常与范围变化

- 两三轮下来仍然没有接近你想要的效果时，Agent 停下来说明可能的原因：方案本身不合适时转[有游戏表现想法，需要拆解需求并选择实现方案](<../美术、声音、界面与表现/有游戏表现想法，需要拆解需求并选择实现方案.md>)；缺合适的图像或声音时标出资源缺口；帧率下降时转[运行出现卡顿，先测量并定位瓶颈](<../出了问题/运行出现卡顿，先测量并定位瓶颈.md>)。
- 要换一种技术或新增组成部分，属于表现设计的变化，不在调参中悄悄完成。
- 想在 Godot 编辑器里改参数：编辑器检查器显示的是编辑器自己的资源副本，不是游戏当前值，只在调试台里改。

## 完成状态与验证标准

你对效果满意并已采纳到游戏，收尾已提交，相关自动测试仍然通过。采纳到游戏不是人工验收；需要验收的 Feature 仍在 Stage 5 正式验收，验收针对游戏原值。
