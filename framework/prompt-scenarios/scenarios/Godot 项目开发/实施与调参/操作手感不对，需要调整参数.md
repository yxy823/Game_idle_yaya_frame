# 操作手感不对，需要调整参数

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如角色移动已经做好，你玩的时候觉得停下来会往前滑、跳跃按下去要等一下才起跳，想边玩边调到顺手。操作所属的 Feature 早已完成、之后才想调时，改用[已完成的内容要再调速度、节奏或手感](<已完成的内容要再调速度、节奏或手感.md>)。

需要的材料：

- 哪个操作、在什么情况下感觉不对，用自己的话说，例如“松开方向键后还往前滑一段”。
- 想保持不变的地方（可空），例如“最高速度不要变”。
- 其余（所属 Feature、参数所在的调参资源、调试台登记）由 Agent 直接读取。

## 前置条件与适用范围

操作已经实现、能运行。调整属于一个已授权的 Feature 或你要求的限定范围调整；没有这类授权时，Agent 只给调整建议，不改文件。感觉不对其实来自规则或数值设计时，例如关卡节奏、经济成长，改用[已有数值需要调整，更新模型与参数](<../要求变了/已有数值需要调整，更新模型与参数.md>)。

## 执行步骤

使用[预设提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 实施与调参 → 操作手感不对，需要调整参数”。填入上述材料。本页使用 [$debug-console-godot](../../../../../project-source/skills/debug-console-godot/SKILL.md)；调试台的具体机制见[调试台共享代码](../../../../../project-source/defaults/dev/debug/_shared/README.md)。

**S1｜让参数可调**

当前 Agent 找到相关参数。参数还写死在代码里时，在当前授权内提到 `game/<对象>/tuning/` 的调参资源，它在调试台里就是一个插槽。然后告诉你启动命令（项目 `dev/debug/README.md` 中那一条）和要调的插槽。

**S2｜一轮轮调整**

每一轮 Agent 说明建议改哪一两个参数、改多少、为什么。你在调试台里改值，接着在游戏窗口里操作，按 ` 键在“当前改动”和“游戏原值”之间切换比较。Agent 在 Feature notes 中记下这一轮，Feature 之外的调整记在 Progress。

**S3｜采纳到游戏**

你满意后，在调试台点“采纳到游戏”并确认一次。

**S4｜收尾并提交**

当前 Agent 按[收尾步骤](../../../../../project-source/defaults/dev/debug/_shared/README.md#收尾步骤)补回 UID，运行资源格式检查和所选测试（至少包括写入资源所属组件的测试和依赖方向测试），然后提交。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 要调的参数已在调参资源中，你已拿到启动命令和插槽名称 |
| S2 | notes 中每一轮有建议改的参数和你的判断 |
| S3 | 调试台提示“已采纳”；`dev/debug/adoption-log.md` 有待收尾的记录 |
| S4 | 收尾提交哈希和测试结果 |

## 资源与文件影响

修改调参资源和读取它的代码；把写死的参数提到调参资源属于本次实现修改。`dev/debug/<对象>/` 下的插槽登记随之更新。插槽预设和组合只是候选设定，不进验证，游戏也不读取。

## 阻塞、异常与范围变化

- 两三轮下来仍然没有接近你想要的手感时，Agent 停下来说明可能的原因，例如输入延迟、动画锁住了输入，需要先查原因时转[发现异常，先定位原因，不修改实现](<../出了问题/发现异常，先定位原因，不修改实现.md>)。
- 要改变操作规则本身（例如新增二段跳），属于游戏设计的变化，不在调参中完成。
- 想在 Godot 编辑器里改参数：编辑器检查器显示的是编辑器自己的资源副本，不是游戏当前值，只在调试台里改。

## 完成状态与验证标准

你对手感满意并已采纳到游戏，收尾已提交，相关自动测试仍然通过。采纳到游戏不是人工验收；需要验收的 Feature 仍在 Stage 5 正式验收，验收针对游戏原值。
