# 规则和公式已确定，需要批量制作关卡或内容表

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

例如三消的关卡规则和目标类型已经写进 GDD，现在要做第 1–30 关；或者放置类的产出和成本公式已经定了，要填出 20 个生产者和它们的升级表，并让 Agent 检查成本是否递增、解锁时间是否落在目标范围内。

需要的材料：

- 要做的内容和数量，例如“第 1–30 关”“20 个生产者及其升级”。
- 你对这批内容的特别要求（可空），例如“前 5 关是教学关，每关只引入一种新元素”；不提供时按 GDD 的节奏目标。
- 其余（所属 Feature、规则、公式和目标区间、已有数据）由 Agent 直接读取。

## 前置条件与适用范围

内容属于一个已授权的 Feature，所需的规则写在 GDD、公式和目标区间写在 `balance/`。没有所属 Feature 时，Agent 只给出内容方案和检查方案，不改运行时文件。规则或目标还没定、需要新元素或新目标类型时，先用[已有模块的玩法要求变了，需要更新需求](<../要求变了/已有模块的玩法要求变了，需要更新需求.md>)或[已有数值需要调整，更新模型与参数](<../要求变了/已有数值需要调整，更新模型与参数.md>)。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 实施与调参 → 规则和公式已确定，需要批量制作关卡或内容表”。填入上述材料。本页使用 [$content-data-authoring](../../../../../project-source/skills/content-data-authoring/SKILL.md)，在所属 Feature 的执行（[$feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md)）中进行。

**S1｜确定数据与检查方案**

当前 Agent 读取规则、公式、目标区间和节奏目标，确定数据文件的位置和格式、哪些内容手写、哪些用生成器生成，以及要新增哪些内容检查。这些写进 Stage 1 的批准材料，由你批准。

**S2｜编写或生成内容**

当前 Agent 按批准的方案写入数据。用生成器时，种子和参数是生成器的输入，同样的输入连续生成两次结果一致；生成产物不手工修改。

**S3｜运行检查并请你试玩**

当前 Agent 用生产加载器加载全部数据，运行内容不变量测试和长耗时的核对脚本，报告结果；再列出值得你重点试玩的内容，例如自动对局通过率最低的几关。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 批准材料中列出了数据文件路径、格式、手写与生成的划分和新增检查的逻辑 ID |
| S2 | 数据文件已写入；用生成器时，两次生成逐字节一致并与提交的文件一致 |
| S3 | 加载、不变量测试和核对脚本的实际结果已报告，列出了需要你试玩的具体内容 |

## 资源与文件影响

新增或修改 `game/<module>/` 下的数据文件、生成器和 `tests/invariants/content/` 中的检查；GDD 中补上指向数据文件的链接。`balance/` 不复制每行数值。

## 阻塞、异常与范围变化

- 做内容时发现规则或公式不够用：这部分停下，交回 `design-gdd` 或 `design-balance`，不在数据里悄悄补一条规则；不受影响的内容继续做。
- 你试玩后觉得难度或节奏不对：要改公式或目标区间，交给 `design-balance`；只是个别关卡或数值，在当前 Feature 中修改数据并重跑检查。

## 完成状态与验证标准

内容数据已写入，加载与内容检查全部通过，你试玩过重点内容；需要验收的 Feature 仍在 Stage 5 正式验收。
