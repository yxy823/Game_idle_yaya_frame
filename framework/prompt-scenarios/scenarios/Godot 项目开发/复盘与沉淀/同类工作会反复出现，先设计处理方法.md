# 同类工作会反复出现，先设计处理方法

[返回场景索引](../../scenario-index.md)

## 触发场景与使用时机

同一类工作已经反复出现、每次都要重新交代，或者预计今后会经常做，想先确定一套固定的处理方法。例如：多次接入资源都要重新说明同一组检查；或者准备频繁调整 UI 动效，想先讲清每次从哪里开始、交付什么。

## 前置条件与适用范围

在实际 Godot 项目中处理，不为设计方法重新收集 GDD 或 Product 需求。本次只在对话里分析，不写文件。要查明某个任务为什么反复返工，改用[当前任务反复返工，先复盘原因](当前任务反复返工，先复盘原因.md)。

## 执行步骤

使用[Godot 开发提示词库](../../../prompts/godot-development-prompts.json)中的「复盘与沉淀 → 同类工作会反复出现，先设计处理方法」，由当前 Agent 使用项目自己的 `loop-me` Skill。

**S1｜提供这类工作的信息**

填写这类工作是什么、何时发生、每次的输入与产出和限制；有过往实例就附上，没有就注明属于预计工作。

**S2｜确认处理方案**

Agent 区分每次相同和每次变化的部分，比较沿用现有入口、补充引用和最小新增，交付建议的入口、输入、关键判断、产出、完成条件和正文位置。你从中决定是否采用、采用到什么范围。

## 完成状态与验证标准

得到一份可以直接采用或修改的处理方案，采用前需要你决定的选择都已列出。方案只经过推演，还没有实施或实际验证。

## 流程关联与衔接关系

决定采用后，按方案内容选择对应场景实施；需要把重复操作做成脚本时，使用[重复操作已确认值得固化，需要做成项目脚本](重复操作已确认值得固化，需要做成项目脚本.md)。依据：[任务路由表](<../../../../../project-source/methodology/00-overview.md#任务路由表>)中的 `loop-me` 一行。
