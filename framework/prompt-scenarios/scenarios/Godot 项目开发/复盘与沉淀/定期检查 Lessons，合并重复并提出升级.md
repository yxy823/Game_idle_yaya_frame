# 定期检查 Lessons，合并重复并提出升级

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

Lessons `docs/lessons.md` 已经记了一段时间，想定期整理。说法不同、其实是同一件事的条目要合并。出现 3 次或后果严重的失误，要提出升级成规则、脚本、钩子、Skill 或配置。由用户按自己的节奏发起，没有自动提醒。

需要的材料：

- **关注线索**：想重点核对的条目或时间范围；不提供时检查全部条目。

## 前置条件与适用范围

Lessons 里已有条目。Lessons 为空时没有可做的事。本场景只整理 Lessons、提出升级方案，升级本身由用户批准后另行执行。

## 执行步骤

使用[预设提示词库](../../../prompts/godot-development-prompts.json)中的“Godot 项目开发 → 复盘与沉淀 → 定期检查 Lessons，合并重复并提出升级”，填入关注线索。当前 Agent 按 Lessons 的规则执行，不启动专用 Skill。

**S1｜合并重复条目**

Agent 按“触发”和“症状”比较条目，指同一件事的合并为一条，保留全部日期和证据；没有证据的那次不计数。

**S2｜分出事实类陷阱**

Agent 把属于“工具或引擎怎样运作”的条目挑出来，提议移到项目知识 `docs/knowledge/`。

**S3｜列出升级建议**

Agent 列出出现 3 次或严重的条目，按[经验的归宿与规则提升](../../../../../project-source/methodology/04-project-rules.md#经验的归宿与规则提升)的去向表给出建议去向和要改的文件。

**S4｜提交并交付**

Agent 提交 Lessons 的整理结果，在对话中交付升级建议，等用户选择。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 每条的次数等于保留的日期个数 |
| S2 | 事实类条目已列出建议位置 |
| S3 | 每条升级建议写明去向、理由和要改的文件 |
| S4 | 提交哈希和升级建议 |

## 资源与文件影响

只修改 `docs/lessons.md`；规则、Skill、工具和配置只读。

## 阻塞、异常与范围变化

条目缺少证据、无法判断是不是同一件事时，保持分开并在报告里说明。用户选定升级后，按对应的修改入口另行实施。

## 完成状态与验证标准

Lessons 已整理并提交，升级建议已交付。
