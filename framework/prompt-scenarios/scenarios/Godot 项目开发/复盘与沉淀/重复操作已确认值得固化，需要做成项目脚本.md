# 重复操作已确认值得固化，需要做成项目脚本

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

同一串手工命令或检查已经做过多次，例如每次导出前都手动核对同一组文件，用户确认值得写成项目脚本。

需要的材料：

- 重复的证据：做过几次、每次的命令或步骤，原话或记录路径都可以。
- 期望的脚本（可选）：输入、输出和由谁调用（用户或某个 Skill）；不提供时 Agent 按现有做法提出，写入前请用户确认。

现有命令、工具和调用方由 Agent 直接读取。

## 前置条件与适用范围

已确认值得固化。还没想清楚以后怎样处理这类工作时，先用[同类工作会反复出现，先设计处理方法](<同类工作会反复出现，先设计处理方法.md>)。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 复盘与沉淀 → 重复操作已确认值得固化，需要做成项目脚本”。填入上述材料。本页使用 [$engineering-change-plan](<../../../../../project-source/skills/engineering-change-plan/SKILL.md>)、[$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)。

**S1｜确定工具契约**

当前 Agent 比较复用现有命令、合并和最小新增工具，明确操作目标、副作用、失败和清理。尚未规划时用 engineering-change-plan 的 maintenance 模式展示方案，取得用户批准后写入；当前请求已明确批准具体方案及其执行时沿用。

**S2｜完成工程实现**

当前 Agent 使用 feature-execute 固化最小实现，去除一次性绝对路径，复用已有基础函数。

**S3｜验证并说明用法**

覆盖实际输入、输出及失败保护，按工具所在目录的 README 补使用说明；有可复用经验时链接知识条目。按所属任务交付。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | maintenance Feature（输入输出、副作用、失败处理）已获批写入，`check-feature-list` PASS |
| S2 | 脚本不含一次性绝对路径，能通过真实入口调用 |
| S3 | 正常与失败输入的实际运行结果；使用说明已写 |

## 资源与文件影响

项目工具、必要用法、验证与任务记录修改。

## 阻塞、异常与范围变化

重复证据不足、处理方式还没定时，改用[同类工作会反复出现，先设计处理方法](<同类工作会反复出现，先设计处理方法.md>)。需要改变已有工具的契约时，先说明影响并取得确认。

## 完成状态与验证标准

最小工具实现及用法、必要验证和任务交付完成。
