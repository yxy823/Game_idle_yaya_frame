# 经验已经确认，需要整理进项目知识

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

复盘或任务中已经确认了一条以后还会用到的做法，例如“某种写法会触发警告，让 gdUnit 判失败，要改成另一种写法”，想写进 `docs/knowledge/`，让下一个 Feature 能查到。

需要的材料：

- **经验原话**：要保存的做法或教训，以及适用的版本、平台或条件。
- **证据**：支撑它的 Feature ID、提交、测试或报告路径；已在当前对话中的可以不再提供。

## 前置条件与适用范围

当前目标和写入范围已明确。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 复盘与沉淀 → 经验已经确认，需要整理进项目知识”。填入上述材料。

**S1｜核对知识归属**

当前 Agent 按[知识维护约定](../../../../../project-source/defaults/docs/knowledge/README.md)读取最近主题索引和已有条目，判断更新或合并到唯一正文。

**S2｜整理可复用解释**

使用 [technical-documentation-writing-godot](../../../../../project-source/skills/technical-documentation-writing-godot/SKILL.md) 整理 docs/knowledge/ 中 S1 选定的条目及最近索引，写场景、做法、原因、边界与原始依据链接。

**S3｜交付文档变化**

检查链接和语义，按项目规则提交；局部事件经过仍留原 notes，不复制整段历史。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 已有相关条目已列出，确定是更新、合并还是新建 |
| S2 | 条目写明场景、做法、原因、适用边界并链接原始证据 |
| S3 | 链接检查结果和提交哈希 |

## 资源与文件影响

相关知识条目与索引修改，原始记录只读。

## 阻塞、异常与范围变化

证据不足的经验保留假设身份；跨项目规则或 Skill 修改需其实际授权，不能从本场景推导。

## 完成状态与验证标准

已确认经验写入 S1 选定的知识条目，索引和证据链接有效。
