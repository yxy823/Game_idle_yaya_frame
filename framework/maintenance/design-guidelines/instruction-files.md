# 规则、Skill 与提示词文件的维护

[职责设计准则](README.md)

维护 AGENTS、Skill、任务提示词及条件引用时，读取当前正文与必要调用方，按实际变化核对以下内容。编写方法参考 [OpenAI 的 Astra 指令设计建议](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)，并以本仓库已确认的边界为准。

- **内容归属与去重**：AGENTS.md 只保留代码和配置无法推断的约束；任务提示词补充本次目标、输入与特有约束。定义、条件与例外集中在所属规范，流程与测试规则以权威规范为唯一正文；其他入口只保留准确引用和必要提醒，已有 README 或工具配置负责的内容不重复展开，同义规则合并。较长或仅供部分任务使用的资料按条件引用，普通参考不必包装成 Skill。
- **触发与按需阅读**：Skill 的 description 简短说明职责和具体适用任务，必要时注明易混淆的排除项，不堆砌关键词或用宽泛领域强制触发。引用资料时写明适用任务或条件，核对直接调用、续接和跳过上游准备时仍能找到必要约束；复用仍有效的上下文，不把固定文档组、通读目录或全仓地图设为每轮任务的前置。框架与生成项目分别使用各自有效路径。
- **流程粒度**：写清必要依赖，保留 Agent 对普通实现细节的判断；不照搬逐动作配方，不设置无依据的提问轮数、产物数量或逐阶段发言要求。
- **授权与完成**：按本次授权定义完成标准，覆盖适用的实现、必要验证与交付；已有具体授权按[会话延续约定](../maintenance-and-sync.md#授权在后续对话中的延续)跨 Skill、阶段和后续口语请求沿用。Skill 返回或局部步骤完成不结束已授权工作；授权范围完成、必要前置受阻、缺少决定、范围实质变化或用户要求暂停时停止。只读、只讨论、暂停、人工验收和提交条件仍有效，静态检查和实现授权都不替代实际运行或人工验收。
- **阻塞可解释**：指令确实导致暂停或改变方向时，指出具体文件、条款与当前缺口；先核对适用范围和已有授权，不因推测的风险追加确认。
- **Skill 格式与元数据**：`SKILL.md` 保留 `name`、`description`；界面名称和短描述由 `agents/openai.yaml` 的 `interface` 保存，不能替代正文。维护时保留未获准调整的调用策略和无关配置。
- **格式或产品行为变化**：按当前 Codex 官方资料及可用的 `skill-creator` 核对字段和格式；普通改字不必重复查证。格式、路径、已加载后的行为与客户端实际选择分别验证，不互相冒充。

表达与排版沿用[框架文档编写 Skill](../../../.agents/skills/technical-documentation-writing-yaya/SKILL.md)。模型或工作方式变化后，按真实误触发、冲突、等待和重复工作检查相关指令，不因个别现象叠加普遍规则。

框架范围、验证地点与提交沿用根规则；具体反馈、排错、方案判断和交接直接按本次任务及对应场景处理，不再为通用做事方法增加框架 Skill。
