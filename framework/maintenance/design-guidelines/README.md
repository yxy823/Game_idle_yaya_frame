## 适用范围与判断原则

框架的适用范围以根 AGENTS.md 与[使用范围](../../README.md#使用范围)为准；评价时不为范围外的需求扩展能力，也不把规划或规格写成已有的素材制作能力。

评价对象包括框架及生成项目的文档产物契约、维护命令、项目自研工具和它们的共享实现、框架自用或分发的 Skill，以及预设提示词库和对应场景。第三方原始实现与测试夹具必须与生产入口区分；审核接入和调用关系时可以读取，不把未审查的上游实现写成通过。

先确认入口、目标、必要输入、允许的副作用、输出和完成条件，再判断职责是否独立。一个目标可以包含多个步骤、多个相关文件和多条验收条件。“有多个”是调查线索，不能直接作为拆分结论。

评价比较保留、收窄、改名、拆分、提取共享方法、合并和删除的实际效果。不计算总分，不设置“命中若干项就拆”的阈值，不以文件长度、数量或方法数量作为单独依据，也不增加 Agent 动作监督、重复状态或新的开发完成门槛。

## 维护与应用

新增对象或实质改变职责时，按对应维度判断并核对调用方、源规范、复制映射、说明和相关验证；普通局部修改不触发无关全量审核。根据真实误触发、职责冲突或维护成本修订相应条款与正反例，同时核对受影响引用；避免仅为单个异常叠加全局限制，也不增加独立规则版本号、评分或自动审批流程。
