# 框架验证范围

[框架维护](../README.md) · [测试与夹具](../../tests/README.md#按需检查) · [创建器契约](../../godot-project-manual/foundations/framework-and-project.md#创建器用法)

本页说明修改框架后要做哪些验证，以及每一层验证能证明什么。

`project-source/` 是尚未初始化的分发材料：带有最小入口 `main/main.tscn`，但没有游戏玩法、本机配置、业务需求或已完成的任务，也不在这里启动 Godot。框架是否可用，要靠两方面共同证明：静态检查源材料，以及在独立项目中真实运行。

## 按修改选择验证范围

| 修改 | 相称检查 |
| --- | --- |
| Markdown、目录与导航 | 对照源材料核对修改涉及的事实与示例、链接、锚点和导航；保留两册独立阅读边界 |
| 提示词或场景 | JSON/名称/路径检查与对应正文自查；不将其写成已逐条执行 |
| 创建器或清单 | 映射、边界及按需创建器回归 |
| Python 项目工具 | 相关实现与调用静态核对，指定外部项目中的工具回归 |
| Godot 代码、插件、场景或资源 | 按实际影响在指定外部项目运行真实引擎验证 |
| 仅静态或只读请求 | 不生成项目、不启动 Godot、不运行测试 |

注意事项：

- **仓库回归**：文档指纹和人工验收的用例使用临时 Git 夹具，不创建业务项目，也不能代替真实的人工体验。
- **外部项目工具回归**：入口不会替用户创建或更新项目，也不启动引擎。
- **复用结果**：已有结果只在内容和覆盖范围仍然对应时才能复用；没执行的部分如实说明。
- **复制范围**：确认手册等维护材料没有进入复制清单时，静态展开清单即可，不需要创建真实的游戏项目。
- **关系图**：静态核对图的源文件，不等于检查了渲染或视觉效果。
- **不回灌**：外部测试项目的机器路径、主场景、台账与历史，不写回框架的默认文件。

## 分层验证

| 层次 | 要检查的结果 | 证据与限制 |
| --- | --- | --- |
| 源材料与分发 | 清单可展开；相对引用、JSON/TOML、Skill 元数据、Prompt 路由及文档链接一致；默认配置不包含就绪结论；GDD 目录和 Product 只保留用途说明，Feature/Registry 无业务条目 | 静态核对及创建器回归；不代表引擎或 Agent 已执行 |
| 项目工具 | 在指定外部项目调用既有工具回归，验证输入拒绝、任务规划/演进、测试选择、证据、人工记录及文档指纹 | unittest 是工具契约验证；合成夹具不是实际游戏或人工体验 |
| 新项目初始化 | 从正式复制清单创建全新外部目录；核实工具版本、环境检查通过、正常导入与随带最小入口；按授权实际启动 | 保留实际命令、退出码、配置与初始化报告；就绪检查、入口存在、启动成功和测试通过分别判断 |
| 真实 Godot 行为 | 导入真实资源；解析、lint、gdUnit、独立入口及消费场景实际运行；按本次变化检查保存、重载、取消、音频和生命周期 | 原始引擎/JUnit/诊断、可选截图与运行观察；画面和声音的人工接受单独记录 |
| 工作流与迁移 | 对一个明确的小任务，实际经过需求、规划、开发/维护、验证、记录和续接；再在新路径从无缓存副本核对启动与资源引用 | 标明实际执行的 Skill/脚本和未经过分支；不能据一次样例宣称全部 Skill、所有提示词及所有平台已验证 |

每次按改动选择需要的层次；纯文档修改不需要建立游戏项目。

- **命令入口**：见 [维护命令的按需检查](../../tests/README.md#按需检查)；外部项目夹具见下文[外部项目夹具](#外部项目夹具)。
- **流程入口**：[想用一个小任务实际验证框架流程](<../../prompt-scenarios/scenarios/Yaya 框架维护/维护与复盘/想用一个小任务实际验证框架流程.md>)。
- **证据区分**：格式检查、脚本测试和一次真实委派是三种不同证据。
- **未验证项**：reviewer/researcher 的客户端加载与独立实例执行没有实测时，必须明确保留该缺口。

## 测试载体与文件归属

按验证目标选择载体：

- **复制、首次初始化或干净重建**：按授权从当前源材料创建全新外部项目，避免缓存或旧文件遮住遗漏。
- **工具回归或局部集成**：使用明确指定的既有外部项目，核对被测文件对应本次修复；不为普通回归重新创建项目。

测试项目独立拥有文件，只在本次授权内修正具体文件，不增加自动同步或升级机制。

| 文件类别 | 保留位置 | 是否回到分发材料 |
| --- | --- | --- |
| 最小入口与共同骨架、框架通用代码、必要第三方依赖和明确提供的 `example_*` 素材 | `project-source/` | 属于正式分发源，通过清单复制 |
| Godot 为这些源文件生成的可移植 `.gd.uid`、素材 `.import` | 经目标版本核验后随对应源文件保留 | 可以，范围限定在本次正式分发文件；不复制 `.godot` 缓存 |
| 回归套件、截图驱动、合成任务与测试资源 | `framework/tests/` 的维护夹具，以及外部项目 `tests/` | 不进入 `project-source/` 或复制清单 |
| 测试项目名称/主场景、本机工具配置、GDD、Product、Feature、测试登记表、Git 历史 | 外部测试项目 | 不回灌；分发默认文件不夹带该项目的业务条目或就绪结论 |
| 导入缓存、引擎日志、JUnit、截图、测试运行证据 | 外部项目 `.godot/`、`reports/` | 不回灌；维护报告只链接和总结事实 |

使用已有项目作为载体时：

- **不能用创建器覆盖**：创建器只接受不存在或空的目标目录。已初始化的项目可以在明确的范围内用于集成验证，但已有的 `project.godot`、机器配置和业务文件，要按接入或迁移的范围逐项合并。
- **设计来源**：新项目可以导入已有的 GDD，也可以在获准范围内用 `design-gdd` 形成设计；依赖设计的实施要等当前范围的设计明确后再做。
- **小任务验证**：该入口限定使用已有的 GDD，不会扩大为从零创作或修改验证项目的游戏目标。
- **维护夹具不是游戏项目**：维护层的中立工具夹具只用于测试工具本身。

## 一次有意义的流程抽样

执行入口见[小任务验证场景](<../../prompt-scenarios/scenarios/Yaya 框架维护/维护与复盘/想用一个小任务实际验证框架流程.md>)。本节只限定证据含义：

- **回归不等于走过流程**：对已有实现做保存、使用和试调的回归，只说明本轮实际运行的行为，不说明重新经历了需求、规划和开发。
- **补录不是当时的证据**：事后补写的文档不能证明当时做过需求讨论或 TDD；一个样例也不能说明所有 Skill 和提示词都执行过。
- **人工验收不可替代**：涉及观感、音色和手感的 AC 仍要实际人工验收。

迁移检查：把项目复制到另一条干净的路径（没有 `.godot` 缓存、没有已初始化的数据），重新导入、加载资源并启动入口。为避免外层 Godot 扫描到重复的全局类，可以把这个副本放在指定测试项目中已被 `.gdignore` 排除的报告区里。这只证明本次版本在所测的 Windows、Godot 版本和路径下可以重建；换一台机器仍要重新配置工具路径并验证。
