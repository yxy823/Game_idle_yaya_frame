## 发现与闭环

| 问题 | 修正后的核对结果 |
| --- | --- |
| 原正文未统一显式字段，部分执行策略混入验证，环境要求埋在约束中 | 8 个固定字段逐条具备实际内容；实施取舍、实际 CLI 与执行位置、数据兼容、性能和续接记录在触发时单列，未用空字段占位。 |
| 续接、报告丢失、性能定位、临时观测和文实冲突调查中，受阻或仅记录缺口可能被写成目标完成 | 完成条件与停止、异常分开；定位须有足够证据，临时信号须实际取得。明确暂停、交接材料或检查报告本身是目标的场景，可以完成该局部目标，但不冒充原 Feature 完成。 |
| 只读或验证页尾的通用继续语句可能覆盖当前明确收窄 | 当前明确只调查、只检查、暂停等限制优先；属于完整授权任务的内部步骤结束后仍按所属流程推进，不增加普遍等待或重复确认。 |
| 不保留旧存档的场景误加无损转换要求，保留旧数据的场景未体现已批准的损失范围 | 前者按当前结构读写与失败处理验证，不增旧版本迁移义务；后者按已确认保留字段和允许损失验证转换，并保护原始数据。 |
| 实际运行器的合法 `not_required` 与缺报告、测试通过未充分区分 | 自动测试及三项证据恢复入口区分实际运行器判定、无 Godot 运行和无报告的分支；不伪造报告，不向 `record-tests` 导入不存在的原件，不把它记作自动测试通过。既有失败或中断仍按规范处理。 |
| CLI 和人工验收参数容易在归纳时失真 | 保留 `--target` 与 `--feature` 互斥、同次多个 `--run`、测试引用整组替换及失败清空当前引用的语义；保留人工结果文件与 `--status` 互斥、`accepted/rejected`、原清单及结果绑定。`show` 仅显示实际记录。 |
| 只读经验总结入口误写为已确定“写入范围” | 场景入口改为已结束阶段和可读材料，不由总结请求推导写入知识、规则或脚本的授权。 |
| 框架替换的数据保留段与新增兼容性段重复 | 最终完整保留段只位于兼容性要求；约束仍保留一次本地提交等特有要求。原件保护、混合文件判断、有限无损适配及严重冲突停止未丢失。 |
| 本地化规格归属、暂停与跨对话恢复记录不够明确 | 规格明确归 `docs/localization/localization-spec.md`；后续记录使用既有 Progress、报告或任务记录，不新增重复台账，不自行创建对话或发送消息。 |

Bug 的特有不提交约束在交付前、交付后两条中均保留：实际人工验收与适用验证满足之前，不以计划、检查点或阶段切换为理由创建本地提交。两条分别沿用未交付 Feature 与独立 Bug 诊断路线，不能互相替代。
