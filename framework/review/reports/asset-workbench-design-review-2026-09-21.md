# 美术与音频工作台设计适配审核

日期：2026-09-21。对象：用户在本次会话提供的《Godot 美术与音频资源预览、分析与调试工作台实现规范》40 节。
框架检查基线：`7f86f60`；本轮开始时工作区干净。目标技术栈为 Windows / Godot 4.7 / GDScript，现有配置预填 Godot 4.7.1 路径，但环境状态仍需在选定项目核实。
本报告是设计审核和实施范围建议，不代表已采纳全部要求、已开发工作台或已完成独立审核 Agent/引擎运行验证。

## 结论

统一工作台、独立资源模式、事件组合预览、试调与正式保存分离，以及回正式场景验证，都与当前框架适配。
建议保留该方向，收缩首期范围；先补齐预览隔离、保存契约和音频控制语义，再在指定实际项目实现一个代表性事件。
专业分析和批量能力作为后续按需扩展，不能由总流程图变成每次接入资源的必经步骤。

当前框架提供专业规格、资源准备与接入、独立原型、验证和审核的方法，但没有工作台、通用游戏对象/事件模型或音频运行系统。
因此这是一项新的项目开发工具能力，不能仅通过新增 Skill 宣称完成。框架可在试点后沉淀必要方法和可复用代码；具体项目独立拥有其副本，不回查框架。

## 实施前需要补齐的关键问题

### 1. 明确开发工具形态与运行隔离（第 3、5、7、25、27、32 节）

建议首期定位为项目内可单独启动的 Godot 开发场景。只有确实需要 Inspector、编辑器撤销或导入集成时，再增加相应 EditorPlugin 入口。
两种形态的写回、生命周期和暂停语义不同，不能先按一个模糊的“平台”开发，最后才决定。

加载真实对象可能执行 `_ready()`、Autoload、存档、掉落或网络行为。预览应复用真实表现组件和数据，以受控输入触发；不调用会修改真实业务状态的完整游戏事件。
没有可复用表现入口时，首期只为试点对象补最小入口，不建设通用 Object/State/Event 执行引擎。尚未实现的逻辑使用明确的样例状态。
工作台、分析工具和仅供预览的启动配置应与正式导出分开；正式游戏确实依赖的播放代码和资源则保留。

这延续了现有原型规范中“独立入口、隔离业务与 Autoload 副作用”的要求，并不意味着维护另一套视觉/音频实现。

### 2. 试调隔离与保存需要可验证契约（第 25、26 节）

Godot 会缓存并共享按路径加载的 Resource；复制对象并不保证所有外部材质、动画、音频子资源已经独立。
试调要明确哪些参数是局部覆盖、哪些资源保持共享，遵循 [现有复制规则](../../../project-source/agent-rules/21-resources/duplication-and-runtime-state.md)，不能一律 `duplicate(true)` 后宣称安全。[Godot 4.7 Resource](https://docs.godotengine.org/en/4.7/classes/class_resource.html)

首期选定一个真实保存目标，而非同时支持 Event、Object、共享资源、Variant、Preset 五种完整写回方式。保存应说明目标与影响，支持放弃/恢复试调，保留保存失败时的待保存状态。
保存前核对目标是否在试调期间被其他编辑修改；遇到冲突不静默覆盖。保存后重新加载，核对数值、引用、类型及正式场景消费结果。
新增正式 Resource 的 UID 持久化按现有编辑器/导入规则核验；运行实例的变化、保存返回成功与完整持久化是不同事实。

工作台写回属于开发期 authoring；不能据此允许导出的游戏依赖修改 `res://` 中的仓库定义文件。

### 3. 音频插件可优先采用，但能力与集成方式须限定（第 8、9、21、23、39 节）

本次核对了 `v2.6.2`（`fd96cad9d7939044fe59b00b8f8a1e7e758e7876`）和后续提交 `1c041582db806a0d0edad77111d1fb7a009346ef`。
标签发布于 2024-04-18；所查提交历史在 2026-03-29 包含 Godot 4.6 更新与池状态修复。
标签及所查 main 的 `plugin.cfg` 都仍写 2.6.2，因此仅记录这个版本字段不足以固定代码。
维护迹象与 README 的兼容声明不能代替本项目 Godot 4.7.1 实测。[标签](https://github.com/nathanhoad/godot_sound_manager/tags)、[提交历史](https://github.com/nathanhoad/godot_sound_manager/commits/main/)、[标签配置](https://raw.githubusercontent.com/nathanhoad/godot_sound_manager/v2.6.2/addons/sound_manager/plugin.cfg)、[所查 main 配置](https://raw.githubusercontent.com/nathanhoad/godot_sound_manager/main/addons/sound_manager/plugin.cfg)

下列事实以 `1c041582db806a0d0edad77111d1fb7a009346ef` 源码为依据；没有安装或运行该插件：

| 已核实事实 | 对工作台的影响 |
| --- | --- |
| 音效、UI、环境声、音乐各有入口；音乐入口包含交叉淡化，公开的 pause/resume 主要针对音乐 | 不把概念上的统一 `pause()` 等同于插件对所有类别已有相同语义；按首期需求提供控制并验证 |
| 分类 `set_*_volume` 修改 AudioServer 总线音量；播放接口返回 AudioStreamPlayer | 单个事件的音量不能直接映射为分类总线音量，否则会影响同总线其他声音；区分单次播放增益、分类增益与监听音量 |
| 播放池创建 AudioStreamPlayer，池空时可增加播放器 | 它提供非空间音频池；不能宣称已经覆盖 2D/3D 位置与衰减，也不能把初始池大小当同时发声上限 |
| 插件启用注册 SoundManager Autoload；管理器还注册引擎 singleton | 与项目已有音频服务核对名称、生命周期、暂停及退出清理；不要同时引入互不知情的两套管理器 |

依据：[管理器源码](https://github.com/nathanhoad/godot_sound_manager/blob/1c041582db806a0d0edad77111d1fb7a009346ef/addons/sound_manager/sound_manager.gd)、[播放器池](https://github.com/nathanhoad/godot_sound_manager/blob/1c041582db806a0d0edad77111d1fb7a009346ef/addons/sound_manager/abstract_audio_player_pool.gd)、[插件入口](https://github.com/nathanhoad/godot_sound_manager/blob/1c041582db806a0d0edad77111d1fb7a009346ef/addons/sound_manager/plugin.gd)。

建议保留“优先 godot_sound_manager”：在缺少等价播放能力时，核实后锁定具体提交接入；已有合适项目音频系统时优先复用。
首期用一个薄播放封装隔离插件即可，不同时强制 Service、Adapter、抽象基类三套层级。播放操作及停止、调参的目标要能识别“本次播放”，避免旧播放器引用在池复用后控制了另一次声音；不要求为此创建庞大的句柄框架。
空间声、声音优先级或并发限制有实际需求时再补，不能假定插件已经实现。现有 GDScript 栈无需因为插件附带 C# 包装而切换 .NET；分发仍保留 MIT 许可。

### 4. 共享上下文需要区分浏览与绑定（第 6 节）

共享当前对象、事件、候选和必要筛选条件是合适的，但普通资源浏览不能意外替换正在调试的事件。
从某个事件的声音槽打开选择器时，候选切换可立即更新该槽的预览；独立浏览/试听只改变浏览选择。取消选择恢复原预览，应用候选仍不等于正式保存。
这样保留快速联动，也让“选中了什么”和“写到了哪里”可解释。

### 5. 重播与 A/B 比较必须能恢复同一条件（第 22—24 节）

补充重置、停止全部预览、退出清理及延迟回调取消；切换事件或候选后，上一次动画、VFX、声音、定时触发不得继续污染当前比较。
沿用 [异步有效期规则](../../../project-source/agent-rules/10-gdscript/godot-lifecycle-and-input.md#signals-and-async)，不把“节点仍有效”当作结果仍属于当前操作。
随机效果在比较时保持可复现的条件；分别支持真实间隔与有意快速触发，后者是探查边界，不能直接冒充真实玩法复现。
音频 A/B 明确是否使用相同监听条件、是否为比较临时匹配响度；保留原始增益，避免为了比较改写素材。
时序参数说明单位及相对哪个事件/动画标记；普通界面调度不能默认承诺采样级精确同步。

### 6. 分析结果还缺“测的是什么”和“不知道”（第 12—17、30 节）

现有结果字段可作为概念起点，实施时按实际指标补足以下语义：

| 信息 | 必要性 |
| --- | --- |
| 输入对象与测量阶段 | 原始文件、Godot 导入结果、显示截图、播放器/总线输出各不相同；离线源文件分析不能证明最终混音或屏幕表现 |
| 方法、参数、单位与范围 | 响度/峰值需说明采用的度量、时间段、声道等；颜色/亮度需说明色彩空间、透明像素及区域处理。不同定义不能直接比较 |
| 每项指标的适用/可用状态 | 区分有效结果、不适用、缺数据、失败和未运行；爆炸声没有稳定基频不能记为 0 Hz，未分析不能显示为规范通过 |
| 规则来源与适用范围 | 规则检查引用已确认的 Art/Sound Bible、资源规格或项目规则；不要让新 Profile 成为第二份要求权威 |
| 输入版本与算法版本 | 慢任务和缓存必须对应实际输入、算法和参数；涉及导入、场景或总线时也纳入相关变化，避免源文件没变便复用错误结论 |

“客观测量”应表述为“按明确方法得到的测量或估计”。光照方向、复杂度、描边与音色等结果可能依赖假设或模型，应给出适用条件与必要不确定性；不存在统一的自动真值。
算法返回可计算不表示指标对当前任务有用，首期也不需要先定全量 JSON Schema 或实现通用规则引擎。

### 7. 后台分析应可失败、取消和丢弃过期结果（第 28—30 节）

保留慢任务不阻塞交互的要求，但不要把所有解码、Resource 或渲染操作直接丢到线程。
活动 SceneTree 与共享可变 Resource 有明确线程限制；外部分析以必要输入/输出跨边界，UI 回主线程更新。[Godot 4.7 线程安全说明](https://docs.godotengine.org/en/4.7/tutorials/performance/thread_safe_apis.html)
切换资源、重新分析和关闭工作台时，应取消或忽略旧任务；设置符合工作量的超时和并发范围，失败不妨碍仍可用的预览。
首个高成本 Analyzer 出现后再做对应缓存；缓存可删除重建。不要预置数据库、常驻服务、统一进程调度平台或无需求的历史系统。

### 8. 资源管理、规则检查和阶段范围需要收缩（第 1、7、18、31—40 节）

资源浏览优先用现有目录、文件身份、导入信息和清单。首期只暴露当前候选，已有标签可读取；没有明确检索问题时不新建标签库、资产登记表或关系图系统。
规则自动检查限于可执行且有已确认来源的条件，不能从风格描述自动发明阈值，也不能将辅助分析结果直接写回规格。
采用工作台与否由当前任务的收益决定；单纯替换已明确资源不必走完整浏览—分析—比较链。

“Godot 4.7+”应改为“目标项目确认的具体 Godot 4.7.x；依赖固定版本或提交”。兼容未来版本属于以后验证，避免扩大现有框架技术边界。
可替换性表示隔离外部格式与 API，不能保证任意底层替换都无需修改接口或调用者；先定义当前真实语义，避免为了未来替换提前抽象。

## 建议的首期范围与验收

先在用户指定的实际项目内，选择已有且能安全独立触发表现的对象与事件；不在本维护仓库开发示例游戏，也不先建设完整通用平台。

| 首期范围 | 可观察的完成条件 |
| --- | --- |
| 项目内开发入口与一个代表性事件 | 能独立启动，使用真实/代表性资源，预览不改变真实存档或业务状态 |
| 单项查看/试听与事件内候选切换 | 从事件槽进入候选后立即预览；取消可恢复，独立浏览不误改绑定 |
| 必要视觉/音频参数与时序 | 所改数值对应实际表现，音量单位和控制范围明确；无需求参数不暴露 |
| 重播、重复触发与 A/B | 能恢复比较初态；停止、切换、退出后没有遗留声音、特效或过期回调 |
| 一个正式写回目标 | 试调不污染共享资源；保存失败可见；保存后重新加载与正式游戏使用一致，无需手抄 |
| 适用验证与人工体验 | 验证实际受影响行为，并取得对应观察；工作台能启动、自动分析通过与正式功能接受分别记录 |

基础尺寸、时长等廉价信息可随首期提供；专业 Analyzer 不作为前置。
第二阶段只解决已观察到的问题，例如同类 UI 声音音量比较或图片透明留白/显示尺度；第三阶段再按实际规模考虑批量与一致性分析。
首期不要求通用时间轴、统一事件引擎、资产数据库或多个可替换后端；也不建立新的 Skill/Agent/验收状态机来包装尚未实现的工具。

后续若采纳并回灌框架，再按影响同步原型规范、专业工作与资源接入说明、复制清单（仅有可复用产物时）、advisor 场景及相关提示词。
正式专业要求仍由现有所属 Skill 维护，分析原始输出和观察沿用项目 reports / notes / Progress；获准参数直接保存到正式消费方。
