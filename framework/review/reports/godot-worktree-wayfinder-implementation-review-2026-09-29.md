实施前基线为 `fa7dda66f4cf97541870acce0007210fcd311376`。澄清入口改名已在 `858382effb398d3a6eca3769345c2fb5019befc4` 提交；本报告覆盖该改名及随后新增入口的最终材料。原[拟改报告](godot-worktree-wayfinder-skill-proposal-2026-09-29.md)作为讨论历史保留。

三份新 Skill 各自配有 `agents/openai.yaml`，沿用默认隐式调用策略，没有添加禁用调用字段。元数据有效不证明客户端已经自动选中入口。项目 Skill 整包分发的原复制映射继续适用；没有增加框架版、PR 工作流、独立冲突 Skill 或外部游戏项目同步。

Git 规则、人工验收、Feature 完成和记录仍归原规范。尤其两个 Bug 入口所需的实际人工验收与明确提交许可必须分别满足；创建、搬运、整合或修冲突都不能用中间提交绕过条件。采用成果不自动授权清理来源目录或分支。

## 3. 独立审核与修正

入口作者之外的 Agent 分别审核了 worktree 方法、wayfinder 方法、4 条提示词及其场景，以及 9 个公共路由和手册文件。以下是对最终材料的静态情境推演，不是执行这些操作后的测试结果。

| 情境 | 入口、允许动作与停点 |
| --- | --- |
| Bug 尚未验收，已有未提交修改，要求另开目录比较方案 | 创建入口核对基准与获准带入的本地内容，保护原目录和暂存状态；不能为搬运创建提交。运行缺口与 Git 检出结果分别报告，已有实验授权继续有效。 |
| 已有 worktree 可能共享 `user://`，只要求运行 gdUnit | 由验证入口直接按条件读取共享运行参考，检查测试写入与清理目的地；不要求再创建目录，串行运行也不等于数据互不影响。 |
| Git 没有文本冲突，但目标资源关系改变，来源只有旧 PASS | 整合入口核对场景、资源和真实依赖；原 PASS 不能替代组合版本所需的证据，仍有效的检查可以复用。 |
| 接手已经发生冲突的整合，其中包含未知业务取舍 | 识别当前操作、已有人工处理和双方意图；解决不依赖该取舍的部分，仅向用户询问影响结果的选择，不擅自启动另一次整合或替用户发明行为。 |
| 只读比较两个分支的脚本 | 保持只读，不因比较请求创建 worktree、启动引擎或进行运行准备。 |
| 只问当前 Feature 状态与下一入口 | advisor 解释事实和路线，不启动 wayfinder 探索。 |
| 容量、搜索与性能相互影响，用户只想讨论 | wayfinder 按依赖讨论并调查所需事实，不写原型、创建目录或新增记录；交付结论与真实缺口。 |
| 已授权列表和网格原型，当前目录可分别保留两份场景 | 使用限定原型入口；多个备选本身不要求 worktree，观察结果也不代替采用决定或人工验收。 |
| 已授权 Feature 实现的唯一疑问得到答复 | 返回原执行入口继续实现和适用验证，不再统一索取确认，不把问题解决当作 Feature 完成。 |

审核发现一处接入缺口：仅经过环境或验证 Skill 的已有 worktree，原先可能绕过运行准备参考。现已在这两个入口补上条件引用：相关写入或清理目的地未知、变化时读取，复用仍有效的准备，不触发创建 Skill，也不扩大限定检查范围。依据包括现有 gdUnit4 的 `user://tmp` 及套件收尾清理行为。独立复核最终路由后未发现必须修改的问题。

提示词与场景审核覆盖 8 个固定字段、名称和分类对应、37 个本地链接、授权与 Bug 特例，以及方法返回后的继续职责；最终 9 份公共接入文件也通过了职责和边界审核。
