Skill 审核者还独立核对了本轮职责准则及相关入口修改，未发现阻塞落盘的问题：没有按多阶段机械拆分，旧“一提示词多场景”现行规则已替换，目标目录与未迁移样稿明确区分。具体实现仍以各专项报告的证据和限制为准。

## 专项建议汇总

| 范围 | 子智能体建议 | 原始依据 |
| --- | --- | --- |
| Skill 的独立产物 | 从 Product 编写拆出纯术语维护；分开本地化规格与运行接入。保留共同提问方法及职责明确的执行编排 | Skill 报告 S1、S2 及横向比较 |
| Skill 的触发边界 | 收窄澄清入口与 Product elicitor 的 Bug 触发，避免把已明确的术语写入或纯实现缺陷引入需求重写 | Skill 报告 S3、S4 |
| 单人范围 | 将已确认范围贯彻到可复制 Git 规则、工程计划、advisor 和相关提示词；保留普通差异检查、内容保护与有效授权 | Skill 报告 S5；提示词报告关键问题 4 |
| 工具职责 | 收窄 `show` 的成功条件，整项完成判定保留给 `validate`；调整快照与通用写入的模块归属，统一重复的源格式与可比身份规则 | 脚本报告 S1–S4；提示词报告关键问题 3 |
| 提示词与场景 | 先拆清不同目标和授权／产物，再统一 JSON 名称和场景路径；修正动态审核提示词中旧创建器职责措辞 | 提示词报告逐项判断与关键问题 1、2、5、6 |
| HTML 工具 | 继续保留并暂缓；重新引入阅读版前适配书籍输入和目录 | 脚本报告 S5 |

两份专项独立指出 `show` 与样稿表达存在冲突，后续作为同一问题处理，不重复建两套修复。Skill 和脚本允许共享职责明确的方法；提示词与场景的一对一关系不能被推广成“每篇场景复制一个 Skill 或脚本”。

## 当前场景迁移缺口

提示词报告核对现有 50 条入口对应的新路径，精确匹配为 0；8 篇样稿都仍在旧目录，标题与所引用的旧提示词名称匹配为 0，且有两组复用。它们是新契约尚未迁移的事实，不是本轮修改导致的执行故障。

重构后的提示词数量会随职责拆分而变化，不能按现有 50 条直接生成空页面。后续先以八篇样稿验证专用提示词和三层同名路径，再迁移全部入口及补充场景；仍覆盖常见流程、环境和证据恢复，素材制作保持待扩展。打包与发布是否纳入仍待决定。
