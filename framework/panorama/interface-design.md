# 框架全景的界面设计

[框架全景](README.md)

本文写框架全景的界面约定：新增模块或控件时长什么样、放在哪里、为什么这样做。颜色、圆角、尺寸和层级的取值只写在 [src/styles.css](src/styles.css) 开头 `:root` 的 CSS 变量里，本文只写变量名和用途；两处不一致时，按缺陷报告给用户，不自行选一边。

## 风格方向

框架全景是给一位使用者在本机查资料的桌面工具，所以按“信息优先、位置稳定、可以信任”来设计：紧凑、扁平、对称，几乎不用动效。

- **沿用熟悉的工具**：布局和交互照 VSCode：左侧活动栏切换模块，右侧详情面板显示选中对象，顶栏放搜索。详情面板照 draw.io 的属性面板。不自创交互，因为使用者已经熟悉这些工具的位置和快捷键。
- **本地单文件**：页面是一个 HTML 文件，用 Edge 直接打开，不需要服务器和网络。
- **用 Node 构建**：构建脚本读取文档、渲染 Markdown，生成页面；第三方库用 npm 安装并固定版本，页面不从网络加载脚本、字体和样式。
- **React 加 Vite**：界面用 React 写，Vite 打包成一个内联全部脚本和样式的 HTML，因为 Edge 直接打开本地文件时会拦住外部的模块脚本。样式写普通 CSS，颜色、尺寸和层级都用本文的 CSS 变量，不用 Tailwind，因为变量已经统一了这些取值，换成 Tailwind 要再映射一遍。
- **排除营销页做法**：不用大留白、大卡片、插画、渐变和装饰性动画，因为这些占掉信息的位置，也让使用者分不清哪里能点。

## 尺寸与对齐

同一种元素在全页只用一个尺寸。尺寸写成 CSS 变量，组件引用变量，不在各处另写像素值，因为各处随手写的像素值会让同类元素差一两个像素。

| 元素 | 尺寸 | 变量 |
| --- | --- | --- |
| 顶栏高度 | 36px | `--bar-h` |
| 控件高度（输入框、按钮、菜单项、属性行的第一行） | 28px | `--control-h` |
| 图标按钮 | 28px 见方 | `--control-h` |
| 活动栏宽度 | 44px | `--activity-w` |
| 详情面板宽度 | 320px | `--panel-w` |
| 图标 | 16px | `--icon` |
| 活动栏图标 | 22px，因为活动栏按钮是 36px 见方，16px 的图标显得太小 | `--icon-activity` |
| 面板左右内边距 | 12px | `--pad` |
| 正文、小节标题（加粗） | 13px | `--fs` |
| 名称、说明等次要文字（`--muted-fg`） | 12px | `--fs-small` |
| 圆角 | 4px | `--radius` |
| 点击区 | 不小于 24px 见方；控件画得更小时用内边距扩大点击区 | — |

对齐规则：

- **左缘对齐**：同一面板里，标题、小节折叠三角和名称列的左缘落在同一条竖线上。
- **垂直居中**：名称与控件的第一行垂直居中；多行内容向下排，名称不跟着居中到整块中间。
- **菜单文字对齐**：普通项、勾选项和单选项的文字左缘对齐。每一项都留一个 16px 宽的标记位，放勾、圆点或空着，因为各类菜单项各写一套内边距时，文字会错开几个像素。
- **长文字**：单行截断加省略号，悬浮提示显示全文。文件路径从中间省略，保留开头和文件名，因为文件名在末尾。没有断点的长串（网址、哈希）用 `overflow-wrap: anywhere` 换行，不出现横向滚动条。
- **说明文字限宽**：模块说明和占位说明最宽 48em，因为一行太长时读到行尾找不回下一行开头。

## 布局

### 位置稳定

这是本页最重要的约定：常驻控件和已有内容的位置不随状态变化，界面不抖动。使用者靠位置记住按钮；控件一移位，下一次点击就会落到别的按钮上。

反例：详情面板的收起按钮放在面板标题行里，面板收起后，展开按钮改到顶栏出现。顶栏因此多出一个按钮，搜索框整体左移；再展开时按钮消失，搜索框又移回去。

- **一个开关一个位置**：展开和收起是同一个按钮，位置固定在顶栏，只换名称和提示。面板里不再放第二个收起按钮；快捷键可以另外保留。
- **不出现、不消失**：常驻控件不因选中对象、内容有无或面板开合而出现或消失；暂时不可用时置灰。
- **状态在原位切换**：开关、加载中、成功等状态在同一个位置换图标或颜色，占的尺寸不变。
- **悬停才显示的控件预留位置**：用透明度或 `visibility` 隐藏，不用 `display: none`，所以悬停时周围内容不移位。
- **选中、悬停不改尺寸**：选中描边和高亮用 `outline` 或 `box-shadow`，不加粗 `border`。元素选取的高亮框也遵守这一条。
- **变化的文字给固定宽度**：计数和状态文字设固定宽度，数字用 `tabular-nums`。
- **滚动条不挤内容**：会出现滚动条的区域用 `scrollbar-gutter: stable`。
- **视口不自己移动**：图谱中使用者拖动或缩放后，视口不自动平移或缩放；只有“定位”这类明确要求移动的操作才移动视口。
- **验证**：开合面板、切换模块、选中对象前后，各量一次常驻控件的坐标，坐标不变才算通过。

### 整体框架

| 区域 | 位置 | 内容 |
| --- | --- | --- |
| 顶栏 | 顶部 | 左侧页面名称；右侧依次是全局搜索框、详情面板开关、设置 |
| 活动栏 | 左侧 | 7 个模块的图标按钮，顺序固定 |
| 主区域 | 中间 | 当前模块 |
| 详情面板 | 右侧 | 选中文件的详情：摘要、大纲、用在哪里、最近修改 |
| 状态栏 | 底部 | 生成时间、元素选取的状态 |

- **顶栏分组**：按用途分组，组间用 1px × 20px 的竖线隔开。页面名称靠左；搜索等独立入口靠右，和右侧的开关、设置放在一起，因为鼠标从搜索框移到这几个按钮的距离最短。
- **详情面板默认展开**：本页的主要用法是“选一个对象，看它在各处的位置”，所以面板默认展开。选中对象不改变面板的开合状态。
- **窄窗口**：主区域不足 480px 时，先收起详情面板。

### 详情面板

用“名称列 + 内容列”的双栏行：

- 名称列固定宽 64px，12px 次要色；内容列第一行高 28px。
- 所有属性行用同一个 `.row` 样式，不在各处单独写对齐，因为行样式不统一时，名称、内容和分隔线会接连对不齐。
- 内容按小节排列，不用标签页切换。每个小节有标题和折叠三角，可以单独收起。
- 没有选中对象时，只显示一行“在主区域选中一个文件”，告诉使用者下一步做什么。
- 关系列表里的文档名用正文色，悬停时才变成 `--brand` 并加下划线，因为一节里常有几十个链接，全用蓝色会连成一片。路径、“第 N 行”这类单个链接仍用 `--brand`。
- 超过 20 条的小节默认收起，标题旁的数字写出条数。

### 卡片

框架全景里每个对象各是一张卡片：文件、Skill、工具、场景和问答。

- **密度**：沿用「尺寸与对齐」的表：13px 字、4px 圆角、内边距 10px、卡片间距 8px。描述最多显示 2 行，全文在详情面板里看。
- **配色**：`--surface` 底、`--border` 边框。悬停时只把边框混入 `--brand`，不加阴影，因为阴影只给菜单这类浮层用；尺寸不变，遵守「位置稳定」。
- **字段**：全部从文档读出：标题取一级标题或 Skill 的 name，描述取第一段或 description，类型按目录判断。不另建卡片数据文件。
- **点击**：点卡片只在详情面板显示它的属性和关系，不跳转页面。

### 图谱

- **选中与退出**：点一个点就选中它，它和直接相连的点突出，其余变淡；点另一个点直接换成它。点空白处不取消选中，因为误点大多落在空白处。退出有三种：按 `Esc`、再点一次已选中的点、点画布左上角的“取消选中”按钮。这个按钮一直在原位，没有选中时置灰。
- **名称**：默认只写一部分点的名称作为路标，最多 15 个：文件全景挑被引用最多的文档，开发场景先挑主线上的场景。选中后，选中的点一定写名称，邻居的名称和已写的重叠就不写，变淡的路标也不写。路标和邻居都按顺序挑，和已写的名称重叠就跳过。写出的名称按缩放反算字号，屏幕上始终是 13px。
- **连线**：文件全景的连线不分方向，两份文档之间只画一条。开发场景的连线带箭头，从场景指向它的下一步；主线用 `--brand` 实线，比其他线粗，其余是分类色虚线。
- **布局**：第一次打开时自动排布，之后切换视图再回来，各点位置不变。
- **分组折叠**：开发场景默认把每个分类折叠成一个大点，写出分类名和场景数，先看分类之间怎样衔接。分类之间的连线合并成一条，线上写条数；其中有主线时画成主线。点分类的大点就展开它；图例每行有折叠开关，另有“全部展开”和“全部折叠”。展开后的场景停在全图布局里的位置，不重新排布，所以展开和折叠时其他点不动。选中的场景在折叠的分类里时（例如从搜索选中），自动展开它所在的分类。
- **邻居视图**：点场景只是选中，不重新排布；要看邻居时点画布左上角的“只看邻居”，图里只留选中场景几跳以内的场景，并重新排布。旁边的“1 跳 / 2 跳”切换默认 2 跳，因为 1 跳的邻居通常只有两三个，详情面板的上一步、下一步已经列全。点“返回全图”、按 `Esc` 或取消选中，回到原来的布局和视口。这几个按钮一直在原位，用不了时置灰。

### 关系与引用段落

卡片之间的关系从文档的 Markdown 链接读出，不另建关系文件：

| 关系 | 从哪里读 |
| --- | --- |
| 下一步 | 场景页「流程关联与衔接关系」末尾的下一步清单，冒号前是条件 |
| 依据 | 问答「依据」一段里的链接 |
| 引用 | 其余所有链接；反过来就是“被引用” |

- **被引用的段落**：详情面板的「被引用」一节列出每个引用它的段落原文，引用处的链接高亮。点高亮的链接跳到来源卡片。点“打开”用 `vscode://file/路径:行号` 在 VSCode 里打开原文件。段落太长时，只显示链接前后各约 150 字，这个字数是初值。
- **问答卡片**：问答主题文件里每个二级标题是一张卡片。详情面板显示结论、为什么、依据和所属主题。“打开问答页”在新标签页打开 `am.mjs` 生成的问答页，并跳到这一条；它在每张问答卡片的右下角和详情面板里都有，主题标题旁的链接打开整个主题页，因为详情面板收起时点卡片看不到变化。
- **文档关系**：节点和关系从 Godot 项目手册的 Mermaid 关系图读出，规则写在 [doc-graph.js](tools/doc-graph.js) 开头：大部分节点写成“名称<br/>路径”的图才算关系图，同名节点合并。节点按路径对应到 `project-source/` 里的模板文件，介绍取模板文件的第一段；没有模板文件的节点写明项目里按需要创建。箭头上的说明只在选中点的连线上写，详情面板按“指向”“来自”列全。
- **学习**：章节顺序从 Godot 项目手册 README 读出，规则写在 [manual.js](tools/manual.js) 开头：先手册首页，再「第一次阅读」的教程，再「全部专题」各组的链接；目录按这些分组排列。正文在构建时转成 HTML，标题锚点和 GitHub 一致，所以手册里的 `#锚点` 链接照常能跳。正文里指向其他章节的链接切换章节并跳到锚点；指向其他文档的链接在详情面板显示那张卡片，不离开正文；外部网址在新标签页打开。
- **数据**：构建时把全部段落写进页面，每段只存一份，链接记下段落编号。不分块加载，因为现在全部正文只有 2.59MB。

## 颜色用途

组件只用下表的语义变量，不写颜色值。浅色和深色两套取值都在 `:root` 里，两套的变量必须一一对应。

| 变量 | 用途 | 不用于 |
| --- | --- | --- |
| `--brand` | 品牌色，全页唯一的强调色；`--primary` 和 `--ring` 取它 | 大面积背景 |
| `--primary` | 每个区域唯一的主要操作；卡片和图谱节点的选中描边；开关打开时的底色 | 普通链接、装饰 |
| `--danger` | 错误提示 | 普通警示 |
| `--fg`、`--muted-fg` | 正文；辅助信息、占位、禁用态 | — |
| `--accent` | 悬停、按下等交互反馈底色 | 静态强调 |
| `--selection` | 目录树和列表里选中行的整行底色，照 VSCode | 卡片（卡片选中用 `--primary` 描边） |
| `--bg`、`--surface` | 主区域和输入框底色；面板底色 | 区分状态 |
| `--chrome` | 顶栏、活动栏、状态栏底色，比主区域深一级 | 主区域 |
| `--border` | 分隔线、装饰性边框 | 强调 |
| `--field-border` | 输入框边框 | 装饰 |
| `--pick`、`--pick-fg` | 元素选取的高亮框和名称标签，标签文字用 `--pick-fg` | 其他用途 |
| `--tip-bg`、`--tip-fg` | 悬浮提示和“已复制”提示的反色底与文字 | 其他用途 |
| `--shadow` | 菜单等浮层的阴影 | 页面内元素 |

- **一个强调色**：全页只用 `--brand` 一个强调色。`--pick` 是例外，因为选取高亮框必须和页面里的选中描边分得开。
- **不用纯黑纯白**：底色和文字不用 `#000`、`#fff`，用略偏灰的近白、近黑，因为纯白底配近黑字在大屏上刺眼。阴影按底色调色，不用纯黑阴影压在浅色底上。
- **对比度**：正文和次要文字对所在底色至少 4.5:1；输入框边框、开关底色对相邻底色至少 3:1。改颜色后按 WCAG 公式重算这几组：次要文字对 `--surface`、`--chrome`、`--accent`；`--field-border` 对 `--chrome` 和 `--bg`；`--pick-fg` 对 `--pick`。浅色和深色两套都要算。
- **主题**：默认跟随系统，设置里可以改成固定浅色或深色。
- **图谱分组色**：分组是分类信息，所以是「一个强调色」的第二个例外。13 种颜色取自 Tableau 分类色板，写成 `--p1` 到 `--p13`，两套主题共用。文件全景的分组用 `--g-分组` 变量取色，分组和路径的对应写在 [read-docs.js](tools/read-docs.js) 开头；开发场景的分类按目录顺序取 `--pN`。每个分组在图例里都写出名称和数量，不只靠颜色区分。

## 层级

浮层的上下顺序只用下面的变量，不在组件里写数字，因为各处随手写的数字迟早会让提示被菜单盖住。

| 变量 | 浮层 |
| --- | --- |
| `--z-menu` | 设置菜单 |
| `--z-tip` | 悬浮提示 |
| `--z-pick` | 元素选取的高亮框和名称标签 |
| `--z-toast` | “已复制”提示 |

## 组件约定

### 图标与按钮

- **图标优先**：顶栏和活动栏的命令只显示图标，名称写在 `aria-label` 和悬浮提示里。
- **保留文字的按钮**：对话框的确认和取消、首页的主要入口，以及图标表达不清的命令。
- **图标来源**：只用 npm 包 `@tabler/icons-react` 的线条图标（outline），不手画图标，也不混用别的图标库，因为不同来源的线宽和圆角对不齐。这个包含有全部图标，缺图标时直接引入，不另外下载。
- **图标写法**：写成 `<IconSettings aria-hidden="true" />`，图标用 `currentColor`，所以能跟着主题换颜色。尺寸和线宽由 `svg.tabler-icon` 样式统一定为 16px 和 1.5，不在组件上另传 `size`、`stroke`。
- **按钮分级**：每个区域最多一个用 `--primary` 的按钮；其余用无边框的图标按钮或普通按钮。
- **禁用的按钮**：禁用后的按钮收不到悬停，提示显示不出来。需要说明禁用原因时，在按钮外套一层可聚焦的 `span` 承载提示，提示写原因。
- **不只靠颜色**：只靠颜色区分的信息（例如节点分组色）要有文字替代。

### 悬浮提示

用页面自带的提示组件，不用原生 `title`，因为原生提示延迟长、样式不跟主题、不能显示快捷键。

- 全页一个提示层：延迟 400ms 显示；离开一个按钮后 300ms 内移到相邻按钮，立即显示。
- 反色底（`--tip-bg`）、12px 字、内边距 4px × 8px，距触发元素 6px，离窗口边缘至少 8px。
- 有快捷键时写成“名称（快捷键）”。
- `Esc` 关闭提示。
- 截断的文字、路径等按钮以外的提示也用同一个组件。

### Mermaid 图

- 文档里的 Mermaid 图用 Pele 渲染。图的原文在生成时从文档读出，页面不另写一份。
- 图的颜色和字体只通过 `.pele` 上的 `--pele-*` 变量取页面的语义变量，不给单张图另配颜色，所以换主题时图跟着变，不用重画。
- 渲染失败时保留原文，并用底部提示写明失败原因。
- **首页的文字和图都从文档读出**：框架入口的开头一段、「框架做什么」一节的第一段和流程图，Godot 项目手册 README「先建立的整体印象」的第一段和 Feature 主线图，规则写在 [panorama-data.js](tools/panorama-data.js) 的 `section`。每段下面放进入对应模块的链接。
- **首页流程图可以点**：点一步，切到开发场景并展开这一步相关的分类。步骤和分类的对应写在 [modules.jsx](src/modules.jsx) 的 `STEP_SCENES`，键是流程图里的节点 ID；没写进对应表的步骤不能点。

### 空状态与错误

- 没有内容的区域写一行字，说明怎样让内容出现，例如“在主区域选中一个文件”。
- 操作失败时在原处或用底部提示写明失败了什么，例如“复制失败：”加上要复制的内容，让使用者能手动复制。
- 还没做的模块在主区域写明“待实现”和数据来源；活动栏按钮照常可点，不置灰。

### 动效

- 默认不加动效。状态切换直接变，不做淡入、滑动和弹跳。
- 以后确实要加过渡时，写在 `@media (prefers-reduced-motion: no-preference)` 里，因为在系统里设置了减少动态效果的使用者不想看到动效。

### 焦点与键盘

- 所有可聚焦的元素都有可见的焦点环，颜色用 `--ring`，和元素之间留 2px 间隙。
- 菜单关闭后，焦点回到打开菜单的按钮，不掉回页面开头。
- 全局快捷键带 `Alt`，不用单字母，以免和搜索框的输入冲突。

### 元素名称

元素选取靠元素名称定位要修改的代码。每个使用者可能要求修改的元素都有一个名称，写在 `data-ui` 属性里，例如 `data-ui="topbar.search"`：

- 名称用“区域.元素”两段，小写英文，和元素选取复制出来的名称一致。
- 编译时，[babel-data-src.js](tools/babel-data-src.js) 给每个带 `data-ui` 的 JSX 元素补上它在源文件中的行号（`data-src`），所以复制出来的位置能直接对到 `.jsx` 文件的那一行。
- 新增元素时同时写 `data-ui`；没有名称的元素在选取时归到最近的带名称的父元素。

## 不做的事

- 不用原生 `title` 做提示。
- 不用渐变、大阴影、毛玻璃，不用动画吸引注意。
- 不在图标按钮旁边再写一遍同名文字。
- 不让常驻控件随状态出现、消失或换位置。
- 不用 emoji 当图标或标记。
- 不从网络加载脚本、字体和样式。

## 参考来源

本文的约定来自两处：

- **桌面工具界面约定**：由使用者提供，包括位置稳定、双栏属性面板、提示和焦点等。
- **design-taste-frontend Skill**：只取适用于工具页面的条目，包括一个强调色、统一圆角、不用纯黑纯白、对比度、层级变量、空状态、减少动效、用图标库不手画图标。

图标库是 [Tabler Icons](https://tabler.io/icons) 3.48.0，Mermaid 渲染库是 [Pele](https://github.com/obsidianmd/pele) 1.6.0，都是 MIT 许可证；它们和 React、Vite 一样用 npm 安装，版本固定在 [package.json](package.json) 里，许可证随包装在 `node_modules/` 下。

design-taste-frontend 主要写营销落地页，下列条目不适用于本页，修改时不按它们改：

- Tailwind 和 Motion，因为样式已经用 CSS 变量统一，本页也几乎不用动效。
- 不对称版式、大标题字号、首屏布局和滚动动画，因为本页是对称的紧凑工具界面。
- 按下时的位移或缩放反馈，因为 VSCode 这类工具没有这种反馈，加上后和参照的工具不一致。
- 字体建议，因为本页显示中文，用 Windows 自带的 Segoe UI 和微软雅黑。

## 怎样修改

- 换整体色调：只改 `:root` 里 `--brand` 等原始值，浅色和深色两套都改，再按「颜色用途」的对比度一条重算。
- 新增颜色用途或浮层：先在本文的表里加一行，再在 `:root` 里加变量；颜色变量两套主题都加。
- 风格方向、布局或组件约定变化时，先和使用者确认，再更新本文。
