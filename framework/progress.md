## Asset Workbench 视觉效果扩展规划

本规划覆盖当前可以预期的 2D 表现扩展、组合使用、规模管理和成熟交付；范围可随实际需求调整，不承诺未知功能或固定工期。
E0–E7 仅用于本节引用，不替代框架开发 Stage，也不重编号此前 Analyzer 和分组分析的第一至第三阶段。
整体规划已完成；用户明确授权的 E1、E3、E5、E6 实现与自动验证、E4 当前设备与样例的规模测量均已完成。E7 整合、独立审核、修复与自动验证完成，新效果、组合与编排的人工体验待确认。E2 未开工；各轮具体通过范围见报告，不把实施授权或独立审核当作人工验收。

### 已有基础与实施边界

扩展前基线为 `4332ce1`：三个独立 F6 入口、图像/音频/Shader 独立绑定、对象与场景 A/B、Cue 保存、源分析及 UI 整理已实现；E1 从规划提交 `f76c29f` 开始实施，当前新增粒子与动画第四入口。
用户确认本次画面修复通过验收；其他已有能力的验证和人工待确认范围仍见上表与原报告，不据此扩大验收结论。

[Presenter](../project-source/components/feedback/feedback_presenter.gd) 沿用配置、触发、停止入口，原脉冲仍由逐帧计算与绘制驱动，新增粒子、Tween 与 AnimationPlayer 由独立局部组件负责；
[Cue](../project-source/components/feedback/feedback_cue.gd) 已将 E1 新字段接入草稿隔离、显式比较/校验、未保存判断和保存后的重读核对。
运行实例与可变材质由各表现对象持有，预设只读共享；同一属性应有明确控制者，避免 Tween、AnimationPlayer 与现有绘制逻辑同时覆盖。
当前能力和使用边界见 [示例说明](../project-source/examples/asset_workbench/README.md)，现有回归与真实渲染捕获可按新增风险扩充，不能把既有通过记录算作新机制已验证。

早期沿用独立 F6 工作台、真实表现组件、原生场景与少量明确参数。图像、音频、Shader、粒子可各自留空；Tween 等动画机制须声明操作目标，没有目标时不暗中补选素材。
源分析继续针对原始图像/音频，效果组合由运行和渲染验证；不因规划增加 Shader/粒子分析引擎、通用属性编辑器、3D、全屏后处理或完整音频制作能力。
本轮 E5、E6 以双组合的分组取消、并发取舍与先后/并行播放为具体案例；复用现有 Presenter，不增加全局服务、对象池或任意属性动画编辑器。

### 依赖关系与后期能力的启动条件

基础主线是 E0 → E1 → E3 → E4。E2 在 E1 后按素材需求加入，E3 只依赖实际使用的 E2 项。
E5、E6 是 E4 后的两个已选分支：管理器解决“哪些实例由谁管理、如何限额与取消”，时间轴解决“哪些效果何时发生”。
本轮时间轴使用局部 Manager 的对象句柄，因此有 E5 → E6 依赖，不要求全局管理器。更重的池化、可视化编辑或跳转仍需具体需求与证据。
E7 汇总实际选择的范围，未开展的条件分支继续明确留空；新需求与前置变化直接调整本表，不复制另一套规划台账。

### 跨阶段验证与进度维护

每个获准实施阶段都包含必要的实现、说明同步与验证。复用已有夹具，按新增风险补独立/空配置、属性与材质隔离、A/B、重复触发、停止/切换/退出清理、保存冲突/重载与真实消费；
组合测试覆盖关键交互及代表性完整组合，不为了穷举覆盖率扩建。性能从 E1 就关注明显泄漏或失控，E4 才针对规模集中测量。
真实引擎检查在明确指定且文件对应本次修改的外部项目执行，同步沿用明确授权范围，不自动更新既有游戏；静态核对、工具回归、引擎/渲染和人工体验分别记录。

后续任务续接时更新本节同一阶段的状态、实际完成范围、验证缺口和下一项依赖，详细证据链接该轮报告；进行中只标实际已开始的工作，部分完成不写成整阶段完成。
每次交付前同步上方当前工作摘要；仅有建议或等待选择时保留计划状态。暂不新增功能任务文件、自动同步、计划执行器或另一份长期台账。
