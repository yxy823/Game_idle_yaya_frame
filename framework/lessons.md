# 框架 Lessons

记录框架维护中 Agent 自己的流程失误出现了几次，次数够了就提出升级。记什么、条目格式、计数和升级条件沿用生成项目的[Lessons](../project-source/methodology/09-records-reports-and-handoff.md#lessons)；框架这边的区别见 `framework/AGENTS.md` 的[Lessons](AGENTS.md#lessons)。

## 规则或 README 宣称的效果，至少实测一次

- 触发：审核或复用规则、工具 README 中“工具保证 X”“这样做就 Y”的说法时
- 症状：新项目扫描后总冒出 `.uid`、`.import` 或格式差异；同类文件反复要补交
- 出事：2026-10-05 发现 `resave_godot_files.gd` 的 README 说“重存后与编辑器格式一致”，实际普通 `--headless` 不写 uid，分发的 35 个场景资源都是手写格式；多轮审核照单全收
- 做对的例子：涉及 `.tscn`、`.tres`、`.import` 的修改，在新生成项目执行 `--headless --editor --path . --quit-after 300` 和 `--headless --path . --import`，确认 git 无变化
- 出现 1 次（2026-10-05）；严重：否

## 交互工具交付前，按真实用户任务从头走一遍

- 触发：调试台这类界面或交互工具交给用户试用前
- 症状：用户操作时看到引擎原始报错或内部路径，例如 “Invalid data … res://dev/… 请先走候选采纳”
- 出事：2026-10-07 调试台“采纳到游戏”；两轮偏工程的对抗性审核都没发现，其中一轮还提出了这条限制
- 做对的例子：按“换一个音效并采纳”“改参数后和原版对比”这类任务，用程序驱动界面走一遍并检查文案；工程约束由工具自己处理
- 出现 1 次（2026-10-07）；严重：否

## 按目标规模设计，不因 demo 用不到就推迟

- 触发：评估某个机制要不要做、要不要分层时
- 症状：提出“超过 20 个再分层”这类要 Agent 以后再判断的触发条件
- 出事：2026-10-06 讨论 demo_v2 演示页分层时被用户纠正；目标是增量三消这类上百个特效的游戏
- 做对的例子：能明确定下的规则现在就定；删掉的是没有真实问题支撑的机制，不是规模带来的必要结构
- 出现 1 次（2026-10-06）；严重：否

## 用户没回答的决定题，不按推荐项先做

- 触发：用户只回答了部分题，或没回答某道题时
- 症状：交付里有用户没选过的方案
- 出事：2026-10-11 图解问答接入时，第 3、5、6 题被按推荐项实现
- 做对的例子：只做答过的部分，依赖未答题的改动先不动，在回复里重新问
- 出现 1 次（2026-10-11）；严重：否

## 环境前提按本机实测，不写降级分支

- 触发：工具、脚本依赖程序路径、Python 环境、字体等前提时
- 症状：代码里出现“找不到就降级”或为别人机器准备的兼容分支
- 出事：2026-10-11 图解问答接入时被用户指出；用户只个人使用
- 做对的例子：不确定本机有没有某个依赖时先实测，确认后直接使用
- 出现 1 次（2026-10-11）；严重：否

## 写临时脚本时就判断要不要保存，并在汇报里写出结论

- 触发：任务中写了检查或批处理用的临时脚本时
- 症状：完成汇报只说“临时写了脚本”，没说这类脚本以后还用不用、是否满足保存条件
- 出事：2026-10-15 agy 审核修复中，为场景图新连线写了“折线是否穿过节点”的检查脚本，没按[何时把临时脚本做成工具](maintenance/design-guidelines/skills-and-scripts.md#何时把临时脚本做成工具)判断，用户追问后才补上
- 做对的例子：写完脚本当场按三条保存条件判断；满足时复制到 `tmp/<任务>/` 并在待确认里征求同意，不满足时在验证里写一句不保存的原因
- 出现 1 次（2026-10-15）；严重：否
