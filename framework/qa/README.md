# Q&A

[框架入口](../README.md)

本目录收集用户在讨论中实际问过、以后还会用到的问题，按主题分文件。读者是用户本人：用来补上对框架做法或游戏开发专业知识不清楚的地方。它和两本手册的分工是：Godot 项目手册按对象讲“项目里的东西是什么”，场景速查手册按情况讲“遇到这种事怎么处理”，Q&A 按真实问过的问题讲“为什么这样、能做到什么”。

## 主题

全部主题和问题列在首页 `index.html`，由 [qa-explainer-yaya](../../.agents/skills/qa-explainer-yaya/SKILL.md) 的生成命令按各主题文件的标题自动生成，不在本页另列。

## 什么时候添加

Agent 在讨论中发现下面的情况时，在当次回复的结尾列出建议记入 Q&A 的问题标题和主题文件，用户同意后再添加或更新问答：

- 用户的追问暴露出一个理解缺口，例如“为什么这样设计”“这样分散好吗”“X 能做到什么程度”；
- 这个问题换一个项目、换一次对话还会用到。

用户没有回应的候选不写入。用户明确要求记下某个问题，或要求“用图解释”时，直接写入。写入后在回复的「改动」里列出新增或修改了哪几条。

不添加：

- 只关于当次对话的问题，例如 Agent 刚才读了什么、某个任务进行到哪一步；
- 正文已经写清、用户只是没读到的内容。这种情况直接给出正文链接；同类问题第二次出现时再添加。

## 怎样写

使用 [qa-explainer-yaya](../../.agents/skills/qa-explainer-yaya/SKILL.md)。主题文件是扩展 Markdown：每条问答是一个 `##` 节，标题就是问题本身，用通用的说法，不照抄某次对话的原话；正文按“结论 / 为什么 / 依据”写，没有内容的段落省略，图放在“为什么”里。文件格式和生成页面的命令见该 Skill。主题文件是正文；同名的 `.html` 页面和首页由它生成，不提交。

按问题类型决定写多少：

| 问题类型 | 写法 |
| --- | --- |
| 框架怎样运作，例如某类内容写在哪里、为什么这样分工 | 只写结论和理由，链接到规范、手册或规则中的正文；不复述命令、路径细节、字段和数值，因为正文修改后这些复述会过时 |
| 通用专业知识，框架中没有它的正文，例如音频合成、矢量图、字体许可 | Q&A 本身就是正文，写完整；区分事实、推测和没有实测的内容，外部事实写明来源 |

不写日期、状态、提问次数或提问人；历史由 Git 保存。问答被证明错误时直接改正，不保留旧答案。

只在出现第一条问答时创建主题文件，不预建空主题。一个主题文件超过约 15 条问答、查找变难时，再按问题的共同对象拆分。
