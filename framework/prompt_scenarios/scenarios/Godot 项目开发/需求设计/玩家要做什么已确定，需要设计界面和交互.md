## 前置条件与适用范围

项目已有真实 GDD，行为已确认，本次补足当前界面规格。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 需求设计 → 玩家要做什么已确定，需要设计界面和交互”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$design-ui-spec](<../../../../../project-source/skills/design-ui-spec/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜拆解交互状态**

当前 Agent 用 design-ui-spec 先读取 GDD 已有设计，再核对入口、动作、可见反馈、错误和空状态。

**S2｜确定页面规格**

说明布局、信息层级、输入方式和状态转换，必要视觉未知先实验。

**S3｜保存规格引用**

在 `docs/ui/<interface>-design.md` 补足布局、状态和界面专用资源章节；完整表现引用 `docs/presentation/` 中的正文，在交互使用处与末尾“关联游戏表现”导航保留链接。界面规格固定归 UI 文档，原先写在 GDD 的本次规格迁入该文件并更新引用；GDD 保留玩法规则与整体目标，Product 保留交付范围和来源。
