# 已有图片要替换，需要保留界面引用

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已有图片要替换，需要保留界面引用。

需要的材料：

- 替换资源与规格：旧新图片、确认的视觉规格。
- 消费关系：受影响节点和共享消费者。

## 前置条件与适用范围

文件和消费目标已经确认，当前 Feature 或工程任务已授权替换图片。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 已有图片要替换，需要保留界面引用”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$content-asset-integration](<../../../../../project-source/skills/content-asset-integration/SKILL.md>)、[$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜核对接入契约**

当前 Agent 使用 content-asset-integration 核对新旧尺寸、切片、UID/路径及依赖，确认实际消费者及文件来源。

**S2｜更新资源并保留消费关系**

保留必要旧信息后更新资源及引用，检查所有共享消费者，不仅替换看到的一个文件。

**S3｜验证实际反馈**

返回 feature-execute，在获准运行范围检查所有共享显示位置与不同界面状态，真实视觉或听觉结果由用户体验确认。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 输入资源适合当前消费目标 |
| S2 | 实际资源引用有效 |
| S3 | 实际体验与自动检查分别记录 |

## 资源与文件影响

- 修改：对应资源、场景/脚本引用、必要导入设置和原清单实际位置。
- 保留：原规格与原件。

## 阻塞、异常与范围变化

文件缺失、规格冲突或来源不清时停在对应缺口；不在此制作素材或改变目标要求。

## 完成状态与验证标准

替换图片已完成，指定消费关系有效，适用运行与体验结果明确，原任务剩余完成检查可继续。
