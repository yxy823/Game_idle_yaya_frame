# 准备增加语言支持，先确定本地化要求

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

准备增加语言支持，先确定本地化要求。

需要的材料：

- 语言与文本范围：目标语言、文本范围。
- 内容与显示约束：术语、字体与版面约束。

## 前置条件与适用范围

项目已有真实 GDD，本地化目标待定稿，本次只补足规格。

## 执行步骤

使用[集中提示词库](<../../../prompts/godot-development-prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 准备增加语言支持，先确定本地化要求”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$design-localization-spec](<../../../../../project-source/skills/design-localization-spec/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜确认语言与显示需求**

当前 Agent 使用 design-localization-spec 核对目标语言、文本所有者、术语和字体覆盖。

**S2｜定义最小约定**

说明键管理、回退、复数或格式化的实际需要、排版和验收样本，不为未用语言扩建框架。

**S3｜保存规范**

语言覆盖、回退、排版与本地化用词规格固定保存到 `docs/localization/localization-spec.md`；原先写在 GDD 的当前范围内规格迁入该文件并更新引用，GDD 保留整体体验目标。游戏术语定义引用 `docs/terminology.md`；目标语言用词统一写入本地化规范的“术语译名”章节，记录概念链接、目标语言、已采纳译名和语境，候选标为待定。完整译文继续由运行资源维护。核对消费者后交接目标语言实现。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 语言范围及关键显示要求明确 |
| S2 | 实现者有明确可验证要求 |
| S3 | 规格有唯一来源 |

## 资源与文件影响

本地化规格及必要来源引用修改；不写翻译资源或运行接入。

## 阻塞、异常与范围变化

语言和措辞决定不足时保留待定，不通过生成占位翻译掩盖。

## 完成状态与验证标准

当前语言支持要求已确认且可实现验证，未宣称翻译完成。
