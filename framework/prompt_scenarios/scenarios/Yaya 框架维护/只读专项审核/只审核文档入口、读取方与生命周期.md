# 只审核文档入口、读取方与生命周期

[返回场景索引](../../scenario-index.md#只读专项审核) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

孤立扫描出现疑点，或文件虽有导航却不清楚实际使用时机，需要核对其保留价值。

## 前置条件与适用范围

通过 GitHub 审核框架快照，准备以下输入：

- **版本**：默认分支，或指定分支、标签、完整提交 SHA。
- **审核对象**：一类文档、一个目录或孤立文档扫描结果；可描述有文件却不知道何时读取的情况。
- **可选线索**：具体疑问、已确认决定或旧报告；历史材料不直接作为当前结论。

所选文档的产生、导航、条件读取和保留契约，以及必要的生产方、使用方和现行排除依据。只追查能影响所选文档用途的关系，不要求全仓文档互相链接。

## 参与角色与职责边界

在未参与被审成果创作的审核 Agent 会话中使用本入口。用户选择专题和对象，审核 Agent 只读核对实际材料，不执行被审代码或修改仓库；默认在对话交付结论。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 只读专项审核 → 只审核文档入口、读取方与生命周期”。填写版本、审核对象和可选线索；已有对话补齐材料即可，不必重发入口。

**S1｜固定版本与实际对象**

审核 Agent 将版本解析到完整 SHA，说明本专题的实际对象与必要依赖。后续材料及证据绑定同一提交；只为核对当前问题读取相关规范与上下游。

**S2｜核对本专题的实际契约**

审核 Agent 沿文档的产生和读取场景检查用途，同时核对现行 README 入口与扫描排除的理由；新增文件单独核实，不把既有排除泛化。

README 入口是否足够取决于已有读取约定，不能一律认定仅导航就不合格，也不能仅因被排除就认定新文件必然合格。单次报告有明确的当次用途即可，不要求第二个消费者或两两回链。

**S3｜交付有依据的专项结论**

审核 Agent 给出实际范围、主要判断，以及可定位的问题、影响和最小建议；同一根因合并，静态问题、风险和可选改进分开。只列影响本专题结论的材料或运行证据缺口，不逐项罗列范围外领域。

## 阻塞、异常与范围变化

关键文件不可读、截断或对象仍跨越过大的独立范围时，说明缺口或拆分建议，请用户确定后续范围；可独立判断的部分先完成。不得用抽样冒充指定范围已全部检查，也不能把静态推演写成真实运行。

## 完成状态与验证标准

已核对所选文档的入口、使用与保留理由，交付有依据的阅读缺口、归位建议或保留结论。所选对象的结论均可回到同一 SHA 的证据，没有实施修复或自动开展其他专题。

## 流程关联与衔接关系

尚不清楚应选哪个专题时，可先做[结构总览](<想先总览 GitHub 框架，再选择审核专题.md>)。拿到报告后，需要判断哪些意见值得修改时，使用[外部意见复核](<../维护与复盘/收到外部审核意见，先核实哪些值得修改.md>)。
