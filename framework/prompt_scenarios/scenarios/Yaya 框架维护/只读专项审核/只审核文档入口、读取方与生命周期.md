# 只审核文档入口、读取方与生命周期

[返回场景索引](../../scenario-index.md#只读专项审核) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

孤立扫描出现疑点，或文件虽有导航却不清楚实际使用时机，需要核对其保留价值。

## 前置条件与适用范围

默认审核当前 Yaya 框架的最新内容，直接使用本场景提示词即可，无需填写参数。

框架维护文档、两册手册及生成项目文档契约中的产生、导航、条件读取和保留关系，包括必要的生产方、使用方与现行排除依据。只追查影响文档用途的关系，不要求全仓文档互相链接。内容归属使用[文档职责与存放位置审核](<只审核文档职责与存放位置.md>)；本入口按已确定的归属检查实际使用关系。

## 参与角色与职责边界

在未参与被审成果创作的审核 Agent 会话中使用本入口。用户选择预设专题，审核 Agent 只读核对实际材料，不执行被审代码或修改仓库；默认在对话交付结论。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 只读专项审核 → 只审核文档入口、读取方与生命周期”。直接按预设范围开始；已有对话沿用当前专题和有效线索，不必重发入口。

**S1｜定位本专题材料**

审核 Agent 按预设范围识别当前框架中的实际对象，读取相关正文与必要上下游。结论引用实际读到的文件、行号或可核实符号。

**S2｜核对本专题的实际契约**

审核 Agent 沿文档的产生和读取场景检查用途，同时核对现行 README 入口与扫描排除的理由；新增文件单独核实，不把既有排除泛化。

README 入口是否足够取决于已有读取约定，不能一律认定仅导航就不合格，也不能仅因被排除就认定新文件必然合格。单次报告有明确的当次用途即可，不要求第二个消费者或两两回链。

**S3｜交付有依据的专项结论**

审核 Agent 给出实际范围、主要判断，以及可定位的问题、影响和最小建议；同一根因合并，静态问题、风险和可选改进分开。只列影响本专题结论的材料或运行证据缺口，不逐项罗列范围外领域。

## 阻塞、异常与范围变化

关键材料不可读、截断或缺少决定性上下文时，说明具体缺口并继续能独立判断的部分；未覆盖内容如实保留，不用抽样冒充预设范围已全部检查。需要改变职责或实施修复时交付建议，后续按明确授权处理；静态推演不能写成真实运行。

## 完成状态与验证标准

已核对本专题文档的入口、使用与保留理由，交付有依据的阅读缺口、归位建议或保留结论。本专题结论均有当前材料的文件依据，没有实施修复或自动开展其他专题。

## 流程关联与衔接关系

尚不清楚应选哪个专题时，可先做[结构总览](<想先总览框架，再选择审核专题.md>)。拿到报告后，需要判断哪些意见值得修改时，使用[外部意见复核](<../维护与复盘/收到外部审核意见，先核实哪些值得修改.md>)。
