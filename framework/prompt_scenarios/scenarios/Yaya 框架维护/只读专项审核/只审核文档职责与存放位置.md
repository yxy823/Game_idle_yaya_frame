# 只审核文档职责与存放位置

[返回场景索引](../../scenario-index.md#只读专项审核) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

同一内容可能放进不同文档，文档之间职责重叠，或框架规则只要求“保留一份”却没有确定这份正文的位置，需要单独检查内容归属。

## 前置条件与适用范围

通过 GitHub 审核框架快照，提供版本、一组相关文档或产物规范，以及已有疑问。版本可以是默认分支、指定分支、标签或完整提交 SHA；已有讨论和报告作为线索，当前快照的正文作为事实来源。

本入口检查内容职责、固定文件或命名模式，以及必要生产方和使用方的归属是否一致。文档何时被读取、更新或结束使用，由[文档入口与生命周期审核](<只审核文档入口、读取方与生命周期.md>)处理，不在本入口展开。

## 参与角色与职责边界

由未参与被审成果创作的审核 Agent，按[审核覆盖与结论](../../../../docs/framework-maintenance/baselines/skill-script-prompt-design.md#审核覆盖与结论)执行。用户确定对象，审核 Agent 读取材料并交付结论；不执行被审代码、不修改仓库，也不将发现问题视为迁移文档的授权。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 只读专项审核 → 只审核文档职责与存放位置”。填写版本、审核对象和可选线索；已有对话可直接补齐材料。

**S1｜固定版本与内容范围**

审核 Agent 将版本解析为完整 SHA，明确要检查的内容类型、文档及相邻职责。读取[文档职责与固定归属](../../../../docs/framework-maintenance/baselines/skill-script-prompt-design.md#文档职责与固定归属)，沿所选产物的规范、Skill、模板和使用方核对实际契约；生成项目的路径由复制清单核实。

**S2｜用实际写入情境检查归属**

审核 Agent 对照“内容类型与作用域 → 权威位置 → 使用方”，判断同一输入能否确定唯一位置，是否存在任选文件、依赖先写位置或多个现行正文竞争的情况。确定场景、内容职责和作用域后，必须对应唯一文件或确定的命名模式，禁止保留让 Agent 多选一的描述。文档可以按需创建，但不按游戏规模、篇幅或复杂程度改变存放方案，不为简单游戏单设分支；关键词命中、不同对象的文件、必要摘要和历史材料不能直接作为重复证据。

**S3｜交付专项结论与归属建议**

审核 Agent 列出已审内容、当前归属及判断。每项问题提供同一 SHA 下的位置、具体触发、竞争正文或规则、影响，以及一个有依据的归属建议和需要同步的入口；没有问题时说明保留依据。缺少材料或需要设计决定的部分单独注明。

## 阻塞、异常与范围变化

关键材料不可读、无法固定版本或指定范围尚未覆盖时，说明具体缺口并完成可独立判断的部分；不靠抽样宣布全部通过。发现职责需要改变时交付建议，后续实施按新的明确授权处理。

## 完成状态与验证标准

指定范围的内容归属与相邻职责已逐项核对，问题和保留结论可追溯到实际正文与生产、使用关系。交付的是静态专项审核，没有运行验证、自动修复或全框架通过结论。

## 流程关联与衔接关系

尚不清楚对象时先用[结构总览](<想先总览 GitHub 框架，再选择审核专题.md>)选择范围；拿到外部结论后，使用[外部意见复核](<../维护与复盘/收到外部审核意见，先核实哪些值得修改.md>)判断当前版本仍需处理的问题。
