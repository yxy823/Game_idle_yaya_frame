# 只审核 Godot 资源与插件接入

[返回场景索引](../../scenario-index.md#只读专项审核) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

接入或搬动 Godot 资源、插件或工作台消费示例后，想先核对文件契约与边界。

## 前置条件与适用范围

通过 GitHub 审核框架快照，准备以下输入：

- **版本**：默认分支，或指定分支、标签、完整提交 SHA。
- **审核对象**：一个插件、一组资源或一次接入变更；可描述资源引用、插件启用或消费导出的疑问。
- **可选线索**：具体疑问、已确认决定或旧报告；历史材料不直接作为当前结论。

所选对象的 project.godot 配置、plugin.cfg、入口与依赖资源、适用本地修改、相关说明和验证夹具。第三方内部实现只沿接入问题所需部分追查，不声明完整审核上游。

## 参与角色与职责边界

在未参与被审成果创作的审核 Agent 会话中使用本入口。用户选择专题和对象，审核 Agent 只读核对实际材料，不执行被审代码或修改仓库；默认在对话交付结论。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 只读专项审核 → 只审核 Godot 资源与插件接入”。填写版本、审核对象和可选线索；已有对话补齐材料即可，不必重发入口。

**S1｜固定版本与实际对象**

审核 Agent 将版本解析到完整 SHA，说明本专题的实际对象与必要依赖。后续材料及证据绑定同一提交；只为核对当前问题读取相关规范与上下游。

**S2｜核对本专题的实际契约**

审核 Agent 追查所选配置、资源依赖、第三方与本地补丁关系；涉及导出时核对过滤和探针的真实约定。

静态可见的接入不一致与待真实引擎验证的生命周期风险分开；没有作者机器或图形环境不等于不兼容，旧日志也不能证明当前兼容。只评价已确定的 Godot 技术栈。

**S3｜交付有依据的专项结论**

审核 Agent 给出实际范围、主要判断，以及可定位的问题、影响和最小建议；同一根因合并，静态问题、风险和可选改进分开。只列影响本专题结论的材料或运行证据缺口，不逐项罗列范围外领域。

## 阻塞、异常与范围变化

关键文件不可读、截断或对象仍跨越过大的独立范围时，说明缺口或拆分建议，请用户确定后续范围；可独立判断的部分先完成。不得用抽样冒充指定范围已全部检查，也不能把静态推演写成真实运行。

## 完成状态与验证标准

已核对所选接入契约，交付有依据的问题或保留结论，并说明确有需要的定向引擎验证；不把静态检查写成插件兼容或导出通过。所选对象的结论均可回到同一 SHA 的证据，没有实施修复或自动开展其他专题。
