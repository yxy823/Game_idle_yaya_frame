# 只审核测试选择与完成证据

[返回场景索引](../../scenario-index.md#只读专项审核) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

担心选出的测试不完整，或跳过、旧报告和人工未验收状态被当作已完成。

## 前置条件与适用范围

通过 GitHub 审核框架快照，准备以下输入：

- **版本**：默认分支，或指定分支、标签、完整提交 SHA。
- **审核对象**：一条验证或完成判定流程、相关数据契约或一次变更；可描述漏选、旧结果复用或误报完成的疑问。
- **可选线索**：具体疑问、已确认决定或旧报告；历史材料不直接作为当前结论。

所选流程中的测试选择、登记映射、结果解析、证据身份和完成读取方；必要时追查人工验收契约。不审核无关测试的断言质量或所有引擎功能。

## 参与角色与职责边界

在未参与被审成果创作的审核 Agent 会话中使用本入口。用户选择专题和对象，审核 Agent 只读核对实际材料，不执行被审代码或修改仓库；默认在对话交付结论。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 只读专项审核 → 只审核测试选择与完成证据”。填写版本、审核对象和可选线索；已有对话补齐材料即可，不必重发入口。

**S1｜固定版本与实际对象**

审核 Agent 将版本解析到完整 SHA，说明本专题的实际对象与必要依赖。后续材料及证据绑定同一提交；只为核对当前问题读取相关规范与上下游。

**S2｜核对本专题的实际契约**

审核 Agent 从验收与登记输入追到测试选择、报告解释和完成读取方，核对异常及旧证据分支。

历史结果只证明其记录的版本与范围；没有运行环境不构成静态缺陷。不得把流程文字写成已实现的自动拦截，也不通过增加收据、来源哈希台账或通用验收包装层解决假想问题。

**S3｜交付有依据的专项结论**

审核 Agent 给出实际范围、主要判断，以及可定位的问题、影响和最小建议；同一根因合并，静态问题、风险和可选改进分开。只列影响本专题结论的材料或运行证据缺口，不逐项罗列范围外领域。

## 阻塞、异常与范围变化

关键文件不可读、截断或对象仍跨越过大的独立范围时，说明缺口或拆分建议，请用户确定后续范围；可独立判断的部分先完成。不得用抽样冒充指定范围已全部检查，也不能把静态推演写成真实运行。

## 完成状态与验证标准

已核对所选测试集合与证据使用契约，交付有依据的问题或保留结论；需要定向运行才能确认的判断已说明。所选对象的结论均可回到同一 SHA 的证据，没有实施修复或自动开展其他专题。

## 流程关联与衔接关系

尚不清楚应选哪个专题时，可先做[结构总览](<想先总览 GitHub 框架，再选择审核专题.md>)。拿到报告后，需要判断哪些意见值得修改时，使用[外部意见复核](<../维护与复盘/收到外部审核意见，先核实哪些值得修改.md>)。
