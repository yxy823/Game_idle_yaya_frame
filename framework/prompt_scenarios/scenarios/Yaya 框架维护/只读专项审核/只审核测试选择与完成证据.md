# 只审核测试选择与完成证据

[返回场景索引](../../scenario-index.md#只读专项审核) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

担心选出的测试不完整，或跳过、旧报告和人工未验收状态被当作已完成。

## 前置条件与适用范围

默认审核当前 Yaya 框架的最新内容，直接使用本场景提示词即可，无需填写参数。

生成项目验证流程中的测试选择、登记映射、结果解析、证据身份、完成读取方及人工验收契约，包括相关规范、工具与回归。只判断检查集合与证据使用，不审核无关测试的断言质量或所有引擎功能。

## 参与角色与职责边界

在未参与被审成果创作的审核 Agent 会话中使用本入口。用户选择预设专题，审核 Agent 只读核对实际材料，不执行被审代码或修改仓库；默认在对话交付结论。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 只读专项审核 → 只审核测试选择与完成证据”。直接按预设范围开始；已有对话沿用当前专题和有效线索，不必重发入口。

**S1｜定位本专题材料**

审核 Agent 按预设范围识别当前框架中的实际对象，读取相关正文与必要上下游。结论引用实际读到的文件、行号或可核实符号。

**S2｜核对本专题的实际契约**

审核 Agent 从验收与登记输入追到测试选择、报告解释和完成读取方，核对异常及旧证据分支。

历史结果只证明其记录的版本与范围；没有运行环境不构成静态缺陷。不得把流程文字写成已实现的自动拦截，也不通过增加收据、来源哈希台账或通用验收包装层解决假想问题。

**S3｜交付有依据的专项结论**

审核 Agent 给出实际范围、主要判断，以及可定位的问题、影响和最小建议；同一根因合并，静态问题、风险和可选改进分开。只列影响本专题结论的材料或运行证据缺口，不逐项罗列范围外领域。

## 阻塞、异常与范围变化

关键材料不可读、截断或缺少决定性上下文时，说明具体缺口并继续能独立判断的部分；未覆盖内容如实保留，不用抽样冒充预设范围已全部检查。需要改变职责或实施修复时交付建议，后续按明确授权处理；静态推演不能写成真实运行。

## 完成状态与验证标准

已核对本专题测试集合与证据使用契约，交付有依据的问题或保留结论；需要定向运行才能确认的判断已说明。本专题结论均有当前材料的文件依据，没有实施修复或自动开展其他专题。

## 流程关联与衔接关系

尚不清楚应选哪个专题时，可先做[结构总览](<想先总览框架，再选择审核专题.md>)。拿到报告后，需要判断哪些意见值得修改时，使用[外部意见复核](<../维护与复盘/收到外部审核意见，先核实哪些值得修改.md>)。
