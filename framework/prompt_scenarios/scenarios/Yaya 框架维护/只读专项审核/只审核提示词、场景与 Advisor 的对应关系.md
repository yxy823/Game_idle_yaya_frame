# 只审核提示词、场景与 Advisor 的对应关系

[返回场景索引](../../scenario-index.md#只读专项审核) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

新增提示词后担心缺少场景或索引，或 Advisor 的建议与当前项目事实不匹配。

## 前置条件与适用范围

通过 GitHub 审核框架快照，准备以下输入：

- **版本**：默认分支，或指定分支、标签、完整提交 SHA。
- **审核对象**：一组提示词、一个分类或一次入口变更；可描述场景缺失、名称不符或 Advisor 选错入口的情况。
- **可选线索**：具体疑问、已确认决定或旧报告；历史材料不直接作为当前结论。

所选提示词的 Project、分类、名称、正文和对应场景及索引；Godot 入口涉及状态选择时再检查 Advisor，涉及图中关系变化时再检查对应图节点。不把 Yaya 维护场景加入 Godot 场景图。

## 参与角色与职责边界

在未参与被审成果创作的审核 Agent 会话中使用本入口。用户选择专题和对象，审核 Agent 只读核对实际材料，不执行被审代码或修改仓库；默认在对话交付结论。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 只读专项审核 → 只审核提示词、场景与 Advisor 的对应关系”。填写版本、审核对象和可选线索；已有对话补齐材料即可，不必重发入口。

**S1｜固定版本与实际对象**

审核 Agent 将版本解析到完整 SHA，说明本专题的实际对象与必要依赖。后续材料及证据绑定同一提交；只为核对当前问题读取相关规范与上下游。

**S2｜核对本专题的实际契约**

审核 Agent 对照所选 JSON 条目、场景和导航；只有 Godot 入口需要时才追查 Advisor 与开发场景图。

Advisor 固定引用本机 Godot 库是现行明确取舍，远端审核环境打不开该本机路径本身不构成缺陷；仍需核对字面路径与所属契约。不要把路径配对通过当成语义或实际选择正确。

**S3｜交付有依据的专项结论**

审核 Agent 给出实际范围、主要判断，以及可定位的问题、影响和最小建议；同一根因合并，静态问题、风险和可选改进分开。只列影响本专题结论的材料或运行证据缺口，不逐项罗列范围外领域。

## 阻塞、异常与范围变化

关键文件不可读、截断或对象仍跨越过大的独立范围时，说明缺口或拆分建议，请用户确定后续范围；可独立判断的部分先完成。不得用抽样冒充指定范围已全部检查，也不能把静态推演写成真实运行。

## 完成状态与验证标准

已核对所选入口的名称、路径、语义及必要选择条件，交付有依据的问题或保留结论；发现问题时明确需要同步的入口。所选对象的结论均可回到同一 SHA 的证据，没有实施修复或自动开展其他专题。

## 流程关联与衔接关系

尚不清楚应选哪个专题时，可先做[结构总览](<想先总览 GitHub 框架，再选择审核专题.md>)。拿到报告后，需要判断哪些意见值得修改时，使用[外部意见复核](<../维护与复盘/收到外部审核意见，先核实哪些值得修改.md>)。
