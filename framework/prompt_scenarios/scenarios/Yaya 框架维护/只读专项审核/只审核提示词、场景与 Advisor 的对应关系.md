# 只审核提示词、场景与 Advisor 的对应关系

[返回场景索引](../../scenario-index.md#只读专项审核) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

新增提示词后担心缺少场景或索引，或 Advisor 的建议与当前项目事实不匹配。

## 前置条件与适用范围

默认审核当前 Yaya 框架的最新内容，直接使用本场景提示词即可，无需填写参数。

两份集中提示词库的 Project、分类、名称与正文，对应场景、场景索引，以及 project-next-step-advisor 的选择来源与条件。涉及图谱关系时核对对应节点；不把 Yaya 维护场景加入 Godot 场景图。

## 参与角色与职责边界

在未参与被审成果创作的审核 Agent 会话中使用本入口。用户选择预设专题，审核 Agent 只读核对实际材料，不执行被审代码或修改仓库；默认在对话交付结论。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 只读专项审核 → 只审核提示词、场景与 Advisor 的对应关系”。直接按预设范围开始；已有对话沿用当前专题和有效线索，不必重发入口。

**S1｜定位本专题材料**

审核 Agent 按预设范围识别当前框架中的实际对象，读取相关正文与必要上下游。结论引用实际读到的文件、行号或可核实符号。

**S2｜核对本专题的实际契约**

审核 Agent 对照本专题 JSON 条目、场景和导航；只有 Godot 入口需要时才追查 Advisor 与开发场景图。

Advisor 固定引用本机 Godot 库是现行明确取舍，审核环境打不开该本机路径本身不构成缺陷；仍需核对字面路径与所属契约。不要把路径配对通过当成语义或实际选择正确。

**S3｜交付有依据的专项结论**

审核 Agent 给出实际范围、主要判断，以及可定位的问题、影响和最小建议；同一根因合并，静态问题、风险和可选改进分开。只列影响本专题结论的材料或运行证据缺口，不逐项罗列范围外领域。

## 阻塞、异常与范围变化

关键材料不可读、截断或缺少决定性上下文时，说明具体缺口并继续能独立判断的部分；未覆盖内容如实保留，不用抽样冒充预设范围已全部检查。需要改变职责或实施修复时交付建议，后续按明确授权处理；静态推演不能写成真实运行。

## 完成状态与验证标准

已核对本专题入口的名称、路径、语义及必要选择条件，交付有依据的问题或保留结论；发现问题时明确需要同步的入口。本专题结论均有当前材料的文件依据，没有实施修复或自动开展其他专题。

## 流程关联与衔接关系

尚不清楚应选哪个专题时，可先做[结构总览](<想先总览框架，再选择审核专题.md>)。拿到报告后，需要判断哪些意见值得修改时，使用[外部意见复核](<../维护与复盘/收到外部审核意见，先核实哪些值得修改.md>)。
