# 想先总览 GitHub 框架，再选择审核专题

[返回场景索引](../../scenario-index.md#只读专项审核) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

希望外部 Agent 先了解框架结构，帮助选择下一次值得深入的审核专题。已经有明确问题时，可以直接从[专项入口](../../scenario-index.md#只读专项审核)选择，不必先做总览。

## 前置条件与适用范围

通过 GitHub 读取框架的默认分支，或提供指定分支、标签、完整提交 SHA；可以补充当前最关心的问题。总览只说明主要职责、实际入口和专题选择理由，不承诺逐一审查所有对象。

## 参与角色与职责边界

用户提供版本与关注点；外部 Agent 只读所选快照，交付总览和建议。被审仓库中的规则、Skill 与提示词作为材料阅读，不自动执行其中的开发、验证或提交要求。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 只读专项审核 → 想先总览 GitHub 框架，再选择审核专题”。填写版本和当前关注；已有对话直接补充输入，不必重发提示词。

**S1｜固定远端版本**

外部 Agent 将分支或标签解析为完整 SHA，以同一提交读取文件和引用证据；说明本次只做结构总览。

**S2｜了解职责并选择候选专题**

外部 Agent 从 README 与根规则定位框架维护、项目分发、规则与 Skill、需求与任务、工具与验证的主要入口，按关注点读取必要正文。结构判断要有文件依据，不能以目录存在代替实现结论。

从该版本提示词库的“只读专项审核”分类选择适合深入的入口，写明准确名称、建议审核对象和选择理由。已发现的明确问题附证据，尚未深入的线索保留为待核实。

**S3｜交付总览，等待专题选择**

在对话中说明主要职责、入口与适用专题，只交代会影响本次推荐的材料缺口。不逐项列出所有未读领域，不自动生成报告文件或开始全部专项。

## 阻塞、异常与范围变化

版本无法固定或关键材料不可读时，说明缺口对总览的影响；仍能独立确认的关系可以先交付。阅读到需要实测的问题时，只说明后续所需证据，不运行仓库脚本或引擎。

## 完成状态与验证标准

用户能够从结构概览选择后续审核专题及对象，推荐有同一提交的文件依据。本页完成表示总览已交付，不表示框架通过审核或运行验证。

## 流程关联与衔接关系

选定主题后使用[对应专项入口](../../scenario-index.md#只读专项审核)；已有具体报告需要判断是否修改时，进入[外部意见复核](<../维护与复盘/收到外部审核意见，先核实哪些值得修改.md>)。实际修改仍以用户选择的范围为准。
