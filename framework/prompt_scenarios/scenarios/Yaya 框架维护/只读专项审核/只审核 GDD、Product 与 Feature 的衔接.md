# 只审核 GDD、Product 与 Feature 的衔接

[返回场景索引](../../scenario-index.md#只读专项审核) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

GDD、Product 和 Feature 重复保存同一设计，或讨论过的范围限制没有进入后续规划。

## 前置条件与适用范围

默认审核当前 Yaya 框架的最新内容，直接使用本场景提示词即可，无需填写参数。

框架中 GDD、Product、Feature 的衔接规范、相关 Skill、模板、默认文件及必要读写方。审核框架约定，不推断未提供的外部游戏项目已有设计或已完成开发。

## 参与角色与职责边界

在未参与被审成果创作的审核 Agent 会话中使用本入口。用户选择预设专题，审核 Agent 只读核对实际材料，不执行被审代码或修改仓库；默认在对话交付结论。

## 执行步骤

使用[集中提示词库](../../../prompts/yaya-maintenance-prompts.json)中的“Yaya 框架维护 → 只读专项审核 → 只审核 GDD、Product 与 Feature 的衔接”。直接按预设范围开始；已有对话沿用当前专题和有效线索，不必重发入口。

**S1｜定位本专题材料**

审核 Agent 按预设范围识别当前框架中的实际对象，读取相关正文与必要上下游。结论引用实际读到的文件、行号或可核实符号。

**S2｜核对本专题的实际契约**

审核 Agent 沿本专题需求检查设计来源、交付划分、任务契约与后续读取方，分别核对默认文件和实际生成约定。

合法占位不等于设计缺陷，也不能支撑真实实施；不以旧讨论中的已撤回归属覆盖当前规范。若现行规则自身矛盾，列出双方依据。

**S3｜交付有依据的专项结论**

审核 Agent 给出实际范围、主要判断，以及可定位的问题、影响和最小建议；同一根因合并，静态问题、风险和可选改进分开。只列影响本专题结论的材料或运行证据缺口，不逐项罗列范围外领域。

## 阻塞、异常与范围变化

关键材料不可读、截断或缺少决定性上下文时，说明具体缺口并继续能独立判断的部分；未覆盖内容如实保留，不用抽样冒充预设范围已全部检查。需要改变职责或实施修复时交付建议，后续按明确授权处理；静态推演不能写成真实运行。

## 完成状态与验证标准

已核对设计与任务的衔接及正文归属，交付有依据的问题或保留结论；不要求补齐所有未来 Product 和 Feature。本专题结论均有当前材料的文件依据，没有实施修复或自动开展其他专题。

## 流程关联与衔接关系

尚不清楚应选哪个专题时，可先做[结构总览](<想先总览框架，再选择审核专题.md>)。拿到报告后，需要判断哪些意见值得修改时，使用[外部意见复核](<../维护与复盘/收到外部审核意见，先核实哪些值得修改.md>)。
