# 声音准备、接入与试听

[速查入口](README.md) · [执行步骤](#5-执行步骤) · [步骤产出](#6-步骤产出与状态变化) · [卡住时](#9-异常与非正常退出) · [完成判定](#10-完成状态与验证标准)

## 1. 触发场景与使用时机

功能需要音效、音乐或氛围音，希望从声音要求推进到实际文件、游戏内触发和试听。共享声音方向需要调整时，也可从本页识别影响和交接位置。

## 2. 前置条件与适用范围

已有可说明的使用场景及本次范围。规格讨论不要求音频文件已经存在；接入时才要求可读取、符合用途的真实文件、相应实施授权及可运行环境。

本页完整终点是游戏内接入和实际试听，再交回原 Feature 验证。只请求方向或规格时交付相应文档。已有合格文件和明确要求时直接走资源接入。当前音乐、音效制作仍为预留能力，规格 Skill 不生成音频，文件需要用户或外部制作流程提供。

## 3. 参与角色与职责边界

| 主体 | 负责什么 |
| --- | --- |
| 用户 | 决定未明确的声音目标，提供或安排实际文件，并反馈真实听觉体验 |
| Agent / 声音方向与规格入口 | 分别维护共享方向及当前资源要求、样本引用、待试听问题 |
| 用户或外部制作工具 | 制作、加工或提供真实音频 |
| Agent / 资源接入入口、Godot | Agent 导入文件并连接播放器与触发；Godot 实际播放 |

设计、制作、接入和试听的结果分别核实；文本要求、占位名称和静音不能充当音频成果。

## 4. 流程概览

明确触发与体验目的 → 复用或确定声音方向 → 写具体规格 → 取得文件 → 接入并试听 → 定稿来源与清单 → 回原任务验证。

## 5. 执行步骤

提示词入口：`Godot 项目开发 → 需求设计 → 确定或调整声音风格 / 设计音效与音乐需求`，按实际缺口选一条。提供触发场景、参考样本和限制；文件到位后可用 `资源、性能与数据 → 接入或替换游戏资源`。

1. **S1 确认声音行为。** Agent 核对何时播放、停止或切换，以及玩家应得到的反馈，区分正式触发与原型试听按钮。
2. **S2 确定当前声音方向。** Agent 复用已有适用约束，仅在缺失或获准变化时维护共享方向。
3. **S3 维护具体规格。** Agent 在同一资源清单中写出时长、循环、重复与叠加、优先关系、样本及待试听问题。
4. **S4 取得并核对文件。** 用户或外部流程提供音频；Agent 核实真实内容、格式、时长、声道、来源记录和目标位置。
5. **S5 接入并实际试听。** Agent 在原任务内处理导入、路径/UID、播放器或总线与触发引用；用户在游戏中试听实际效果。
6. **S6 定稿并交回原任务。** Agent 按试听结果更新确认规格与同一清单，处理计划影响，继续原 Feature 的适用验证。

## 6. 步骤产出与状态变化

| 步骤 | 直接产出与可继续的判据 |
| --- | --- |
| S1 | 触发、停止/切换条件和反馈目的有依据 |
| S2 | 当前所需共享约束明确，无需先设计全游戏音频 |
| S3 | 资源要求可用于制作和检查；确认值、建议值、实测值和未知分开 |
| S4 | 文件可读取并符合当前用途；样本与最终资源身份明确 |
| S5 | 游戏内能按要求触发，技术播放结果与真实听觉结论分别记录 |
| S6 | 来源、清单和接入位置一致；剩余验证与适用验收可定位 |

## 7. 资源与文件影响

| 对象（生成项目内） | 影响类型与发生条件 |
| --- | --- |
| Product、当前 Feature、参考样本 | 读取触发与范围；行为改变由 Product 入口处理 |
| `docs/audio/sound-bible.md` | 读取；确有共享方向变化时修改 |
| `docs/resource-requirements/<scope>.md` 与目录导航 | 新增或修改本范围音频条目、实际位置及准备状态；不另建接入台账 |
| 实际音频、导入设置、播放器/总线、消费场景与脚本 | 接入授权内新增或修改；保存外部原件，只处理实际需要的设置 |
| 旧音频与引用 | 获准替换时调整对应消费者，不连带移除无关素材 |
| 原任务验证与计划 | 来源变化时评估计划影响；最终版本恢复失效的验证与验收 |

## 8. 条件分支与路径规则

| 条件 | 路径与汇合位置 |
| --- | --- |
| 声音方向与合格文件均已具备 | 复用已有决定，从 S4 核对后进入 S5 |
| S4 文件尚在正常准备中 | 交接制作输入，暂停依赖素材的接入；到位后回 S4 |
| S5 播放实现有误 | 在原任务修复接入并重验 S5 |
| S5 素材不符合仍有效要求 | 回 S4 准备文件，再接入试听 |
| 用户确认要改变声音要求或触发行为 | 回所属来源入口，必要时转[计划对齐](requirements-change.md)，再返回相应步骤 |
| 尚未实际试听 | 保留待试听入口、操作与项目版本，不记录接受 |

## 9. 异常与非正常退出

| 无法继续的情况 | 停止范围、保留与恢复 |
| --- | --- |
| 必需文件无法取得或无法读取 | 保留规格和原件，暂停依赖接入；取得可用文件后回 S4 |
| 环境无法播放或触发路径不可运行 | 保留日志、场景与已知现象，恢复实际播放条件后回 S5 |
| 触发要求或采用决定冲突 | 暂停相关实现，交所属来源解决后回 S1/S3 |
| 试听问题需要超出授权的重制或重设计 | 保留具体问题和当前文件，补齐实质决定后回 S3/S4 |

## 10. 完成状态与验证标准

完整接入场景完成时：真实文件存在并已核对；游戏内触发、停止或切换符合要求；适用的相对音量、循环接缝、重复、截断与叠加已实际检查；用户听觉结论明确；规格、资源位置与清单一致；原 Feature 的后续验证责任清楚。

只交付规格或制作输入时，明确尚缺文件、接入或试听。接入和试听完成不自动满足原 Feature 的全部测试与最终验收。
