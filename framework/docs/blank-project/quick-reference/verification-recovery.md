# 测试失败与证据恢复

[速查入口](README.md) · [执行步骤](#5-执行步骤) · [步骤产出](#6-步骤产出与状态变化) · [卡住时](#9-异常与非正常退出) · [完成判定](#10-完成状态与验证标准)

## 1. 触发场景与使用时机

测试未启动、未发现预期套件、断言或引擎诊断失败，结果无法导入，或过去的成功不能用于当前内容。先确定失败发生在哪一层，再判断要修复环境、调用、测试还是实现。

## 2. 前置条件与适用范围

能定位失败尝试及相关项目，具备已有输出或知道哪些原件缺失。先收集材料和诊断；执行修复前须有具体授权、可确认的契约及写入前提。

本页处理验证恢复，终点是取得当前义务需要的有效结果并返回交付核对。只有运行行为异常、尚无测试失败材料时可先走 Bug。性能、长测等专项结果使用各自契约，不能伪装为 gdUnit 报告。

## 3. 参与角色与职责边界

| 主体 | 负责什么 |
| --- | --- |
| Agent | 保留失败现场，判断层次与责任，执行获准修复并核实实际覆盖 |
| 测试运行器、Godot、结果导入工具 | 分别执行测试/引擎动作、保存原件、检查并记录证据引用 |
| 用户或要求所属入口 | 解决不明确或冲突的预期，以及范围外的修复决定 |

只验证请求不自动授权修改实现。工具成功导入只证明其负责的条件成立，不代替静态检查、专业验证或人工接受。

## 4. 流程概览

保存失败现场 → 判断是否实际执行及失败层 → 核对有效预期 → 确定责任并修复 → 复验正确范围 → 导入有效原件 → 返回交付。

## 5. 执行步骤

提示词入口：只测与诊断用 `Godot 项目开发 → 验证与收尾 → 单独验证某次变更`，提供对象、报告及允许的验证范围；包含修复时沿用已有任务授权或 `修复与改进 → 定位与修复 Bug`。

1. **S1 固定失败尝试。** Agent 记录目录、版本/差异、Feature、命令、退出码与报告位置，核实未结束的进程状态。
2. **S2 判断失败层。** Agent 查看实际结果、发现列表、日志及原件，区分未启动、发现不完整、行为断言、引擎诊断与导入失败。
3. **S3 核对预期与责任。** Agent 比较确认要求、测试和实现，确定原任务、独立 Bug 或工具修复的归属。
4. **S4 完成获准修复。** Agent 针对真实原因修正环境、调用、测试或实现；行为缺陷按适用要求建立回归。
5. **S5 复验所需范围。** Agent 先验证原触发恢复，再取得当前 Required、affected 及必要 full 范围，核对最终内容与旧证据有效性。
6. **S6 导入并返回。** Agent 用实际结果路径导入满足义务的原件，核对引用后返回静态、专项及适用人工验收等交付检查。

命令与参数查[三种测试调用](../reference/commands-and-validation.md#三种常见测试调用)及[导入测试结果](../reference/commands-and-validation.md#导入测试结果)，在实际项目中使用其已确认工具路径。

## 6. 步骤产出与状态变化

| 步骤 | 直接产出与可继续的判据 |
| --- | --- |
| S1 | 可指出哪次尝试、哪个版本和范围失败，已有原件得到保留 |
| S2 | 失败层明确，或缺失材料及最小补查明确；命令退出 0 但仅显示帮助不算测试已执行 |
| S3 | 有来源依据的预期与责任分类；测试失败本身不证明测试错或实现错 |
| S4 | 针对原因的修复已完成，或缺少的授权/环境明确 |
| S5 | 最终版本的真实运行覆盖当前义务；较新失败被之后覆盖其失败范围的成功解决 |
| S6 | 需要的测试证据已有效导入；恢复验证链路，可继续剩余交付义务 |

## 7. 资源与文件影响

| 对象（生成项目内） | 影响类型与发生条件 |
| --- | --- |
| 失败命令输出、`result.json`、`engine.log`、发现与 JUnit 原件 | 读取并保留；通常位于 `reports/gdunit-wrapper/<Feature-ID>/run-<id>/` |
| 当前 Feature、Registry、来源与环境配置 | 读取；仅在诊断证明需要且授权允许时修改对应对象 |
| 测试代码、运行器或实际实现 | 按确认的责任修复；只验证场景不写入 |
| 新运行目录 | 真正重跑时新增，需保留历史时使用未占用的运行子目录 |
| `docs/feature-completion-evidence.json` | 导入时更新引用；失败导入可能清除旧测试引用，不能手改哈希恢复通过 |
| 原 Progress | 有阻塞或需要续接时更新具体停点及原件链接 |

## 8. 条件分支与路径规则

| 条件 | 路径与汇合位置 |
| --- | --- |
| 只有导入失败，已有满足当前义务的有效原件 | 修正引用后到 S6；不为修链接重复测试 |
| 未启动或发现不完整 | 查环境、参数、套件与运行器，到 S4/S5；不先改业务断言 |
| 测试预期错误或确认要求已变化 | 按真实来源修正测试及登记；要求变化先走[计划对齐](requirements-change.md) |
| 实现违反有效要求 | 当前任务内修复，或转 [Bug 场景](bug-fix.md)，再回 S5 |
| 同一内容有较新失败，旧成功或较窄成功不足以覆盖 | 补齐 S5 的真实覆盖后再到 S6 |
| 内容、范围和原件均满足的结果已存在 | 复用有效结果，完成缺少的检查和导入，不机械重复运行 |

## 9. 异常与非正常退出

| 无法继续的情况 | 停止范围、保留与恢复 |
| --- | --- |
| 原件不足，不能判断执行结果或覆盖 | 保留已有输出，补取最小所需材料；无法恢复时执行获准验证，不据摘要补 PASS |
| 环境、运行器或所需 full 范围不可用 | 暂停完成判定，记录具体缺口；条件恢复后回 S4/S5 |
| 预期冲突、修复未获准或修改归属未知 | 保留诊断与现场，只继续允许的只读工作；解决后回 S3/S4 |
| 导入仍因原件、版本或覆盖不符而失败 | 保留失败，回 S2/S5；不得转人工接受来抵消机器证据缺口 |

## 10. 完成状态与验证标准

失败原因和归属有实际依据；获准修复已完成；必要运行覆盖最终版本及当前义务；所需原件完整、引用有效且导入满足契约；未解决的失败或未完成运行已得到真实处置；可继续剩余交付检查。

JUnit 显示绿色但包装器失败、仅配置检查通过或仅报告文件存在，都不满足本场景完成条件。仅诊断时交付分类、证据与下一动作，明确恢复尚未完成。
