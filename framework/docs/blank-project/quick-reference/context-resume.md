# 恢复上下文并续接任务

[速查入口](README.md) · [执行步骤](#5-执行步骤) · [步骤产出](#6-步骤产出与状态变化) · [卡住时](#9-异常与非正常退出) · [完成判定](#10-完成状态与验证标准)

## 1. 触发场景与使用时机

对话压缩、中断、换对话或较久未继续后，不能确定当前任务、修改归属、批准范围或验证状态。任务事实已清楚、只想知道下一步时，可以直接使用只读指导入口。

## 2. 前置条件与适用范围

可访问实际项目或原 worktree，并有现存文件、Git 状态或交接材料可核对。不要求能够访问全部旧对话，也不要求工作区先变干净才开始只读恢复。

恢复写入前，必须核实目录、任务、差异归属、有效决定及本次授权。原任务 WIP 可在确认属于同一任务后继续；混合或未知修改先保留并澄清。本页终点是恢复事实与合法的下一动作，原任务交付仍按其自身流程推进。

## 3. 参与角色与职责边界

| 主体 | 负责什么 |
| --- | --- |
| 用户 | 说明本次是查状态、准备交接还是继续实施，补齐无法从材料恢复的实质决定 |
| 当前 Agent | 核对实际现场、现有记录与原件，恢复停点并执行仍有效的授权 |
| 原对话与接收对话中的 Agent | 原对话准备交接后停止实施；接收方重新核实同一项目或原 worktree 的现场 |

交接正文供用户复制，流程不自动创建或投递新对话。摘要是核对线索，不能替代真实文件、授权或验收结果。

## 4. 流程概览

核对现场 → 恢复任务与决定 → 核实验证和运行 → 判断可继续范围 → 输出状态、准备交接或续接原任务 → 接收方复核。

## 5. 执行步骤

提示词入口：`Godot 项目开发 → 日常开发 → 继续中断的当前任务 / 判断当前状态与下一步`；准备换对话时用 `验证与收尾 → 整理进度与任务交接`。提供实际项目位置、当前线索和本次目标。

1. **S1 核对真实现场。** Agent 检查项目/worktree 绝对路径、规则、分支、Git 差异、相关提交和当前 Progress。
2. **S2 恢复任务与决定。** Agent 读取当前任务、相关来源及必要历史，区分计划、已实现、失败尝试、放弃方案和仍有效授权。
3. **S3 核实证据与进程。** Agent 检查结果对应版本和覆盖，核实未结束运行与已落盘原件，识别失效或缺失结果。
4. **S4 确定下一动作。** Agent 结合当前范围、用户最新要求与实际反馈，判断可直接继续的步骤以及依赖缺口的部分。
5. **S5 按目标交付或续接。** 查状态时交付事实与建议；同对话续接时执行原任务；准备换对话时，在写入前提满足的范围内更新现有记录并生成可复制交接。
6. **S6 接收后复核。** 用户在同一项目或原 worktree 的新对话粘贴交接；接收方核对现场是否改变，再从有效停点继续。

## 6. 步骤产出与状态变化

| 步骤 | 直接产出与可继续的判据 |
| --- | --- |
| S1 | 目录、分支、暂存/未暂存/未跟踪内容与已知归属清楚 |
| S2 | 当前任务、Stage 或实际维护停点、有效决定及未知项可定位 |
| S3 | 有效、失败、未执行和过期结果分开，未结束运行没有被误当作失败或完成 |
| S4 | 可执行第一步和需要补齐的具体条件明确 |
| S5 | 有符合本次目标的状态说明、可用交接正文，或已经从原停点续接；没有人为创建新的完成状态 |
| S6 | 接收方已核对当前现场，能够从明确步骤继续；交接材料与实际冲突已处理 |

## 7. 资源与文件影响

| 对象（生成项目内） | 影响类型与发生条件 |
| --- | --- |
| 项目规则、配置、Git 分支/差异/历史 | 只读核对；不自动 stash、清空或提交未知改动 |
| 当前 Feature、来源、设计与必要历史 | 按缺口读取；没有 Feature 的工作不为恢复而造一个 |
| 原始测试、人工与审核材料，运行进程 | 核实版本与结果；不凭摘要生成或覆盖原件，不重复启动尚未结束的运行 |
| `docs/progress.md` 与现有历史链接 | 必要且获准时更新当前停点和引用，不复制整段聊天 |
| 对话中的交接正文 | 准备换对话时生成，包含目录、停点、差异、授权、证据及下一步 |
| 原任务代码或其他文件 | 真正续接后按原任务范围修改；仅查状态或交接不因此取得实施授权 |

## 8. 条件分支与路径规则

| 条件 | 路径与汇合位置 |
| --- | --- |
| 本次仅判断当前状态 | S4 后交付事实、未知与建议；不执行建议中的修改 |
| 同对话续接，现场和授权可核实 | S5 从原阶段继续，复用已完成且仍有效的工作 |
| 准备换对话，写入前提满足 | S5 更新必要现有记录并输出交接，原对话停止实施；新对话到 S6 |
| 准备换对话，暂不满足写入前提 | S5 保留全部现场，输出只读交接与缺口，接收方从 S1 复核 |
| 旧验证因源码或规格变化失效 | 返回原任务补足适用验证；只变动纯 Progress 历史不机械重跑 |
| 原任务正在等待人工验收 | 明确清单与实际入口，沿原[交付流程](feature-delivery.md)等待真实结果，不重复批准已定方案 |

## 9. 异常与非正常退出

| 无法继续的情况 | 停止范围、保留与恢复 |
| --- | --- |
| 目录不明，或改动归属混合/未知 | 暂停写入，保留所有文件；核实位置与归属后回 S1 |
| 只有摘要，无法确认关键授权或产品决定 | 明确未知及最小所需信息；补齐后回 S2/S4，不把“继续”当作缺失决定 |
| 原件缺失或摘要与实际结果矛盾 | 以可核实材料说明事实，转[验证恢复](verification-recovery.md)补足依据，再回 S3 |
| 交接后现场已经变化 | 接收方重查受影响部分，回 S1–S4，不照搬旧下一步 |

## 10. 完成状态与验证标准

恢复结果能指出真实项目和任务、当前停点、差异归属、仍有效授权、有效结果与剩余义务，以及第一项可执行动作或具体阻塞。

本次只查状态时，上述说明就是约定交付；准备交接时，正文能供接收方核对现场并找到第一步；续接实施时，恢复完成后继续原已授权工作。恢复或交接完成均不把原 Feature 记为 `done`。
