# 设计 UI 并验证视觉原型

[速查入口](README.md) · [执行步骤](#5-执行步骤) · [步骤产出](#6-步骤产出与状态变化) · [卡住时](#9-异常与非正常退出) · [完成判定](#10-完成状态与验证标准)

## 1. 触发场景与使用时机

需要新界面或明显的布局、素材变化，希望在接入依赖它的业务逻辑前，确认实际尺度、信息层级、可读性与操作感受。

## 2. 前置条件与适用范围

可定位当前界面目标、相关行为来源和本次范围。尚缺行为决定可以先澄清；写规格须有相应文档授权，建立和运行原型须有 Feature 或限定实验授权及可用 Godot 环境。

本页完整终点是原型取得实际体验结论并完成采纳交接。只请求规格时停在规格成果。已有验收过且适用的界面可复用；纯逻辑工作无需等待无关原型。

## 3. 参与角色与职责边界

| 主体 | 负责什么 |
| --- | --- |
| 用户 | 决定未明确的玩家行为，实际操作并反馈视觉与交互结果 |
| Agent / UI 规格入口 | 维护布局、状态、显示条件与待验证问题；行为变化交回 Product |
| Agent / 当前 Feature 或实验 | 建立原型、接入评估所需资源与交互、修正获准问题 |
| 用户或外部制作工具、Godot | 前者提供缺少的实际素材；Godot 负责真实显示和运行 |

UI 规格入口不因文档完成而自动取得场景实现授权。已有具体原型授权可跨步骤沿用。

## 4. 流程概览

明确界面任务 → 形成规格 → 准备代表性资源 → 建立独立原型 → 实际操作与修正 → 保存采纳结果 → 交回正式开发。

## 5. 执行步骤

提示词入口：`Godot 项目开发 → 需求设计 → 设计界面与交互`。提供界面目标、行为来源、目标显示条件和已有资源；原型执行沿当前 Feature 或获准实验继续。

1. **S1 明确使用任务。** Agent 核对玩家主要操作、核心状态、目标窗口与输入条件；用户解决影响当前原型的行为缺口。
2. **S2 写出 UI 规格。** Agent 在所属 UI 文件描述布局、层级、状态差异、真实内容与待验证问题。
3. **S3 核对代表性资源。** Agent 检查实际图片、字体和动画是否足够；缺少样本时更新同一资源清单并交接准备。
4. **S4 建立独立原型。** Agent 在授权任务内创建可单独运行的场景，接入本地样例状态及评估所需交互，展示必要的周围上下文。
5. **S5 实际操作与修正。** 用户在目标显示条件下检查尺度、裁切、文字密度、操作和状态辨识；Agent 按具体问题修正对应内容。
6. **S6 保存采纳结果。** Agent 写回确认要求，处理已有计划影响，把可复用布局和资源交回正式任务，明确样例状态与原型文件的去向。

## 6. 步骤产出与状态变化

| 步骤 | 直接产出与可继续的判据 |
| --- | --- |
| S1 | 界面用途、行为、主要状态与显示条件明确 |
| S2 | 当前原型需要验证什么可定位，确认要求与试验参数分开 |
| S3 | 资源足以代表当前评估对象，或缺口、来源和目标位置已说明 |
| S4 | 有独立入口、可复现初始状态和操作路径，主要界面状态可展示 |
| S5 | 有真实体验的接受或具体问题；未实际操作则仍待验收 |
| S6 | 确认规格、资源和采纳边界一致；正式任务知道采用什么以及尚需实现、验证什么 |

## 7. 资源与文件影响

| 对象（生成项目内） | 影响类型与发生条件 |
| --- | --- |
| Product、当前 Feature、适用 Art Bible | 读取行为、范围和共享风格；行为变化由所属入口处理 |
| `docs/ui/<interface>-design.md` 与目录导航 | 新建或修改当前界面规格及必要链接 |
| `docs/resource-requirements/<scope>.md` 与目录导航 | 按缺口更新同一清单、实际位置和准备状态 |
| 实际素材、原型 `.tscn`、必要脚本/主题/资源 | 原型授权内新增或修改；保留外部原件 |
| 样例状态与原型文件 | 采用时移除不应进入正式功能的样例状态；失去用途的文件按授权处理 |
| 计划及已有验证 | 来源实质变化时按同步流程更新；对最终内容恢复失效验证 |

## 8. 条件分支与路径规则

| 条件 | 路径与汇合位置 |
| --- | --- |
| 已有可复用且适用的验收基础 | 核对当前差异后进入 S6，保留新增部分的验证义务 |
| S3 缺少必需样本 | 正常交接素材准备；文件到位后回 S3，期间继续不依赖它的工作 |
| S5 发现布局或状态问题 | 回 S2/S4；素材不符则回 S3；调整后重新实际体验 |
| S5 尚未获得用户操作结果 | 保留待验收入口和操作说明，停在 S5，不当作异常或接受 |
| 确认要求改变并影响已有任务 | 转[计划对齐](requirements-change.md)，处理后回 S6 |
| 本次只做规格或限定实验 | 交付约定规格，或实验观察、采纳决定和文件去向；不扩为正式功能实现 |

## 9. 异常与非正常退出

| 无法继续的情况 | 停止范围、保留与恢复 |
| --- | --- |
| 玩家行为相互矛盾 | 暂停依赖的规格与实现，交所属来源解决后回 S1 |
| 原型不能启动或环境不可用 | 保留场景、错误和调用记录，恢复环境或修复启动问题后回 S4/S5 |
| 必需素材无法取得，无法评价目标问题 | 记录具体缺口和已完成内容，暂停该评估；取得替代或原素材后回 S3，不凭占位画面声称通过 |
| 所需修改超出原任务范围 | 保留问题和当前原型，取得缺少的实质决定后回对应步骤 |

## 10. 完成状态与验证标准

完整原型场景完成时：存在可单独运行的入口；在目标显示条件下完成实际操作；适用界面状态与问题有明确结论；确认要求和资源位置已写回；计划影响已处理；正式任务的采用范围、样例移除与后续验证清楚。

场景能启动、静态检查或截图只能证明各自事实。原型接受不证明正式业务逻辑、存档或整个 Feature 已完成。
