# 场景速查手册的编写与维护

本 README 面向编写者，约定场景的范围、标题、内容分类和维护方式。使用者从[场景索引](scenario-index.md)进入具体页面。当前先编写八篇 Markdown 样稿，讨论样稿后再迁移全部场景。

## 收录什么

收录使用框架开发项目时遇到的具体情境，包括正常推进、要求变化、问题处理和中断续接。每篇交付一个可验证结果。框架概念、配置字段和工具的完整用法由操作手册承担；框架源码维护由独立维护文档承担。

两本手册不互相引用。场景页就地提供必要输入、动作、参数和结果解释，不依赖另一册补齐关键步骤。相同工具可以被不同场景使用，同一场景的完整处理正文只维护一份。来源链接可以直接指向权威规范、实际工具或集中提示词库。

## 目录与单篇范围

采用“要处理的事情 → 当前状态 → 具体场景”。一级按事项分组；状态确实改变处理方式时再分二级，不机械凑满层数。目录只提供选择提示和链接，操作正文放在叶子页。

一篇场景应有明确入口、一个处理目标和一个可验证出口。多个步骤可以共同完成一个目标；出现不同入口、不同任务归属或两套完整处理路径时，应拆页。不要按单个命令碎片化拆分。

新页先检查已有场景。多个入口可指向同一页；同义场景合并，保留最容易识别的标题。任务结束条件与 Feature 的正式完成条件分别说明，不把准备、规划、接入或恢复完成写成 Feature 已交付。

## 标题与措辞

用“已经发生什么，现在遇到什么或想做什么”命名，例如“Feature 已经完成交付，后来又发现它有 Bug”。标题要在目录里独立可懂，不能只写“Bug 修复”“验证恢复”。

保留 Feature、Product 等项目中的准确名称，必要术语就地短释。区分“代码写完”“测试通过”“待人工验收”“完成交付”；不把口语化变成状态模糊。路径和示例 ID 必须说明所属项目与替换位置。

## 11 类信息如何使用

保留以下分类名称、边界和顺序，只展示有内容的栏目；空项省略，不写“无”或“不适用”。未知但会影响执行的信息写明缺口，不当作空项隐藏。正文标题不带固定栏目编号，避免省略后留下编号缺口。

| 分类 | 本栏只负责 |
| --- | --- |
| 触发场景与使用时机 | 什么事件使读者考虑这一页 |
| 前置条件与适用范围 | 当前能否开始，适用与不适用的范围 |
| 参与角色与职责边界 | 谁提供输入、决定、执行和验证 |
| 流程概览 | 从入口到本页出口的阶段路径 |
| 执行步骤 | 具体动作、执行者及操作对象 |
| 步骤产出与状态变化 | 对应步骤的直接结果与继续条件 |
| 资源与文件影响 | 按对象汇总读取、新增、修改和删除影响 |
| 条件分支与路径规则 | 必要的正常路径规则；不能在此塞入另一套完整流程 |
| 异常与非正常退出 | 无法继续的原因、保留内容与恢复位置 |
| 完成状态与验证标准 | 如何客观证明本页目标已经达到 |
| 流程关联与衔接关系 | 相关场景及规范依据，不重复选择规则 |

场景应尽量保持单一正常路径。没有分支就省略该栏；若需要在两套处理方法间选择，先收窄入口或拆成不同场景。正常等待用户体验属于当前步骤的待完成状态，不伪装成异常。

执行步骤使用本页 S1、S2 等编号，产出表按同编号对应；编号只帮助阅读，不新增 Stage 或项目状态。步骤栏写动作，产出栏写结果，避免复制同一段话。短场景可省略没有额外导航价值的流程概览。

## 写到什么程度

使用者应能从本页确认第一步、提供哪些材料、由谁操作、会改什么以及何时结束。Agent 的内部判断保留必要依据，不写成逐动作监督脚本。

可执行命令前写明工作目录、必要准备、替换参数及覆盖等副作用。步骤涉及既有工具时核对当前实际入口；解释工具结果的具体含义，不能把退出码为零泛称为整个任务完成。

项目路径相对生成后的游戏项目根目录，来源链接指向框架材料仅供核对，执行时采用项目自己的副本。保留用户已明确的授权及限制，不因拆页重新索取同一确认；页面出口也不终止仍需继续的已授权工作。

提示词正文统一在 [framework/prompts.json](../../../prompts.json)。页面只写准确入口名称、用途和所需输入，不复制正文或另存提示词文件。

## 写完如何核对

- 从标题、前提、步骤到出口检查是否始终围绕同一目标；用户不应在页内重新选择另一套处理流程。
- 核对实际规则、文件和工具；文章解释现有行为，不新增流程、状态、验收门槛或自动同步。
- 检查步骤和产出编号、内部链接与来源锚点；没有正文的后续场景标为待迁移，不制造空链接或假入口。
- 检查两本手册没有交叉引用，读者必需的动作没有藏在另一册。
- 当前只交付 Markdown，检查内容、路径、链接及锚点；不生成 HTML，不将旧构建成功写成本轮验证结果。样稿的阅读体验由用户反馈。

样稿讨论关注：能否找到自己的情况，能否明确开始与结束，步骤和产出是否便于对照，以及是否仍有应拆分的正文。后续迁移同时更新现有索引与引用，不建立新的流程台账。
