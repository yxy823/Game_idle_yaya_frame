# 场景速查手册

[打开独立 HTML 阅读版](quick-reference-handbook.html) · [完整使用手册](../README.md) · [原场景检查单](../guides/scenario-procedures.md)

遇到具体问题时，先选下面的一种情况，再直接进入该页的执行步骤。每页围绕一个目标，说明从触发到完成或移交的完整路径；八篇不是必须依次执行的开发阶段。

这是首批八个结构样稿，用于比较统一 11 栏的查找和操作体验。原专题提供详细解释与命令依据，实际工作仍遵循生成项目自己的规则、方法和 Skill。样稿中的流程说明不代表已经在真实游戏项目中执行或验证。

## 按当前情况选择

| 当前情况 | 场景样稿 | 本场景要得到什么 |
| --- | --- | --- |
| 有新功能想法或 GDD，尚无当前模块计划 | [新功能形成可执行计划](feature-planning.md) | 已确认来源、当前模块计划及实施入口 |
| 已确认要求改变，已有任务可能过时 | [需求变化后对齐已有计划](requirements-change.md) | 来源变化与任务、依赖、验证责任的对应 |
| 新界面或明显布局变化，需要先看实际效果 | [设计 UI 并验证视觉原型](ui-prototype.md) | 可运行原型、实际体验结论及采纳结果 |
| 需要音效或音乐，尚未完成准备与游戏内接入 | [声音准备、接入与试听](audio-integration.md) | 真实文件、游戏内播放与试听结论 |
| 出现异常行为，需要定位、修复并防止复发 | [Bug 定位、修复与回归](bug-fix.md) | 根因、修复和有效回归结果 |
| 测试或证据导入失败，不知道应该修哪里 | [测试失败与证据恢复](verification-recovery.md) | 失败层次、获准修复及可用验证依据 |
| 实现已写完，需要判断能否正式交付 | [Feature 验证、验收与交付](feature-delivery.md) | 满足完成条件并收尾，或明确剩余缺口 |
| 中断或换对话后，需要恢复现场继续工作 | [恢复上下文并续接任务](context-resume.md) | 当前任务、真实停点及可以执行的下一步 |

创建、迁移、独立审核、资源单独替换及其他场景，继续从[完整场景索引](../guides/scenario-procedures.md)进入。

## 每页怎样查

| 当前要判断什么 | 查哪一栏 |
| --- | --- |
| 这是不是我的情况，现在能否开始 | 1. 触发场景与使用时机；2. 前置条件与适用范围 |
| 谁来决定或执行，整体怎样推进 | 3. 参与角色与职责边界；4. 流程概览 |
| 当前做什么，做到什么程度可以继续 | 5. 执行步骤；6. 步骤产出与状态变化 |
| 会读写什么，条件不同怎样分流 | 7. 资源与文件影响；8. 条件分支与路径规则 |
| 卡住以后保留什么、怎样恢复 | 9. 异常与非正常退出 |
| 整个场景是否完成，接到哪里 | 10. 完成状态与验证标准；11. 流程关联与衔接关系 |

11 栏是信息目录。实际顺序以第 4、5、8 栏为准；每页顶部可直接跳到动作、产出、阻塞和完成判定。第 5 栏的 S1、S2 等步骤与第 6 栏同编号对应；S 编号只用于本页导航，不是新的 Stage、任务 ID 或台账字段。第 8 栏负责判断去向，第 11 栏集中提供相关流程与依据。

## 共用的操作边界

- **工作位置：** 八个场景均面向生成后的游戏项目。正文中的 `docs/`、`tools/`、场景与资源路径相对该项目根目录；来源链接指向框架材料，实际操作时核对项目自己的副本。`F0XX`、`<scope>` 等须换成真实对象。
- **范围与授权：** 用户提供目标、必要决定和真实体验结果，Agent 完成已有具体授权内的工作。只诊断、只规划、只写规格分别在其约定成果处结束；已有端到端授权继续沿用。人工接受必须来自实际反馈。
- **写入前提：** 新写入任务按项目规则从干净工作区开始；续接须核实未提交改动都属于原任务。混合或未知差异未厘清时保留现场，先做允许的只读核对。独立同步另有已提交来源前置，见需求变更样稿。
- **结果表述：** 第 6 栏中的“已定位”“待试听”等通常是事实描述，不自动写成 Feature 状态。场景完成、正常移交和 Feature `done` 分别判断；失败、未执行、过期依据和有效结果分别记录。
- **缺口与恢复：** 预期内的返工、交接和等待见第 8 栏；无法完成必要动作时见第 9 栏。只暂停依赖缺口的工作。没有相关内容写“不适用”，尚不知道则写“待确认”。

实际命令及准备见[命令与验证](../reference/commands-and-validation.md)。操作提示词正文统一在 [framework/prompts.json](../../../prompts.json)，各页只给入口名称和所需输入，不另存一份提示词。

## 试读时重点看什么

用一个当前真实问题查对应页，尝试找出第一步、该步产出以及失败后的返回位置。反馈时指出具体场景、栏目和卡住的文字即可，无需另填检查表。

| 样稿中需要检验的组织方式 | 重点观察 |
| --- | --- |
| 动作和产出分栏，以同一 S 编号对应 | 能否快速对照，是否频繁来回滚动 |
| 规划、原型、接入和交付各有场景终点 | 是否会误把准备完成或正常移交看成 Feature 完成 |
| 正常等待与阻塞分别说明 | 能否判断是在等已安排的交接，还是缺少继续所需条件 |
| 资源按对象和发生条件汇总 | 能否知道哪些文件只是读取，哪些在当前分支才会修改 |
| 每页保留 11 栏及顶部跳转 | 简单场景是否显得过长，栏目名称是否有助于查找 |

这批样稿暂与原检查单并存用于试读。确定采用方式时，再收敛重叠的操作正文与导航；当前不替换原流程说明。Markdown 原文只在本目录维护，HTML 由[现有生成器](../../../commands/build_blank_project_handbook.py)的 `--quick-reference` 入口生成，构建方法见[维护说明](../maintenance/updating-the-blank-project.md#生成离线阅读版)。本目录不进入项目复制清单。
