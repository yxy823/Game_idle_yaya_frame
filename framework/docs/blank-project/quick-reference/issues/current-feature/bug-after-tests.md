# 测试通过了，但试玩时发现本次改动还有 Bug

[返回场景索引](../../scenario-index.md#问题修复) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

当前 Feature 的自动测试已经通过，试玩本次改动时又发现实际行为不符合原要求。

## 前置条件与适用范围

Feature 尚未完成交付，问题属于本次未完成任务，预期仍然有效，已有修复授权。能够访问项目和现象材料；不要求先稳定复现才开始调查。

本页修复当前任务内的缺陷。出问题的行为已正式交付时，使用[交付后发现 Bug](../completed-feature/bug-after-delivery.md)。用户改变原要求、无关功能出错或只请求诊断时，先按对应范围处理。

## 参与角色与职责边界

用户提供实际表现与试玩材料，并完成适用人工复验；Agent 在原任务内定位、修复和核对验证；测试工具与 Godot 提供真实运行结果。先前测试通过不能推翻新的失败事实。

## 流程概览

保留新问题 → 查明根因 → 补回归并修复 → 验证最终内容 → 回到原任务交付检查。

## 执行步骤

在当前任务中提供期望、实际表现、触发条件及日志、截图等证据，沿用原修复授权。

1. **S1 固定问题。** Agent 核对本次版本和未提交差异，记录原始现象、要求来源及最短已知触发。
2. **S2 查明根因。** Agent 检查相关代码、场景、资源及调用关系，把证据支持的原因与待验证假设分开。
3. **S3 修复并补回归。** Agent 针对原触发补足有意义的回归保护，实施当前范围内的最小完整修复。自动化不合理时，说明原因并采用可重复人工路径。
4. **S4 验证最终内容。** Agent 复验原问题和当前义务要求的受影响范围，记录有效结果；用户完成适用的人工复验。
5. **S5 接回交付检查。** Agent 将原因、修复、真实结果与剩余义务记录到当前任务，继续原 Feature 的完成核对。

## 步骤产出与状态变化

| 步骤 | 产出与继续条件 |
| --- | --- |
| S1 | 实际差异和现象有记录，原失败材料保留 |
| S2 | 根因有证据；尚未确认时不能跳到修复完成 |
| S3 | 修复针对真实原因，回归能够暴露原错误 |
| S4 | 最终内容满足适用验证，原问题得到复验，实际人工结果有效 |
| S5 | 修复可交回原任务收尾，Feature 仍按全部完成条件判断状态 |

## 资源与文件影响

| 项目内对象 | 影响 |
| --- | --- |
| 当前 Feature、AC、专业规格、原始材料 | 读取有效预期和范围，保留失败事实 |
| 出错的代码、场景或资源 | 修改当前任务内的实现 |
| 测试代码及 `docs/test-registry.json` | 按实际需要补充回归与登记 |
| 本次运行报告、完成依据、当前任务记录 | 保存和引用真实结果，更新必要诊断与进展 |
| 已确认需求 | 不为迎合错误实现而改写 |

## 异常与非正常退出

缺少现场或日志导致根因无法推进时，保留尝试和具体未知，只补取所需材料；一次未复现不能作为修复证据。环境无法验证时，保留修复和错误，暂停完成结论。

发现问题属于已交付行为或新的要求时，停止扩大当前修复范围，交回对应入口。修复后原问题仍在，继续当前根因调查；不会因已有绿色测试而忽略实际失败。

## 完成状态与验证标准

根因有证据，修复归属原任务；针对原问题的回归成立，最终内容已取得适用验证及真实人工结果，必要诊断和剩余义务可定位。本页完成表示这次缺陷修复可以交回收尾，不直接代表整个 Feature 已完成。

## 流程关联与衔接关系

测试结果有效但引用导入错误时，可使用[结果导入恢复](../../verification/existing-results/import-passed-tests.md)。其他交付场景待后续迁移，本页不省略原任务已有的完成义务。
