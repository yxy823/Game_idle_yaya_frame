# 专业来源与资源

[操作手册](../README.md)

专业设计描述要求，资源准备提供真实文件，接入建立运行关系，验证和审核取得不同性质的证据。一个任务只使用所需能力；存在 Art Bible 或 Sound Bible 的占位文件，不要求先设计整款游戏的美术和声音。

专业设计、接入、测量和审核遵守同一 [GDD 前提](../../../../project-source/methodology/01-product-doc-structure.md#gdd-prerequisite-and-authority)：项目须已有真实设计正文，缺少时停止。已有 GDD 不必预先写完所有专业细节；本次依赖的决定明确后即可处理当前范围。

## 来源的唯一维护者

| 内容 | 项目位置 | 维护 Skill |
| --- | --- | --- |
| 游戏设计、玩家行为与反馈意图 | `docs/gdd/` | `product-author` 维护已有设计 |
| 交付预拆分与当前 Product 范围 | `docs/product.md`、`docs/product/` | `product-author` |
| 含义不变的共享定义 | `docs/terminology.md`；局部定义可留在所属 GDD 或专业来源 | `project-terminology` |
| 共享视觉方向 | `docs/art/art-bible.md` | `design-art-direction` |
| 共享声音方向 | `docs/audio/sound-bible.md` | `design-audio-direction` |
| 界面布局与状态要求 | `docs/ui/<interface>-design.md` | `design-ui-spec` |
| 具体视觉资源准备要求 | `docs/resource-requirements/<scope>.md` 中对应条目 | `design-visual-asset-spec` |
| 具体音频资源准备要求 | 同一业务范围资源清单的对应条目 | `design-audio-asset-spec` |
| 语言覆盖、回退、排版与翻译惯例 | `docs/localization/localization-spec.md` | `design-localization-spec` |
| 已定要求的实际资源接入 | 当前 Feature/实验的资源、引用与配置 | `content-asset-integration` |
| 已定本地化要求的运行实现 | 翻译资源、字体、界面适配与语言逻辑 | `content-localization` |

专业文档把 GDD 的设计意图细化为可使用、可验证的规格；GDD 已定义的细节直接引用，不另存一套正文。Product 选择交付范围并保存必要引用。专业 Skill 继续维护自己的规格，专业工作若改变游戏规则或已确认整体方向，则由 `product-author` 协同更新 GDD。维护职责不授权自行采用未决要求；本地化翻译用词也不能改玩法语义。

## 来源如何约束任务

Feature 有一个主 `source`，相应 GDD 规则及其他适用专业要求在 AC 或设计中精确引用。共享来源的适用范围、实际依赖与引用共同确定消费者；“符合 GDD”或“符合 Art Bible”不是充分的 AC，应描述本任务的实际状态、尺度和可观察结果。

要求变化由所属入口修改来源，并分析已规划任务；实现违反已确认专业要求可以作为 Bug 依据，不要求再抄一份 Product。未经采用的设计建议不是缺陷。旧同步锚点也不自动证明新纳入来源曾被吸收，历史未知与当前对齐分开说明。

GDD、规格、资源清单及本地化要求在最终验证前完成本轮必要更新。这些文件按当前全局指纹契约参与内容绑定，准备状态或文字变化也可能使旧结果失效；GDD 目录中的 README 同样参与。约束正文不能只藏在豁免指纹的普通 README、notes、知识或报告中。

## 素材准备清单

清单以稳定业务范围命名，如 `docs/resource-requirements/<业务范围>-<用途>.md`，不按每个 Feature 或收件批次复制。资源 ID 在该清单内唯一；详细规格确有需要时按 ID 链接，不再建第二份接入台账。

| 基础字段 | 说明 |
| --- | --- |
| 资源 ID、文件名、类型、用途 | 可追溯同一对象；文件名是候选还是已存在须清楚 |
| 尺寸、风格、格式 | 视觉写源像素、显示尺寸与透明留白后的主体尺度；音频另说明时长、声道、循环和播放条件 |
| 状态、备注 | 区分待准备、已收到、已检查和实际接入；未知明确待定，不适用写明不适用 |

以上九类基础列可按实际资产增补。

- **补充信息：** 来源、许可、样本、目标位置和待体验问题留在条目或引用中；无法核实的许可不能编造。
- **复用与授权：** 先复用合适的现有素材、主题或程序表现，资源清单请求本身不授权制作、购买、复制外部文件或实现。

框架当前覆盖准备要求、接收和检查素材；视觉美术、音乐、音效的实际制作能力保留待扩展边界。没有提供相应制作 Skill 或统一生产工具。用户或另行授权的外部制作流程交付真实文件；参考图、占位文件名或规格文档不是成品，缺少样本只阻塞依赖它的工作。

## 视觉原型与实际接入

UI 规格描述信息层级、ASCII 布局、状态差异、显示条件和待验证问题；节点、路径和参数属于实现。新界面或明显布局变化需要能单独运行的 Godot 原型作为视觉判断材料，已有且适用的有效基础可复用。

- **原型范围：** 位于已授权 Feature 或限定实验，可用本地样例状态、Hover、焦点等必要交互；不默认接入正式存档和业务规则。
- **判断条件：** 真实素材、目标窗口、缩放、空/密集状态、裁切与可读性共同影响结论，图片原始像素不足以证明主体尺寸合适。
- **接受与采用：** 原型接受只覆盖原型范围，正式业务仍有独立验证义务；采用后处理样例状态与失去用途的副本，不长期维护两套竞争界面。

素材接入时：

- 对照实际文件、规格、源记录和消费者，检查导入设置、路径/UID、场景/主题/代码绑定。
- 声音的触发、停止、循环接缝、重复叠加和相对音量要在真实场景下试听；文件存在或播放器启动不能证明听觉效果可接受。
- 保存外部原件和无关资产，不盲目重导整个库。

占位资源采用 `_placeholder_` 前缀并在原任务说明用途、替换及验收缺口。源资源、导入结果、工作台预览与正式游戏分别有验证边界；示例通过不能替代游戏 Feature 完成。

## 测量与实现

- `diagnostics-instrumentation` 提供有目的、单位和成本边界的日志、计数或时序信号。
- `diagnostics-performance` 获取可重复负载下的测量和瓶颈依据。
- `diagnostics-soak-test` 获取明确时长与停止条件下的趋势和失败。

只有静态猜测时不能写成已定位瓶颈。

- **授权与副作用：** 仅测量与诊断不自动授权持久优化，日志、缓存和报告仍有副作用。接入、本地化、埋点和优化的持久修改由原 Feature、限定实验或获准工程任务承接。
- **版本与测量条件：** 临时埋点版本与最终交付版本分开，可比性要包含设备、引擎版本、场景、负载、参数和测量条件；计划六小时只实际运行四十分钟仍有缺口。

专项结果不能包装为 gdUnit 成功；完成工具也不负责判断性能、长测或感官证据充分性。修复后相应真实检查仍适用。

## 独立审核

`review-code`、`review-ux`、`review-art`、`review-audio`、`review-assets`、`review-localization` 和 `review-balance` 分别核对自己的对象。同一个新上下文可以使用多个适用方法，不要求每项 Skill 各审一轮，也没有默认每个 Feature 都独立审核的要求。

- **审核输入：** 包括明确范围、权威来源、实际版本/差异、原始证据与允许运行范围。
- **快照范围：** 应包含相关未提交内容，只复制 HEAD 可能漏掉本次成果。
- **独立性：** 作者解释是待核实陈述；作者自查不能称为独立审核，角色配置存在也不证明独立性或隔离成立。

被审成果、原验收记录和原证据只读。获准的针对性验证使用安全副本或指定外部验证环境，将日志、缓存、导入和测试数据一起隔离；只改报告目录不够，不为此引入 worktree 流程。条件不足时保留未验证项，未实际看到或听到时不宣称视觉/音频体验通过。

现状审核无需 Feature 或虚构差异基线，但仍须已有 GDD。某项具体要求缺失时，限定符合性结论，在其余有依据的范围内检查质量。报告说明检查版本、实际覆盖、问题、依据和限制；过程中成果变化时限定结论或补查对应变化。

报告默认在对话，需留存时在相应 `reports/features/` 或 `reports/maintenance/`。报告已交付、审核条件满足、用户人工接受是三个不同事实。发现的优先级不授予修复权限；确认的完成阻断项也不能因为审核可选而忽略。

权威边界见 [专业职责规范](../../../../project-source/methodology/11-specialist-workflows.md) 和 [独立审核规范](../../../../project-source/methodology/12-independent-review.md)。
