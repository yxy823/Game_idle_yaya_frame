# 知识、设计与记录

[操作手册](../README.md)

长期定义、当前结构、历史决定、外部调研和执行进度有不同职责。按实际需要保存一次并互相链接，不因为有模板就创建全部文件，也不把要求放进工具不读取的过程记录。

## 文档选择

| 材料 | 内容与边界 |
| --- | --- |
| `docs/gdd/` | 持续维护的游戏设计正文；是项目开发前提，目录说明和空模板不满足此前提 |
| `docs/product.md` / `docs/product/NN-name.md` | 交付预拆分及当前交付范围；具体 Product 轮到时才写，链接 GDD 而不复制规则 |
| `docs/terminology.md` | 可复用标准名称、定义、范围、关系、别名与易混淆项；不放数值、完整行为或当前计划 |
| `docs/features/F0XX-design.md` | 需要较长解释的局部设计：职责、生命周期、接口、失败处理、顺序及验证理由；Feature JSON 仍拥有 AC 和验证义务 |
| `docs/architecture.md` | 当前结构的模块位置、状态所有者、依赖和阅读入口；不枚举全仓文件或复制历史设计 |
| `docs/architecture/` | 需要展开的子系统、重要 ADR；从架构总览导航 |
| `docs/project-rules.md` | 项目长期适用约束；强度区分 MUST / PREFER / REVIEW |
| Feature notes | 该任务局部决定、真实根因、链接与有价值的过程信息 |
| `docs/knowledge/` | 可复用的项目实践及适用条件；不是规则或需求的替代正文 |
| `docs/research/` | 外部来源的结论、证据、建议和未知项；不是项目已经实测的经验 |
| `docs/unadopted-ideas.md` | 暂未采纳的设想及其原因；不构成开发承诺，采纳后链接 GDD、Product 交付范围或对应专业来源 |
| `docs/progress.md` | 当前任务/阶段、真实阻塞、未决项、下一步及资料链接 |

术语由 `project-terminology` 维护；只有实质歧义才由 `project-grill-me` 讨论。确认且保持含义的定义直接保存，不能强迫重新访谈。行为、数值与状态转换归 GDD，专业语言要求归对应来源。以上项目工作同样遵守 [GDD 前提](../../../../project-source/methodology/01-product-doc-structure.md#gdd-prerequisite-and-authority)。

## 局部设计与当前架构

Feature 设计是可选材料，简单任务只需 notes。

- **引用位置：** 在该 Feature JSON 的 notes 中使用相对链接 `[设计说明](F0XX-design.md)`。
- **保存与更新：** 方案批准后保存设计，实际实现改变时对齐。
- **理由与依据：** 引用适用工程规则并解释用途，不复制整本规则。

架构地图在源码难以表达模块关系时才有价值。总览区分实际直接协作与允许的依赖方向，说明谁创建/释放状态、谁有权修改及关键入口。模块 README 已能导航时链接即可，不预设 Bootstrap 或 Autoload。运行说明可按需包含触发、状态变化、Godot 生命周期和失败路径。

图中的箭头要分清代码依赖、装配、继承、消息或时序；静态引用搜索不证明动态加载、运行时 Signal 和真实状态归属。观察、推断、建议和已实现行为分别表述。地图更新职责、路径、入口和理由，旧设计正确记录过去时保留历史，不改成一直如此。

设计新核心对象或调整结构时，实际判断来自已确认行为、状态与生命周期、调用方负担及真实依赖。比较复用、不改、局部修正、删除/合并与必要新增；API 更短、文件更少或采用模式本身都不是收益。枚举状态、Command、序列化或新管理层只服务实际用途，不为假想未来预建体系。具体方法见 [架构规范](../../../../project-source/methodology/10-architecture-overview.md)。

## ADR 的阈值

ADR 使用 `docs/architecture/adr-NNNN-<slug>.md`，同时考虑：

- 撤销是否有实质成本。
- 仅靠源码和当前结构是否难以恢复原因。
- 是否确有候选与重要取舍。

普通局部选择留在设计或 notes；独立架构讨论可以保存已获准 ADR，不必虚构 Feature。

记录问题、约束、候选、决定、收益、成本、依据和有用的重新考虑条件。Proposed、Accepted、Superseded 是普通文档状态，后者保留旧理由并链接替代决定；Accepted 说明决定已确认，不证明代码运行通过。已有具体授权直接沿用，不加额外批准。

## 项目规则与领域规则

- **根 AGENTS：** 规则入口。
- **`docs/project-rules.md`：** 项目约束。
- **`agent-rules/`：** 按领域提供工程语义。
- **`methodology/`：** 流程和验证。

领域可叠加，例如测试 `.gd` 同时遵循脚本与测试规则。按当前修改读取领域 README 的相关路由，不每轮通读全部目录。

| 领域 | 规则目录 |
| --- | --- |
| 通用、GDScript | `00-core/`、`10-gdscript/` |
| Scene、Resource、Shader | `20-scenes/`、`21-resources/`、`30-shaders/` |
| 项目配置、导出 | `40-project-config/`、`41-export-config/` |
| 数据、资产、测试 | `50-data-files/`、`60-assets/`、`70-tests/` |

规则可能过时或范围过宽。怀疑错误时说明具体条款、事实与影响，将代码符合性和规则正确性分别判断；合理的 PREFER 偏离不必自动改规则。不能因个人偏好暗中豁免约束，也不把每个 Bug 教训升级为硬规则。

增改删规则的写前自检保留在对话；一批可合并说明但各项可对应：

- **变化与依据：** 说明原文和变化、真实依据、长期价值与归属。
- **范围与影响：** 说明强度/范围、重复或冲突、下游影响。
- **判断与授权：** 说明结论及已有授权。
- **特定修改：** 删除解释承接位置或不再需要的原因，措辞/链接修订说明语义和强度不变。

没有规则变化不生成报告，不新建规则台账。

规则变化先处理当前任务的实际影响，沿用具体授权；新决定才等待用户。原 Feature 内辅助文档不另起“必须清空工作区”的任务。适用记录在最终验证前定稿，较晚采纳也检查失效依据。唯一细则见 [规则增量维护](../../../../project-source/methodology/04-coding-rules-4-layers.md#incremental-rule-maintenance)。

## 调研与项目知识

调研按问题需要进行，可直接查询或委派 researcher，不是每个 Feature 必经阶段。涉及引擎/API 写明实际版本，核对所读页面；stable/latest 不代替版本号。一手来源事实、项目推断、本地实测分别说明，损坏抽取或遗漏代码保留原文链接及限制。

有长期价值时写 `docs/research/<明确主题>.md`，同主题优先维护已有报告，重要结论变化保留日期、原因与被引用历史。最低信息为问题与范围、日期和适用环境、结论、依据、建议、未知；角色文件维护详细报告约定。采纳的游戏设计回到 GDD，交付安排回到 Product，其他决定回到专业来源、设计或 ADR，不让研究建议自动变成要求。

知识目录初始有 `godot-runtime/`、`gdscript/`、`debugging-testing/`、`tools-pipeline/` 主题索引。

- **保存与索引：** 每条独立经验保存一个 Markdown，索引链接和简述；按真实内容扩展，不每个 Feature 建目录，不多处复制。
- **查阅与续接：** 规划、调试、实现或审核按问题定位相关已有经验并核对版本条件；空索引不阻塞，续接复用有效已读内容。

- **经验内容：** 说明场景、有效做法或根因、适用范围与真实依据；成功经验不必编造根因。Feature notes 保存原事件，知识提炼方法并链接原件。
- **落盘授权：** 只读请求不因此获得落盘权限，有价值的已授权知识在收尾提交前保存。
- **验证影响：** 纯知识/调研 Markdown 不使业务测试指纹失效，可执行文件、规则和契约仍按实际范围检查。

## 报告与历史

工具原件使用固定路径，自定义结果按 [目录说明](../框架基础/project-layout.md#模板与按需记录) 放置；正式证据和临时输入分开。直接引用 gdUnit 原件，额外控制台日志只补原件没有的信息，不新建报告总索引或用文件名 final 代替有效结果。

- **临时材料：** 需要跨任务保留时，在现有 notes/Progress 说明用途和结束保留条件。
- **证据保留：** 当前验收、未解决失败、后续工作、历史与知识引用需要的证据继续保留。
- **归组与迁移：** 核对生成命令、读取脚本和引用，不能只移动文件；工具原件不随意迁移。
- **清理范围：** 清理是需明确范围的维护动作，旧、未跟踪、后有成功或目录名 scratch 都不等于可删除。

Progress 保存真实停点和必要链接，不能由“下一步实施”推断批准。正式完成的执行历史归档一份到 `docs/progress/<key>.md`，已有记录先读，保留原文和证据；未解决事项仍留当前交接，不每阶段重复复制报告。代码提交不保证默认忽略的报告存在于另一目录或机器。

## 任务续接的信息契约

交接正文按以下主题保留信息：

- **当前现场：** 真实项目路径、分支和现有差异。
- **任务与决定：** 目标与最新要求、有效决定/授权、实际阶段。
- **验证与后续：** 已做和未做的验证、证据及下一步。

未知保持未知，未结束命令说明已知状态。原对话交接后停止实施，接收方在该任务的目标工作目录核对实际文件再继续；普通同目录续接沿用原目录，已有明确 worktree 目标时以该目标为准。

会话摘要帮助定位，不替代权威文件；不要求为换对话清空现场、提交半成品、另开分支、建 worktree 或重跑全部检查。具体交接步骤的临时只读/输出限制不永久覆盖接收方后续已授权任务。这里不建立 Handoff 文件、CONTEXT.md 或平行任务状态表。
