# 错误与结果的含义

[操作手册](../README.md)

本页解释工具输出，具体恢复任务按其实际范围处理。先区分环境、调用、发现、行为断言、引擎诊断和记录导入，不把所有非零退出都解释为游戏 Bug，也不把文件或成功摘要当作完整证据。

## 创建与环境

| 现象 | 含义与需要核对的对象 |
| --- | --- |
| 创建器拒绝目标 | 目标可能是文件、非空目录、其他仓库范围，或路径含中文/空白、与框架存在祖先/后代关系；拒绝不是覆盖许可 |
| 复制/Git 失败后留下目录 | 创建器没有自动回滚；保留原输出判断哪些动作完成，不凭目录存在报告创建成功 |
| 普通配置检查成功 | 字段结构满足检查；Godot 暂时为空也可能合法，不能当作 require-ready 通过 |
| Godot 文件存在但就绪失败 | 实际启动、返回码或版本不满足；目录名不证明 4.7.x 可执行 |
| 相对路径或带参数路径错误 | Godot 相对项目根解析，不能写 shell 引号、参数或裸 PATH 命令；Python 支持已确认的 PATH 命令名 |
| CLI 缺测试基类/运行器全局类 | 首次资源/类扫描可能未完成，测试尚未实际执行；就绪检查不完成扫描 |
| Windows GUI 命令退出码缺失 | 可能没有等待结束；空值不能当作零。命令例子的 Out-Host 用于等待 |
| 权限、AppData、缓存或沙箱错误 | 先按实际环境规则定位；不能据此修改业务断言、删除未核实目录或宣称引擎行为错误 |

配置与就绪检查边界见 [配置参考](../框架基础/configuration.md)，创建器副作用见 [框架与项目](../框架基础/framework-and-project.md#创建器用法)。

## 台账与任务

| 现象 | 结果边界 |
| --- | --- |
| 索引或必要详情缺失 | 不是“空项目已初始化”；应保留真实文件状态 |
| eligible 为空 | 当前没有依赖就绪的 pending 项；可能阻塞，不等于所有 Product 完成 |
| ID、依赖循环、废弃依赖或引用不一致 | 计划结构或历史关系不满足契约；结构错误不能通过任意改完成状态消除 |
| 组件没有单元测试路径 | `unit_test_paths: []` 合法；已登记却缺失的路径是另一种错误 |
| planned 或 retired 用于当前完成 | 不能代替真实 active 映射；可追溯历史接受退役记录不意味着当前 Feature 可以使用它完成 |
| 修改 AC 后测试通过 | 是否已正式采用新意图仍需真实决定；不能由绿色测试推断需求获准 |

## 测试与完成依据

| 输出或现象 | 可据此判断什么 |
| --- | --- |
| 零测试、发现集合不完整、必需 case 跳过 | 不满足覆盖；源文件有方法不等于实际执行 |
| focused / baseline 通过 | 只证明该次用途与范围，不可直接导入为最终 Feature 完成依据 |
| JUnit 绿色但 wrapper 失败 | 仍可能存在引擎诊断、退出、覆盖或报告问题，不能改 wrapper 结果为通过 |
| 超时、result 仍 running | 当前运行未取得完整成功；旧摘要不能补全原件，也不应并发重复同一运行 |
| 运行器提示历史结果无效 | 该历史文件不能提供有效依据；继续测试与是否可正式完成由当前结果及契约分别判断 |
| 报告写入失败或仅打印路径 | 路径不是原件存在的证明；保留真实输出与缺失范围 |
| record-tests 非零 | 本次测试引用导入失败，旧测试引用被清除；原件仍在，不手填哈希或通过次数 |
| show 退出 0 | 文件结构与 Feature 身份匹配、记录可展示；pending 或不足以完成的记录也可成功展示 |
| validate 退出 0 | 工具负责的自动与适用人工依据满足；不包括直接静态、独立评审、性能或所有平台 |
| record-acceptance 退出 0 | 实际状态已记录，可能 accepted/rejected/pending；不是自动完成 |
| 人工 JSON 导入失败 | 文件、版本、覆盖或内容不满足契约；旧记录被保留也不能抵消本次错误 |
| 合法 not_required | 当前有效 manual 计划无自动义务且无阻断条件；不是自动测试 PASS，仍需其余义务 |

较新的失败需要后来的充分成功覆盖，不能拿更早或更窄通过抵消。测试预期和实现哪方错误，依据已确认 Product、专业规格或工具契约判断；缺少意图不能先改断言求绿。

指纹失效不只来自代码：术语、专业规格、设计、规则、架构或资源状态的字节变化都可能影响。Progress 历史、知识和调研 Markdown 等有特定豁免，不能泛化成“文档都不影响”。原件缺失是未知，不是修改摘要或哈希即可修复的状态。准确边界和退出码见 [命令与验证证据](commands-and-evidence.md)。

## 引擎诊断和专项观察

`Orphan StringName`、`Unclaimed StringNames` 等 verbose 输出本身不能证明业务泄漏。同版本同参数且不含业务的最小对照有助于定位，但出现相同信息也不足以直接断言是引擎缺陷；退出零同样不证明无泄漏。保留版本、复现、原件和仍未知的影响。

场景启动、图片显示、声音试听、输入、长时间运行、资源包或导出依赖都需要对应实际结果。静态检查、一次 F6、运行器成功或人工清单已生成不能互相代替。未执行、失败、报告丢失、旧版本成功分别报告，不压缩成“没有问题”。

工具的实际错误契约见 [工具说明](../../../../project-source/tools/README.md)、[测试策略](../../../../project-source/methodology/08-testing-strategy.md) 和 [人工验收文件契约](../../../../project-source/methodology/manual-acceptance-files.md)。
