# 界面布局已经确定，想先做一个能点击的原型

[返回场景索引](../../scenario-index.md#界面与资源接入) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

纸面布局已经明确，需要在接入依赖它的业务逻辑前，实际检查按钮、文字和状态切换是否合用。

## 前置条件与适用范围

当前 Feature 已包含明确的原型工作及运行授权。界面规格、主要状态、目标窗口和输入方式已确认，代表性图片、字体等素材已具备，Godot 环境可运行。

本页从已定方案建立原型。设计尚未明确、必需素材仍缺失或只是讨论规格时，先完成对应准备；独立技术实验另按其实验范围处理。

## 参与角色与职责边界

Agent 建立并检查原型；Godot 实际显示和运行；用户操作原型，给出视觉与交互体验结论。Agent 的截图或启动结果不能替代用户的体验反馈。

## 流程概览

确认本次体验点 → 建立可运行原型 → 检查入口 → 实际体验 → 保存结论和采纳范围。

## 执行步骤

使用 [集中提示词库](../../../../prompts.json)中的“Godot 项目开发 → 日常开发 → 执行指定或下一项 Feature”。填入真实 Feature ID，并在补充范围中限定本次原型、界面规格、素材位置、目标窗口与输入方式。当前 Agent 使用 [$feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md)继续该任务；框架没有单独的原型制作 Skill 或原型 Agent。

**S1｜列出体验点**

Agent 从当前 Feature 和已确认界面规格中提取需要体验的布局、文字、操作及状态，列出实际场景入口、初始状态和可切换的样例状态。`design-ui-spec` 负责上游规格，本步读取既有结果，不重新设计整套界面。

**S2｜建立原型**

Agent 在 `feature-execute` 的实现范围内创建可单独运行的 Godot 场景，接入代表性图片、字体、主题和最少的交互脚本。用明确的本地样例数据驱动主要状态，避免把样例误接为正式业务或存档数据。

**S3｜检查运行**

Agent 读取 `docs/methodology-config.json` 中的 Godot 路径，在实际游戏项目打开该场景。按 [解析与 lint 规范](../../../../../project-source/methodology/gdscript-lint.md)检查受影响脚本，并完成适用的测试；实际运行并操作主要路径，保留启动、输入和状态切换的问题。

**S4｜进行体验**

Agent 给出场景路径、启动方式、样例状态及待体验操作；用户在约定窗口和输入条件下实际操作。Agent 修正本次范围内偏离有效要求的问题，再让用户复验受影响部分。截图、自动测试和启动成功均不替代实际体验。

**S5｜保存结论**

Agent 依 `feature-execute` 的记录要求保存实际反馈与接受范围，标明采用的布局、资源位置及样例代码后续如何处理。将尚未实现的业务行为留在当前任务中，继续原 Feature 的后续工作。

本页由当前执行 Agent 和用户协作完成；独立审核仅在用户明确指定时，按所选范围交给 `independent-reviewer`，不把原型制作自动变为独立 UX 审核。

## 步骤产出与状态变化

| 步骤 | 产出与继续条件 |
| --- | --- |
| S1 | 体验点与实际入口明确 |
| S2 | 原型具备主要状态和可操作路径 |
| S3 | 原型真实运行，已知启动或交互问题有结果 |
| S4 | 当前版本取得对应范围的实际体验结论；未体验时仍停留本步 |
| S5 | 采纳哪些布局与资源、还需实现什么已说明 |

## 资源与文件影响

| 项目内对象 | 影响 |
| --- | --- |
| Product、Feature、界面规格 | 读取已确认范围；仅定稿本次确实改变的规格内容 |
| 原型场景、必要脚本、主题和样例状态 | 新增或修改 |
| 代表性素材与资源清单 | 使用实际文件，记录当前位置与准备情况 |
| 当前任务记录 | 保存真实体验结果与采用范围，不新建原型台账 |

## 阻塞、异常与范围变化

原型无法启动或主要状态不可到达时，保留原型和错误，先修复本次运行问题再回 S3。素材不能代表目标效果时，暂停依赖它的体验结论，补齐素材后重验。

反馈改变了已确认要求，或需要超出原型范围的实现时，保留原型及反馈，交回要求所属入口处理。用户尚未操作属于正常待体验，不记录接受，也不把等待本身标成执行失败。

## 完成状态与验证标准

原型有可单独运行的入口，主要状态可到达；用户实际体验当前版本并明确接受本次范围；确认规格、素材位置和采纳边界可定位。正式业务逻辑、存档和整个 Feature 的交付仍按原任务继续。
