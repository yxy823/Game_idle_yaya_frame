# 音效文件和播放位置都已确定，现在要把声音接进游戏

[返回场景索引](../../scenario-index.md#界面与资源接入) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

某个功能已经确定要在哪个动作或状态下播放声音，现在已有真实音频文件，需要让它在游戏中触发。

## 前置条件与适用范围

本次是当前 Feature 中新增一项已确定的声音接入，已有实施授权。真实音频可读取，播放、停止、重复或叠加等适用要求已确认，消费场景和 Godot 环境能够运行。

本页不包含声音风格设计、素材制作或替换已有共享音频。素材或播放要求尚未确定时，先补齐相应输入。

## 参与角色与职责边界

用户提供或确认音频，并完成实际听觉体验；Agent 核对文件、接入播放与触发、验证技术行为；Godot 实际导入和播放。音频规格文档本身不会生成声音。

## 执行步骤

使用 [集中提示词库](../../../../prompts.json)中的“Godot 项目开发 → 资源、性能与数据 → 接入或替换游戏资源”。明确本次为新增接入，填入音频文件、资源编号、目标场景或节点、播放与停止要求，以及承接修改的真实 Feature ID。

当前 Agent 使用 [$content-asset-integration](../../../../../project-source/skills/content-asset-integration/SKILL.md)处理资源接入方法，沿用 [$feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md)承接的当前 Feature。切换 Skill 不代表新建声音 Agent；实际听觉验收由用户完成。

**S1｜核对音频**

Agent 按 `content-asset-integration` 读取声音规格、已有资源清单与真实音频，检查格式、时长、用途和来源，确定项目目标路径、消费节点及对应资源编号。核实触发、停止、重复和叠加要求均已确定。

**S2｜接入消费场景**

Agent 将音频放入约定位置，通过 Godot 完成必要导入，设置实际播放器及已有总线引用，将播放和停止连接到约定事件或状态。检查资源路径、UID 与场景引用，处理本次涉及的节点生命周期；保留外部原件和无关素材。

**S3｜运行并试听**

Agent 用项目配置的 Godot 启动真实消费场景，触发播放、停止及约定的重复或叠加情境，检查运行错误和适用测试。向用户提供场景入口和试听操作，由用户确认音量关系、截断及叠加效果；未试听时不记录听觉接受。

**S4｜定稿接入记录**

Agent 在原 `docs/resource-requirements/<scope>.md` 对应条目更新实际文件、消费位置及剩余缺口，保存本次运行与用户试听结果。按 `feature-execute` 接续原 Feature 的验证和完成检查，不另外创建资源接入台账。

## 步骤产出与状态变化

| 步骤 | 产出与继续条件 |
| --- | --- |
| S1 | 实际文件与要求对应，目标位置明确 |
| S2 | 资源有真实消费引用，触发与停止已连接 |
| S3 | 游戏内技术行为符合要求，用户给出真实听觉结论；尚未试听则仍待本步完成 |
| S4 | 文件、清单与消费位置一致，后续验证责任明确 |

## 资源与文件影响

| 项目内对象 | 影响 |
| --- | --- |
| 当前 Feature、声音规格和共享声音约束 | 读取 |
| 实际音频及必要导入文件 | 新增，保留外部原件 |
| 消费场景、播放器、必要脚本或总线 | 在本次范围内修改 |
| `docs/resource-requirements/<scope>.md` | 更新已有对应清单，不另建接入台账 |

## 阻塞、异常与范围变化

文件无法读取、Godot 无法播放或触发路径不可运行时，保留文件、错误和场景，处理实际缺口后回 S1–S3 的对应步骤。

试听发现播放实现违背已有要求时，在当前范围修复后重新试听。文件本身不合格或用户要改变声音要求时，暂停接入结论，保留具体问题并交回素材准备或要求处理；不在本页扩展为重制音频流程。

## 完成状态与验证标准

真实音频存在且有消费引用；约定的触发、停止等技术行为已在游戏中验证；用户实际试听并明确本次接受范围；清单与实际文件一致。接入完成不自动把 Feature 记为完成。
