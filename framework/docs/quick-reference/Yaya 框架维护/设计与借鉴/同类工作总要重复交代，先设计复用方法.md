# 同类工作总要重复交代，先设计复用方法

[返回场景索引](../../scenario-index.md)

## 触发场景与使用时机

为我已经发现反复发生的同一类工作设计可复用的处理方法。例如，多次调整 Skill 都需要重新交代提示词、场景和手册的同步范围，想确定下次应从哪个入口开始。

## 前置条件与适用范围

在框架维护仓库处理。只处理指定的重复工作，分清共同判断与每次变化，不调查个人全部习惯或追求解释历史失败。本次只读分析，结论留在对话。

## 执行步骤

使用[集中提示词库](../../../../prompts.json)中的“Yaya 框架维护 → 设计与借鉴 → 同类工作总要重复交代，先设计复用方法”。提供反复进行的工作、相关实例或重复步骤、每次变化的输入、希望减少的交代与限制。已有对话直接补齐必要材料，不必重发模板。当前 Agent 使用 [workflow-design-yaya](../../../../../.agents/skills/workflow-design-yaya/SKILL.md) 处理。

**S1｜找出共同与变化的部分**

从相关实例识别稳定输入、变化内容与反复判断，检查现有入口、文档和工具；比较复用、补充引用与最小新增。

**S2｜形成可复用的处理方案**

交付建议入口、每次所需输入、关键判断、预期产出、完成条件和详细正文归属，并说明是否值得新增 Skill 或工具。必要选择成组说明推荐与影响，普通实现细节由 Agent 判断。

## 资源与文件影响

相关材料可按需只读查阅，包括文件与 Git 历史；不写知识、报告或流程文件，不执行项目运行或验证命令，不创建自动任务。

## 阻塞、异常与范围变化

缺少会改变方案的关键输入时，完成不依赖它的设计，保留具体未决选择。本场景不授予实施权限，后续明确授权由原有负责者承接。

## 完成状态与验证标准

这类重复工作的建议处理方法与承载位置已讲清，采用前真正需要决定的取舍明确，没有自动创建机制。选用相关真实实例静态推演，检查方法能否减少重复交代、保留必要判断且不重复维护已有正文；不把推演当实测或宣称未经证实的节省效果。
