# 想用一个小任务实际验证框架流程

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

想用一个小任务实际验证框架流程。需要的材料：检查范围、版本或原始材料、报告输出位置。

## 前置条件与适用范围

已授权指定外部验证项目、微型任务和运行范围；框架源只读。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Yaya 框架维护 → 维护与复盘 → 想用一个小任务实际验证框架流程”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用现有规则和工具处理；需要独立审核的步骤明确交给独立实例。

**S1｜建立验证项目**

当前 Agent 在框架根目录使用已确认 Python 执行 `framework/commands/create_project.py --output <指定外部空目标>`，读取真实退出码、目标路径和创建器生成的独立 Git 初始提交。随后进入目标项目，按其 `docs/methodology-config.json` 填写确认路径并执行 `tools/checks/check-project-environment.py --require-ready`。

**S2｜完成微型任务**

只在外部验证项目中使用 `product-init-elicitor` 和 `product-author` 定稿一个微型 Product，使用 `feature-plan` 形成最小 Feature，再由 `feature-execute` 完成实际实现和适用检查。项目 Python 调用 `tools/checks/check-feature-list.py` 核对计划，自动测试通过 `tools/testing/run-gdunit-tests.py --feature <实际ID> --scope <实际范围>` 执行；保留所有原始结果。人工义务到真实体验交接点停止，不伪造接受；维护仓库不激活这些项目流程。

**S3｜回报流程问题**

区分原框架、使用误解和环境问题，保存实际命令、失败、停止位置及最小改进建议。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 项目及运行授权可核实 |
| S2 | 每阶段有原始结果而非模拟通过 |
| S3 | 动态覆盖及未覆盖范围明确 |

## 资源与文件影响

框架维护源和已有游戏项目只读；指定外部验证项目获准新增 Product、计划、业务实现、测试、运行报告、必要进度记录和本地提交。创建器负责初始 Git 和初始提交，后续遵循该项目实际规则。不得修改复制后的框架规则、Skill 或公共工具来使验证通过；原始证据保留。

## 阻塞、异常与范围变化

证据不可用时收窄结论；不把静态推演写成真实运行。

## 完成状态与验证标准

指定微型流程的实际证据报告完成；未获得人工验收的工作如实保留。

## 流程关联与衔接关系

项目 Skill 在目标自己的 `.agents/skills/` 使用；源契约可核对 [product-author](../../../../../project-source/skills/product-author/SKILL.md)、[feature-plan](../../../../../project-source/skills/feature-plan/SKILL.md)和 [feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md)。

依据：[维护约定](<../../../../../AGENTS.md>)、[职责设计准则](<../../../../review/baselines/skill-script-prompt-design.md>)。本页达到出口后，仍已明确授权的后续工作按其所属场景继续；准备、诊断、规划或记录完成不替代 Feature 的正式完成。
