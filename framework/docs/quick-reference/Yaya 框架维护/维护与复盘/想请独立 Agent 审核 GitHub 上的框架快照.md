# 想请独立 Agent 审核 GitHub 上的框架快照

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

想请独立 Agent 审核 GitHub 上的框架快照。需要的材料：

- **审核对象与范围：** 检查范围、版本或原始材料。
- **交付位置：** 报告输出位置。

## 前置条件与适用范围

指定 GitHub 仓库与分支或提交；只读取远端快照。

## 执行步骤

使用[集中提示词库](<../../../../yaya-maintenance-prompts.json>)中的“Yaya 框架维护 → 维护与复盘 → 想请独立 Agent 审核 GitHub 上的框架快照”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用现有规则和工具处理；需要独立审核的步骤明确交给独立实例。

**S1｜固定远端版本**

独立审核 Agent 将指定分支解析到完整 SHA，以该 SHA 读取目录和文件永久链接。

**S2｜检查快照契约**

独立审核 Agent 读取实际正文与实现，对照框架承诺追查复制、规则、工具和完成条件；标明截断和不可读部分。

依据同一 SHA 的[核心决策原则](../../../../../AGENTS.md#核心决策原则)及实际适用的项目规则，检查职责、唯一正文、必要性和最小完整修改等要求是否落实。按原文区分作用域、适用条件与 MUST/PREFER/REVIEW 的强度；涉及 GDD 范围边界与开放问题时追查后续使用约定，快照没有具体游戏正文时不推断外部项目违规。

检查“孤立文档”：文档产生后由哪个场景在什么条件下读取、影响什么决定，以及何时更新或结束使用。识别只有产生入口、缺少实际用途或应有读取场景，以及后续工作绕过现有正文另行决定的情况；导航可达不能代替实际使用关系，也不要求两两回链。单次报告有明确的审核、验收或证据用途即可。

发现这类缺口时，列明文档、产生入口、预期使用场景和已核查的读取入口。先判断内容能否归入现有权威文档、文件是否值得独立保留，再建议归位、合并、删除或补充必要读取条件；不为保留文件硬加使用流程。

按该 SHA 中的[职责设计准则](../../../../review/baselines/skill-script-prompt-design.md)分别核对：

- **文本编写**：标题与术语、列表和目录层级、重复正文及内容归属。
- **Skill 职责**：意图、输出、依赖、生命周期和授权边界。
- **脚本职责**：公开命令/接口、成功条件、副作用、失败重试和清理。
- **提示词与场景**：单一目标、同名路径、输入与出口。

涉及的实际对象逐一形成结论，无法完整读取时收窄覆盖，不能将抽查称为全面审核。

**S3｜输出中文报告**

独立审核 Agent 给出问题、依据、影响、最小建议和未运行项。判定违反核心规则时，说明具体条款、为何适用及违反内容；规则本身有冲突时另行指出，简化建议与违规分开。报告分别汇总上述四类的覆盖与结论，详情引用同一问题；无问题、证据不足与未涉及分别说明。按专用提示词在平台允许位置交付报告，不写入被审仓库。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 整份报告使用同一快照 |
| S2 | 每项判断可回到版本证据 |
| S3 | 快照审核报告可独立复核 |

## 资源与文件影响

被审源与原始证据只读；只写获准报告。

## 阻塞、异常与范围变化

证据不可用时收窄结论；不把静态推演写成真实运行。

## 完成状态与验证标准

同一 SHA 的独立报告已交付，没有执行被审代码或推断本地状态。
