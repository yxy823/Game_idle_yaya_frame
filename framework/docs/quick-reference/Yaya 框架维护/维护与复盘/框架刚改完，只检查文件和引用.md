# 框架刚改完，只检查文件和引用

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

框架刚改完，只检查文件和引用。需要的材料：本次差异、静态检查范围。

## 前置条件与适用范围

修改已完成，本次仅判断文件契约和引用是否一致。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Yaya 框架维护 → 维护与复盘 → 框架刚改完，只检查文件和引用”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用现有规则和工具处理；需要独立审核的步骤明确交给独立实例。

**S1｜读取实际差异**

当前 Agent 固定当前版本，追查受影响规范、实现、配置与复制映射。

**S2｜核对结构与引用**

使用现有只读解析与路径检查，检查 JSON、Markdown 链接、脚本语法和调用参数。

**S3｜说明证据边界**

报告静态发现、失败和需要运行才能判断的内容，不生成项目或启动引擎。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 静态检查范围对应改动 |
| S2 | 实际结构结果有记录 |
| S3 | 静态结果不冒充运行通过 |

## 资源与文件影响

修改范围只读；输出静态检查结论。

## 阻塞、异常与范围变化

用户本次明确只检查时，交付发现和验证缺口，不据较早的实施授权顺手修复。若静态检查是已授权完整任务中的一个步骤，则将发现交回原任务的获准修复范围，不因步骤切换重新索取同一授权。

## 完成状态与验证标准

所选静态契约已核对，失败和未验证运行项明确。

## 流程关联与衔接关系

依据：[维护约定](<../../../../../AGENTS.md>)、[职责设计准则](<../../../../review/baselines/skill-script-prompt-design.md>)。本入口只交付静态核对，不授予修复或运行权限；后续是否继续按当前有效的具体授权判断，保留本次明确的只检查限制。静态结论不代表工具运行、人工验收或 Feature 正式完成。
