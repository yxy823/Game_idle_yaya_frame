# 想检查本地框架是否自洽，先做静态审核

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

想检查本地框架是否自洽，先做静态审核。需要的材料：检查范围、版本或原始材料、报告输出位置。

## 前置条件与适用范围

本地源可读，指定检查范围与报告位置；本次不实施修复。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Yaya 框架维护 → 维护与复盘 → 想检查本地框架是否自洽，先做静态审核”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用现有规则和工具处理；需要独立审核的步骤明确交给独立实例。

**S1｜固定检查基线**

独立审核 Agent 核对当前提交和真实差异，按范围建立生产入口、规范与调用者清单。

**S2｜追查实际契约**

逐对象读取正文与实现，检查读写方、完成语义、复制边界和说明关系；不能用目录枚举代替审查。

**S3｜交付独立结论**

区分已确认问题、推断与运行缺口，列最小调整及复验建议，保存获准报告。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 被审版本和覆盖边界明确 |
| S2 | 问题具有可定位依据 |
| S3 | 报告覆盖、发现与限制明确 |

## 资源与文件影响

被审源与原始证据只读；只写获准报告。

## 阻塞、异常与范围变化

证据不可用时收窄结论；不把静态推演写成真实运行。

## 完成状态与验证标准

有当前文件依据的审核报告已交付，未修改被审源。
