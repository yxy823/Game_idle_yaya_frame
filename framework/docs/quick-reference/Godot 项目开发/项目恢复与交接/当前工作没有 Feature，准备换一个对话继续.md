# 当前工作没有 Feature，准备换一个对话继续

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

当前工作没有 Feature，准备换一个对话继续。准备材料：

- **任务范围**：原任务、已有决定和有效授权。
- **项目现场**：项目目录与实际资料。

## 前置条件与适用范围

研究、讨论或审核等当前任务未建立 Feature，需要交给新对话；本页产出可复制交接文本。

## 执行步骤

使用[集中提示词库](../../../../prompts.json)中的“Godot 项目开发 → 项目恢复与交接 → 当前工作没有 Feature，准备换一个对话继续”。已有对话补齐实际材料即可，续接不重新索取已经存在的授权。 本页的执行者、角色和具体方法见各步骤；没有专用 Skill 时使用当前 Agent 与现有职责契约。

**S1｜核对实际上下文**

当前 Agent 使用 [task-handoff-godot](../../../../../project-source/skills/task-handoff-godot/SKILL.md)，读取当前任务材料、已有结果、有效规则与必要差异，区分已证实结论、建议、失败和未知事实；按本页范围保留必要记录并生成交接文本。

**S2｜整理必要记录**

只在现有 Progress 或所属报告补充真实停点及链接，保留原读写边界，不为交接重跑研究或验证。

**S3｜生成接收指令**

输出一个可整体复制的代码块，包含以下信息：

- **工作上下文**：具体目录、原目标、当前方法。
- **依据与边界**：版本和原件、权限。
- **续接信息**：未决项及第一步。

没有 Feature 就明确说明，不能虚构任务 ID。

## 步骤产出与状态变化

| 步骤 | 继续条件 |
| --- | --- |
| S1 | 交接的事实可回到原件 |
| S2 | 接收方能读到实际资料 |
| S3 | 接收方有同一任务的明确续接范围 |

## 资源与文件影响

必要现有记录可修改，原资料保留；不自动新建任务或发送消息，不为清空现场提交。

## 阻塞、异常与范围变化

原件缺失或事实冲突时说明缺口，不把交接摘要变成新的批准、证据或人工接受。

## 完成状态与验证标准

交接文本和必要记录完整，原工作暂停；接收方收到用户续接指令后按对应实际方法恢复。

## 流程关联与衔接关系

依据：[methodology/09-artifact-lifecycle.md](<../../../../../project-source/methodology/09-artifact-lifecycle.md>)。

本页完成后停止原工作的实施。原授权保留为后续范围依据；收到用户明确续接指令后，再从记录的真实停点恢复。
