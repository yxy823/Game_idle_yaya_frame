# 换了一个对话，想继续上次没做完的 Feature

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

换了一个对话，想继续上次没做完的 Feature。需要的材料：

- **任务定位**：实际项目目录与 Feature ID。
- **续接上下文**：交接材料和新增信息。

## 前置条件与适用范围

同一项目的一项 Feature 尚未完成，用户要求继续其已有范围。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 项目恢复与交接 → 换了一个对话，想继续上次没做完的 Feature”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜恢复真实停点**

接收 Agent 核对同一项目目录、当前规则、Progress、任务原文和实际差异，交接摘要仅作线索。

**S2｜继续剩余工作**

使用 feature-execute 从真实阶段推进，保留有效成果与证据，不因换对话或暂停重建台账。

**S3｜完成或交接缺口**

完成适用实现、验证与交付；缺实质决定或人工结果时说明具体需要。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 任务、现有改动和授权可核实 |
| S2 | 已授权工作持续推进 |
| S3 | 没有把继续请求当验收 |

## 资源与文件影响

只修改原任务剩余授权范围；保留现有内容和真实 Git 差异。

## 阻塞、异常与范围变化

具体重叠内容或不可分离提交边界才构成需解决的冲突，不要求整树清空或逐文件证明归属。

缺少实质决定、验证前置或实际人工验收时保留未完成停点，说明具体缺口及恢复条件；不把已恢复上下文或已报告阻塞写成原任务完成。

## 完成状态与验证标准

原任务已授权范围内的剩余工作、适用验证、验收与交付均已完成；当前记录和证据能够支持该结论。
