# 仍在原对话，想继续暂停的 Feature

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

仍在原对话，想继续暂停的 Feature。需要的材料：

- **任务与授权**：Feature ID 和有效授权。
- **暂停与变化**：暂停原因、当前补充。

## 前置条件与适用范围

同一项目的一项 Feature 尚未完成，用户要求继续其已有范围。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 项目恢复与交接 → 仍在原对话，想继续暂停的 Feature”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜恢复真实停点**

当前 Agent 复用仍有效上下文，核对暂停后实际文件与证据变化，不重复读取无关历史。

**S2｜继续剩余工作**

使用 feature-execute 从真实阶段推进，保留有效成果与证据，不因换对话或暂停重建台账。

**S3｜完成或交接缺口**

完成适用实现、验证与交付；缺实质决定或人工结果时说明具体需要。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 任务、现有改动和授权可核实 |
| S2 | 已授权工作持续推进 |
| S3 | 没有把继续请求当验收 |

## 资源与文件影响

只修改原任务剩余授权范围；保留现有内容和真实 Git 差异。

## 阻塞、异常与范围变化

具体重叠内容或不可分离提交边界才构成需解决的冲突，不要求整树清空或逐文件证明归属。

## 完成状态与验证标准

原任务已授权范围完成，或准确停在缺失决定、验证前置或人工验收处。

## 流程关联与衔接关系

依据：[项目路由依据](<../../../../../project-source/methodology/00-overview.md>)。本页达到出口后，仍已明确授权的后续工作按其所属场景继续；准备、诊断、规划或记录完成不替代 Feature 的正式完成。
