# Feature 还没做完，准备换一个对话继续

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

Feature 还没做完，准备换一个对话继续。需要的材料：

- **任务上下文**：当前 Feature、原目标与已决定事项。
- **交接意图**：换对话意图。

## 前置条件与适用范围

当前对话需要为同一目录中的原任务准备可靠交接。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 项目恢复与交接 → Feature 还没做完，准备换一个对话继续”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用现有规则和工具处理；需要独立审核的步骤明确交给独立实例。

**S1｜核对任务现场**

当前 Agent 读取真实文件、Git、Progress 与原始证据，区分实施、建议、失败和待人工事项。

**S2｜保存必要进度**

更新现有 Progress 和必要 notes，保留 ID、状态与验收语义，不创建 Handoff 状态文件。

**S3｜输出接收指令**

生成可整体复制的代码块，写具体目录、任务、授权、证据、真实停点和第一步；不自动建新对话。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 续接事实清楚 |
| S2 | 必要记录可从文件恢复 |
| S3 | 接收方无需依赖旧会话记忆 |

## 资源与文件影响

必要进度文档修改；不为清空现场提交、回滚或清理现有实现。

## 阻塞、异常与范围变化

缺少原始结果时明确未知，不凭交接摘要补通过；不要求 worktree 或改动归属流程。

## 完成状态与验证标准

完整交接文本和必要记录已准备，原任务暂停在真实位置。

## 流程关联与衔接关系

依据：[项目路由依据](<../../../../../project-source/methodology/00-overview.md>)。本页完成后暂停原任务的实施，保留原有具体授权和真实现场；收到用户续接指令后，再从记录的停点恢复。不得因先前存在实施授权而立即继续已被要求暂停的工作。
