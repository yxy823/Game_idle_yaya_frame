# 进度记录太长，需要整理当前状态和历史

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

进度记录太长，需要整理当前状态和历史。需要的材料：现有 Progress、需要整理的范围。

## 前置条件与适用范围

需要整理可读性与有效状态，本次不生成交接或停止开发的指令。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 项目恢复与交接 → 进度记录太长，需要整理当前状态和历史”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用现有规则和工具处理；需要独立审核的步骤明确交给独立实例。

**S1｜核对当前事项**

当前 Agent 读取 Progress、相关任务和必要原件，区分未完成工作与已完成经过。

**S2｜合并唯一正文**

当前状态留 Progress，必要历史放既有 Feature notes 或 docs/progress/，保留一处正文及链接。

**S3｜检查整理差异**

确认未改 Feature ID、状态、AC 和验收语义，按项目文档约定交付。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 保留的当前事项仍有效 |
| S2 | 信息不重复且历史可追查 |
| S3 | 只是记录组织变化 |

## 资源与文件影响

现有进度、必要历史与链接修改；不改业务代码或完成状态。

## 阻塞、异常与范围变化

事实无法核实就标未知，不把摘要压缩为虚构成功。

## 完成状态与验证标准

Progress 能直接读到真实当前事项，必要历史有明确位置。
