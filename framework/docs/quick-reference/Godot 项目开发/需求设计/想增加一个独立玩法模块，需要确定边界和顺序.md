# 想增加一个独立玩法模块，需要确定边界和顺序

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

想增加一个独立玩法模块，需要确定边界和顺序。

需要的材料：

- 模块目标与关系：新模块目标、与现有模块关系。
- 采用范围：版本采用范围。

## 前置条件与适用范围

新能力具有独立模块身份，本次确立需求与依赖顺序。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 需求设计 → 想增加一个独立玩法模块，需要确定边界和顺序”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$product-init-elicitor](<../../../../../project-source/skills/product-init-elicitor/SKILL.md>)、[$product-author](<../../../../../project-source/skills/product-author/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜确定独立边界**

当前 Agent 用 elicitor 确认模块职责、输入输出和与既有玩法的关系，避免重复模块。

**S2｜保存新模块**

product-author 使用实际下一个模块编号维护来源，并更新总览顺序和共享契约。

**S3｜安排后续时机**

核对当前 Product 尚未完成范围，新模块未轮到时保留需求而不提前拆任务。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 新模块身份和依赖清楚 |
| S2 | 新模块正式来源可定位 |
| S3 | 规划时机符合实际依赖 |

## 资源与文件影响

Product 总览、新模块及必要共享来源修改；不预分配未来 Feature 和测试 ID。

## 阻塞、异常与范围变化

边界与现有模块重叠时先合并需求，而非为名字新增独立模块。

## 完成状态与验证标准

新模块需求、身份、依赖与执行顺序已确认保存。
