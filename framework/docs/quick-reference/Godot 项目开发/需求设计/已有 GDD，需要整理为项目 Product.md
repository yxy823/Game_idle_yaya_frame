# 已有 GDD，需要整理为项目 Product

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已有 GDD，需要整理为项目 Product。

需要的材料：

- 来源与版本：GDD 原件、确认版本。
- 适配边界：当前项目约束和采用范围。

## 前置条件与适用范围

已有较完整设计材料，本次正式适配其已采纳内容。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 需求设计 → 已有 GDD，需要整理为项目 Product”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$product-author](<../../../../../project-source/skills/product-author/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜核对原件与采用范围**

当前 Agent 读取完整相关章节，区分已批准内容、候选设想与内部冲突。

**S2｜按职责转写**

product-author 保存玩家行为，专业规格由所属 Skill 保存并链接，原 GDD 保持原件。

**S3｜检查语义保真**

对照采用章节核对遗漏、变化与未决项，完成文档提交并移交规划入口。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 原文与采纳决定可追查 |
| S2 | 正式 Product 不是附件副本堆积 |
| S3 | 来源适配关系明确 |

## 资源与文件影响

原 GDD 只读；Product、必要专业来源与链接修改。

## 阻塞、异常与范围变化

无法确定哪个版本或冲突含义时先补齐决定，不能静默取舍。

## 完成状态与验证标准

已采纳 GDD 内容完整进入正式来源，原件和实质差异可追查。
