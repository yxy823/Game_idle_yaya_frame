# 已确认的界面要求要变，需要更新规格并明确影响

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已确认的界面要求要变，需要更新规格并明确影响。需要的材料：现有规格、确认变更、现有实现和消费 Feature。

## 前置条件与适用范围

原规格已存在，当前决定会改变界面要求。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 需求设计 → 已确认的界面要求要变，需要更新规格并明确影响”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$design-ui-spec](<../../../../../project-source/skills/design-ui-spec/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜定位规格差异**

当前 Agent 比较原决定与新要求，确认行为变化是否已由 Product 承接。

**S2｜修改所属规格**

design-ui-spec 更新受影响状态、布局和反馈，保留其他有效要求与稳定引用。

**S3｜追查消费者**

核对直接引用和共享设计使用者，列现有任务需同步范围并交 feature-sync。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 变更意图和来源有效 |
| S2 | 新要求形成正式来源 |
| S3 | 已有实现影响没有遗漏 |

## 资源与文件影响

既有 UI 规格和必要链接修改；原完成历史不改，当前实现不在此页修改。

## 阻塞、异常与范围变化

新要求与 Product 行为冲突时先明确 owning 来源；不能用改规格掩盖 Bug。

## 完成状态与验证标准

新规格已保存，受影响消费者及计划同步范围明确。
