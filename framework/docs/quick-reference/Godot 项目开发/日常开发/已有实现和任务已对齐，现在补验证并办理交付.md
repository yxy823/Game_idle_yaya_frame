# 已有实现和任务已对齐，现在补验证并办理交付

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已有实现和任务已对齐，现在补验证并办理交付。需要的材料：Feature ID、对齐后的来源、已有实现、实际证据与待补缺口。

## 前置条件与适用范围

需求和任务记录已确认，本次授权完成剩余验证、必要修复和交付。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 日常开发 → 已有实现和任务已对齐，现在补验证并办理交付”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜确认真实缺口**

当前 Agent 按 feature-execute 读取现有实现、AC、原始验证及历史，不重演已有效完成步骤。

**S2｜补足适用验证**

运行实际需要的静态、测试和专项检查，修复已授权范围内失败，真实人工部分交用户。

**S3｜办理完成检查**

核对当前完成条件、用户指定评审与真实接受，按项目规则记录实际完成时间并提交。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 剩余义务已确定 |
| S2 | 证据覆盖最终实现 |
| S3 | 交付结论对应当前事实 |

## 资源与文件影响

当前 Feature 实现及必要修复、测试证据、完成记录和 Progress 会修改；历史证据不篡改。

## 阻塞、异常与范围变化

缺失人工体验或原始报告时不能倒推接受；只停在真实缺口。

## 完成状态与验证标准

当前 Feature 的适用验证和验收已满足，并完成实际收尾；缺口仍在时只报告待办。
