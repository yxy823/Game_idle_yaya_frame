# 人工验收已有结果，继续原 Goal

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

人工验收已有结果，继续原 Goal。需要的材料：原 Goal 范围、用户实际结果、当前 Feature 与有效授权。

## 前置条件与适用范围

上一段停在人工交接，用户现已给出结果并明确继续。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 日常开发 → 人工验收已有结果，继续原 Goal”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)、[$feature-plan](<../../../../../project-source/skills/feature-plan/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜核对实际人工结果**

当前 Agent 读取原清单或明确口头决定及当前版本，按适用入口记录，不能把继续指令代替接受。

**S2｜处理当前任务**

通过 feature-execute 先修复获准失败并复验，或完成已接受任务的适用收尾。

**S3｜继续下一段目标**

旧 Goal 已结束时按当前继续请求启动下一段，否则沿用；按原范围逐个推进到下个人工交接点。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 本次接受或失败范围明确 |
| S2 | 当前任务完成条件真实满足 |
| S3 | 目标范围及真实人工停点保持一致 |

## 资源与文件影响

当前任务、验收记录和 Progress 修改；后续仅在原 Goal 明确范围内推进。

## 阻塞、异常与范围变化

结果无效或版本不符时停在真实缺口，不绕过人工检查；新玩法不自动纳入 Goal。

## 完成状态与验证标准

当前结果已正确承接，并推进到下一真实人工交接点或原范围全部完成。
