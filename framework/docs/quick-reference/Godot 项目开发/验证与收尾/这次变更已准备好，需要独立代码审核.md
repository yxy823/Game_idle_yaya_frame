# 这次变更已准备好，需要独立代码审核

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

这次变更已准备好，需要独立代码审核。需要的材料：Feature 或提交差异、比较基线、规则与原始证据、验证权限。

## 前置条件与适用范围

明确启用一次独立评审；变更范围已准备好。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 这次变更已准备好，需要独立代码审核”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$review-code](<../../../../../project-source/skills/review-code/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜核实独立实例**

主 Agent 交接范围、版本、权威来源和运行权限给新上下文 independent-reviewer，核实真实独立性。

**S2｜读取实现并追查**

独立 Agent 使用 review-code，读取相关 AC、最终差异和原件，追查直接调用者；按既有 Stage 6 处理已选变更。

**S3｜交付有界结论**

分别说明需求符合性和质量，给文件定位、触发、影响与最小建议；验证只在隔离范围。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 检查者没有把作者总结当事实 |
| S2 | 问题依据来自实际实现 |
| S3 | 建议不自动构成修复授权 |

## 资源与文件影响

被审源和原证据只读；获准报告与隔离缓存可写。

## 阻塞、异常与范围变化

版本在审查中变化时补查受影响部分或限定版本；不能把作者自查称独立。

## 完成状态与验证标准

当前差异的需求符合性与代码质量分别有独立结论，未修改被审内容或历史完成状态。
