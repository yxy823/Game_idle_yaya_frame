# 我手动改过项目，想确认是否仍符合要求

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

我手动改过项目，想确认是否仍符合要求。

需要的材料：

- 改动事实与意图：实际改动、修改意图。
- 比较依据：比较基线和当前来源。

## 前置条件与适用范围

需要独立静态核对手改内容与有效要求，本次不修复。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 我手动改过项目，想确认是否仍符合要求”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$review-code](<../../../../../project-source/skills/review-code/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜确定实际检查版本**

独立审核 Agent 核对未提交或指定提交差异；工作区干净不代表没有历史修改。

**S2｜对照需求与实现**

用 review-code 检查 Product、专业规格、Feature/AC 与实际行为，区分新决定和未批准冲突。

**S3｜建议所属处理入口**

交付一致、冲突和未知部分及最小后续动作；不改来源或放宽 AC 消除冲突。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 范围和基线确实对应本次手改 |
| S2 | 遗漏、越界及证据不足可定位 |
| S3 | 结论可供选择修复范围 |

## 资源与文件影响

被审文件、原证据与验收历史只读；对话报告不运行测试。

## 阻塞、异常与范围变化

历史基线不可还原时核对当前一致性并说明变化未知，不猜测旧状态。

## 完成状态与验证标准

独立静态一致性报告已交付，未替用户批准需求或修复。
