# 测试摘要还在，但原始报告找不到了

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

测试摘要还在，但原始报告找不到了。需要的材料：Feature ID、已有摘要、记录路径和可查运行位置。

## 前置条件与适用范围

无法取得摘要所称成功的原件，需要恢复真实验证依据。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 测试摘要还在，但原始报告找不到了”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜查找原件位置**

当前 Agent 先在既有报告和实际运行输出定位，确认缺失范围，不把没读到当不存在。

**S2｜补足真实验证**

确实丢失时按当前义务重新运行必要测试，用当前实际输出替代不能证明的旧结论。

**S3｜导入当前证据**

按完成记录工具导入有效整组引用，保留旧摘要为历史限制而非通过证据。


调用示例：在游戏项目根目录执行，将 `F0XX`、测试范围和运行编号换成实际值；以运行器输出的真实结果路径为准。先确认运行实际结束成功及报告完整，再执行导入。失败、零测试或中断不得作为成功结果导入。

```powershell
$projectConfig = Get-Content -LiteralPath 'docs/methodology-config.json' -Raw | ConvertFrom-Json
$projectPython = $projectConfig.python_executable
& $projectPython -B tools/testing/run-gdunit-tests.py --feature F0XX --scope affected
$LASTEXITCODE
& $projectPython -B tools/features/record-feature-completion.py record-tests --feature F0XX --run 'reports/gdunit-wrapper/F0XX/run-<实际编号>/result.json'
$LASTEXITCODE
& $projectPython -B tools/features/record-feature-completion.py show --feature F0XX
$LASTEXITCODE
```

`--scope` 按真实义务选择 `auto`、`required`、`affected` 或 `full`。多份结果必须在同一次 `record-tests` 调用重复提供 `--run <真实result.json>`，包括需要保留且相互兼容的全部运行。该命令用这一整组替换当前测试引用；导入失败会清除旧测试引用，但保留原始报告。不要拆成多次调用并假定累加。`show` 仅用于查看匹配记录；读到记录不等于整个 Feature 完成。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 原件是否可恢复有依据 |
| S2 | 新结果有完整原件 |
| S3 | 当前完成依据可追查 |

## 资源与文件影响

新增必要运行报告和当前证据引用；不伪造旧报告、结束时间或通过记录。

## 阻塞、异常与范围变化

缺少运行权限或环境时报告验证缺口，不让人工接受抵消自动证据缺失。

## 完成状态与验证标准

当前必要验证已取得可核实原件并导入，或明确尚未解除的验证阻塞。
