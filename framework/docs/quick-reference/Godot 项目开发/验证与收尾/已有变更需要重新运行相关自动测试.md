# 已有变更需要重新运行相关自动测试

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已有变更需要重新运行相关自动测试。需要的材料：当前 Feature ID、改动范围、测试授权。

## 前置条件与适用范围

需要已有 Feature 当前内容的实际测试结果，本次不顺手修复实现。没有 Feature 的组件检查使用[没有 Feature，只想运行指定组件的自动测试](<没有 Feature，只想运行指定组件的自动测试.md>)，不为运行测试创建虚构任务。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 验证与收尾 → 已有变更需要重新运行相关自动测试”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用现有规则和工具处理；需要独立审核的步骤明确交给独立实例。

**S1｜选择实际测试范围**

当前 Agent 对照 AC、登记与影响选择 required、affected 或确有需要的 full，不为凑数量扩测。

**S2｜运行现有入口**

在项目根目录用配置 Python 调用 tools/testing/run-gdunit-tests.py --feature <实际ID> --scope <已选范围>，读取真实结束结果。

**S3｜解释结果与缺口**

核对实际用例、失败、跳过和零测试，指出仍需人工或专项检查；需要导入时使用完成记录入口。

项目工具命令在实际游戏项目根目录执行；使用 `docs/methodology-config.json` 中的 `python_executable`，调用形式为 `& $projectPython -B <脚本路径> <参数>`，每次立即检查 `$LASTEXITCODE`。尖括号参数替换为实际值。命令成功只证明该操作完成。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 选择覆盖本次实际义务 |
| S2 | 当前运行原件可定位 |
| S3 | 运行结果不冒充整个 Feature 完成 |

## 资源与文件影响

测试运行写 reports/gdunit-wrapper/ 和必要缓存；实现与验收标准不修改。

## 阻塞、异常与范围变化

运行中断、零测试或旧报告不能记通过；失败保留供所属修复任务。

## 完成状态与验证标准

所选测试实际结束并有完整原件，当前通过与失败如实说明。
