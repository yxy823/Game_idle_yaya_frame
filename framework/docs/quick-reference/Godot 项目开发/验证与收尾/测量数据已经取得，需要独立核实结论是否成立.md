# 测量数据已经取得，需要独立核实结论是否成立

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

测量数据已经取得，需要独立核实结论是否成立。

准备材料：

- 待核实对象：待核实性能或长测结论、版本。
- 测量证据：原始数据、采样条件。
- 实现与复测边界：测量代码及允许复测范围。

## 前置条件与适用范围

已有测量结果和具体结论，本次是独立评估证据是否支持该结论；不重新执行整套诊断或优化。

## 执行步骤

使用[集中提示词库](../../../../prompts.json)中的“Godot 项目开发 → 验证与收尾 → 测量数据已经取得，需要独立核实结论是否成立”。已有对话补齐实际材料即可，续接不重新索取已经存在的授权。 适用 Skill：[$review-code](../../../../../project-source/skills/review-code/SKILL.md)。

**S1｜交接独立审核**

主 Agent 将结论、被测版本、完整原件、设备/负载/时长、采样方法及权限交给新上下文 independent-reviewer，作者说明仅作待核实陈述。

**S2｜核实证据与推导**

独立 Agent 读取实际数据，按结论类型核对：

- 性能结论：前后条件是否可比、样本与指标是否支持差异。
- 长测结论：是否达到声明负载/时长且保留中断。

涉及采集和统计实现时使用 review-code，追查单位、采样、聚合及遗漏数据。

**S3｜交付有界判断**

分别说明已支持、不能支持及待补证据；确需针对性复测只在明确授权隔离范围运行，不能用审核请求自动授权优化。

## 步骤产出与状态变化

| 步骤 | 继续条件 |
| --- | --- |
| S1 | 独立性和证据范围可核实 |
| S2 | 结论的适用边界有原始依据 |
| S3 | 报告说明证据充分性而不代作验收 |

## 资源与文件影响

原始测量、被审实现和验收记录只读；可写获准报告和隔离复测产物，不改原始数据。

## 阻塞、异常与范围变化

- 原件缺失、版本不明或条件不可比：给出受限结论。
- 没有真实满时长：不能认可长跑完成。
- 缺少用户体验：不能推定人工接受。

## 完成状态与验证标准

独立报告逐项判断测量结论是否受支持，并明确版本、覆盖和局限，没有修改被审成果。
