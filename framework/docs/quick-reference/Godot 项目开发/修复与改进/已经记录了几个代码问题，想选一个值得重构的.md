# 已经记录了几个代码问题，想选一个值得重构的

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已经记录了几个代码问题，想选一个值得重构的。需要的材料：既有问题记录、当前目标与可用范围。

## 前置条件与适用范围

候选已经存在，需要选择一个有价值的明确目标。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 修复与改进 → 已经记录了几个代码问题，想选一个值得重构的”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$engineering-refactor-select](<../../../../../project-source/skills/engineering-refactor-select/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜核对候选仍成立**

当前 Agent 使用 engineering-refactor-select 读取既有 notes 和对应当前代码，排除已解决或失效项。

**S2｜比较实际收益**

按当前变化需要、风险与成本推荐一个最小候选及不变行为。

## 资源与文件影响

现有 notes 与代码只读；不创建或执行重构任务。

## 阻塞、异常与范围变化

没有值得处理的候选时直接说明，不为使用 Skill 造任务。

## 完成状态与验证标准

已给出有当前证据的一个推荐目标或明确不重构结论。

## 流程关联与衔接关系

依据：[项目路由依据](<../../../../../project-source/methodology/00-overview.md>)。本入口只承担候选选择，不由结论授予创建或执行重构任务的权限。用户本次明确只要求候选选择时，在推荐或不重构结论交付后结束本次范围；若它是已授权完整任务中的一个步骤，按仍有效的具体授权进入后续所属流程，不因步骤结束重复确认。当前明确限制不能由旧授权撤销，检查结论也不代替 Feature 正式完成。
