# Feature 交付前发现 Bug

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

Feature 交付前发现 Bug。

需要的材料：

- 任务与要求：所属 Feature、仍有效要求。
- 问题证据：实际表现、复现与日志。

## 前置条件与适用范围

正式交付以项目规定的 Feature 完成状态和完成记录为准，不以测试通过、代码提交或用户试玩作为单独依据。本页限定当前未交付 Feature 内出现缺陷。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 修复与改进 → Feature 交付前发现 Bug”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜记录问题与现场**

当前 Agent 核对仍有效要求、实际失败和交付状态，保留复现、日志与受影响范围。

**S2｜修复既有要求**

留在原 Feature 定位并修复，必要补回归测试，不为当前未完成范围再建独立 Bug 任务。遵循专用入口当前有效的提交约束。

**S3｜取得实际复验**

完成受影响自动验证，向用户提供实际体验入口并记录明确结果；未通过继续在授权内修复。

**S4｜返回完成检查**

核对测试原件、当前接受与必要评审，按本次提交约束交回所属任务完成检查。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 缺陷事实和任务归属明确 |
| S2 | 修复没有放宽原验收要求 |
| S3 | 最终内容有真实复验结果 |
| S4 | 本页出口与原任务收尾衔接 |

## 资源与文件影响

实现、回归测试和所属任务记录修改；原 Feature 继续承担范围和验收，既有自动通过不覆盖新的失败。

## 阻塞、异常与范围变化

- 要求实质改变：转需求变更。
- 无关功能缺陷：另按所属场景处理。
- 只诊断请求：使用只读定位。
- 无法复现：保留证据缺口，不宣称修复。

## 完成状态与验证标准

原 Feature 的新增实际失败已消除，必要复验完成并返回原任务完成检查。
