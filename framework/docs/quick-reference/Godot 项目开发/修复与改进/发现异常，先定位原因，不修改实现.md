# 发现异常，先定位原因，不修改实现

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

发现异常，先定位原因，不修改实现。

需要的材料：

- 问题表现：期望、实际表现。
- 复现材料：复现、日志。
- 诊断范围：允许的诊断运行范围。

## 前置条件与适用范围

当前只需要原因与处理建议，不授权修复实现。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 修复与改进 → 发现异常，先定位原因，不修改实现”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用现有规则和工具处理；需要独立审核的步骤明确交给独立实例。

**S1｜整理可核实表现**

当前 Agent 读取原始日志、需求和实际代码，区分明确事实与假设。

**S2｜定位原因**

在获准范围复现或静态追查调用链，必要查询证据，不增加持久埋点。

**S3｜交付修复建议**

说明最小修改位置、验证方式与交付前后所属入口，不代执行。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 异常与正常预期可比较 |
| S2 | 原因有证据或清楚的不确定性 |
| S3 | 后续修复范围具体 |

## 资源与文件影响

实现和任务状态只读；诊断运行只产生获准日志。

## 阻塞、异常与范围变化

运行无权限或证据不足时给受限结论；不把仅怀疑原因写成已确认根因。

## 完成状态与验证标准

已交付原因证据、限制和最小建议，没有实施修复。
