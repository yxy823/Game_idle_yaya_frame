# 共享能力准备修改，先明确契约和影响范围

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

共享能力准备修改，先明确契约和影响范围。

准备材料：

- 项目与对象：游戏项目路径、项目内具体共享对象。
- 契约与范围：拟改变的契约、当前消费者和已授权范围。

## 前置条件与适用范围

当前独立游戏项目的共享工具、模块或规则即将变更，需要在实施前明确影响；本页只分析该项目的边界与验证范围，不处理框架维护源。

## 执行步骤

使用[集中提示词库](../../../../godot-development-prompts.json)中的“Godot 项目开发 → 修复与改进 → 共享能力准备修改，先明确契约和影响范围”。已有对话补齐实际材料即可，续接不重新索取已经存在的授权。 本页的执行者、角色和具体方法见各步骤；没有专用 Skill 时使用当前 Agent 与现有职责契约。

**S1｜确认项目内的对象职责**

当前 Agent 在用户指定的游戏项目内读取真实共享对象、公开入口和消费者，确认对象属于本次范围。项目独立拥有其文件，不向框架维护源同步修改。

**S2｜追查契约影响**

- 契约与责任：核对输入输出、错误传播、权限、副作用、状态、生命周期和清理责任。
- 影响对象：定位配置、直接/间接调用方、现有数据及必要说明。

**S3｜交付修改边界**

给出必须一起修改的最小集合、保留行为、原子性/重试与验证建议。实现交原授权任务，不在分析中顺手改共享代码。

## 步骤产出与状态变化

| 步骤 | 继续条件 |
| --- | --- |
| S1 | 执行仓库和责任对象清楚 |
| S2 | 受影响消费者与失败路径明确 |
| S3 | 后续实施有完整边界而非全仓重构 |

## 资源与文件影响

共享实现、配置、调用者和现有证据只读；默认输出影响分析，不建立共享修改台账。

## 阻塞、异常与范围变化

对象在范围外仓库或实际调用无法确认时明确缺口；不把消费者相似当允许批量替换。

## 完成状态与验证标准

具体共享变更的契约、消费者、改动集合和相称验证范围已明确。

## 流程关联与衔接关系

依据：[methodology/00-overview.md](<../../../../../project-source/methodology/00-overview.md>)。

本页只分析共享变更的契约与影响，不由建议授予实施权限。用户本次明确只分析时，在交付边界后结束该范围；若分析属于已授权完整任务的步骤，按仍有效的具体授权进入后续所属流程，不因步骤结束重复确认。当前明确的只读限制不能由旧授权撤销。
