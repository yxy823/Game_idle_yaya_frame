## 触发场景与使用时机

某处代码总是难改，先调查是否值得重构。

需要的材料：

- 调查对象与问题：相关模块、维护痛点。
- 后续变化：下一项预期变化。

## 前置条件与适用范围

需要从实际源码发现重构候选，本次不实施。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 修复与改进 → 某处代码总是难改，先调查是否值得重构”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用现有规则和工具处理；需要独立审核的步骤明确交给独立实例。

**S1｜追查修改阻力**

当前 Agent 阅读实际模块、调用关系与必要历史，找到重复变化和不清晰责任。

**S2｜比较最小调整**

比较不改、局部整理和结构重构的收益与成本，明确保持的行为和验证建议。

## 资源与文件影响

代码只读；建议或获准调查报告不修改任务状态。

## 阻塞、异常与范围变化

只有风格偏好或未来假设时不强行提出架构层。

## 完成状态与验证标准

重构机会、依据和最小候选已交付，不自动开始重构。
