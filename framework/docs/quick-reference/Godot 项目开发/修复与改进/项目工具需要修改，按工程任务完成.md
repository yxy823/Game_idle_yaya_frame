# 项目工具需要修改，按工程任务完成

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

项目工具需要修改，按工程任务完成。

需要的材料：

- 修改目标：工具问题、具体目标。
- 契约与运行边界：输入输出契约、运行范围。

## 前置条件与适用范围

需要实现或配置类工程维护，不改变玩家需求。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 修复与改进 → 项目工具需要修改，按工程任务完成”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$engineering-change-plan](<../../../../../project-source/skills/engineering-change-plan/SKILL.md>)、[$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜明确维护契约**

当前 Agent 阅读实际命令、实现和调用者，用 engineering-change-plan maintenance 建立有界任务，说明公开入口、成功条件、副作用、失败重试与资源清理，简述修改和验证范围。

**S2｜修改工具及调用者**

当前 Agent 使用 feature-execute 按职责准则完成最小实现，保持无需变化的 CLI/API 和依赖，同步必要配置、调用链和说明；不把查询入口顺带变成写入入口。

**S3｜验证工具结果**

当前 Agent 覆盖受影响正常与失败路径、错误传播及必要清理，检查差异并说明关键改动与限制，按项目完成条件交付；不靠 --help 当行为通过。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 维护目标可验证 |
| S2 | 入口和实际行为一致 |
| S3 | 工程任务有真实必要验证 |

## 资源与文件影响

项目工具、必要配置与调用方、回归和任务记录修改。

## 阻塞、异常与范围变化

机器路径失效交环境恢复；只是规则文字改动用规则文档场景。

## 完成状态与验证标准

工具目标及关联契约已实现并验证，工程任务完成条件满足。
