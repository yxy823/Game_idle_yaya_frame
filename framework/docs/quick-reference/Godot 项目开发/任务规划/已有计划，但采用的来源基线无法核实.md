# 已有计划，但采用的来源基线无法核实

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已有计划，但采用的来源基线无法核实。

需要的材料：

- 当前对照依据：现有计划、当前有效来源。
- 历史缺口：缺失或不完整历史说明。

## 前置条件与适用范围

不能证明旧锚点或新专业来源历史覆盖，本次恢复可解释的当前对齐。

## 执行步骤

使用[集中提示词库](<../../../../godot-development-prompts.json>)中的“Godot 项目开发 → 任务规划 → 已有计划，但采用的来源基线无法核实”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$feature-sync](<../../../../../project-source/skills/feature-sync/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜确认历史缺口**

当前 Agent 核对现有 Git 和修订原件，区分不存在与未读到，不猜补旧差异。

**S2｜对照当前要求**

使用 feature-sync 在授权范围逐项比较已规划任务与当前来源，列真实不一致。

**S3｜保存对齐与限制**

按现有规范修订必要计划并记录历史未知，检查台账后交回原工作。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 不可恢复的范围明确 |
| S2 | 采用当前事实而非伪历史 |
| S3 | 未来可依据当前明确关系继续 |

## 资源与文件影响

现有计划及必要修订记录修改；不制造来源收据、旧提交或虚构 R000。

## 阻塞、异常与范围变化

关键来源本身未确认时保留待定，不把恢复任务当批准所有当前文字。

## 完成状态与验证标准

获准范围已按当前有效来源对齐，无法恢复的历史明确记录且检查通过。
