# 前一个模块已完成，准备规划下一个 Product

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

前一个模块已完成，准备规划下一个 Product。

需要的材料：

- 规划对象与前置：下一 Product、已完成前置模块。
- 当前记录：现有计划与修订。

## 前置条件与适用范围

当前 Product 所需任务已真实完成，轮到未规划的下一模块。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 任务规划 → 前一个模块已完成，准备规划下一个 Product”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$feature-plan](<../../../../../project-source/skills/feature-plan/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜核对模块顺序**

当前 Agent 按 feature-plan 读取总览、前置任务完成依据和本次来源，不能只看 ID。

**S2｜展示本次拆分**

读取当时完整需求，展示范围、依赖、AC 和测试安排；按有效规划授权确认。

**S3｜追加并检查**

追加新 ID 与详情，保留旧索引、历史和同步锚点；调用 check-feature-list.py 检查并提交。

项目工具命令的使用要求：

- 工作目录：实际游戏项目根目录。
- Python 与调用形式：使用 `docs/methodology-config.json` 中的 `python_executable`，按 `& $projectPython -B <脚本路径> <参数>` 调用，每次立即检查 `$LASTEXITCODE`。
- 参数：尖括号参数替换为实际值。
- 结果边界：命令成功只证明该操作完成。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 下一个模块确实具备规划条件 |
| S2 | 本次要求没有被旧锚点遗漏 |
| S3 | 新计划与旧历史并存一致 |

## 资源与文件影响

追加 Feature 与必要测试登记；不重置 R000 或历史同步锚点。

## 阻塞、异常与范围变化

前项尚未完成或当前模块已有计划时退出追加，改用其真实处理入口。

## 完成状态与验证标准

下一 Product 的计划已追加并检查，旧 ID、历史及锚点完整。
