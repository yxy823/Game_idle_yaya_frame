# 旧项目想采用当前框架，先评估复制迁移方案

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

旧项目想采用当前框架，先评估复制迁移方案。需要的材料：

- **来源与目标**：原项目、当前框架、拟用独立目标。
- **数据要求**：数据保留要求。

## 前置条件与适用范围

原项目与框架均只读，本次只评估方案。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 项目创建与接入 → 旧项目想采用当前框架，先评估复制迁移方案”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用现有规则和工具处理；需要独立审核的步骤明确交给独立实例。

**S1｜核对两端实际内容**

当前 Agent 读取规则、复制清单、实际实现、任务和配置，使用只读 Git 确认版本及工作区成果。

**S2｜安排一次性转换**

按职责列保留、替换、合并、转换和不复制项；说明目标路径、历史接入、数据保护与验证。

**S3｜交付具体取舍**

指出不能判定的字段、旧证据限制和预期续接点，提供最小推荐方案。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 有效成果与必要定制可定位 |
| S2 | 独立副本方案能保留成果 |
| S3 | 用户可选择明确实施范围 |

## 资源与文件影响

原项目、当前框架只读；迁移建议不创建目标。

## 阻塞、异常与范围变化

目标嵌套、符号链接回到原件或关键数据保留不明时明确阻塞，不猜测覆盖方案。

## 完成状态与验证标准

完整的副本迁移方案已交付，包含取舍、验证和原件保护。
