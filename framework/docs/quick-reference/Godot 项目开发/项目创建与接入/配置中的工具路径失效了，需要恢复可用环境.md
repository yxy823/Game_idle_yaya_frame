# 配置中的工具路径失效了，需要恢复可用环境

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

配置中的工具路径失效了，需要恢复可用环境。需要的材料：

- **失败信息**：具体错误、配置路径。
- **恢复依据**：确认可用的新路径或安装信息。

## 前置条件与适用范围

现有命令因已配置工具不存在或无法启动而受阻。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 项目创建与接入 → 配置中的工具路径失效了，需要恢复可用环境”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用项目自己的 `project-environment-godot` Skill；[源码入口](<../../../../../project-source/skills/project-environment-godot/SKILL.md>)仅供核对。

**S1｜确认失败位置**

当前 Agent 检查配置路径存在性和原始报错，区分文件缺失、权限与版本问题。

**S2｜恢复指定工具**

用户提供或确认有效路径后，Agent 更新对应字段；未提供时只补问该缺口，不全盘猜找替代。

**S3｜重新检查**

调用环境检查器 --require-ready，追加初始化记录，再交回原任务的失败步骤。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 阻塞有准确对象 |
| S2 | 所用工具身份与路径明确 |
| S3 | 环境恢复有当前证据 |

## 资源与文件影响

只修改确认的机器路径和初始化记录；保留原始失败。

## 阻塞、异常与范围变化

权限审批未通过或工具尚未安装时保留阻塞，不改项目规则绕过。

## 完成状态与验证标准

所需工具可以被当前项目调用，环境检查结果明确，原任务恢复位置可定位。
