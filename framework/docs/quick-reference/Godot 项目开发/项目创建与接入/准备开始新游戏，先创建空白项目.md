# 准备开始新游戏，先创建空白项目

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

准备开始新游戏，先创建空白项目。需要的材料：不含中文或空白的新项目绝对路径。

## 前置条件与适用范围

目标在维护源外且不存在或为空，只需要独立空白项目。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 项目创建与接入 → 准备开始新游戏，先创建空白项目”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用现有规则和工具处理；需要独立审核的步骤明确交给独立实例。

**S1｜确认目标和清单**

当前 Agent 在框架目录核对目标路径与 framework/project-files.json；不对非空目录运行创建器。

**S2｜调用创建器**

在框架根目录使用框架已确认 Python 执行 `framework/commands/create_project.py --output <目标目录>`，将尖括号参数替换为实际绝对路径，并立即检查 `$LASTEXITCODE` 与创建结果。新项目尚未完成环境配置，不使用其模板中的 Python 路径运行创建器。

**S3｜交付项目位置**

核对实际目标与初始提交，告知后续在新项目配置环境。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 目标满足创建前提 |
| S2 | 清单复制及独立 Git 初始提交完成 |
| S3 | 目标可定位，未开始 Feature |

## 资源与文件影响

仅创建目标清单内容、独立 .git 和初始提交；不复制维护手册或完整提示词库。

## 阻塞、异常与范围变化

目标非空或复制失败时保留原始错误和现场，不覆盖、不自动清理。

## 完成状态与验证标准

独立空白项目与本地初始提交已建立，没有配置环境或推送远端。

## 流程关联与衔接关系

新项目尚无设计正文、且用户希望先把想法写成设计时，在新项目使用[形成 GDD 草稿](<../需求设计/只有游戏想法，先形成 GDD 草稿.md>)；它不要求先完成 Godot 环境配置。创建项目本身不自动包含设计或开发授权。
