# 空白项目已经创建，现在配置开发环境

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

空白项目已经创建，现在配置开发环境。需要的材料：目标项目、已确认 Python 3.12+ 和 Godot 路径、可选项目名称。

## 前置条件与适用范围

新项目尚未完成首次环境配置。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 项目创建与接入 → 空白项目已经创建，现在配置开发环境”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页由当前 Agent 使用现有规则和工具处理；需要独立审核的步骤明确交给独立实例。

**S1｜写入真实配置**

当前 Agent 核对 docs/methodology-config.json 中 engine_executable 和 python_executable，按用户指定路径填写；检查插件存在。

**S2｜检查环境**

在项目根目录用配置 Python 调用 tools/checks/check-project-environment.py --require-ready；首次扫描仅在需要运行且获准时按工具说明执行。

**S3｜保存初始化结果**

写 reports/initialization.md，记录命令、失败、未执行、Git 与剩余问题，更新 Progress 后按项目规则提交。

项目工具命令在实际游戏项目根目录执行；使用 `docs/methodology-config.json` 中的 `python_executable`，调用形式为 `& $projectPython -B <脚本路径> <参数>`，每次立即检查 `$LASTEXITCODE`。尖括号参数替换为实际值。命令成功只证明该操作完成。

## 资源与文件影响

环境配置、可选 project.godot 名称、初始化报告和 Progress 修改；不创建业务任务。

## 阻塞、异常与范围变化

路径无效时报告具体问题，不搜索替代 Godot；空项目无业务测试不虚构测试。

## 完成状态与验证标准

真实路径已配置、环境检查通过，报告和适用提交完成；未执行的首次扫描明确。
