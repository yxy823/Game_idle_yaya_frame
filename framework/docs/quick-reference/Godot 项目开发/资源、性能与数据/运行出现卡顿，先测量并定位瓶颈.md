# 运行出现卡顿，先测量并定位瓶颈

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

运行出现卡顿，先测量并定位瓶颈。

需要的材料：

- 测量场景与环境：卡顿或耗时场景、设备、构建。
- 指标与预算：指标、采样预算。

## 前置条件与适用范围

当前只需实际瓶颈证据，不授权优化实现。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 运行出现卡顿，先测量并定位瓶颈”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$diagnostics-performance](<../../../../../project-source/skills/diagnostics-performance/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜固定测量条件**

当前 Agent 用 diagnostics-performance 明确版本、硬件、输入和可比较采样条件。

**S2｜取得原始指标**

按问题记录帧时分位与尖峰，或加载、内存等对应指标，不仅看平均 FPS。

**S3｜解释瓶颈**

区分实测与推断，说明最小候选及潜在代价，不修改生产结构。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 测量不会混合不同场景 |
| S2 | 瓶颈分析有原始数据 |
| S3 | 后续优化目标有证据 |

## 资源与文件影响

获准测量产物和报告写入；实现与持久观测不修改。

## 阻塞、异常与范围变化

测量条件不可比或工具不可用时保留限制，不编造提升空间。

## 完成状态与验证标准

实际瓶颈与依据明确或说明仍需哪些测量，没有实施优化。
