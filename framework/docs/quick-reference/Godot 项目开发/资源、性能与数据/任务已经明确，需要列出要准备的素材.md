# 任务已经明确，需要列出要准备的素材

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

任务已经明确，需要列出要准备的素材。

需要的材料：

- 任务与去向：当前任务、消费位置与所属设计章节。
- 资源现状：已有资源。

## 前置条件与适用范围

任务已定，需要确认最小素材集合和缺口，不重新维护专业方向。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 任务已经明确，需要列出要准备的素材”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$design-visual-asset-spec](<../../../../../project-source/skills/design-visual-asset-spec/SKILL.md>)、[$design-audio-asset-spec](<../../../../../project-source/skills/design-audio-asset-spec/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜盘点消费需求**

当前 Agent 按任务实际界面、表现和声音盘点已有文件与缺项，只纳入当前采用且获准方案的资源需求。

**S2｜引用准备规格**

已有视觉或音频规格直接引用；缺少局部参数时由所属 asset-spec 方法补到原表现方案、UI 或共享设计的资源章节。

**S3｜交付准备要求与缺项**

交付所属章节的引用、用途、预计文件去向和未到位项概述；规格、状态和文件关系留在原章节，不另建清单，制作不在本次范围。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 最小素材集合对应实际消费 |
| S2 | 每项文件要求只有一处正文 |
| S3 | 准备者知道需要提供什么 |

## 资源与文件影响

所属表现方案、UI 或共享设计中的资源章节修改；不复制、制作或购买素材。

## 阻塞、异常与范围变化

用途或任务边界未定时保留具体缺口，不先列全游戏素材。

## 完成状态与验证标准

本任务必要素材、已有覆盖、准备要求与文件去向明确。
