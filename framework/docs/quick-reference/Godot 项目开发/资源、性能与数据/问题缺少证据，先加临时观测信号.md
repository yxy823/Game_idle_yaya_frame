# 问题缺少证据，先加临时观测信号

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

问题缺少证据，先加临时观测信号。

需要的材料：

- 诊断问题：待区分的原因。
- 修改与清理边界：允许插入位置、观测运行与清理范围。

## 前置条件与适用范围

现有证据不足，已授权临时诊断修改。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 问题缺少证据，先加临时观测信号”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$diagnostics-instrumentation](<../../../../../project-source/skills/diagnostics-instrumentation/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜选择最小信号**

当前 Agent 用 diagnostics-instrumentation 从待判断假设选择事件或计数，不采集无关信息。

**S2｜观测并保存证据**

在指定版本添加临时信号，运行获准场景，记录采样条件与原始输出。

**S3｜清理临时修改**

取得所需结果后移除临时埋点及无用临时文件；保留必要原件和结论。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 信号足以区分具体原因 |
| S2 | 结果绑定实际诊断版本 |
| S3 | 诊断生命周期已结束 |

## 资源与文件影响

临时观测代码在本次范围内新增后清理；原始诊断报告按需保留。

## 阻塞、异常与范围变化

信号改变行为或开销过高时停止并说明；改为长期指标需要独立明确目标。

## 完成状态与验证标准

所需信号已取得或明确无法取得，临时修改清理且原始依据保留。
