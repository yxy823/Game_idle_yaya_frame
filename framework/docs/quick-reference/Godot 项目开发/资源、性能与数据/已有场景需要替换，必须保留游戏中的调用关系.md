# 已有场景需要替换，必须保留游戏中的调用关系

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已有场景需要替换，必须保留游戏中的调用关系。所需材料：当前任务、旧新场景、消费位置、信号和节点契约。

## 前置条件与适用范围

已有场景由明确的新场景替换，需要保护其既有消费者。

## 执行步骤

使用[集中提示词库](../../../../prompts.json)中的“Godot 项目开发 → 资源、性能与数据 → 已有场景需要替换，必须保留游戏中的调用关系”。由当前 Agent 使用 [$content-asset-integration](../../../../../project-source/skills/content-asset-integration/SKILL.md)，运行修改与交付返回 [$feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md)。

**S1｜核对接入契约**

当前 Agent 使用 content-asset-integration，追查实际实例位置、外部节点路径、信号和脚本调用，区分需保持契约与批准改变的行为。

**S2｜完成资源接入**

在获准范围替换场景并修复直接消费者，保留必要标识和原件，不因同名覆盖跳过依赖核对。

**S3｜检查真实运行**

返回 feature-execute，运行受影响入口及重复创建/释放，检查原消费者行为和必要回归，记录真实体验结果。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 输入和实际依赖明确 |
| S2 | 目标项目引用已建立 |
| S3 | 运行与体验结果如实记录 |

## 资源与文件影响

旧场景可能替换，相关消费者和依赖引用修改；原确认需求与历史验收不篡改。

## 阻塞、异常与范围变化

资源缺失、依赖不明或要求冲突时保留缺口；不凭导入成功宣称功能或体验通过。

## 完成状态与验证标准

新场景承担已确认职责，实际消费者调用有效，必要运行与回归有结果。
