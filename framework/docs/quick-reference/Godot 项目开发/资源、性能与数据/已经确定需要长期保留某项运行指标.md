# 已经确定需要长期保留某项运行指标

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已经确定需要长期保留某项运行指标。

需要的材料：

- 观测用途：指标目的、实际消费者。
- 保留与成本要求：保留范围、开关和开销要求。

## 前置条件与适用范围

长期观测有已确认用途，本次实现可维护的持久能力。

## 执行步骤

使用[集中提示词库](<../../../../godot-development-prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 已经确定需要长期保留某项运行指标”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$diagnostics-instrumentation](<../../../../../project-source/skills/diagnostics-instrumentation/SKILL.md>)、[$engineering-change-plan](<../../../../../project-source/skills/engineering-change-plan/SKILL.md>)、[$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜明确维护责任**

当前 Agent 在所属任务内写清指标含义、消费者、采集开关、保留/清理与成本；独立工程工作用 maintenance 规划。

**S2｜实现最小观测**

diagnostics-instrumentation 提供专业方法，feature-execute 完成采集与必要消费，避免通用平台。

**S3｜验证生命周期**

检查启停、重置、开销和长期资源释放，按所属任务完成验证与交付。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 长期职责和验收明确 |
| S2 | 指标可以被实际使用 |
| S3 | 长期运行责任没有遗漏 |

## 资源与文件影响

获准代码、配置和必要指标说明修改；不另外复制 Feature 状态。

## 阻塞、异常与范围变化

没有实际消费者或保留理由时重新评估必要性，不能只因临时日志有用永久保留。

## 完成状态与验证标准

所选指标可用，开销和生命周期有验证，持久责任归属明确。
