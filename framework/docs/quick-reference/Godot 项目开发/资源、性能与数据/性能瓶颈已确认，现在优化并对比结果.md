# 性能瓶颈已确认，现在优化并对比结果

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

性能瓶颈已确认，现在优化并对比结果。

需要的材料：

- 瓶颈依据：已确认瓶颈、基线原件。
- 任务与优化目标：所属任务、优化范围与指标。

## 前置条件与适用范围

有可比较的瓶颈基线和实现授权，原任务或独立 maintenance 已承接。

## 执行步骤

使用[集中提示词库](<../../../../godot-development-prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 性能瓶颈已确认，现在优化并对比结果”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$diagnostics-performance](<../../../../../project-source/skills/diagnostics-performance/SKILL.md>)、[$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜核对比较基线**

当前 Agent 用 diagnostics-performance 确认采样条件、瓶颈与允许改变的范围。

**S2｜实施最小优化**

feature-execute 优先修正数据访问、算法或生命周期，不凭猜测搭缓存框架。

**S3｜对比收益和代价**

在同一场景测量当前结果，并检查行为、画质、内存和资源成本，移除无收益复杂改动。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 前后对照可用 |
| S2 | 修改直接针对已证实瓶颈 |
| S3 | 收益与副作用都有证据 |

## 资源与文件影响

获准实现和必要回归修改，保留前后原始测量；性能方法本身不办理任务完成。

## 阻塞、异常与范围变化

指标条件变更时重新说明可比范围，不能混用数据宣称提升。

## 完成状态与验证标准

瓶颈目标得到可比较改善且副作用可接受，所属任务适用验证完成。
