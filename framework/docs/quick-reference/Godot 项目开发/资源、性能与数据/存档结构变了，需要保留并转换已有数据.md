# 存档结构变了，需要保留并转换已有数据

[返回场景索引](../../scenario-index.md) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

存档结构变了，需要保留并转换已有数据。

需要的材料：

- 格式与样本：旧新格式、获准样本副本。
- 数据保留要求：必须保留字段、允许损失。

## 前置条件与适用范围

数据变化已明确且由正式任务承接；玩家含义变化先在 GDD 中确认，并核对 Product 交付影响。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 存档结构变了，需要保留并转换已有数据”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$engineering-change-plan](<../../../../../project-source/skills/engineering-change-plan/SKILL.md>)、[$feature-execute](<../../../../../project-source/skills/feature-execute/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜明确保留契约**

当前 Agent 核对真实旧样本、字段含义、默认值、信息损失与失败后保留方式。

**S2｜实现最小转换**

在所属 maintenance 任务按获准结构做一次性或必要转换，不覆盖原件，不搭通用迁移平台。

**S3｜验证保留与失败**

比较转换前后需要保留的信息，核对新数据往返及异常样本，保留失败原件。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 转换责任和数据取舍明确 |
| S2 | 样本副本可被新读写使用 |
| S3 | 保留要求和失败保护有证据 |

## 资源与文件影响

获准数据实现和样本副本修改；真实唯一存档与未授权个人数据不动。

## 阻塞、异常与范围变化

字段含义未定、无法满足已确认的保留要求，或信息损失超出已允许范围时，停止依赖部分并保留原件及失败样本。说明实际缺口和需要的取舍，不静默丢弃必须保留的信息或扩大数据访问；已明确允许的损失不另加无损转换门槛。

## 完成状态与验证标准

获准样本转换可用且必要信息保留，原件安全，转换限制和验证明确。
