# 短测看不出问题，需要按约定负载持续运行

## 触发场景与使用时机

短测看不出问题，需要按约定负载持续运行。需要的材料：场景、真实负载、目标时长、设备、预算和停止条件。

## 前置条件与适用范围

需要时间跨度上的实际证据，具备运行条件及授权。

## 执行步骤

使用[集中提示词库](<../../../../prompts.json>)中的“Godot 项目开发 → 资源、性能与数据 → 短测看不出问题，需要按约定负载持续运行”。填入上述材料；已有对话直接补齐输入，不必重发入口。本页使用 [$diagnostics-soak-test](<../../../../../project-source/skills/diagnostics-soak-test/SKILL.md>)，具体执行者和切换位置见下文。

**S1｜固定长跑条件**

当前 Agent 使用 diagnostics-soak-test 记录版本、负载、指标和停止条件，核对必要信号已存在。

**S2｜执行实际运行**

按获准条件持续运行并采集原始信息，故障和中断即时保留实际时长。

**S3｜解释结果**

报告趋势、异常、真实持续时间和未覆盖部分，返回所属任务处理发现。

## 步骤产出与状态变化

| 步骤 | 可继续的依据 |
| --- | --- |
| S1 | 计划时长与判断标准明确 |
| S2 | 运行覆盖可核实 |
| S3 | 中断不冒充满时长 |

## 资源与文件影响

只产生获准长跑日志、缓存和报告；原实现与验收要求不改变。

## 阻塞、异常与范围变化

缺信号或运行被中断时说明有效覆盖，不伪造 gdUnit 通过代替长跑。

## 完成状态与验证标准

实际运行与证据已经交付，达到计划或未达的原因如实说明。
