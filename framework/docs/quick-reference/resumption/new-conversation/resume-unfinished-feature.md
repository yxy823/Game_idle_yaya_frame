# 换了一个对话，想继续上次没做完的 Feature

[返回场景索引](../../scenario-index.md#中断与续接) · [执行步骤](#执行步骤) · [完成标准](#完成状态与验证标准)

## 触发场景与使用时机

已经来到新对话，希望接着原来的 Feature 开发，不重复已经完成的工作，也不遗漏实际失败和待验收事项。

## 前置条件与适用范围

新对话能够访问同一项目或原 worktree，原 Feature 尚未完成。当前目标明确为续接实施，已有项目文件、Git 状态、Progress 或交接材料可供核实。

本页处理接收方恢复现场。原对话准备交接、只读查询状态、切换另一个任务分别属于其他场景。开始只读核对不要求工作区先变干净。

## 参与角色与职责边界

用户提供实际项目位置、任务线索和续接目标，补齐无法从现有材料恢复的实质决定；接收方 Agent 核对现场并继续已有授权。旧摘要提供线索，不能代替当前文件和实际验收结果。

## 执行步骤

在实际项目或原 worktree 的新对话中，使用 [集中提示词库](../../../../prompts.json)中的“Godot 项目开发 → 日常开发 → 继续中断的当前任务”。填入真实目录、Feature ID、交接材料，以及最近结果、已有决定和新增要求。

执行者是新对话的接收方 Agent，使用 [$feature-execute](../../../../../project-source/skills/feature-execute/SKILL.md)恢复原任务，不需要专门的交接 Agent。仅请求状态建议时才适用 `project-next-step-advisor`；本页已请求继续实施，不先退回只给建议。

**S1｜核对位置**

接收方 Agent 读取当前项目 `AGENTS.md` 和 `docs/progress.md`，用 `git status --short`、`git branch --show-current` 及实际差异核对目录、分支与修改归属。原任务在 worktree 时继续使用该 worktree。

**S2｜恢复任务**

Agent 读取 `docs/feature-list.json`、当前 Feature 详情、相关来源与必要交接历史，依据 `feature-execute` 确定真实 Stage、已做内容、剩余义务和仍有效授权；不从 Stage 1 机械重跑。

**S3｜核实结果**

Agent 检查原始运行报告、完成依据与实际人工反馈，对照当前内容判断哪些仍有效，并查明已有进程是否尚未结束。需要查看完成记录时，在项目根目录用配置的 Python 调用 `tools/features/record-feature-completion.py show --feature <实际ID>`；展示结果不能替代原件核对或人工接受。

**S4｜接回下一步**

Agent 说明真实停点和下一项具体动作，使用 `feature-execute` 从对应阶段继续已有授权工作。只对影响下一步且无法恢复的决定集中补问；必要时更新现有 `docs/progress.md` 中的真实停点，不另建交接台账。

## 步骤产出与状态变化

| 步骤 | 产出与继续条件 |
| --- | --- |
| S1 | 实际目录与原任务对应，差异归属可检查 |
| S2 | 当前任务、已完成部分、待办和有效决定清楚 |
| S3 | 有效、失败、过期及未执行结果分别确认，未结束运行没有被重复启动 |
| S4 | 接收方已经接回原任务；没有仅因换对话重复规划或索取同一授权 |

## 资源与文件影响

| 项目内对象 | 影响 |
| --- | --- |
| 规则、Git 状态、Feature、来源及相关历史 | 只读恢复现场 |
| 原始测试和人工材料、运行状态 | 核实真实结果，不凭摘要制造原件 |
| docs/progress.md | 有必要时更新真实停点，保留必要历史链接 |
| 原任务代码或其他文件 | 恢复后仅按原任务的授权和相应步骤修改 |

## 阻塞、异常与范围变化

目录或差异归属不清时，保留全部现场，暂停写入并核实；不自动清空、stash 或提交未知内容。只有摘要且关键授权、产品决定无法核实时，集中补问影响下一步的必要事项。

交接后实际内容发生变化时，重新核对受影响部分。证据丢失或过期时，保留真实缺口，回原任务补足所需验证；等待人工体验时，给出当前入口和待验收项，不冒充已接受。

## 完成状态与验证标准

能够明确指出真实目录、原 Feature、当前停点、差异归属、有效决定、验证状态和下一动作，并已把执行接回原任务。恢复完成不把 Feature 标为完成，也不结束尚未完成的已授权实施。

## 流程关联与衔接关系

本页可接续任一未完成场景。纯报告路径错误可以转[结果导入恢复](../../verification/existing-results/import-passed-tests.md)；接回后的完成标准仍属于原任务。
