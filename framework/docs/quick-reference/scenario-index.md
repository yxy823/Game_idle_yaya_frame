# 场景速查索引

先找“要处理什么事情”，再选当前状态，进入对应场景。当前是八篇 Markdown 样稿；下面有链接的页面已经成稿，文末列出的其他范围等待样稿讨论后迁移。

当前样稿尚未迁入 `Project/分类/提示词名称.md`，也尚未补齐同名专用提示词；后续按[编写要求](README.md#目录与单篇范围)调整，现有链接仅用于试读。

各页中的项目文件路径均相对生成后的游戏项目根目录。Feature 是一次有明确验收条件的开发任务；测试通过与 Feature 完成交付分别判断。页面是查阅入口，不替代实际项目规则或用户授权。

## 需求与计划

### 当前模块的要求已经明确，还没有计划

[当前模块的需求已确认，准备做项目的第一份 Feature 计划](requirements/ready-to-plan/plan-confirmed-module.md)

目标：形成当前模块的正式计划。本样稿限定首次规划，来源已确认且项目的任务索引与修订记录均为空。

### 已有计划，Feature 还没开始开发

[Feature 还没开工，但已经确认要修改其中一条要求](requirements/confirmed-plan/change-before-development.md)

目标：将已提交的要求变化同步到尚未开工的计划。正在开发或已经完成的任务变化另列场景。

## 界面与资源接入

### 界面方案和代表性素材已经具备

[界面布局已经确定，想先做一个能点击的原型](interface-assets/ui-ready/build-clickable-prototype.md)

目标：做出可单独体验的界面原型，并取得对应范围的实际体验结论。

### 音效文件和播放要求已经具备

[音效文件和播放位置都已确定，现在要把声音接进游戏](interface-assets/audio-ready/connect-approved-sound.md)

目标：完成这一项声音的游戏内接入与实际试听，不在本页设计全局声音风格或制作素材。

## 问题修复

### 当前 Feature 尚未完成交付

[Feature 交付前发现 Bug](issues/current-feature/bug-after-tests.md)

目标：在当前任务内修复，取得针对问题的验证结果，再返回原 Feature 的完成检查。

### 出问题的 Feature 已经完成交付

[Feature 交付后发现 Bug](issues/completed-feature/bug-after-delivery.md)

目标：以独立工程 Bug 任务修复，取得验证结果并返回该任务的完成检查；保留原 Feature 的完成历史。

## 测试与交付

### 已有成功运行，只缺结果导入

[测试已经通过，但结果没有导入成功](verification/existing-results/import-passed-tests.md)

目标：修正错误的结果路径引用并导入有效原件。测试本身失败、原件缺失或内容已经变化时不适用。

## 中断与续接

### 已经来到同一项目的新对话

[换了一个对话，想继续上次没做完的 Feature](resumption/new-conversation/resume-unfinished-feature.md)

目标：恢复真实停点并接回原任务。准备交接、只查状态、切换其他任务分别属于其他场景。

## 样稿讨论后补齐的范围

| 事项 | 后续应拆分并迁入的情境 |
| --- | --- |
| 项目创建与接手 | 新建空白项目、准备环境、复制迁移已有项目、接管已有实现 |
| 需求与计划 | 整理想法/GDD、后续模块规划、插入 Product、开发中与交付后的要求变化 |
| 界面与资源接入 | 缺少素材、资源替换、美术与声音规格、本地化、工作台在具体任务中的使用 |
| 问题修复 | 启动失败、无法复现、测试失败、引擎诊断失败、原件缺失与过期 |
| 工程调整与调查 | 共享修改、设计过重、重构、项目工具维护、限定实验、观测及性能测量、独立审核 |
| 测试与交付 | 准备人工验收、人工拒绝、自动验收后的收尾、完成记录与交付 |
| 中断与续接 | 中途插入工作、原对话准备交接、仅查询状态 |
| 资料与知识维护 | 调研、术语、设计/架构、规则、经验沉淀、文档与实际不一致 |

这些条目说明后续覆盖范围，不是已经写好的场景，也不要求使用者顺序执行。首轮请重点对照两个 Bug 页面，检查状态差异是否足以选对入口；再检查导入恢复页是否仍混入测试修复。

编写和调整页面时使用本册的[编写说明](README.md)。
