# 导出配置验证

```text
preset discovery and parse
-> target and template availability
-> credential availability
-> resource selection
-> feature and override resolution
-> export plugin hooks
-> actual export
-> package and artifact content
-> exported runtime startup
-> target-specific checks
```

上面的验证链依次为：发现并解析预设 → 目标与模板可用 → 凭据可用 → 资源选择 → feature 与覆盖解析 → 导出插件钩子 → 实际导出 → 包与产物内容 → 导出后的运行时启动 → 针对目标的检查。

- **[必须]** 修改导出配置的行为时，运行对应的实际 Godot 导出预设和构建模式。
- **[必须]** 记录本次验证使用的准确预设、导出模式和解析后的产物路径。路径解析遵循[预设](presets-and-targets.md#预设)。
- **[必须]** 检查官方进程或 API 的结果，以及位于该解析路径的产物。其他目录中同名的旧输出，或残留在目标路径上的旧输出，都不算 PASS。
- **[必须]** 验证目标、预设和模式要求的完整产物集合，包括配套的包和针对目标的文件，不孤立地只检查一个输出文件。
- **[必须]** 仅导出 PCK 或 ZIP 包不是完整的可执行导出。ZIP 作为主包使用时，验证实际的 `--main-pack` 或项目启动器以及加载契约。
- **[必须]** 对打包敏感的修改，核实相关内容确实存在或确实不存在，最好通过检查包内容、导出后运行时使用方的行为，或两者兼用。
- **[必须]** 检查包内容时，核实生成的产物内部包含所需路径，包括对原始文件和隐藏路径的预期；仅在源码树中存在或仅看过滤器配置都不够。
- **[必须]** 修改资源过滤器、自定义 feature 和导出插件时，通常要包含一次导出后的运行时冒烟测试，并有明确的就绪或成功条件。从本次验证生成的产物启动，不从之前的构建启动。
- **[必须]** 只修改签名时，需要对应目标的 release 检查和签名检查；除非其他行为也改变了，否则不需要运行无关的玩法测试套件。
- **[必须]** 依赖主机或平台的分发行为，需要实际的目标环境，或经明确认可的等效构建管线。
