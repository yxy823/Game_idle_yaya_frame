# Export Configuration Validation

```text
preset discovery/parse
-> target/template availability
-> credential availability
-> resource selection
-> feature/override resolution
-> export plugin hooks
-> actual export
-> package/artifact content
-> exported runtime startup
-> target-specific checks
```

- **[MUST]** Export-config behavior changes run the corresponding actual Godot export preset/build mode.
- **[MUST]** Record the exact preset, export mode, and resolved artifact path for the validation run. Resolve a relative CLI `--export-*` path from the project root, not the shell working directory.
- **[MUST]** Check the official process/API result and the artifact at that resolved path; an old same-named output in another directory, or an old output left at the target path, is not PASS.
- **[MUST]** Validate the complete artifact set required by the target/preset/mode, including companion packs or target-specific files, rather than checking one output file in isolation.
- **[MUST]** A pack-only PCK/ZIP export is not a complete executable export. For a ZIP used as the main pack, validate the actual `--main-pack` or project launcher/loading contract.
- **[MUST]** Packaging-sensitive changes verify relevant content is actually present or absent, preferably through package inspection and/or exported runtime consumer behavior.
- **[MUST]** Package inspection verifies required paths inside the generated artifact, including raw-file and hidden-path expectations; source-tree presence and filter configuration alone are insufficient.
- **[MUST]** Resource-filter, custom-feature, and ExportPlugin changes normally include an exported-runtime smoke with a defined readiness/success condition, launched from the artifact generated by this validation run rather than a previous build.
- **[MUST]** Signing-only changes need the appropriate target Release/signature checks, not unrelated gameplay suites unless other behavior also changed.
- **[MUST]** Host/platform-sensitive distribution behavior needs the actual target environment or an explicitly approved equivalent build pipeline.
