# Export Configuration Validation

```text
preset discovery and parse
-> target and template availability
-> credential availability
-> resource selection
-> feature and override resolution
-> export plugin hooks
-> actual export
-> package and artifact content
-> exported runtime startup
-> target-specific checks
```

- **[MUST]** Changes to export configuration behavior run the corresponding actual Godot export preset and build mode.
- **[MUST]** Record the exact preset, export mode and resolved artifact path for the validation run. Path resolution follows [Presets](presets-and-targets.md#presets).
- **[MUST]** Check the official process or API result and the artifact at that resolved path. An earlier output with the same name in another directory, or one left at the target path, is not PASS.
- **[MUST]** Validate the complete artifact set that the target, preset and mode require, including companion packs and target-specific files, rather than checking one output file in isolation.
- **[MUST]** A pack-only PCK or ZIP export is not a complete executable export. For a ZIP used as the main pack, validate the actual `--main-pack` or project launcher and loading contract.
- **[MUST]** For packaging-sensitive changes, verify that the relevant content is actually present or absent, preferably through package inspection, exported runtime consumer behavior, or both.
- **[MUST]** Package inspection verifies the required paths inside the generated artifact, including expectations for raw files and hidden paths; presence in the source tree and filter configuration alone are insufficient.
- **[MUST]** Changes to resource filters, custom features and export plugins normally include an exported-runtime smoke test with a defined readiness or success condition. Launch it from the artifact generated by this validation run, not from a previous build.
- **[MUST]** Signing-only changes need the appropriate target release and signature checks, not unrelated gameplay suites unless other behavior also changed.
- **[MUST]** Distribution behavior that depends on the host or platform needs the actual target environment or an explicitly approved equivalent build pipeline.
