# 导出插件与钩子

`EditorExportPlugin` 是构建管线代码，可以改变最终打包的内容。

## 适用范围

- **[必须]** `EditorExportPlugin` 的修改除了是 GDScript 和编辑器插件修改，还要当作构建管线修改处理。
- **[必须]** 修改文件的包含、跳过或重映射，场景或 Resource 的定制，原生库打包或导出 feature 时，需要通过实际导出验证。
- **[必须]** 不要用 `path.contains('test')` 这类含糊的子串推断来决定生产包包含什么。对路径和职责使用项目自己定义的明确契约。

## 执行契约

- **[必须]** 只在 `_export_file()` 中调用 `skip()`，用于跳过当前正在处理的文件。
- **[必须]** `add_file(..., remap = true)` 只有在 `_export_file()` 中调用时才会重映射当前文件。用 `add_file()` 添加的字节不经过导入器；要替换已导入的 Resource，使用场景或 Resource 定制 API。
- **[必须]** `_get_name()` 返回稳定且唯一的插件名称。Godot 按这个名称给导出插件排序。多个插件可能影响同一产物时，明确各自负责的部分和预期顺序，然后验证最终的包。

## 定制

- **[必须]** `_get_customization_configuration_hash()` 覆盖每个会影响结果的选项，再加上一个稳定的定制实现或模式版本号——这个实现或模式改变时，定制结果会改变。
- **[必须]** 定制算法改变时，修改这个实现版本号，让之前缓存的输出失效。不要假定只编辑插件脚本就会重新执行定制。
- **[必须]** 对相同的源文件、预设、影响结果的配置和工具版本，导出定制的结果是确定的。避免不受控的系统时钟、RNG 或 UUID 值，无序遍历和机器上的绝对路径。
