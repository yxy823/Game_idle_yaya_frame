# 导出预设与目标

`export_presets.cfg` 是构建与分发配置，不是运行时的 `project.godot` 配置。

## 预设

- 建议：结构性的预设修改通过 Godot 导出对话框完成。手工文本修改只用于小而确定的改动，并用实际导出验证。
- 被命令行或脚本引用的预设名称是构建 API；重命名时同步迁移所有引用。
- debug 导出、release 导出和仅 PCK 导出证明的是不同的契约。验证本次真正需要的模式。
- 命令行 `--export-release`、`--export-debug`、`--export-pack` 的相对输出路径从项目根目录解析，不从 shell 的工作目录解析。注意：目标目录必须已经存在，否则导出失败。
- 建议：提交到仓库的预设 `export_path` 使用项目内的相对路径，不写特定机器或特定用户的绝对路径。

## 目标身份

- 不要为整理或方便修改目标平台、架构、渲染器、模板或应用身份。
- 已发布的应用名称、包名和产品标识是分发身份。修改它们可能让新版本被识别为另一个应用；修改前检查对已安装版本更新的影响。
- 导出模板的版本与验证所用的 Godot 4.7 编辑器一致。

## 密钥

- 导出密码、加密密钥、私钥、访问令牌等密钥不写进 `export_presets.cfg`、测试、AGENTS 文件、项目配置或日志。
- 敏感凭据放在 Godot 编辑器的凭据设置或受支持的环境变量中。
- 按字段的实际用途判断是否保密：包名和证书名称不算密钥，密码和私钥是密钥。
- 构建或测试的诊断输出中不打印完整的密钥值。

## 签名

- 生产签名凭据不可用时，报告 release 验证受阻。
- 不要为了让 release 导出通过而悄悄禁用签名、改用 debug 签名或使用临时凭据，除非任务明确要求这种模式。
