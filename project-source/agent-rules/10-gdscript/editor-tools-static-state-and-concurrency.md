# GDScript 编辑器工具、静态状态与并发

## 编辑器与工具代码

- 只在确有编辑器期行为时使用 `@tool`。在 `@tool` 脚本中用 `Engine.is_editor_hint()` 分开编辑器路径和运行时路径，预期只在编辑器中发生的副作用放进编辑器路径。不用 `OS.has_feature("editor")` 代替它：从编辑器启动的游戏也带有这个特性。
- 工具脚本在编辑器中实例化另一个脚本，或访问它的成员和实例方法时，那个脚本也要声明 `@tool`。静态方法、常量和枚举可以直接使用；非工具脚本的静态变量在编辑器中读取时总是 `null`，而且没有警告或错误。
- 继承 `@tool` 脚本的子脚本不会自动成为工具脚本，需要在编辑器中执行时自己声明 `@tool`。
- 编辑器中对场景或资源的修改没有自动的撤销。用户能作为一次操作执行的修改，通过 `EditorUndoRedoManager` 提交。
- 建议：可复用脚本的依赖由检查器指定、且可能配置错误时，实现 `_get_configuration_warnings()`，并在相关属性变化时调用 `update_configuration_warnings()`。这需要 `@tool`；实际的失败仍由运行时校验处理。

## 静态与全局状态

- 可变的 `static var` 是进程级全局状态，在整个运行期间存续。使用前写明所属方和重置时机；不用它绕开依赖注入或权威所有权。需要全局所有权时用 Autoload，需要跨运行保留的状态用文件或 Resource。
- `_static_init()` 保持确定、轻量，不访问文件、网络或 SceneTree。
- 静态函数不能访问 `self` 或实例成员。

## 对象池与性能

- 建议：只有性能分析证明存在分配热点时，才为高频创建的对象（例如伤害数字）建对象池。
- 回收到池中的 Node 显式停用：`hide()`、`set_process(false)`、`set_physics_process(false)`，以及停用碰撞或输入等它实际使用的处理。不用 `set_deferred("process_mode", ...)` 作为通用的停用方式。
- Debugger 的 Monitors 中 Orphan Nodes 持续上升时，查找移出树后没有释放的 Node。

## 线程

- 建议：只有工作负载确实受益于并发时才用线程；否则保持单线程。
- 工作线程不访问活动的 SceneTree，也不修改主线程拥有的 Node。对活动树的修改用 `call_deferred()` 交回主线程。
- 在树外由单个线程构建 Node 或场景，只有在用到的每个 API 都线程安全时才允许；加入活动树前回到主线程。
- 多个线程共享的可变数据（包括 Resource、会改变大小的 Array 和 Dictionary）用 `Mutex` 或其他同步手段保护，并写明所有权。注意：Godot 的 `Mutex` 可重入，同一线程每次加锁都要有一次对应的解锁。
- 加锁区段内会调用回调或发出信号时，检查加锁顺序和跨线程等待，以及回调是否会看到更新到一半的状态。
- 渲染、物理、导航等 Server API 的线程安全要求各不相同。把这类工作移出主线程前，查对应类文档和所需的 ProjectSettings。
