# 3D 模型

## 格式与交付边界

- 游戏项目只接收 glTF 2.0 的 `.glb` 运行时文件。Blender `.blend` 母版和导出、换色脚本留在项目外的制作项目，见 methodology 11 的 **在项目外制作**。
- 注意：`.blend` 不放进工程目录。项目设置 `filesystem/import/blender/enabled` 默认开启，Godot 扫描到 `.blend` 会调用 Blender 导入；本机没有配置 Blender 路径时会报导入错误，配置了也会让导入结果依赖本机的 Blender 版本。
- GLB 只含游戏要用的节点、网格和材质。制作时的预览相机、灯光和定位标记不导出，否则它们会出现在游戏场景里。

## 坐标、单位与缩放

- glTF 规定 +Y 向上、1 单位等于 1 米。整条链路只做一次轴转换，由制作工具导出时完成（Blender 导出开启 `+Y Up`）。不在场景或脚本里再叠加 ±90° 修正，因为下一版重新导出时修正会叠加或失效。
- 根节点和网格的缩放保持 1。尺寸不对时回到制作项目改源文件，不在导入设置或实例上补缩放，因为补偿值不会跟着重新导出的文件走。
- 接收时核对导入后的包围盒和原点，与资源条目里记录的尺寸、原点和正面方向比较；只看文件能否加载，查不出轴向或缩放错误。

## 材质与颜色

- 颜色和材质在制作项目里改，再重新导出 GLB。不把 GLB 的材质提取成独立的 `.tres` 再手改颜色，因为提取后材质不再随 GLB 更新，下次重新导出时改动不会生效。
- GLB 内嵌的贴图在导入时按 `gltf/embedded_image_handling` 处理，默认提取成工程里的图片文件。替换某版 GLB 时，检查旧版本提取出的贴图是否还有使用方，没有就一起删掉。
- 注意：金属材质依赖环境反射。`WorldEnvironment` 没有天空或其他反射来源时，金属表面会接近黑色，看起来和制作工具里的预览不一致。先补场景的环境反射，不改 GLB 的颜色。
- 比较 Godot 画面和制作工具的预览时，写明双方的渲染器、抗锯齿和色调映射；条件不同时，差异不能归到模型本身。抗锯齿的取值属于显示基线，见 `40-project-config/subsystem-settings.md` 的 **视口、窗口与拉伸**。

## 验证

在一般素材验证之外：

- 在游戏实际的镜头和显示尺寸下截图查看，不只在独立的检查场景里看；展示尺寸、伸出和遮挡按资源条目的口径测量。
- 替换模型后，核对每个使用方都指向新版本，旧版本文件和它提取出的贴图已删除或仍有使用方。
- 帧时间和性能结论只在目标 Windows PC 上测得才算数，同时记录可见实例数和图元数。
