# 场景结构、实例与归属

本页规定场景修改的编辑范围、层级与 owner、PackedScene 实例和继承场景的处理，修改任何 `.tscn` 时读。

场景层级表达所有权、生命周期、变换和属性传播。拆分或合并场景按职责判断，不按节点数、树深度或行数，见[职责](../10-gdscript/structure-and-dependencies.md#职责)。

## 编辑范围

- 聚焦的场景修改不顺带做序列化规范化、段落重排、ID 清理或格式化。
- 不为减少节点数而移除合理的 Timer、AnimationPlayer、包装节点或组件节点。
- 场景可以同时包含游戏逻辑和表现。跨越这条边界时，按 [docs/game-organization.md](../../../docs/game-organization.md) 找出状态的权威所属方；动画回调可以提供时机，是否生效由游戏规则的所属方决定。

## 层级与 owner

- 父子结构反映所有权、生命周期和变换依赖。
- `parent` 和 `owner` 是两回事。不图省事把每个节点的 owner 递归设为场景根节点；owner 决定节点是否随场景保存。
- 建议：根脚本提供场景的公共 API，子脚本负责各自的组件或子树。
- 多个独立的写入方修改同一个视觉或玩法属性时，指定一个协调者，不依赖“最后写入者生效”。
- 更换节点的父节点或加一层包装时，检查变换、处理与暂停模式、可见性、`modulate`、主题、owner 和其他会从父节点继承的行为。跨越实例边界或 owner 边界的更换父节点，同时检查所有引用和消费方。

## PackedScene 实例

- 保留实例的 PackedScene 身份，除非任务要求把它本地化或拆开。
- 修改前先决定它属于源场景，还是实例上的本地覆盖。
- 运行时代码用 `PackedScene.instantiate()`。编辑器工具要在当前编辑的场景中创建会被保存的实例时，用 `instantiate(PackedScene.GEN_EDIT_STATE_INSTANCE)`，并只把实例根节点的 owner 设为被编辑场景的根节点；不递归改写实例内部节点的 owner。
- `Editable Children` 会打开实例边界，只在确有需要时启用，不为修补深层子节点图方便而启用。

## 继承场景

- 继承场景是“基础场景加覆盖”。共享行为放在基础场景，派生场景只保留最小的覆盖。
- 不为方便编辑而把继承场景展平，或把基础场景的状态复制进派生场景。
- 基础场景的结构或节点名变化时，检查所有派生场景及其覆盖。
