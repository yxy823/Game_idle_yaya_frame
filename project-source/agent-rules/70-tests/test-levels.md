# 测试层级

静态检查（解析、lint、文件校验）和行为测试是两类证据，分开报告，不能互相代替。行为测试按需要多少真实的 Godot 运行时语义分为三层，选择能证明契约的最低一层。

| 层级 | 验证对象 | 运行时边界 |
| --- | --- | --- |
| 单元测试 | 一个规则或状态单元：计算、校验器、状态转换、Command 规则 | 不需要 SceneTree 生命周期。用到 Node 类型不会让测试升层 |
| 集成测试 | 真实协作：组件之间，或与 Node、Resource、Signal、SceneTree 的协作 | 被验证的协作者保持真实。全部协作者都被 mock 时仍是单元测试 |
| 运行时场景测试 | 跨系统的关键玩法流程 | 从合法场景出发，经生产 Command、API 或输入路径驱动 |

层级只决定测试怎样写，不决定放在哪个目录。测试按保护的对象放进 `tests/unit`、`tests/features` 或 `tests/invariants`，见[测试分类](../../methodology/08-test-traceability-and-evidence.md#测试分类)；调试台自身的测试在 `dev/debug/` 下，全量运行同时包含 `tests/` 与 `dev/debug/`。

## 通用要求

- 项目只用 gdUnit4，见 [gdunit4-profile.md](gdunit4-profile.md)。不引入第二个测试框架，也不把引擎的 `--test` 基础设施当作 GDScript 测试框架。
- 每个测试用例都有可观察的断言。提前返回或不做断言的测试不算通过。
- 预期值不照搬生产算法。使用已知示例、表格、独立的不变量，或单独维护的参考实现。
- 断言可观察的契约。不锁定私有实现步骤或内部调用顺序，除非顺序本身是业务契约。
- 可调的表现或手感参数（粒子数量、动画时长、移动速度等）不在断言里写死调优值：对照它所在的参数资源，需要证明参数生效时传入测试专用的参数。写死的值会让每次调参都变成测试失败。
- 能可靠自动化的业务 Bug 修复，新增或更新回归测试。纯视觉或美术缺陷用人工验收。
- 纯规则写大量单元测试，真实协作写适量集成测试，高价值流程写少量运行时场景测试。不为了“更真实”把测试都改成从主场景开始的端到端测试。

## 单元测试

- 测试纯计算、校验器、状态转换或 Command 规则时，不启动主场景或无关的 Autoload。
- 一个契约有多组输入时，用参数化或表驱动测试，用例名称要能看出业务场景。无关的契约不塞进同一个参数矩阵。
- 重构覆盖薄弱的旧行为前，先补最少的特征测试。特征测试记录下的已知 Bug 不因此成为正确行为。

## 集成测试

- 用承载被测协作的最小夹具场景，由真实的生产子场景和组件组合而成。不维护需要手工同步的完整生产场景副本。
- 夹具场景只提供组合和已知状态，不重新实现生产行为，也不自动启动主场景。
- 集成目标之外的外部、平台和不确定依赖，用受控的 Fake 或 Stub 替换。
- 用例覆盖边界、连接、生命周期和序列化的代表情况，不重复单元测试的输入矩阵。
- 大量使用 mock 的模块，补代表性的集成测试，证明生产中的连接与被 mock 的契约一致。

## 运行时场景测试

- 从最接近该流程的合法场景或检查点开始。只有启动流程本身是契约时，才从主场景开始。
- 夹具可以快速建立合法的前置条件，但不能直接产出被测操作的结果。
- 通过 SceneRunner 直接改属性或调方法，只用于准备状态或白盒诊断，不能据此声称业务操作可用。
- 流程内的核心系统使用真实实现。流程之外的平台、网络和遥测边界，可以用保留生产接口的 Fake。
- 断言权威的最终状态和领域事件，再加少量帮助定位失败的中间里程碑。

## 测试替身

- 只替换当前测试目标之外的依赖，不 mock 被测的核心行为。
- mock 了 Godot 生命周期、Signal、Resource 或 Input 语义的测试，不能作为真实 Godot 集成的证据。
- 只在协作本身是契约时使用 Spy 和交互断言，不验证每一次内部辅助调用。
- 建议：简单的有状态端口用小型内存 Fake，比复杂的 mock 编排好维护。

## 视觉验证边界

- 项目不设截图、基准图、像素差异、动画相似度或布局检查门槛，普通交付也不隐含这类要求。
- 任务明确约定了客观的渲染契约时，可以加限定范围的截图或像素检查作为补充证据，并写明契约和环境限制。这类检查不代替人工视觉验收。
- 构图、美术一致性、布局外观和动画手感，用人工验收。
- 测试进程不能证明渲染器、窗口或平台语义，这类行为在目标环境中验证。

## 覆盖率与性能策略

- 项目不设覆盖率百分比门槛。覆盖率只作辅助信息，不代替行为断言、集成测试或运行时场景测试。
- 没有项目专属的性能预算和目标硬件约定时，不设通用的性能阈值。
