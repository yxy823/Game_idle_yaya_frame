# 第三方、生成与临时文件

## 先确定所属方和角色

- 编辑一个性质不明显的文件前，确定它的所属方（项目、第三方、工具、测试或未知）和角色（源文件、配置、生成产物、缓存或临时文件）。
- 不仅凭扩展名、是否位于 `addons/`、文件名或 Git 跟踪状态判断。已提交的生成产物仍然是生成产物。生成文件的文件头和清单是有力证据；没有这类标记，也不能证明文件是手写的源文件。

## 第三方代码与素材

- 第三方代码（包括 `addons/` 下的插件）默认是外部依赖。不为项目的 lint、风格、清理警告或让测试变绿而修改它。
- 确需修补第三方代码时，先比较上游更新、适配层和本地补丁，考虑许可证和后续维护成本，并让本地补丁与上游代码能区分开。
- 能否修改第三方素材，由它的许可证、来源和项目策略决定。

## 生成文件与工具管理文件

- 生成产物需要变化时，找到它的权威来源和生成器，修复上游原因后重新生成。不手工修补生成结果。
- `<asset>.import` 是 Godot 管理的导入元数据，既不是普通源文件，也不是可随意丢弃的缓存。通过导入设置修改它，不手工编辑其中的 UID、remap 或其他生成字段。
- `.godot/imported/` 是可重建的缓存，不直接编辑，也不复制进源文件。没有具体的诊断目的并评估影响前，不递归删除整个 `.godot/`。
- 意外出现的流程产物先诊断它是否该存在，不默认用 `.gitignore` 或 `.gdignore` 把它藏起来。

## 临时、备份与草稿文件

- 临时产物要有明确的创建者、有限的用途，以及清理方式或保留期限。存放位置见记录、报告与交接中的[报告与清理](../../methodology/09-records-reports-and-handoff.md#报告与清理)。
- 只清理任务、测试或项目明确拥有的临时产物。不按 `tmp*`、`backup*`、`old*` 这类名称模式删除来历不明的文件。
- 备份、自动保存和恢复副本不是权威来源。没有明确的恢复意图时，不用它们覆盖当前工作。
- 建议：有破坏性的编辑器、导入或序列化实验，在测试拥有的草稿目录或临时 Godot 项目中进行，不在正式内容上试验再指望能恢复。
