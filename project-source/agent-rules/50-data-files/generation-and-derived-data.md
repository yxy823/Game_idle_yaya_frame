# 生成数据与派生数据

解析器、校验器、规范化器和生成器各自承担不同职责；生成的输出可以复现。

## 管线

- **[必须]** 生成器使用经过校验和规范化的输入，不使用部分无效的原始结构。
- **[必须]** 输入的发现方式是明确的。不要扫描任意目录，以免意外收入临时文件、第三方文件或无关文件。
- **[必须]** 派生字段从权威输入重新计算。为了运行时性能而落盘保存时，它们仍属于生成内容，不手工编辑。
- **[必须]** 先把规范输出写到临时位置并校验完整性，再原子地替换提交到仓库的产物或运行时产物，避免失败后留下写了一半或已过期的“成功”状态。

## 版本控制策略

- **[必须]** 生成产物提交到仓库时，重新生成检查的结果与已提交的输出一致，生成产物不手工编辑。
- **[必须]** 生成产物不提交到仓库时，干净检出的仓库能从声明的依赖完整地重新生成它们。
- **[必须]** 源文件哈希可以发现过期的字节，但它不是语义哈希，也不是 schema 版本。
- **[必须]** 修改生成器和规范化器时，重复生成的确定性是验证目标。
