# 数据生命周期与权威来源

外部数据从文件到玩法依次经过：解析 → 结构与类型校验 → 引用解析 → 规范化 → 规范运行时模型 → 玩法只读使用。每一步完成后才进入下一步，解析器的输出不直接交给玩法。

## 权威来源

- 每个数据领域写明唯一的权威编写源，即由人编辑的那个文件，以及运行时使用的规范表示。
- 玩法读取经过校验的带类型模型（自定义 Resource 或类），不读取解析得到的原始 Dictionary、Array 或 Variant。原始值只出现在解析、迁移等边界代码中。
- 定义数据在运行时只读，规则见 Resource 角色、共享与复制中的[角色](../21-resources/roles-sharing-and-locality.md#角色)。
- 运行时代码不把状态写回 `res://` 下的编写源。玩家状态写入存档。
- 建议：数据不需要在外部表格中编辑时，直接做成自定义 Resource（`.tres`），通过 ResourceLoader 加载，省去原始文件的解析与打包问题。项目附带的 “Edit Resources as Table” 插件（`addons/resources_spreadsheet_view/`）可以用表格批量编辑同一目录下的 Resource。

## 错误

- 解析错误、schema 或类型错误、引用错误分别报告。
- 校验发现错误时，拒绝加载这份数据，不用默认值继续运行。不把错误降级为警告来换取通过。
- 诊断信息写出源文件；能定位时，再写出行号或实体 ID、字段名、实际值和违反的约束。

## 加载、打包与信任

- 通过 `FileAccess` 读取的 `res://` 原始文件不一定进入导出包，遵循导出配置规则中的[打包](../41-export-config/resources-and-filters.md#打包)。编辑器中能读到，不能证明导出包里有。
- 项目自带的数据可信。玩家存档、mod 等 `user://` 或外部数据不可信：
  - 解析前限制文件大小；
  - 解析后校验结构、类型和取值范围；
  - 其中的字段不直接决定加载哪个脚本、场景或资源路径，见 JSON 规则的[信任](json.md#信任)。
- 项目自带的内容表同样由加载器检查单个字段：结构、类型、必填项和 NaN/±Inf，见[数据 schema、身份与迁移](schema-identity-and-migration.md)。跨条目的领域不变量（例如成本递增、合计不溢出）由内容不变量测试检查，不在运行时加载器里重复。
- 写玩家存档等 `user://` 数据时，先写临时文件，再替换正式文件。Godot 在 Windows 上用 `DirAccess.rename_absolute` 覆盖已有文件时，先删除目标再改名，两步之间进程结束就只剩临时文件。读档时正式文件缺失、临时文件或备份存在，要按恢复处理，不能当作首次启动开新档。

## 生成与派生数据

生成器读取校验并规范化后的数据，写出提交到仓库或供运行时使用的派生产物。

- 生成器只读取通过校验的输入。输入文件由明确的清单或固定路径给出，不扫描整个目录，避免收入临时文件或无关文件。
- 派生字段和生成产物不手工编辑。需要修改时，改输入或生成器，然后重新生成。
- 先写到临时文件并校验，再替换目标文件，避免失败时留下写了一半的产物。
- 相同的输入、schema、生成器和选项产生相同的字节：
  - 键顺序、缩进、换行和数值精度固定，JSON 的写法见[规范写出](json.md#规范写出)；
  - 不写入生成时间、本机绝对路径、随语言区域变化的数字或日期；
  - 需要随机性时，种子作为生成器的输入参数。
- 只对 schema 声明为无序的集合排序。顺序有意义的序列保持原样。
- 生成产物提交到仓库时，重新生成的结果与已提交的文件一致。
