# 数据 Schema 与类型

解析器的类型不是业务 schema 的类型。

## 字段

- **[必须]** 每个稳定的数据领域都有一个 schema 负责方，定义字段名称、每个字段是必填、可选还是可为 null、语义类型、单位、范围、枚举与取值域、引用和默认值。
- **[必须]** 缺少必填字段是错误。不要用 `.get(key, default)` 悄悄修补必填数据。
- **[必须]** 默认值只适用于 schema 定义的、语义稳定的可选字段。
- **[必须]** 整数字段接受数学上为整数的值。不要把任意浮点数舍入为整数，也不要用容差修补。
- **[必须]** 规范的玩法数值数据拒绝非有限值（NaN 和 ±Inf）。
- **[必须]** 除非截断明确是编写契约，不要把无效的源值截断到范围内。

## 语义类型

- **[必须]** 区分自由文本、稳定 ID、引用、枚举、路径、本地化键、时长、时间戳、日历日期和其他类似 String 的语义。
- **[必须]** 缺失和 null 含义不同时，可选与可为 null 是两回事。
- **[必须]** List 和 Set 是不同的。类 Set 字段中有重复元素是错误，除非 schema 明确允许去重。
- **[必须]** Map 声明键和值的语义类型。规范 JSON 中的映射键是明确的 String，除非该映射以结构化方式表示。
- **[必须]** 带标签的联合类型使用明确的判别字段；不要根据对象的形状猜测变体。
- **[必须]** 单位、刻度、坐标空间、精度、舍入模式和舍入阶段适用时，都属于 schema 语义。

## 结构选择

- **[优先]** CSV 和 XLSX 适合标量的二维数据和数值平衡数据。一对多数据使用子表或关联表；深度嵌套的对象、映射或联合类型使用 JSON、Resource 或其他结构化格式。
- **[必须]** 不要在 String 中编码没有文档的嵌套小语言。复杂的复合 String 要么改为结构化数据，要么是带语法、解析器、AST、校验、版本和测试的正式 DSL。
- **[必须]** 领域本身是嵌套的 JSON 结构时，不要把 JSON 文本放进 JSON String 中。
- **[必须]** 不要通过解析显示文本、本地化文本或自由文本来推断行为。
