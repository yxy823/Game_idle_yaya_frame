# 数据 schema、身份与迁移

解析得到的类型不是业务类型。每个数据领域由 schema（校验代码或带类型的模型）规定字段、取值和引用。

## 字段与取值

- schema 写明每个字段的名称、必填或可选、类型、单位、取值范围或枚举，以及默认值。
- 缺少必填字段是错误。不用 `.get(key, default)` 填补必填字段；默认值只给 schema 声明了默认值的可选字段。
- 缺失、`null`、空字符串、`0` 和 `false` 含义不同时，分别处理。
- 整数字段只接受数学上的整数，不舍入或截断非整数值。超出范围的值报错，不截断到范围内。
- 数值字段拒绝 NaN 和 ±Inf。
- 百分比和概率写明刻度（`0–1` 或 `0–100`），不根据数值大小猜测刻度。
- 不允许重复的列表出现重复元素时报错，不悄悄去重。
- 一个字段有多种结构变体时，用明确的类型字段区分，不根据对象中有哪些键来猜。
- 不在字符串里编码嵌套结构或自造的小语言；需要嵌套时改用 JSON 对象或 Resource。不把 JSON 文本存进 JSON 字符串。
- 不通过解析显示文本或本地化文本来决定行为。

## 业务 ID 与引用

业务 ID 与 Resource UID、路径、实例 ID 等 Godot 身份的区分，见[身份域](../00-core/godot-resource-references.md#身份域)。

- 数据中的实体用稳定的 String 业务 ID 标识，不用行号、数组下标、文件路径或显示名称。
- ID 不合法时报错。不自动裁剪空白、转小写，或把它修补成另一个 ID。
- ID 被引用或写入存档后不再修改。确需重命名时，作为一次迁移，同时更新所有引用和存档的兼容逻辑。
- 已经用过的 ID 不复用给另一个实体。
- 引用字段写明目标类型，以及必填还是可选。可选只表示字段可以缺失或为 `null`；写出的 ID 仍须能解析到实体。
- 解析不到的引用是错误。不替换为 `null` 或默认值，也不模糊匹配。
- 进入玩法前，集中解析全部静态引用。引用有额外约束时一并校验，例如不能引用自己、层级关系、不能成环。
- 只有 schema 规定顺序有意义时，玩法才依赖数据中条目的顺序。

## 版本与迁移

- `schema_version` 只在数据结构变化时提升，与游戏版本、Godot 版本无关。只改数值或内容时不提升。
- 仓库内的数据随 schema 修改一次性迁移到当前版本，代码不保留读取旧格式的分支。
- 新增带稳定默认值的可选字段通常可以兼容。重命名字段，或修改必填性、类型、单位、引用目标，需要迁移。
- 玩家存档等外部数据需要兼容旧版本时：
  - 迁移写成从版本 N 到 N+1 的逐步函数，不根据数据形状猜测版本；
  - 在内存或临时文件中完成迁移，校验通过后再替换原数据，失败时保留原数据；
  - 遇到高于当前支持范围的版本时拒绝加载；
  - 每个仍受支持的旧版本保留真实样本，作为迁移测试的夹具。
