# 决策依据

## 开关

- 调用本 Skill 即开启。之后本对话的每条回复都写「决策依据」一节，直到用户说“关闭决策依据”或意思相同的话。
- 上下文压缩时，摘要里写明“决策依据已开启”，压缩后继续写。
- 本 Skill 只增加这一节，不改变任务的流程、授权和完成条件。

## 写法

这一节放在回复末尾；完成汇报放在「下一步」之前。分四组，没有内容的组不写：

- **原则**：用下面[原则索引](#原则索引)里的名称。
- **Skill**：Skill 名，以及起作用的小节。
- **脚本与命令**：实际运行的命令或工具，以及它的结果改变了什么。
- **文件**：影响了决定的文件，写 `路径:行号`。其余只为查找而读的文件写总数，例如“另读 12 个文件用于查找”。

每条只写一个选择：

- 改变了做法时写“名称：原本会做 X，改成了 Y”。
- 只确认了原本的做法时写“名称：确认了 Y”。
- 写不出改变或确认了哪个具体选择的，不列。

四组都没有内容时，只写一句“本条回复没有依据原则、Skill、脚本或文件做选择”。
