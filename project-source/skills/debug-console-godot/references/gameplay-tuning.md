# 调操作手感与普通参数

适用于移动、跳跃、攻击响应这类操作手感，以及特效和动画的参数。按下面的方式配合。

## 先让参数可调

- 参数集中放在 `game/<对象>/tuning/` 下的调参资源（`.tres`）中，不散落在代码的常量或场景的节点属性里。新增调参资源属于实现修改，在当前授权内完成，并遵循 `yaya/agent-rules/` 中资源与 GDScript 的规则。
- 已有测试把**来源中标为待定或可调**的参数值写死在断言里（例如“粒子数量等于 8”）时，在调参之前把断言改成对照调参资源；验证参数确实生效，就在测试中传入一份测试专用的参数。否则每调一次值，测试就会失败一次。GDD、规格或 AC 已经确定的数值、上限和不变量，保留独立的字面断言，不改成和资源自己比较；这类值要变，先改所属来源，再同步断言。测试不读取插槽预设和组合。
- 注意：Godot 保存 `.tres` 时，会省略和脚本默认值相同的属性，所以资源文件里没写出来的参数取的是脚本中的默认值。提取参数时让脚本默认值等于当时的值；值被采用之后，不要再修改脚本默认值，否则会悄悄改掉已经验收的效果，要调就改 `.tres`。

## 和用户配合的一轮

- **在调试台里改**：用户用[项目的启动命令](../../../../dev/debug/README.md#启动)打开调试台。Agent 事先告诉用户选哪个插槽、改哪个参数、试哪几个值；用户边玩边改，下一次触发就用新值，按反引号 ` 在当前改动和游戏原值之间切换比较。用户满意后保存为预设，或直接采纳到游戏。
- **Agent 直接改值**：用户已经说定一个具体的值时，Agent 把它写进调参资源，原来的值写在 notes 里备查，用户重新启动后确认。

连续触发或特定局面才出现的问题，告诉用户用哪个固定局面或试播动作比较，在同样的情况下看。

## 从编辑器启动时

主要方式是命令行启动。用户需要脚本热重载、远程场景树或性能分析器，从编辑器运行调试入口时，提醒两件事，其余限制见[从编辑器启动](../../../../dev/debug/_shared/README.md#从编辑器启动)：

- **只在调试台里调参**：编辑器检查器里显示的是编辑器自己的资源副本，不是游戏当前使用的值；在检查器里改 `game/<对象>/tuning/` 下的资源，两边会显示不同的数。
- **停止前先保存**：从编辑器停止（F8）会直接结束游戏进程，不出现“关闭前保存”的提问，调试台里未保存的改动全部丢失。

## 结束时

用户采纳后按 Skill 的[采纳与收尾](../SKILL.md#采纳与收尾)完成收尾，删除只为对比加的临时代码或临时值。Agent 核对调参资源中的值和游戏实际读取的一致，相关自动测试仍然通过。
