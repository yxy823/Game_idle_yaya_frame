# Asset integration

Use `methodology/11-specialist-workflows.md` for scope and ownership. Runtime changes belong to the current authorized Feature or scoped experiment; return there for validation and completion.

Read the affected resource entries and actual source files, then relevant `agent-rules/60-assets/`, resource-reference rules and scene/resource rules. Confirm provenance/usage constraints from available records; unknown provenance is a gap, not a made-up license. Inspect actual type, dimensions, transparency, duration, channels or animation properties as applicable.

Map each reused/supplied file to its existing project destination and consumers. Preserve external originals, unrelated resources and valid UID/path relationships. Choose import settings for the actual use and target constraints; do not blindly reimport the full library. Update affected scenes, themes, resource bindings or audio routing without redesigning the approved requirement.

Verify import and actual in-context rendering/playback or animation where needed. Distinguish file presence, successful import, measured fit and human acceptance. Finalize resource-list locations/status before final task verification, leaving missing files and unverifiable experience checks explicit.

Production methods remain deferred. Formal technical asset inspection uses `review-assets` in a separate instance, with art/audio review for experience.
