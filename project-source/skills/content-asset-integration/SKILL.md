# 资源接入

范围和归属按 `yaya/methodology/11-specialist-workflows.md` 执行。运行时修改属于当前已授权的 Feature 或限定实验；验证和完成回到那里处理。没有所属 Feature 或限定范围的实验时，按 `yaya/methodology/00-overview.md` 的 **任务路由表** 说明需要的入口，不直接修改运行时文件。

## 阅读要求和文件

- 按 `yaya/methodology/11-specialist-workflows.md` 的 **资源需求与交接** 找到资源章节的所属位置：所属的表现方案、UI 规格或共享设计章节。阅读其中受影响的资源章节，以及当前采用的方案和实际源文件。
- 按 `yaya/agent-rules/README.md` 的“常见任务读哪些”中“导入或替换图片、音频、字体”一行阅读；移动或重命名资源时加读 `yaya/agent-rules/00-core/godot-resource-references.md`。
- 根据现有记录确认资源来源和使用限制。来源不明是缺口，不要自行编造许可。
- 素材要先在调试台和其他候选比较时，本 Skill 把它接入为候选：按 `debug-console-godot` 的[候选](../debug-console-godot/SKILL.md#候选)放进候选目录，写明来源与许可，检查下面的文件属性，只建立调试台候选的使用关系，不改游戏的引用；接入后返回 `debug-console-godot`。用户采纳后由调试台把候选移进游戏目录，不需要本 Skill 再接入一次。不经过调试台比较时，本 Skill 接入用户已确认的最终文件。
- 按资源类型检查实际的类型、尺寸、透明度、时长、声道或动画属性。

## 接入

- 把每个复用或外部提供的文件对应到项目中的目标位置和使用方。
- 保留外部原件、无关资源，以及有效的 UID 与路径关系。
- 按实际用途和目标约束选择导入设置；不要盲目重新导入整个资源库。
- 更新受影响的场景、主题、资源绑定或音频路由，不重新设计已批准的要求。

## 验证与记录

验证导入结果；需要时在真实场景中检查实际渲染、播放或动画。文件存在、导入成功、测量结果合适和人工验收是四件不同的事。

在任务的最终验证之前，到所属章节更新准备状态、实际资源路径和使用方路径；如果影响到表现的采用组合，一并更新。缺失的文件和无法验证的体验检查要明确写出。验收结果留在链接的报告或完成证据里。

资源在项目外的制作项目中制作，不由本 Skill 负责（methodology 11 的 **在项目外制作**）；制作项目交来的成品按同一节记录来源。正式的技术检查在另一个实例中使用 `review-assets`；体验部分配合 `review-art` 或 `review-audio`。

返回调用方；Skill 返回不会结束它所在的已授权任务（methodology 03 的 **授权与续接**）。
