# 特效与手感调优

把用户对实际效果的感受，变成一轮轮可比较的参数调整，直到用户满意。判断好坏的是用户：Agent 负责提出改哪些参数、准备对比、记录每一轮，并把最终采用的值放回正确的位置。

## 前提

- 要调的效果已经实现、能运行，参数放在资源、场景或导出变量中，可以单独修改。参数还写死在代码里时，先在当前授权内把它们提到资源或导出变量。
- 调整属于一个已授权的 Feature（通常在 Stage 3），或用户要求的限定范围实验。没有这类授权时，只给出调整建议，不改文件。
- 用户在 Stage 5 人工验收时提出“再调一下”，按 `yaya/methodology/03-execute-loop.md` 的 [Stage 5](../../../yaya/methodology/03-execute-loop.md#stage-5--明确的人工验收仅-manual-模式) 记录未通过的检查项，回到 Stage 3 用本 Skill 调整，之后重做 Stage 4 和 Stage 5。

## 一轮怎么做

1. **听清感受**：请用户说出哪里不对，以及在什么情况下出现，例如“连续消除时闪得刺眼”。用户已经说清楚的不再追问。
2. **提出假设**：说明打算改哪一两个参数、往哪个方向、改多少、为什么。一次只动少数参数，否则看不出是哪个起了作用。对应关系拿不准时，读 [感受与参数的对应](references/feel-to-parameters.md)。
3. **准备对比**：保留当前版本作为 A，修改后的作为 B，让用户在同一条件下对比，而不是只给一个新版本。具体做法按调整对象选：
   - 特效和反馈使用表现反馈组件（`FeedbackCue`）时，用资源工作台的 A/B 草稿，见 [用资源工作台调特效](references/workbench-tuning.md)。
   - 操作手感，或没有使用表现反馈组件的效果，见 [调操作手感与普通参数](references/gameplay-tuning.md)。
4. **记录这一轮**：在当前 Feature 的 notes 中记下改了什么、用户怎么说、保留了哪个版本；独立实验记在 Progress。只写一两行，不另建调整记录文件。
5. **决定下一步**：用户选定一个版本后，把它作为新的 A 继续，或者结束。

## 什么时候停

- **用户满意**：进入写回。
- **几轮下来没有接近目标**：例如来回改了两三轮，用户仍然觉得“哪里都不对”，先停下来，问题可能不在参数上。表现方案本身不合适时，交给 `design-game-presentation` 重新规划；缺少合适的图像或声音时，标出资源缺口；改了参数后帧率下降时，交给 `diagnostics-performance` 测量。
- **用户的要求超出参数范围**：例如要换一种技术或新增一个组成部分，这是表现设计的变化，按 `yaya/methodology/11-specialist-workflows.md` 的 [编写与采纳](../../../yaya/methodology/11-specialist-workflows.md#编写与采纳) 处理，不在调参中悄悄完成。

## 写回采用的值

调好的值只有一处权威位置，不维护第二份规格：

- **运行时的值**：留在 Cue、参数资源或场景中，游戏实际读取的就是它们。节点属性和细粒度参数只放在这里，见 `yaya/methodology/13-prototypes.md` 的 [验证与采纳](../../../yaya/methodology/13-prototypes.md#验证与采纳)。
- **玩家能感知的表现参数**：例如动画时长、节奏、缓动方式，原来在表现或 UI 文档中写着“待定”或已有旧值时，在 Stage 3 的 [最终验证前的文档检查点](../../../yaya/methodology/03-execute-loop.md#3d-最终验证前的文档检查点) 写进所属文档，写法不带验收状态，例如“以下参数由 F012 的调优确定”。
- **采用的组合**：换了表现方案中的某个组成部分时，更新表现文档的“当前采纳与实现”。

写回必须在 Stage 4 之前完成。Stage 4 之后再改这些文件，之前的验证证据就失效了，要重做受影响的验证和验收。

## 验证与交付

- Agent 核对：保存后的值能被消费场景正确加载，相关自动测试仍然通过，没有留下只在工作台里生效的草稿。
- 观感和手感只能由用户实际看、实际操作来判断。截图和录像可以辅助对比，不能代替用户的判断。
- 调优过程中用户说的“这个好”，不等于人工验收。正式验收按 Feature 的验收模式在 Stage 5 进行。

返回调整结果、最终采用的值及其位置、记录写在哪里，以及仍未解决的问题。返回调用方；Skill 返回不会结束它所在的已授权任务（methodology 03 的 [授权与续接](../../../yaya/methodology/03-execute-loop.md#授权与续接)）。
