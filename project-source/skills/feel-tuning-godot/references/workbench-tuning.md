# 用资源工作台调特效

适用于用表现反馈组件实现的特效和反馈：对象通过 `FeedbackCue` 读取图像、音频、Shader、粒子、动画和 Tween 参数。工作台的操作、保存规则和导出排除写在 `yaya/asset_workbench/examples/README.md`，组件的绑定方式写在 `components/feedback/README.md`；这里只说明调优时怎么用。

效果没有使用表现反馈组件时，不要为了调参把它迁移到这套组件，按 [调操作手感与普通参数](gameplay-tuning.md) 处理。

## 准备项目自己的工作台入口

示例工作台加载的是示例场景。调项目自己的效果时，准备一个只用于开发的入口场景：

1. **只含表现的组合场景**：把要调的效果对象（`FeedbackObject`，绑定项目自己的 Cue）放进一个场景，按游戏中的实际位置和层级摆放。不要直接加载完整的游戏场景，避免运行奖励、存档等业务逻辑。
2. **工作台入口**：仿照 `yaya/asset_workbench/examples/composition/example_workbench.tscn`，使用同一个工作台脚本，把导出属性指向上面的组合场景、项目的 Cue 和候选素材。
3. **存放位置**：放在项目根目录的 `dev/` 中，例如 `dev/tuning/reward_burst_workbench.tscn`，不放进 `yaya/`。`dev/` 在导出时整体排除，正式场景和代码不能引用它。
4. **记录用途**：在当前 Feature 的 notes 写明入口路径和用途。之后继续当调参工具保留，还是删除，按 `yaya/methodology/13-prototypes.md` 的 [验证与采纳](../../../../yaya/methodology/13-prototypes.md#验证与采纳) 中原型去留的规则决定。

## 和用户配合的一轮

1. Agent 给出要比较的两组值：A 保持 Cue 中已保存的值，B 由用户在工作台的对象 Inspector 里按 Agent 给的数值修改。工作台的 A/B 草稿只存在于运行中的界面，Agent 不能直接写进去；也可以由 Agent 直接修改 Cue 文件，用户重载后与记下的旧值对比。
2. 用户打开入口场景（编辑器中按 F6），用“触发”“循环”在 A、B 之间对比；需要看多个对象同时出现时，用“触发全部”。
3. 用户选定后，保存当前方案。保存写入 Cue，所有引用这个 Cue 的场景都会受影响；工作台会检查磁盘上的文件有没有被别处改过。
4. 用“打开消费场景”确认保存后的值在游戏里的样子。未保存的草稿不会进入消费场景。

Agent 不能替用户看或听。Agent 能直接核对的是：Cue 文件里的值、保存是否成功、消费场景能否加载。
