# 感受与参数的对应

用户描述的是感受，不是参数。下表给出常见说法最先值得检查的参数，用来提出第一轮假设。它不是规定：同一句话在不同效果里可能对应不同参数，按实际实现判断，拿不准时把两三个候选说给用户，让对比结果来决定。

| 用户的说法 | 先检查 | 常见的改法 |
| --- | --- | --- |
| 太闪、刺眼 | 亮度或发光强度、闪烁频率、同时出现的数量、颜色对比 | 降低峰值强度或缩短最亮的时间；连续触发时限制叠加 |
| 太暗、看不见 | 强度、尺寸、与背景的对比、持续时间 | 提高对比或尺寸，而不是只加亮度 |
| 拖沓、太慢 | 总时长、缓入缓出的曲线、开始前的延迟 | 缩短后半段或改用先快后慢的曲线，保留开头的识别时间 |
| 太快、没看清 | 关键帧停留时间、总时长 | 延长最重要的那一刻，不必整体拉长 |
| 打击感不够 | 命中瞬间的停顿、屏幕或对象震动、粒子爆发的数量和速度、声音与画面是否同时 | 先对齐声画时机，再加短暂停顿或震动；不要一次全部加上 |
| 太吵、太乱 | 同时播放的效果数量、粒子数量与寿命、重复触发 | 合并或错开同时出现的反馈，减少次要部分 |
| 软、没力 | 起始速度、缩放回弹幅度、缓动曲线 | 起始更快、结尾带一点回弹 |
| 移动发飘 | 加速度、减速度、最高速度、空中控制 | 加快减速，减少惯性滑行 |
| 跳跃不跟手 | 输入到起跳的延迟、起跳速度、重力、提前输入和离地宽容时间 | 先查延迟，再调起跳和下落的速度比 |
| 操作迟钝 | 输入延迟、动画是否锁住输入、前摇时长 | 缩短前摇，允许提前输入 |

连续触发、长时间运行和低端设备上的表现可能和单次触发不同。用户反馈只在某种情况下出现时，对比也要在同样的情况下进行。
