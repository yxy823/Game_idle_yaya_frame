# 界面色彩与表面

界面配色的默认做法。`design-art-direction` 定 Art Bible 的色板时使用，`review-art` 审核时用作检查项。Art Bible 或 UI 规格已采用不同的决定时，以已采用的决定为准。文中数值是初始值；用户在调试台采纳的值保存在调参资源中，见 design-art-direction 的[交接](../SKILL.md#交接)。

## 色板

- **C1 按角色定义**：色板按角色定义：底色、各层表面、主文字、次文字、强调色、强调色上的文字、状态色。界面只引用角色。令牌按用途命名，不按外观或数值命名，例如用 `accent`，不用 `orange_button`；整体换风格时，令牌名不用改。
- **C2 配色比例**：底色约占画面的 70–90%。强调色每屏低于 5%，只标主操作和至多一种反复出现的对象，例如“可购买”。只用一个强调色；灰色只用一个色族，全暖或全冷。
- **C6 不用纯黑纯白**：不用纯黑、纯白的大面积色块。暂停遮罩和弹窗背板用半透明加轻微降饱和，不用纯黑半透明，否则背后的游戏画面会被压成一片。
- **C7 强调色派生**：强调色派生四档：低饱和底衬（选中项背景）、默认、悬停加深、高亮（焦点框、关键数字）。派生算法全项目统一，同色相降明度或降饱和二选一，不逐处手调。
- **C11 状态色**：状态色的含义固定，只在表达含义的地方覆盖世界观色板。未激活的状态不用高饱和色。状态标签可以用浅色底配同色相的深色字。

## 表面与边框

- **C3 明度分层**：面板与底色、面板与面板之间靠明度差区分，相邻两层差 2–6 个亮度点：几乎看不出，但拿掉后层级就散了。不在面板里再嵌一层同样的面板。
- **C4 单闭合边框**：容器有边框时，里面的按钮、标签和格子不再加边框。从最外层到最内层，任一路径上的边框不超过 2 层。格子的选中态用格子外侧的焦点框，不在格子内部再画一圈。
- **C5 细边不变粗**：窗口放大后，1px 的细边会被渲染成 2–3 个物理像素，显得笨重。细边随缩放保持 1 个物理像素，或改用明度差分隔。像素风用整数像素的边，不做半透明抗锯齿，否则出现脏边。
- **C12 非自绘控件**：不是自己画的控件也按色板配置，不留 Godot 默认的灰色主题：滚动条、Tooltip、焦点框、输入光标、PopupMenu。

## 可读性

- **C8 彩色底上的次要文字**：用该底色的深色或浅色版本，或前景色加透明度，不用通用灰。
- **C9 对比度**：正文至少 4.5:1；大字、大数字、控件、图标和焦点框至少 3:1。按叠加后的实际背景计算。悬停和焦点只提高对比度。界面背后有会动的游戏画面时，面板的不透明度也是令牌，在最亮和最暗的画面上各检查一次文字。
- **C10 不只靠颜色**：信息不只靠颜色传达，同时用文字、形状、位置或边框粗细区分。例如“买得起”和“买不起”除了颜色，还有按钮状态或文字的差别。
