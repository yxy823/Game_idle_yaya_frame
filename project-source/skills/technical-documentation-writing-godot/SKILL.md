# Godot project technical writing

Turn confirmed project facts into documentation that its readers can locate and use. Cover the project README, existing GDD and Product explanations, Feature design, architecture, knowledge, research and verification records, and tool instructions. Preserve the owning task's authorization, behavior, evidence and completion conditions.

## Choose the writing guidance

Use [Writing guide](references/writing-guide.md) for the current document's contract, wording and verification. For ordinary edits, that guide is sufficient. It routes to:

- [Document structure](references/document-structure.md) when organization, naming, ownership or repeated content needs attention.
- [Procedure writing](references/procedure-writing.md) when explaining how someone operates a project tool, reproduces a problem or performs a check.

These methods support the current task; they do not start another design or delivery workflow. Keep undecided gameplay requirements and unavailable verification visible rather than resolving them through wording.

## Local resources

This package contains its complete writing methods and has no executable helpers; read its references through their relative links. It introduces no installer, synchronization mechanism or additional approval gate.
