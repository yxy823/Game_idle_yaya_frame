## Feature 交付前发现 Bug

来源：Godot 项目开发 → 修复与改进 → Feature 交付前发现 Bug

```text
## 目标

请修复当前尚未交付 Feature 中偏离既有要求的 Bug。

## 背景与入口条件

正式交付以项目规定的 Feature 完成状态和完成记录为准，不以测试通过、代码提交或用户试玩作为单独依据。本页限定当前未交付 Feature 内出现缺陷。

## 范围

修复当前未交付 Feature 内偏离既有要求的行为，留在原 Feature，不新增独立 Bug 任务。

## 输入与事实来源

${1:所属 Feature、仍有效要求、实际表现、复现与日志}

读取所属 Feature 的完成状态与记录、有效要求、复现日志、实际实现和直接消费者；已证实根因与假设分开。

## 决策边界与授权

在原 Feature 授权范围修复；本次特有的验收前不提交限制跨 Skill 和续接沿用，除非用户明确改变。

## 约束

遵循 methodology/03-execute-loop.md 与 methodology/07-engineering-change.md；适用验证完成且用户明确实际验收通过前，计划、修复及阶段性 checkpoint 均不得创建任何本地提交。不放宽 AC、篡改原接受，自动测试、沉默或继续不构成人工接受。

## 执行与变更原则

修改前简述修复位置、影响模块与复验范围；按共用工程规则保持 API、依赖和代码风格，必要时补缺陷回归。

## 输出与交付

交付修复、关键文件、理由和具体剩余风险，取得接受后再按原任务完成检查办理交付。

## 验证要求

保留实际失败并取得修复后必要自动与人工复验，核对最终差异，再返回原 Feature 完成检查。

## 完成条件

原 Feature 的新增实际失败已消除，必要复验及用户明确实际接受已取得，并返回原任务完成检查。

## 停止与异常处理

尚缺实际人工接受时保留真实未完成状态，不提交；缺少根因证据时说明待验证假设，不放宽要求取得通过。
```

## Feature 交付后发现 Bug

来源：Godot 项目开发 → 修复与改进 → Feature 交付后发现 Bug

```text
## 目标

请修复已正式交付行为中偏离既有要求的 Bug。

## 背景与入口条件

正式交付以项目规定的 Feature 完成状态和完成记录为准，不以测试通过、代码提交或用户试玩作为单独依据。本页限定已交付行为出现缺陷。

## 范围

修复已正式交付行为的 Bug，原 Feature 完成事实与历史保持真实。

## 输入与事实来源

${1:所属 Feature、仍有效要求、实际表现、复现与日志}

核对项目完成状态与记录、已交付契约、当前实现、复现证据和直接消费者；不只凭测试或提交判断交付。

## 决策边界与授权

先由 engineering-change-plan 的 bug 模式建立独立任务和 bug_diagnosis，再交 feature-execute；已有修复授权跨步骤沿用。

## 约束

遵循 methodology/07-engineering-change.md；适用验证完成且用户明确实际验收通过前，计划、修复及阶段性 checkpoint 均不得创建任何本地提交。这一特有约束跨后续修复、Skill 切换和续接沿用，除非用户明确改变；不放宽 AC 或篡改原接受。

## 执行与变更原则

修改前区分已证实根因与假设，简述独立修复范围及旧行为回归；保持必要 API、依赖与风格，必要时补缺陷回归。

## 输出与交付

交付独立 Bug 任务成果，说明关键文件、修复理由、真实验证和具体风险，满足条件后完成本地交付。

## 验证要求

保留实际失败并取得修复后必要自动与人工复验，核对最终差异，办理独立 Bug 任务完成检查。

## 完成条件

独立 Bug 任务满足其适用验证与实际人工接受，原交付历史保持真实。

## 停止与异常处理

未取得实际人工接受时保持未完成且不提交；不能把自动测试、沉默或继续请求当接受。
```

```text
已有具体重构目标，不再在本入口筛选候选。

## 范围

对已选定目标调整结构并保持约定行为，不重新筛选异味或顺带改玩法。

## 输入与事实来源

${1:确定目标、当前痛点、不变契约与获准范围}

读取实际实现、依赖、当前痛点和不变 API/行为，复用有效计划。

## 决策边界与授权

由 engineering-change-plan refactor 明确目标、维护收益和回归范围，再交 feature-execute 实施。

## 约束

遵循 methodology/07-engineering-change.md 和共用工程规则；控制影响，不新增无关依赖。

## 执行与变更原则

先简述结构方案，复用有效计划并控制影响；已有测试通过不能单独证明重构值得做。

## 验证要求

完成相关测试和支持的静态检查，核对差异只服务选定目标，并以约定回归证据说明行为保持。

结构目标达成且约定行为保持，适用验证与交付完成。
```
