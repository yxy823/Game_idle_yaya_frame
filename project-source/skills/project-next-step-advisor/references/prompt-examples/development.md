## Feature 已规划并可开始，现在实施这一项

来源：Godot 项目开发 → 日常开发 → Feature 已规划并可开始，现在实施这一项

```text
## 目标

请实施一个已经规划且具备开工条件的 Feature。

## 背景与入口条件

选定任务未开工且依赖满足，本次授权实施一项。

## 范围

默认实施一项未开工且依赖满足的 Feature 及必要配套；已有任务续接沿真实停点，不重做有效工作。

## 输入与事实来源

${1:Feature ID 或下一项可开始任务、本次补充范围}

读取指定或下一项可执行任务的 AC、有效计划、实际实现位置和资源消费者。

## 决策边界与授权

由 feature-execute 完成已授权实施与交付；独立评审仅按明确请求启用，既有明确后续授权继续沿用。

## 约束

遵循 methodology/03-execute-loop.md 和项目共用工程规则，保持无须变化的 API、依赖与代码风格；自动检查不能代替适用人工验收。

## 执行与变更原则

开工前将 AC 对应到实际实现、资源消费者与验证义务，简述修改范围并复用有效计划。

## 输出与交付

交付实现和本地成果，说明关键文件、实现理由、真实结果与具体风险。

## 验证要求

完成相关测试和支持的静态检查，核对最终差异仅含本项与必要配套，取得适用实际人工验收和指定评审。

## 完成条件

本项适用实现、验证、人工验收、指定评审及本地交付均已完成。

## 停止与异常处理

缺少关键决定、必要验证前置或实际人工接受时，停在相关真实条件，说明已完成与待补部分；该停点不表示 Feature 已完成。
```

## 界面布局已经确定，想先做一个能点击的原型

来源：Godot 项目开发 → 日常开发 → 界面布局已经确定，想先做一个能点击的原型

```text
## 目标

请在已确认 UI 规格和当前 Feature 内实现可点击原型。

## 背景与入口条件

布局与行为已确认，本次实现可点击原型而非探索布局。

## 范围

在当前 Feature 内实现已确认布局与行为的可点击原型，只覆盖本次原型范围。

## 输入与事实来源

${1:当前 Feature、确认 UI 规格、真实素材、原型体验范围}

读取当前 Feature、已确认 UI 规格、真实素材和原型体验范围。

## 决策边界与授权

使用 feature-execute；核对原型是当前 Feature 的局部检查点还是独立原型 Feature，按已有授权推进。

## 约束

遵循 methodology/01-product-doc-structure.md 的视觉原型约定；不把局部接受写成完整 Feature 或 Goal 完成。

## 输出与交付

提供可运行可点击的入口、实际体验结论及后续依赖。

## 验证要求

优先采用真实素材和实际操作反馈，核对目标状态变化及可观察反馈。

## 完成条件

原型可运行可点击，目标反馈可观察，实际体验结论与后续依赖明确。

## 停止与异常处理

必要实际体验或用户决定未取得时，说明原型已完成部分和依赖缺口，不宣布该体验目标已完成。
```
