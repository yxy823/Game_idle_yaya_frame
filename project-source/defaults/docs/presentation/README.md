# 游戏表现目录

本目录保存游戏中一次完整表现的设计，例如物品入包或角色死亡（名称仅作说明，不代表项目已有需求）。每份文档记录这次表现的过程、组成部分、候选方案、资源、采用组合、实现与消费位置，以及验收入口。

界面、共享视觉与声音规范也属于表现职责，但分别保存在 [UI 设计](../ui/README.md)、[美术规范](../art/art-bible.md)和[声音规范](../audio/sound-bible.md)。触发表现的游戏规则引用 GDD，实际状态所有者与连接关系引用架构或任务设计；整体关系见[游戏职责与项目组织](../game-organization.md)。

当前状态：尚无游戏表现正文。

## 文件放在哪里

- 一次表现使用 `<scope>.md`，按“触发时刻与玩家感知的结果”命名。例如商店购买和奖励领取都表达同一次物品入包时，共用 `item-added.md`。
- 被两份以上独立表现共用的组件，使用 `components/<component-key>.md`。
- 命名、拆分、组件迁移和验收记录的具体规则见[游戏表现文档约定](../../methodology/11-specialist-workflows.md#game-presentation-documents)。编写时使用 `design-game-presentation`。
