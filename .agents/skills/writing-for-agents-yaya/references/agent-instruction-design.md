# Codex 指令设计参考

编写入口与正式审核入口按实际对象引用本页，核对触发、正文归属、按需阅读和完成边界。它是共用参考，不是编写或审核的执行入口，也不授予写入权限。Skill 职责及分工遵循[职责设计准则](../../../../framework/review/baselines/skill-script-prompt-design.md#skill-的评价维度)，普通文字的表达方法由框架文档写作包维护。

## 让引用能在正确时机生效

链接、Skill description 和规则入口都要说明“处理什么事情时，去哪里解决什么问题”。核对入口措辞与目标正文是否匹配，再决定需要内联提醒还是条件引用。

- **按实际条件引用**：例如“变更测试登记时，读取测试策略的 Registry rules”，能定位具体用途。已在上下文且仍有效的正文可以复用；直接调用或续接也应能找到适用约束。
- **把主要用途放在前面**：合并同一任务的近义触发词，只保留会改变处理路径的分支。排除项用于避免真实混淆，不扩大为关键词黑名单。
- **检查可达性与作用域**：链接应从消费文件到达目标，项目自有材料核对生成后的路径；advisor 的本机共享提示词引用遵循根规则中的固定绝对路径约定。

入口越常加载，越应只保留影响选择的内容；条件细节放在被引用材料中。文件存在、链接可打开与触发可靠是不同结论。

## 安排正文与细节

同一概念的定义、条件与例外放在一起。所有适用任务都需要的边界留在入口，部分任务才需要的细节由条件明确的引用展开。纯参考不必被包装成另一个 Skill，也不必把所有说明改写为步骤。

拆分应减少无关阅读并改善查找；比较复用、合并、局部修正与拆分的实际收益，不因文件长就增加路由层或交接。出现抢先结束时先核对完成条件与授权表达，不靠隐藏后续任务制造停点。正式审核与实现的独立入口要求由职责准则统一定义。

## 去重时保留有用信息

先定位规则的权威正文，再处理其他位置。参数与默认值可从当前配置、入口或帮助核实时，指令保留查阅条件及无法推断的约束；操作说明仍可保留读者需要的命令示例。

- **重复正文**：多处完整维护同一规则、修改需要同步时，归并到所属规范。
- **必要提醒**：恢复上下文、避免漏项或说明动作前提的短提醒可以保留，并准确指向完整规定。
- **表达方式**：使用已有且含义明确的术语，以具体条件与可观察结果代替“严格”“彻底”等强度词。精简不能把信息压成需要猜测的暗语。
- **禁令与例外**：优先说明应该怎样处理；确有必要的禁止事项及其触发条件仍应保留，不能假定否定句必然无效。

例如，测试登记路径和时机归测试策略，规划入口保留操作提醒，schema 负责结构；知识条目写法归知识 README，其他入口保留查询或整理时机。例子说明归属方法，不代替这些对象的当前规范。

## 判断授权与完成含义

对照指令及必要调用方，核对输入、范围、必要依赖、副作用、证据和完成结果。局部步骤完成、当前任务完成和真实人工接受按原契约区分；修改或建议不能扩大授权，也不能取消尚未完成的获准工作。

完成条件应能区分已完成、受阻、待决定和待验收。检验分支时使用具体任务：确认应触发与不应触发的场景、直接入口能否读到约束、有效授权能否持续，以及只读或暂停请求能否保持边界。格式检查、静态推演和实际运行各自只支持其覆盖范围。

本参考沿用 Matt Pocock 的 writing-for-agents 中条件引用、信息层级与正文归属的思路，并按 Codex 与本框架职责重新组织。
