# Yaya 框架任务交接

让下一对话能够核对原件并继续同一维护任务。只供框架维护使用，不随游戏项目分发；不把项目分发源的开发 Stage 当作维护任务状态。

## 核对真实停点

从当前请求判断交接目的：继续原任务、接着讨论某个决定，或完成尚缺的审核。沿用用户已说明的下一对话目标；未说明时根据真实剩余工作组织，只补问会实质改变交接内容的缺口。

核对与交接有关的材料，不重读无关全仓文档：

- **目标与授权**：原目标、当前范围、有效决定、可自主继续的工作与当前限制。依据[会话延续约定](../../../framework/docs/framework-maintenance/updating-the-blank-project.md#后续用口语继续)区分仍有效、已替代及尚未确认的要求。
- **真实现场**：实际目录、当前 Git 提交与必要差异、任务原件和当前仍运行的相关操作。读取现有 [Progress](../../../framework/progress.md) 与必要报告，核对摘要是否符合当前文件。
- **成果与证据**：哪些已完成、哪些只讨论过，实际做了哪些验证、失败在哪里、哪些未执行或仍需人工接受；历史结果保留版本和覆盖限制。
- **恢复位置**：真实剩余工作、阻塞与解除条件、下一对话的具体目的，以及接收方核对原件后应执行的第一步。必要 Skill 或方法按当前任务点名，不列整个工具目录。

## 按请求交付

默认在对话中给出可复制文本，引用原件路径，不重复抄写完整规范、报告或差异。已核实的信息写成事实，未知项明确保留；接收方须先确认实际目录、当前规则和原件，再沿用有效授权恢复。

用户需要可直接发送的续接指令时，按[任务提示词字段约定](../../../framework/review/baselines/skill-script-prompt-design.md#提示词字段与审核原则)组织完整代码块，填入本次真实信息；只要简短摘要时按所需详略输出，不为摘要套完整模板。

已有只读交接场景或仅摘要请求不写文件。当前授权包含必要记录维护时，按[框架待办规则](../../../AGENTS.md#维护边界与查阅)更新现有 Progress，原始证据仍归其现有位置；不另建 Handoff 文件、临时交接文档或状态台账，不为交接清空差异、回滚或制造提交。

## 完成与暂停

交接内容与当前事实一致，接收方能找到必要依据及恢复第一步时，本 Skill 完成交付。用户要求换对话或暂停时，交接后暂停原工作，等待明确续接；旧实施授权不取消本次暂停。仅要求摘要时，不因此取消原任务中仍有效的后续授权。

交接不补造产品决定、运行结果或人工接受，不自动创建对话或向其他对话发送消息。接收方的实际执行由用户续接请求和当时有效规则决定。
